## 1. 목적과 범위
- 목적: 이용약관·개인정보 처리방침·개인정보 수집·이용 동의·민감정보(건강 정보) 처리 동의를 DB(Supabase `account.legal_documents`)에서 관리하기 전에, 지금 문서에 무엇이 들어 있고 무엇이 채워졌고 무엇이 비어 있는지를 한 곳에서 확인한다(PRD-17 §1.1, BE-11-02 A).
- 범위: 개발 단계 반영(초안 검토 → v2 본문 → 시드 SQL → 원격 적용 → 프런트 표시)까지. 서비스는 상용이 아니라 포트폴리오이며 진단·처방·복용량 결정을 하지 않는다.
- 범위 밖: 법률 검토(Recap 9 보류), 법적 필수 기재 여부의 단정, 개인정보 처리방침 작성지침 PDF·개인정보보호위원회 해설서 대조(열지 못함, 아래 7장).
- 모든 본문에는 첫 줄 "초안·법률 검토 전" 안내가 있고 프런트 `LEGAL_NOT_REVIEWED_TAG`(`"초안·법률 검토 전"`)가 그대로 남는다.

## 2. 문서 4종과 age_14 현황
기준: 시드 파일 읽음(2026-11-20). 게시본은 트리거 `freeze_published_document`가 제목·본문·버전·종류 수정을 막으므로 고칠 때는 새 버전 행을 넣는다.

| 문서 종류 | 버전 | 필수·선택 | 재동의(`requires_reconsent`) | 게시 상태 |
|---|---|---|---|---|
| `terms` 이용약관 | v1(`seed_legal_v1.sql`), v2(`seed_legal_v2.sql`) | 필수 | v2 false | 원격 게시 전 |
| `privacy_policy` 개인정보 처리방침 | v1, v2 | 동의 대상 아님(고지, `required=false`, PRD-17-02 A) | v2 false | 원격 게시 전 |
| `privacy_consent` 개인정보 수집·이용 동의 | v1, v2 | 필수 | v2 true(수집 항목·외부 AI 전송 추가) | 원격 게시 전 |
| `sensitive_consent` 민감정보(건강) 처리 동의 | v1, v2 | 선택(`required=false`) | v2 true | 원격 게시 전 |
| `age_14` 만 14세 이상 확인 | v1(`seed_legal_age14.sql`) | 필수(첫 로그인 동의 화면의 별도 체크, PRD-17-09 A) | false | 원격 게시 전 |

- **v2 원격 게시 전**: 원격 `account` 스키마 적용(BE-11-23 A) 전이라 원격 DB에는 약관 행이 없다고 티켓이 기록하고 있다(PRD-17 §1.3). 이 문서를 쓰면서 원격은 다시 읽지 않았다(원격 읽기 전용 확인 결과는 별도로 기록해야 한다, PRD-17 §2 첫 완료 조건 미충족).
- **게시 차단**: `account_repo_pg.assert_publishable`가 `{{…}}` 자리표시(말줄임표 하나인 `{{…}}`는 제외)가 남은 시드의 원격 게시를 막는다(PRD-17-11 A, 허용 목록 없음). 현재 v2 시드에는 `{{PRIVACY_CONTACT}}`·`{{SUPABASE_REGION}}`·`{{BACKUP_RETENTION_DAYS}}`·Supabase 법인 `{{확인 필요: …}}`가 남아 있어 게시가 차단된다(시드 머리 주석 `seed_legal_v2.sql:9-14`와 본문 39·63·76행 등에서 확인). `{{EFFECTIVE_AT}}`는 적용 스크립트가 시행 시각으로 채운다.
- `age_14` 제목·본문은 "만 14세 이상입니다."이며 사용자 확인으로 확정됐다(PRD-17 §3 ⑬). `[필수 체크]`는 화면 표기라 본문에 넣지 않았다.
- v2 4종은 2026-11-19 밤(m36) 사용자가 문서별로 원문 승인했다(PRD-17 §3 ②). 이후 2026-11-20 성별 문구·OpenAI 줄·Recap 45 항목 반영도 사용자가 승인했다(4장).

## 5. 축소 범위와 사진 문구
- **정정(사용자 2026-11-20 "사진은 필수기능이야")**: 약봉투 사진은 필수 기능이다. 축소 대상은 음성 입력뿐이다(PJ2-RFP.md 4장 축소 순서 중 음성). 앞서 적은 "FR-11 사진 축소"는 철회한다.
- 사진 문구는 2026-11-20 승인돼 시드에 반영 중이다(메인 in-process 작업): 처리방침에 "사진을 올리면 약 이름을 읽기 위해 사진이 외부 AI(OpenAI)로 전송된다"는 문장을 넣고, 3절 OpenAI 줄에 위탁 업무(약봉투 사진에서 약 이름 읽기)와 이전 항목(사진)을 더한다. 문장 초안은 `recap45.md` §2 ⑦(a)(b)이고 반영 결과는 시드 현재 원문으로 확인해야 한다(이 문서 작성 시점에는 미확인).
- 사진 판독 제공자는 AG-17-02 A(`gpt-6-luna` 유지)이며 Upstage와 추가 평가 뒤 바뀔 수 있다(PRD-17 §3 ⑫ 메모). 바뀌면 3절 표의 받는 자 줄을 다시 정한다. Upstage 사실(법인 Upstage Co., Ltd. 서울특별시 강남구, 처리방침 시행 2026-11-02, 국외 이전 AWS·Azure·OpenAI 미국)은 기록만 해 둔다(공식 문서 2026-11-20 읽음, `solar-pro4`의 기본 엔드포인트 처리 국가는 확인하지 못함).
- 처리방침 2절의 "약봉투 사진과 음성은 저장하지 않습니다."는 유지한다.

## 6. 남은 일
1. **원격 적용(PRD-17 §3 ④, GROUP-03 4단계)**: 메인이 `data/mock/briefs`의 승인 flag를 실행 직전에 만들고 직후 지운다. `plan` → `apply --yes` → `verify` 순서. BE-11-23 A의 원격 `account` 스키마 적용과 같은 차례이며, `schema_account.sql`을 커밋한 뒤 `age_14` 시드를 따로 실행한다(enum 값 추가 제약, `seed_legal_age14.sql` 머리 주석). 기대 문서 행 수: v1 4 + v2 4 + `age_14` 1(원래 완료 조건은 8, `age_14` 추가로 9가 되는지는 확인 필요).
2. **자리표시 채우기(⑫)**: 4.2의 값이 정해지면 원격 게시 전에 시드의 자리표시만 채운다(본문 문장은 승인 원문 그대로, 문장 수정은 사용자 승인). 그 전에는 `assert_publishable`이 게시를 막는다.
3. **프런트 표시 확인(⑤)**·`age_14` 체크(⑥)·성별 항목(FE-04, GROUP-03 2단계)은 해당 티켓 몫이다.
4. **법률 검토는 보류(Recap 9)**: 개인정보 보호법 조문 대조는 해석이며 처리방침 작성지침 등은 열지 못했다. `legal_review='reviewed'`·"법률 검토 완료" 표현은 어떤 산출물에도 쓰지 않는다.
