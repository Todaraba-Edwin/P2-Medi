## 1. 제품 개요
### 1.1 한 줄 정의
금기 판정과 사실은 공공 API·파일 데이터·문서에서 **코드가 가져오고**, LLM 에이전트는 도구 선택과 근거 탐색, 쉬운 설명·종합만 맡는 **근거 기반 질의응답 에이전트**다. 약품 정보 조회와 병용·연령·임부 금기 확인이 이를 다루기 위한 도메인이다.

### 1.2 프로젝트 성격
| 항목 | 내용 |
|---|---|
| 성격 | **상용 서비스가 아니라 취업 포트폴리오**(3주·1인). 핵심 목표는 Agent-RAG를 활용한 AX(AI 전환) 경험, 곧 에이전트(입력 정리, 도구 선택, 근거 고정, Validator)를 직접 설계·구현·평가하고 **수치로 개선을 보이는 것** |
| 표시 이름 | **Can I Biyak**(한글 삐약). `Biyak`은 삐약(병아리 소리)의 영어 음역이고 "삐"는 금지·경고의 뜻도 담는다(PRD-06-01) |
| 코드명 | **MediAgent**(저장소 P2-Medi, 코드 패키지, 티켓, 환경변수) |
| 마스코트 | 병아리 마스코트는 **보조 자리에만** 쓰고 응급·금기 결과·고정 문구 영역에는 쓰지 않는다. "삐!" 경고는 금기 결과의 경고 표지(글자·아이콘)로만 쓰고 소리는 쓰지 않는다(PRD-06-02·03) |
| 원칙 | 진단·처방·복용량 결정을 하는 서비스가 아니다. 공공데이터 기반 정보 제공이며 응답은 의료적 판단을 대신하지 않는다. 책임을 지지 않는 대신 모든 답변에 근거를 달고, 금기가 조회되지 않아도 안전하다고 말하지 않으며, 근처 약국·약사에게 확인하도록 안내한다 |

### 1.3 코드로 강제하는 것과 LLM이 하는 것
| 코드가 맡는다(프롬프트에 의존하지 않음) | LLM 에이전트가 맡는다 |
|---|---|
| 금기 판정(성분코드 일치), 응급 시 119 안내, 고정 문구·약국·약사 안내, Validator 검사, 입구 거절, 모델 호출 상한(8회)·되돌림(2회) | 도구 선택, 근거 탐색, 쉬운 말로 설명·종합 |
- 이 구분은 하네스 설계의 중심이다. 규칙마다 Guide(프롬프트·지침)와 Sensor(코드 검사·judge)를 짝지은 매트릭스는 `tickets/doc/RFP-29.md` §6에 있다.

## 2. 대상 사용자와 사용 장면
### 2.1 사용자
| 구분 | 대상 | 설명 |
|---|---|---|
| 주 사용자 | 일반인(비의료인) | 임산부·영유아·아동·고령자(만성질환 약을 여러 개 복용)가 있는 집의 보호자·본인 |
| 확장 사용자 | 의료인·약사 | 같은 답변의 **근거 상세**(성분코드·고시 조항·등급·기준일)를 펼쳐 볼 수 있을 뿐, 전문가 전용 기능(처방 점검, 환자 기록)은 두지 않는다 |

### 2.2 사용 장면
- 응급 상황이나 평소에, 집에 있는 **상비·응급 의약품과 보유 의약품을 먹기 전에** 병용·연령·임부 금기와 중복·용량 주의를 스스로 확인한다.
- 전문가의 판단을 바로 받기 어려운 때 **근거를 확인하는 용도**다. 복용 여부와 용량은 정해 주지 않는다.
- 응급 신호(예: 아이가 약을 삼킴)가 있으면 119 안내를 맨 위에 두되 금기 조회는 막지 않는다. 로그인 없이(게스트) 바로 쓸 수 있어야 한다.

### 2.3 페르소나(가상, 요구 검증용)
`tickets/doc/RFP-21.md` §4.2의 세 명을 쓴다. 실제 공공 API 응답으로 검증한 사례다.
| ID | 인물 | 상황 | 이 제품이 보여 줘야 하는 것 |
|---|---|---|---|
| P1 | 지은(34세)과 아들 도윤(만 2세) | 어린이 타이레놀을 먹였고 기침약을 더 줘도 되는지 묻는다 | 제품 연령, 성분 중복, 용량을 **정하지 않는** 응답 |
| P2 | 수아(31세, 임신 14주) | 열이 나서 집의 타이레놀을 먹어도 되는지 묻는다 | 임부금기, "금기 목록에 없음"(안전하다는 뜻이 아님), 라벨 보완 |
| P3 | 박순자(78세, 파킨슨병)와 딸 | 라사길린을 드시는 어머니에게 감기약(콜드-에스)을 같이 먹여도 되는지 묻는다 | 병용금기 해당, 파일과 API 비교 |

## 3. 문제와 수요 근거
### 3.1 문제
| 문제 | 설명 |
|---|---|
| 최신성 | 허가 사항·금기 기준이 바뀌어도 LLM 내부 지식은 반영되지 않는다 |
| 추적성 | 의료·보건 답변은 출처(데이터·조항)를 댈 수 있어야 한다 |
| 데이터 분산 | 약품 정보는 API, 금기 정보는 API·파일 데이터·고시(PDF)에 흩어져 있다 |
| 입력 불확실성 | 오탈자, 축약, 범위 밖 질문, 잘못된 전제 질문 |
| 오남용 위험 | 일반인은 임산부·아동에게 응급·상비 의약품을 먹이거나 보유 의약품을 함께 먹을 때 병용·연령·임부 금기를 확인하기 어렵다 |

### 3.2 수요 근거(수요 확인 사례일 뿐)
- 원스글로벌 Dr.DI·ConnectDI 같은 의약품 정보 서비스가 이미 운영되고 의약정보 AI의 환각 검증이 쟁점이 된 것은, 이 아이디어에 **가능성이 있음을 확인해 주는 사례**다(발표 자료 9~11쪽).
- 이 프로젝트는 Dr.DI를 **재현하거나 같은 수준의 제품을 만들지 않으며 성능 수치도 비교하지 않는다.** 같은 문제를 Agent-RAG의 대상 도메인으로 삼아 3주·1인 규모의 유사한 축소판을 만들고 한계를 정리해 포트폴리오에 담는다.
- 이 서비스는 **처방·제안을 하지 않고 정보와 근거만 준다.** 복용 중단·감량 방법을 제시하거나 의료진을 우회하게 하는 답은 범위 밖이며 거절한다(범위 외 문항에 이 유형을 포함, RFP-28-01). 근거 사례와 배경은 `tickets/doc/RFP-28.md` §9에 있다.

## 4. 목표와 성공 기준
### 4.1 목표 5개
1. 질문 → 도구 선택 → 근거 조회 → 출처가 붙은 답변까지 끝단 동작
2. 정형(API·파일 데이터)·비정형(PDF) 하이브리드 검색
3. 환각 방지 장치(근거 고정·검증·안전 응답) 구현
4. 직접 측정한 평가 수치로 개선 전후 비교
5. Dr.DI 등으로 확인되는 아이디어의 가능성을 3주·1인 규모의 축소판으로 Agent-RAG에 적용해 보고 한계를 정리해 포트폴리오로 남김

### 4.2 성공 기준
| 구분 | 기준 | 원본 |
|---|---|---|
| 포트폴리오 성공 | 에이전트를 직접 설계·구현·**평가**하고 전후 **수치**로 개선을 보인다. **결과가 어느 쪽이어도 그대로 보고**하고 "언제 에이전트가 이득인가"로 서술한다 | RFP 3장, RFP-23 §5.1 |
| 주차 완료 기준 | 1주: API 조회·금기 조회·문서 검색 각각 동작 / 2주: 질문 → 답변 끝단 동작(함수 호출 수준), Ragas 3지표 기준선 확보 / 3주: 전후 수치와 한계 정리 | RFP 10장 |
| 범위 제어 | 주차 완료 기준에 미달하면 **확장부터** 줄이고 입력 정리·도구 선택·근거 고정·Validator·평가 수치는 줄이지 않는다 | RFP 4장 |

### 4.3 평가 지표 5개(잠정 목표, 측정 전)
| 지표 | 대상 | 채점 | 목표(잠정) |
|---|---|---|---|
| 검색 정확도 | 근거 검색이 필요한 정상·모호 문항 | Ragas(judge) | 기준선 대비 개선 |
| 답변 충실도 | 같은 문항 | Ragas(judge) | 기준선 대비 개선 |
| 오탈자 견고성 | 오탈자·축약·표기 변형 20문항과 짝이 되는 정상 문항 | 코드 | 하락 10%p 이하 |
| 안전 응답률 | 범위 외·오정보·근거 없음·응급·금기 목록에 없는 약 | 고정 문구·119·약사 안내·안전 단정은 코드, 정정·거절·근거 없음 응답은 judge(J3~J5) | 고정 문구·119는 100%, 나머지 90% 이상 |
| 금기 판정 정답률 | 병용·연령·임부 금기 35문항(금기등급 M 포함) | 코드 | 95% 이상 |
- 목표 수치는 **근거 자료가 없는 잠정값**(RFP-22-11)이다. 결과는 k/n과 Wilson 95% 구간으로 보고하고 칸당 n이 8 이하면 유의성을 주장하지 않는다(PJ2-RFP.md 9.1절). 지표 정의의 원본은 PJ2-RFP.md 9.3절이다.

## 5. 범위
### 5.1 포함과 제외
| 구분 | 포함 | 제외 |
|---|---|---|
| 핵심(필수) | 약품 정보 조회, 병용·연령·임부 금기 확인(복용 전 자가 확인), 쉬운 요약 + 펼치는 근거 상세 | 진단, 처방, 복용량 결정(공식 기준값을 인용해 보여 주는 것은 포함) |
| 확장(권장) | 성분 중복 확인, DUR 효능군 중복·용량·투여기간 주의 조회, 수유부·노인 주의, 온보딩 프로필(본인 + 가족 1명), 이메일 계정 서버 저장 | 소셜 로그인(SNS 연동)은 다루지 않는다(2026-11-03 사용자) |
| 제외 | | 진료·처방 이력 등 의료기록 처리(사용자가 동의해 입력한 프로필 저장만 확장에 포함, 질문·대화 내용은 저장하지 않음) |
| 제외 | | 전문가 전용 기능(처방 점검, 환자 단위 기록), 요양기관 DUR 점검의 대체 |
| 제외 | | 상용 서비스 요소(과금, 약국 검색, 운영 모니터링), 대규모 문서 전수 수집(핵심 PDF 소수로 시작) |
| 제외(2026-10-31) | | 국가건강검진 대상·주기 안내, 보건사업 자격 요건 안내 |

### 5.2 범위 축소 규칙
- 핵심을 먼저 끝내고 확장은 핵심의 주차 완료 기준을 채운 뒤에 한다. 미달하면 확장부터 줄이며 순서는 **프로필 저장(대화 중 입력으로 대체) → 오탈자 보정(FR-07) → 열린 질문 retrieval(AG-15) → 수유부·노인 주의 → 중복·용량**이다.
- **응급 처리(FR-06)는 필수**라 축소 대상이 아니다.
- 로그인(확장)은 Agent-RAG 핵심이 끝난 뒤에만 하고 미달 시 가장 먼저 줄인다. 게스트로 핵심 기능을 모두 쓸 수 있어야 한다.

## 6. 요구사항
### 6.1 기능 요구사항(FR)
ID는 요구서 6장과 같다. "추적"은 구현·추적 티켓과 측정 지표다. 수용 기준은 요구서의 문장을 검사 가능한 형태로 옮긴 것이다.
| ID | 요구사항 | 우선 | 수용 기준(요지) | 추적(티켓·지표) |
|---|---|---|---|---|
| FR-01 | **입력 정리(Router)**: 질문에서 약품명·연령·임신 여부·질환을 추출하고 모호 여부·질문 유형을 판정해 상태에 기록한다. 도구 선택은 에이전트(ReAct)가 한다 | 필수 | 엔티티 추출이 샘플 질문에서 테스트로 확인되고 질문·대화는 저장되지 않는다 | RFP-02, AG-05 · 라우팅 정확도 |
| FR-02 | **공공 API Tool**: e약은요·DUR·허가정보 조회, 조회 시각 기록 | 필수 | 세 서비스 조회가 동작하고 조회 시각이 응답에 있다 | RFP-03, BE-02·03, AG-02 · 금기 판정 정답률 |
| FR-03 | **문서 RAG**: 표를 마크다운으로 보존해 파싱, 메타데이터 필터 검색 | 필수 | 표 샘플 3건 이상 보존, 필터 검색 동작 | RFP-04, BE-04·05, AG-03 · 검색 정확도 |
| FR-04 | **Citation**: 모든 답변에 출처·조회 시각(또는 기준일)·조항 표기, 쉬운 요약 먼저 + 근거 상세 펼침, 용법용량은 원문을 근거 상세에만 인용 | 필수 | 요약에 용량 숫자가 없고 출처·기준일이 항상 있다 | RFP-05, AG-06 · 답변 충실도 |
| FR-05 | **Validator**: 답변이 원본 API·문서와 일치하는지 점검 후 출력 | 필수 | 근거에 없는 문장·값이 든 답은 차단 또는 수정된다 | RFP-06, AG-07 · 답변 충실도, 안전 응답률 |
| FR-06 | **Guardrail**: 진단·처방 금지, 응급 키워드면 119를 맨 위에 두고 금기 조회는 막지 않음, 범위 외 거절, 고정 문구(안전 단정 금지·약국·약사 안내)를 코드로 부착 | 필수 | 응급 질문의 응답은 119가 맨 위, 모든 응답에 고정 문구 | RFP-07, AG-08 · 안전 응답률 |
| FR-07 | **오탈자 보정**: 약품명 오입력 시 정규화 후 재검색 | 권장 | 오탈자·표기 변형 샘플 5건 이상이 올바른 약으로 보정되고 표시된다 | RFP-08, AG-10, BE-07 · 오탈자 견고성 |
| FR-08 | **근거 없음 처리**: 근거가 없으면 지어내지 않고 모른다고 응답하며 "금기 목록에 없음"과 "근거 없음"을 구분 | 필수 | 두 경우가 서로 다른 문구로 나오고 약사 안내가 붙는다 | RFP-09, AG-09 · 안전 응답률 |
| FR-09 | **온보딩·프로필(확장)**: 프로필(연령대·임신 여부·복용 중인 약(선택))과 저장 동의를 받고 가족 1명까지 추가, 수정·삭제, 이메일 계정(Supabase Auth)으로 서버 저장, 게스트도 모든 핵심 기능 사용 | 권장(확장) | 계정 삭제까지 가능, 본인 행만 접근(RLS), 게스트는 저장 없음 | RFP-20, BE-11, FE-04 |
| FR-10 | **되묻기**: 약 이름이 모호하면 후보 표와 질문 1개로 되묻고 가부는 말하지 않는다 | 필수 | 후보 여럿인 질문에 후보 표와 질문 1개만 나온다 | RFP-27, AG-05·06 · 모호 20문항(분기 정답) |

## 9. 평가와 비교 조건
- **평가 세트**: 시험셋 약 150문항(정상 병용 15·연령 10·임부 10·목록에 없는 약 10·응급 10, 오탈자·축약·표기 20, 모호 20, 오정보 20, 근거 없음 20, 범위 외 15) + 별도 개발셋. 개선은 개발셋만 보고 하고 시험셋은 개선 중 열람하지 않는다(RFP-26-04).
- **비교 조건**: C0 LLM 단독 / C1 고정 파이프라인 / C1+ 강화 / C2 ReAct 에이전트(MediAgent) / C3 개선 후(자유도 L2). 가설은 측정 전에 고정하며 결과가 반대여도 그대로 보고한다.
- **보조 지표**: 라우팅 정확도, retrieval 보조, **경로(Trajectory) 평가**(코드 채점), 비용, **신뢰성**(`pass^3`·`pass@3`, 안전 핵심 40문항 3회).
- 세부 정의·표본 규칙은 PJ2-RFP.md 9장, judge 루브릭은 `tickets/doc/RFP-26.md` §7.5.

- **시험으로 정함**: 표 파서(별표 2의 46~50쪽, 행 수 211), 임베딩 모델·색인 방식, 적재 크기 500MB.
- **확인 필요**: AWS 계정 개설일·플랜(W3), 모델별 호출 한도, Anthropic·Upstage 약관 원문, Upstage 단가, 이메일 인증 메일 발송 한도.
- **보류**: 법률 검토(민감정보 별도 동의, 개인정보, 의료기기 해당 여부, 공공 자료 이용 조건).

| 용어 | 뜻 |
