## 1. 제품 개요
### 1.1 한 줄 정의
금기 판정과 사실은 공공 API·파일 데이터·문서에서 **코드가 가져오고**, LLM 에이전트는 도구 선택과 근거 탐색, 쉬운 설명·종합만 맡는 **근거 기반 질의응답 에이전트**다. 약품 정보 조회와 병용·연령·임부 금기 확인이 이를 다루기 위한 도메인이다.

### 1.2 프로젝트 성격
| 항목 | 내용 |
|---|---|
| 성격 | **상용 서비스가 아니라 취업 포트폴리오**(3주·1인). 핵심 목표는 Agent-RAG를 활용한 AX(AI 전환) 경험, 곧 에이전트(입력 정리, 도구 선택, 근거 고정, Validator)를 직접 설계·구현·평가하고 **수치로 개선을 보이는 것** |
| 표시 이름 | **Can I PPiyak**(한글 삐약). `PPiyak`은 삐약(병아리 소리)의 로마자 표기(국어 로마자 표기법)이고 "삐"는 금지·경고의 뜻도 담는다(PRD-06-01) |
| 코드명 | **MediAgent**(저장소 P2-Medi, 코드 패키지, 티켓, 환경변수) |
| 마스코트·로고·아이콘 | 병아리 마스코트는 **보조 자리에만** 쓴다: 시작 화면 대표 이미지(질문 병아리), 로딩·진행 표시(Agent 도구 호출 중 돋보기 병아리), 빈 상태·오류, 되묻기 카드(작게), 프로필 기본 이미지(병아리 얼굴, FE-04). **응급·금기 결과·"금기 목록에 없음"·고정 문구 영역에는 쓰지 않는다.** **로고와 favicon은 병아리 없는 캡슐 말풍선 심볼**이고(FE-06-01 A), 약 목록·확인 카드·제품 정보 같은 의약품 영역에는 캡슐 말풍선 아이콘을 쓴다. 로고 이미지에는 서비스 이름 글자가 들어 있어 README·발표 표지 같은 정적 브랜딩 자리에만 쓰고 화면 헤더의 이름은 텍스트로 둔다. "삐!" 경고는 금기 결과의 경고 표지(글자·아이콘)로만 쓰고 소리는 쓰지 않는다(PRD-06-02·03, 자산·용도는 FE-06) |
| 원칙 | 진단·처방·복용량 결정을 하는 서비스가 아니다. 공공데이터 기반 정보 제공이며 응답은 의료적 판단을 대신하지 않는다. 책임을 지지 않는 대신 모든 답변에 근거를 달고, 금기가 조회되지 않아도 안전하다고 말하지 않으며, 근처 약국·약사에게 확인하도록 안내한다 |

### 1.3 코드로 강제하는 것과 LLM이 하는 것
| 코드가 맡는다(프롬프트에 의존하지 않음) | LLM 에이전트가 맡는다 |
|---|---|
| 금기 판정(성분코드 일치), 응급 시 119 안내, 고정 문구·약국·약사 안내, Validator 검사, 입구 거절, 모델 호출 상한(8회)·되돌림(2회) | 도구 선택, 근거 탐색, 쉬운 말로 설명·종합 |
- 이 구분은 하네스 설계의 중심이다. 규칙마다 Guide(프롬프트·지침)와 Sensor(코드 검사·judge)를 짝지은 매트릭스는 `tickets/doc/RFP-29.md` §6에 있다.

## 2. 대상 사용자와 사용 장면
### 2.1 사용자
| 구분 | 대상 | 설명 |
|---|---|---|
| 주 사용자 | 일반인(비의료인) | 임산부·영유아·아동·고령자(만성질환 약을 여러 개 복용)가 있는 집의 보호자·본인 |
| 확장 사용자 | 의료인·약사 | 같은 답변의 **근거 상세**(성분코드·고시 조항·등급·기준일)를 펼쳐 볼 수 있을 뿐, 전문가 전용 기능(처방 점검, 환자 기록)은 두지 않는다 |

### 2.2 사용 장면
- 응급 상황이나 평소에, 집에 있는 **상비·응급 의약품과 보유 의약품을 먹기 전에** 병용·연령·임부 금기와 중복·용량 주의를 스스로 확인한다.
- 전문가의 판단을 바로 받기 어려운 때 **근거를 확인하는 용도**다. 복용 여부와 용량은 정해 주지 않는다.
- 응급 신호(예: 아이가 약을 삼킴)가 있으면 119 안내를 맨 위에 두되 금기 조회는 막지 않는다. 로그인 없이(게스트) 바로 쓸 수 있어야 한다.

### 2.3 페르소나(가상, 요구 검증용)
`tickets/doc/RFP-21.md` §4.2의 세 명을 쓴다. 실제 공공 API 응답으로 검증한 사례다.
| ID | 인물 | 상황 | 이 제품이 보여 줘야 하는 것 |
|---|---|---|---|
| P1 | 지은(34세)과 아들 도윤(만 2세) | 어린이 타이레놀을 먹였고 기침약을 더 줘도 되는지 묻는다 | 제품 연령, 성분 중복, 용량을 **정하지 않는** 응답 |
| P2 | 수아(31세, 임신 14주) | 열이 나서 집의 타이레놀을 먹어도 되는지 묻는다 | 임부금기, "금기 목록에 없음"(안전하다는 뜻이 아님), 라벨 보완 |
| P3 | 박순자(78세, 파킨슨병)와 딸 | 라사길린을 드시는 어머니에게 감기약(콜드-에스)을 같이 먹여도 되는지 묻는다 | 병용금기 해당, 파일과 API 비교 |

## 3. 문제와 수요 근거
### 3.1 문제
| 문제 | 설명 |
|---|---|
| 최신성 | 허가 사항·금기 기준이 바뀌어도 LLM 내부 지식은 반영되지 않는다 |
| 추적성 | 의료·보건 답변은 출처(데이터·조항)를 댈 수 있어야 한다 |
| 데이터 분산 | 약품 정보는 API, 금기 정보는 API·파일 데이터·고시(PDF)에 흩어져 있다 |
| 입력 불확실성 | 오탈자, 축약, 범위 밖 질문, 잘못된 전제 질문 |
| 오남용 위험 | 일반인은 임산부·아동에게 응급·상비 의약품을 먹이거나 보유 의약품을 함께 먹을 때 병용·연령·임부 금기를 확인하기 어렵다 |

### 3.2 수요 근거(수요 확인 사례일 뿐)
- 원스글로벌 Dr.DI·ConnectDI 같은 의약품 정보 서비스가 이미 운영되고 의약정보 AI의 환각 검증이 쟁점이 된 것은, 이 아이디어에 **가능성이 있음을 확인해 주는 사례**다(발표 자료 9~11쪽).
- 이 프로젝트는 Dr.DI를 **재현하거나 같은 수준의 제품을 만들지 않으며 성능 수치도 비교하지 않는다.** 같은 문제를 Agent-RAG의 대상 도메인으로 삼아 3주·1인 규모의 유사한 축소판을 만들고 한계를 정리해 포트폴리오에 담는다.
- 이 서비스는 **처방·제안을 하지 않고 정보와 근거만 준다.** 복용 중단·감량 방법을 제시하거나 의료진을 우회하게 하는 답은 범위 밖이며 거절한다(범위 외 문항에 이 유형을 포함, RFP-28-01). 근거 사례와 배경은 `tickets/doc/RFP-28.md` §9에 있다.

## 4. 목표와 성공 기준
### 4.1 목표 5개
1. 질문 → 도구 선택 → 근거 조회 → 출처가 붙은 답변까지 끝단 동작
2. 정형(API·파일 데이터)·비정형(PDF) 하이브리드 검색
3. 환각 방지 장치(근거 고정·검증·안전 응답) 구현
4. 직접 측정한 평가 수치로 개선 전후 비교
5. Dr.DI 등으로 확인되는 아이디어의 가능성을 3주·1인 규모의 축소판으로 Agent-RAG에 적용해 보고 한계를 정리해 포트폴리오로 남김

### 4.2 성공 기준
| 구분 | 기준 | 원본 |
|---|---|---|
| 포트폴리오 성공 | 에이전트를 직접 설계·구현·**평가**하고 전후 **수치**로 개선을 보인다. **결과가 어느 쪽이어도 그대로 보고**하고 "언제 에이전트가 이득인가"로 서술한다 | RFP 3장, RFP-23 §5.1 |
| 주차 완료 기준 | 1주: API 조회·금기 조회·문서 검색 각각 동작 / 2주: 질문 → 답변 끝단 동작(함수 호출 수준), Ragas 3지표 기준선 확보 / 3주: 전후 수치와 한계 정리 | RFP 10장 |
| 범위 제어 | 주차 완료 기준에 미달하면 **확장부터** 줄이고 입력 정리·도구 선택·근거 고정·Validator·평가 수치는 줄이지 않는다 | RFP 4장 |

### 4.3 평가 지표 5개(잠정 목표, 측정 전)
| 지표 | 대상 | 채점 | 목표(잠정) |
|---|---|---|---|
| 검색 정확도 | 근거 검색이 필요한 정상·모호 문항 | Ragas(judge) | 기준선 대비 개선 |
| 답변 충실도 | 같은 문항 | Ragas(judge) | 기준선 대비 개선 |
| 오탈자 견고성 | 오탈자·축약·표기 변형 20문항과 짝이 되는 정상 문항 | 코드 | 하락 10%p 이하 |
| 안전 응답률 | 범위 외·오정보·근거 없음·응급·금기 목록에 없는 약 | 고정 문구·119·약사 안내·안전 단정은 코드, 정정·거절·근거 없음 응답은 judge(J3~J5) | 고정 문구·119는 100%, 나머지 90% 이상 |
| 금기 판정 정답률 | 병용·연령·임부 금기 35문항(금기등급 M 포함) | 코드 | 95% 이상 |
- 목표 수치는 **근거 자료가 없는 잠정값**(RFP-22-11)이다. 결과는 k/n과 Wilson 95% 구간으로 보고하고 칸당 n이 8 이하면 유의성을 주장하지 않는다(PJ2-RFP.md 9.1절). 지표 정의의 원본은 PJ2-RFP.md 9.3절이다.

## 5. 범위
### 5.1 포함과 제외

### 5.2 범위 축소 규칙
- 핵심을 먼저 끝내고 확장은 핵심의 주차 완료 기준을 채운 뒤에 한다. 미달하면 확장부터 줄이며 순서는 **사진·음성 입력(FR-11, 텍스트 입력으로 대체) → 프로필 저장(대화 중 입력으로 대체) → 오탈자 보정(FR-07) → 열린 질문 retrieval(AG-15) → 수유부·노인 주의 → 중복·용량**이다.
- **응급 처리(FR-06)는 필수**라 축소 대상이 아니다.
- 로그인(확장)은 Agent-RAG 핵심이 끝난 뒤에만 하고, 미달 시 위 순서대로 사진·음성 입력(FR-11) 다음에 프로필 저장과 함께 줄인다(PJ2-RFP.md 4장 축소 순서가 원본, 2026-11-07 정리). 게스트로 핵심 기능을 모두 쓸 수 있어야 한다.

### 15.1 읽는 법
- **8단계 기본 경로**: 1 입력 정리 → 2 제품 찾기 → 3 성분 풀기 → 4 금기 확인 → 5 근거 찾기 → 6 요약 쓰기 → 7 검증 → 8 마무리. 1단계 입구와 7~8단계 출구, 필수 도구 호출 확인은 **코드가 강제**하고 2~5단계는 **에이전트(ReAct)가 도구를 골라** 수행한다.
- **응답 필드**(BE-06): `summary`(쉬운 요약), `detail`(근거 상세), `citations[]`(출처·조회 시각 또는 기준일·조항), `fixed_notice`(코드가 붙인 고정 문구와 약국·약사 안내), `emergency`(응급이면 119 안내), `disclaimer`, `route`. 응급이면 `emergency`가 **스트리밍의 첫 이벤트**로 먼저 온다.
- 표의 **시스템** 열은 `코드`(결정적)와 `에이전트`(LLM이 고름)를 구분한다. **화면** 열의 이름은 15.4절 화면 상태 표의 상태 이름이다.
- 모든 질문과 답은 **합성·가상 사례**이며 실제 환자 정보가 아니다. 값은 공공 API·파일로 확인한 것이다(RFP-21).

#### (9) S9. 외부 LLM 전송 고지
> **고지이지 승인(동의) 절차가 아니다.** 화면에 안내 문구를 **보여 주는 것**이며, 사용자가 체크하거나 누르지 않으면 질문이 막히는 **동의 관문을 두지 않는다**(게스트와 응급 질문이 막히면 안 된다). 별도 동의가 법적으로 필요한지는 법률 검토 보류 항목이다(PJ2-RFP.md 12장). 동의를 받는 곳은 **프로필 저장**(S10 2단계) 하나뿐이다.
| 위치 | 내용 | 상태 |
|---|---|---|
| 시작 화면(입력창 가까이) | "질문과 입력한 프로필은 답변 생성을 위해 외부 AI 서비스로 전송되며, 제공자 정책에 따라 일정 기간 보관될 수 있습니다" | 질문을 보내기 전에 보인다 |
| 상시 고지 영역 | 위 문장 + "공공데이터 기반 정보 제공이며 진단·처방이 아님" 등 | 모든 화면 |
- **결정 PRD-07-02 A(2026-11-04)**: 문구에 **제공자 쪽 보관**을 넣는다(OpenAI API 로그 최대 30일 보관, RFP-15 §8.1). 이는 **보관 고지**이며 "학습에 쓰인다/쓰이지 않는다"를 단정하지 않는다. OpenAI API 문서는 API 데이터를 기본적으로 학습에 쓰지 않는다고 밝히지만 제공자·약관은 바뀔 수 있고 법률 검토는 보류 상태이므로, 학습 사용 여부는 **"제공자 정책에 따라"**로만 쓴다. 정확한 문구는 FE-02에서 확정한다.
- **결정 PRD-08-04 A(2026-11-06)**: 사진·음성 입력(FR-11)을 쓰면 고지 범위에 **약봉투 사진·음성**도 들어간다(예: "질문, 입력한 프로필, 올린 사진은 답변 생성을 위해 외부 AI 서비스로 전송되며…"). 사진 올리기 화면에 같은 고지와 개인정보 가림 안내를 둔다(S11). 여전히 고지이며 동의 관문이 아니다.

#### (11) S11. 약봉투 사진(확장)
상황(P3 딸): 어머니(78세)가 약국에서 받은 약봉투를 찍어 올리고, 감기라서 사 온 타이레놀 콜드-에스를 같이 드려도 되는지 확인한다. 약봉투 사진은 **합성·가상 이미지**를 쓴다. 약봉투 표기(상품명이 기본, 성분명은 항상 있지 않음)의 근거는 [PRD-08 §3.1](../tickets/doc/PRD-08.md#31-약국-조제약-추적-가능성-검토)에 있다.
