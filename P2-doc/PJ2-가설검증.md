# PJ2 가설 검증 · 일반인 의약품 오남용 예방 AX

> 대상: 의약품 전문 지식이 없는 일반인(보호자, 임산부 본인과 배우자, 고령 부모를 돌보는 가족 포함). 의료인은 확장 사용자다.
> 목적: MediAgent(Agent-RAG)가 "같이 먹어도 되나요?" 같은 질문에서 오남용 위험(성분 중복, 연령 부적합, 병용금기, 임부금기)을 근거와 함께 짚어 내는지 시나리오로 검증한다. 실제 사용자의 오남용이 줄었는지는 측정하지 않는다. 이 프로젝트는 3주·1인 개발의 취업 포트폴리오이고, 증명하려는 것은 Agent-RAG의 설계·구현·평가다.
> 연결 문서: `PJ2-RFP.md` (FR-01~09, 4장 범위, 9장 평가), `claude-prompt/03_legal_and_medical.md`
> 범위 표시: 핵심 = 병용·연령·임부 금기. 확장 = 성분 중복, 용량·투여기간 주의, 수유부·노인 주의(조건부), 온보딩·로그인. 확장의 축소 순서와 세부는 RFP 4장을 따른다. 복용 여부를 정하지 않고, 스스로 계산한 용량을 말하지 않는다. 출처가 있는 라벨·DUR 값을 인용해 보여 주는 것은 허용한다(RFP 4장).
> 용어: 이 문서의 "LLM 단독"은 도구 없이 모델 기억만 쓰는 조건이다. RFP 9장과 AG-11의 "기준선"은 개선 전 MediAgent의 수치를 뜻하므로 서로 다르다.
> 데이터 사실 표시: "파일에서 확인한 사실"은 병용금기 JSON·임부금기 CSV(기준일 2026-07-21)를 직접 조회한 결과이며 임상 해석이 아니다.

## 1. 대표 시나리오 해부

### 1.1 아동: 8세 여아

**질문**: "8세 여아가 A 약과 타이레놀을 먹으려 해. 괜찮니?"

일반인에게는 질문 하나지만, 안전하게 답하려면 판단이 6단계 필요하다.

| 단계 | 판단 | 왜 필요한가 | 데이터 | 처리 방식 | RFP 범위 |
|---|---|---|---|---|---|
| 1 | **"타이레놀"이 어떤 제품인가** | 타이레놀정 500mg은 만 12세 이상용. 12세 미만은 80·160mg정, 현탁액 등 어린이용 제품 | e약은요 (제품별 사용법 문장) | API로 제품 특정 + **문장 retrieval·인용** | 핵심 |
| 2 | **A 약이 무엇인가** | 브랜드명·오탈자·별칭을 실제 허가 제품으로 특정 | e약은요, 제품명→성분코드 매핑 | API + 규칙 | 핵심 |
| 3 | **성분이 겹치는가** | 종합감기약 등에 아세트아미노펜이 들어 있으면 중복 복용. 라벨: "아세트아미노펜을 포함하는 다른 제품과 함께 복용하지 마세요" | 제품명→성분코드 매핑으로 성분코드 비교, e약은요 (성분·주의) | 규칙(코드 비교) + 라벨 문장 인용 | 확장 |
| 4 | **병용금기인가** | 두 성분이 DUR 병용금기 조합인지 | DUR 병용금기 (파일 적재 + API, 성분코드 정확 일치) | 규칙·API (**retrieval 아님**) + 사유·고시 인용 | 핵심 |
| 5 | **8세에 금기인가** | A 약 성분이 소아 연령금기인지 (예: 코데인 12세 미만 금기, 서방형 아세트아미노펜 12세 미만 금기, 2015년 보도 기준) | DUR 연령금기 (API) | API | 핵심 |
| 6 | **용량을 말해도 되는가** | 소아 용량은 체중과 제품에 따라 다름. 체중 없이 숫자를 말하지 않음 | 제품 라벨 | 결정하지 않음. 라벨 용량표 인용·약사 안내 | 제외 |

> 1·3번은 DUR 병용금기 조회만으로는 잡히지 않는다. 일반 LLM이 가장 쉽게 놓치는 지점이고, MediAgent의 차별점이 된다. 다만 3번(성분 중복)은 확장이라, 일정이 모자라면 확장 중에서도 마지막 순서로 줄인다(RFP 4장 순서).

### 기대 응답 구조: 아동

쉬운 요약을 먼저 보이고, 근거 상세(성분코드·등급·조항·기준일)는 펼쳐 볼 수 있게 한다(RFP FR-04). 고정 문구는 프롬프트가 아니라 코드로 붙인다(RFP FR-06).

```
[요약] 복용해도 되는지는 정해 드릴 수 없습니다. 확인된 내용은 아래와 같습니다.
1. 드시려는 타이레놀이 어떤 제품인가요? 타이레놀정 500mg은 만 12세 이상용입니다. [근거: e약은요 사용법 문장, 조회 시각]
2. A 약에 아세트아미노펜이 [포함/미포함]되어 있습니다. [포함 시: 같은 성분을 중복으로 먹게 됩니다.] [근거]
3. 공공데이터 기준 두 성분은 병용금기로 [등록되어 있습니다/등록되어 있지 않습니다]. A 약 성분의 연령금기 여부: [조회 결과]. [근거]
4. 어린이 복용량은 체중과 제품 라벨 기준입니다. 정확한 양은 제품 용량표나 약국·약사에게 확인해 주세요.
[고정 문구] 금기 목록에 없다는 것이 안전하다는 뜻은 아닙니다. 자세한 확인은 근처 약국·약사에게 해 주세요.
공공데이터 기반 정보이며 진단·처방이 아닙니다. 요양기관의 DUR 점검을 대체하지 않습니다.
자료 기준일: [파일 데이터 기준일] / 조회 시각: [API 조회 시각]

▸ 근거 상세 (펼침): 성분코드, 금기등급 원문, 고시 조항, 출처
```

### 1.2 임산부: 임신 중인 아내와 남편

**질문**: (남편) "임신 중인 아내가 머리가 아프대. 집에 이부프로펜이랑 타이레놀이 있는데 먹여도 돼?"

RFP가 가장 먼저 겨냥하는 장면이다. 전문가의 판단을 바로 받기 어려운 때, 집에 있는 약의 금기를 근거와 함께 확인한다.

| 단계 | 판단 | 왜 필요한가 | 데이터 | 처리 방식 | RFP 범위 |
|---|---|---|---|---|---|
| 1 | **두 약이 어떤 성분인가** | 제품명으로 묻기 때문에 성분코드로 바꿔야 판정할 수 있음 | 제품명→성분코드 매핑, e약은요 | API + 규칙 | 핵심 |
| 2 | **임부금기에 해당하는가** | 성분코드가 임부금기 목록(등급 1·2·M)에 있는지. 등급은 상세정보 원문 그대로 전달 | 임부금기 파일 (성분코드 일치) + DUR API 교차 | 규칙·API (**retrieval 아님**) + 등급 정의·상세정보 인용 | 핵심 |
| 3 | **두 약을 같이 먹어도 되는가** | 병용금기·성분 중복 여부 | DUR 병용금기, (확장) 성분 비교 | 규칙·API | 핵심 / 확장 |
| 4 | **응급 표현이 있는가** | 숨쉬기 힘듦, 출혈 등이 있으면 119 안내가 먼저 | Guardrail 응급 키워드 (코드 규칙) | 코드 규칙 | 필수 |
| 5 | **가부를 말해도 되는가** | "먹여도 된다/안 된다"는 복용 판단이라 하지 않음. 금기 정보와 근거만 알리고 약국·약사에게 확인하도록 안내 | 고정 문구 (코드) | 코드 | 제외 |

### 기대 응답 구조: 임산부

```
[요약] 복용해도 되는지는 정해 드릴 수 없습니다. 임신 중 금기 정보를 확인한 결과는 아래와 같습니다.
1. 이부프로펜: 임부금기 목록에 [해당합니다(등급 1/2/M)/해당하지 않습니다]. 등급 설명은 고시 정의를 인용합니다. [근거: 한국의약품안전관리원 임부금기약물, 자료 기준일]
2. 타이레놀(아세트아미노펜): 임부금기 목록에 [해당합니다(등급)/해당하지 않습니다]. [근거]
3. 두 약을 함께 먹는 경우: 병용금기 [해당/해당하지 않음], 같은 성분 중복 [해당/해당하지 않음(확장)]. [근거]
[등급 M이 있으면] 등급 M은 상세정보 원문 그대로 전달합니다: "[상세정보 원문]". 임의로 1·2등급으로 바꿔 말하지 않습니다.
[고정 문구] 금기 목록에 없다는 것이 안전하다는 뜻은 아닙니다. 임신 중 복용은 근처 약국·약사에게 꼭 확인해 주세요.
[응급 표현이 있으면 맨 위] 119에 연락하세요.
공공데이터 기반 정보이며 진단·처방이 아닙니다. 요양기관의 DUR 점검을 대체하지 않습니다.
자료 기준일: [임부금기 파일 기준일] / 조회 시각: [API 조회 시각]

▸ 근거 상세 (펼침): 성분코드, 금기등급 원문, 고시 번호·일자, 출처
```

### 1.3 고령자: 만성질환 약을 여러 개 복용

고령자는 관절염, 골다공증 같은 만성질환 약을 이미 먹고 있는 상태에서 통증약이나 감기약을 더하는 경우가 많다. 가족(보호자)이 "엄마가 이 약을 먹고 있는데 이것도 먹어도 돼?"라고 묻는 장면이다. 아래는 파일에서 확인한 사실로 시나리오를 고른 것이다.

**파일에서 확인한 사실** (병용금기 JSON, 기준일 2026-07-21)

| 약 | 확인 결과 |
|---|---|
| 메토트렉세이트 **정제**(성분코드 192101ATB, 제품 3개) | 병용금기 쌍이 있는 상대: 아산화질소, 아시트레틴, 디클로페낙(여러 코드), 설파메톡사졸+트리메토프림. 이부프로펜·아스피린·멜록시캄·피록시캄·케토프로펜·에토리콕시브와의 쌍은 **없음** |
| 메토트렉세이트 **주사제**(192132BIJ 외 7개 코드) | 위 상대에 더해 이부프로펜, 아스피린, 멜록시캄, 피록시캄, 케토프로펜, 에토리콕시브 등과 쌍이 있음. 사유 예: "신세뇨관에서 Methotrexate 배설이 지연되어 Methotrexate의 혈액학적 독성 증가" (고시번호 20110070 등) |
| 알렌드로네이트(골다공증약) | 단일제의 병용금기 쌍은 **없음**. 칼시트리올+알렌드로네이트 복합제 1종만 3쌍(알파칼시돌, 파리칼시톨, 부로수맙) |
| 토파시티닙(류마티스약) | 아자티오프린, 사이클로스포린, 타크로리무스와 병용금기 (고시번호 20240466, 사유: "면억억제 효과 증가"로 적혀 있음. 원문 표기이며 '면역억제'의 오탈자로 보이나 원문 그대로 인용한다) |
| 임부금기 CSV | 메토트렉세이트 18행, 알렌드로네이트 49행 등이 있음(고령자 시나리오에는 쓰지 않음) |

이 사실에서 두 가지가 나온다.

1. **"목록에 없음"이 곧 "같은 성분에 문제가 없음"이 아니다.** 같은 메토트렉세이트라도 정제 코드에는 NSAID 쌍이 없고 주사제 코드에는 있다. 성분코드 정확 일치만 쓰면 정제를 먹는 사람의 이부프로펜 질문은 "금기 목록에 없음"으로 나온다. 이 결과를 감추지도, 과장하지도 않으려면 "정제 코드와의 쌍은 목록에 없다", "같은 성분의 주사제 항목은 있다"를 있는 그대로 알리고, 정제에 적용되는지는 단정하지 않으며, 고시 원문과 제품 라벨 문장을 근거로 인용해야 한다. 이 부분이 **retrieval이 필요한 대표 지점**이다.
2. **골다공증약처럼 병용금기가 거의 없는 약은 판정이 비어 있다.** 이때 사용자에게 도움이 되는 정보(복용 방법, 주의 문장)는 제품 라벨 텍스트에 있다. 이 역시 retrieval의 몫이다. 단, 해당 전문의약품이 e약은요에 있는지는 확인하지 못했다(8장).

| 단계 | 판단 | 데이터 | 처리 방식 | RFP 범위 |
|---|---|---|---|---|
| 1 | **복용 중인 약 식별** (제품 → 성분코드, 정제/주사 같은 제형까지) | e약은요, 제품명→성분코드 매핑 | API + 규칙 | 핵심 |
| 2 | **모든 쌍 조회** (약 N개 → 쌍 N(N-1)/2개) | 병용금기 파일 + API | 규칙·API | 핵심 |
| 3 | **조회 결과 구분**: 해당 / 목록에 없음 / 약 미식별 | AG-02 출력 | 규칙 | 핵심 |
| 4 | **목록에 없는 쌍의 보완**: 같은 성분명의 다른 코드에 쌍이 있는가, 라벨에 상호작용·주의 문장이 있는가 | 병용금기 파일(성분명), 고시 원문, 제품 라벨 | **Retrieval + 인용** | 핵심(근거 보강) |
| 5 | **노인주의** (65세 이상 주의 약물) | DUR 노인주의 오퍼레이션(API) | API | 확장(조건부, 오퍼레이션 확인 후) |
| 6 | **가부·용량** | - | 정하지 않음. 고정 문구·약국·약사 안내 | 제외 |

## 2. 처리 방식 분해: 규칙·API와 Retrieval

질문: 이 서비스가 API와 규칙만으로 처리되는가, 아니면 Agent-RAG가 실제로 일을 하는가?

**답: 판정은 규칙·API가 한다. Retrieval은 판정을 설명하고 보강하는 일을 한다.** RFP-17의 결정(2026-10-30)이 정확 일치로 판정하고 RAG는 설명·인용을 맡기는 것이다. 의료 금기를 의미 검색 순위에 맡기면 놓치거나 틀릴 수 있기 때문이다. 그래서 8세 아동 시나리오(1.1)는 대부분 규칙·API로 풀리고, retrieval이 눈에 띄지 않는다. 이 문서는 retrieval이 **실제로 필요한 지점**을 따로 가설로 세워 시험한다.

| 일 | 규칙·API | Retrieval | 근거 자료 |
|---|---|---|---|
| 병용·임부·연령 금기 **판정** | O (성분코드 정확 일치) | X | 병용금기 JSON, 임부금기 CSV, DUR API |
| 금기 **사유 설명**, 고시 번호·적용일 인용 | | O | 병용금기 JSON의 사유 문장, 고시 PDF |
| 금기등급 1·2·M의 **정의** 설명 | | O | 고시 제3조, 심평원 「기능과 역할」(인용만) |
| "목록에 없음"일 때 **보완 근거**(같은 성분명의 다른 제형 항목, 라벨의 상호작용·주의 문장) | | O | 병용금기 파일(성분명), 제품 라벨 텍스트 |
| 제품 **사용 연령·사용법** 문장 인용 | | O | e약은요 문장형 필드 |
| 응급 판별, 고정 문구 | O (코드) | X | Guardrail 코드 |

> Retrieval의 대상은 새로 모으는 PDF만이 아니다. 이미 가진 자료 중 문장형인 것이 모두 후보다. 특히 병용금기 JSON은 쌍마다 사유가 문장(`text`)으로 들어 있어 별도 가공 없이 문서로 쓸 수 있다. 다만 512,464행은 제품 쌍의 반복이라 고시번호·성분쌍·사유 단위로 줄여서 쓴다(RFP-17 결정 6, BE-05).

**Retrieval이 필요하다는 것을 먼저 보이는 방법**: 규칙·API만 쓴 조건에서 TC-14·15가 실패(근거 없는 "목록에 없음", 보완 정보 없음)하는 것을 먼저 보이고, retrieval을 더한 조건에서 개선되는 것을 보인다(5장 비교 실험의 3조건). 자료는 이 실패를 근거로 추가한다.

## 3. 가설

### AX 가설 (사용자 경험)

> H1~H4는 사용자 대상 조사가 필요해서 3주 일정상 **선택 항목**이다. 시간이 남을 때 지인 몇 명에게 동의를 받고 시나리오 테스트로 한다. 하지 못하면 한계로 기록한다. 서비스는 질문·대화를 저장하지 않는다(RFP 7장 개인정보). 참가자에게 질문을 받을 때는 수집 목적과 서비스에는 저장하지 않는다는 점을 먼저 알리고 동의를 받는다.

| ID | 가설 | 검증 방법 | 지표 |
|---|---|---|---|
| H1 | 일반인은 성분이 아니라 **브랜드명**으로 묻는다 | 테스트 참가자에게 평소 약을 어떻게 묻는지 질문 작성·설문 (동의 후 수집, 서비스에는 저장하지 않음) | 브랜드명 질문 비율 |
| H2 | 일반인은 **같은 성분 중복**(타이레놀 + 종합감기약)을 인지하지 못한다 | 응답 전 "괜찮을 것 같다" 예상을 묻고, 응답 후 판단 변화 측정 | 판단 변경률 |
| H3 | "괜찮다/안 된다" 단답보다 **근거 + 조건부 답변**을 더 신뢰한다 | A/B: 단답형 vs 근거형 응답 신뢰도 5점 척도 | 신뢰도 점수 차이 |
| H4 | 보호자는 체중 없이 **"몇 알 먹이면 돼요?"**를 묻는다 | 시나리오 테스트에서 체중 미제공 비율 | 체중 누락 비율, 추가 질문 후 응답률 |

| 성분 중복 (확장) | 아세트아미노펜 등 같은 성분의 중복 여부를 명시 |
| 연령 확인 | 제품 사용 연령 + DUR 연령금기 둘 다 확인 |
| 임부 확인 | 임부금기 조회 결과(등급 원문, 기준일)를 명시. 등급을 임의로 바꾸지 않음 |
| 조회 결과 구분 | "해당", "금기 목록에 없음", "약 미식별", "근거 없음"을 구분해 씀 |
| 보완 근거 | 목록에 없을 때 고시 원문·성분명 쌍·라벨 문장 중 찾은 근거를 인용. 없으면 없다고 씀 |
| 판정 단정 금지 | "먹어도 된다/안 된다"와 스스로 계산한 용량을 쓰지 않음 |
| 고정 문구 | "금기 목록에 없다는 것이 안전하다는 뜻이 아님"과 "근처 약국·약사에게 확인" 포함 (코드로 부착) |
| 수치 출처 | 모든 숫자가 조회 결과에 존재 (Validator 대조) |
| 원문 충실 | 사유·등급·조항을 원문과 대조해 일치. 원문 표기는 바꾸지 않고 병기 |
| 출처 표기 | 데이터 출처 + 조회 시각(API) 또는 자료 기준일(파일 데이터) 포함 |
| 안전 안내 | 응급 시 119, 진단·처방 아님 고지, 요양기관 DUR 점검 대체 불가 |

## 6. 비교 실험

세 조건을 같은 질문 세트에 넣는다. 둘째와 셋째의 차이가 retrieval이 실제로 하는 일이다.

| 조건 | 설명 |
|---|---|
| LLM 단독 | 같은 LLM, 도구 없음 (모델 기억만) |
| 규칙·API만 | Router + e약은요 + DUR(API·적재 데이터) + 고정 문구·Guardrail. 문서 검색(retrieval)과 Validator의 원문 대조는 끈다 |
| MediAgent | 위에 문서 검색(고시·사유·라벨 문장)과 Validator를 더한 전체 구성 |

TC-01~20을 세 조건에 똑같이 넣고, 5장 채점표의 항목별 통과율을 비교한다. 결과는 실행 후에만 기록한다. 이 비교는 RFP 9장의 5개 지표에 더하지 않는 보조 실험이다.

## 8. Retrieval 보강 자료 추천

원칙: **실패를 먼저 보이고 자료를 나중에 더한다.** 6장의 "규칙·API만" 조건에서 TC가 실패하는 것을 확인한 뒤, 그 실패를 메우는 자료만 추가한다. 3주·1인 일정에서 자료를 많이 모으는 것은 목표가 아니다(RFP 4장 "대규모 수집 제외").

### 8.1 이미 가진 자료 (추가 수집 없음)

| 자료 | 쓰임 | 비고 |
|---|---|---|
| 병용금기 JSON의 사유 문장(`text`, `금기사유`) | 사유 설명, 고시번호·적용일 인용 | 512,464행은 제품 쌍의 반복이라 고시번호·성분쌍·사유 단위로 줄인다 |
| 병용금기 파일의 성분명 | 같은 성분명의 다른 코드에 쌍이 있는지 보완 조회 | 판정은 성분코드 정확 일치를 유지하고, 성분명 일치는 참고 정보로만 쓴다. 단위는 BE-05에서 재결정 |
| 임부금기 CSV의 상세정보 | 등급별 사유 설명 | 등급 원문 그대로 인용 |
| 고시 PDF의 조문·정의·비고·별표 | 등급 정의, 연령 기준, 법적 근거 | 표 파서 시험 통과 뒤 사용(RFP 12장) |
| e약은요 응답의 문장형 필드(효능·사용법·경고·주의사항·상호작용·부작용·보관) | 제품 사용 연령, 상호작용·주의 문장 인용 | API로 가져온 뒤 문장 단위로 쪼개 질문과 관련된 문장만 찾는 2단계 구성을 권한다. 전체를 미리 적재할지는 RFP-15에서 결정 |
