# PJ2-RFP · MediAgent

> AI Agent(Agentic RAG) 부트캠프 3주 프로젝트 제품요구서 · fastcampus · 박영찬

## 1. 개요
| 항목 | 내용 |
|---|---|
| 프로젝트 | MediAgent: 공공 보건·의약품 데이터 기반 Agentic RAG 에이전트 |
| 기간 | 3주 (설계 → 구현 → 평가) |
| 형태 | 개인 프로젝트 (팀이면 역할 표 추가) |
| 한 줄 정의 | 사실은 공공 API·문서에서 가져오고, LLM은 설명과 종합만 맡는 근거 기반 질의응답 에이전트 |

## 2. 문제 정의
- **최신성**: 허가 사항·검진 기준이 바뀌어도 LLM 내부 지식은 반영되지 않음
- **추적성**: 의료·보건 답변은 출처(데이터·조항)를 댈 수 있어야 함
- **데이터 분산**: 약품 정보는 API, 금기 정보는 API·파일 데이터·고시에, 자격·기준 규정은 PDF에 흩어져 있음
- **입력 불확실성**: 오탈자, 범위 밖 질문, 잘못된 전제 질문

## 3. 목표
1. 질문 → 도구 선택 → 근거 조회 → 출처가 붙은 답변까지 끝단 동작
2. 정형(API·파일 데이터)·비정형(PDF) 하이브리드 검색
3. 환각 방지 장치(근거 고정·검증·안전 응답) 구현
4. 직접 측정한 평가 수치로 개선 전후 비교

## 4. 범위
| 포함 | 제외 |
|---|---|
| 약품 정보 조회, 병용·연령·임부 금기 확인 | 진단, 처방, 복용량 결정 |
| 국가건강검진 대상·주기 안내 | 개인 의료기록 처리 |
| 보건사업 자격 요건 안내 | 대규모 문서 전수 수집 (핵심 PDF 소수로 시작) |

## 5. 데이터
| 구분 | 소스 | 방식 |
|---|---|---|
| 정형 | 식약처 e약은요 API (제품명·성분·효능·주의사항) | Tool 호출 |
| 정형 | 식약처 의약품안전사용서비스(DUR) 품목정보·성분정보 OpenAPI (병용·연령·임부 금기 등) | Tool 호출 |
| 정형 | 한국의약품안전관리원 병용금기약물(JSON)·임부금기약물(CSV) 파일 데이터 (기준일 2026-07-21) | 수집 후 적재 (적재 방식은 RFP-17에서 결정) |
| 비정형 | 국가건강검진 실시기준, DUR 가이드, 보건사업 안내서 PDF | 파싱·청킹 → Vector DB |
| 비정형 | 식약처 고시 「의약품 병용금기 성분 등의 지정에 관한 규정」 전문 PDF (최신 개정 제2026-52호, 2026-07-21) | 파싱·청킹 → Vector DB (표 파싱 시험 후) |

> 문서 형식(PDF/HWP)과 최신 배포 여부는 각 기관 사이트에서 확인 후 수집
> DUR 데이터의 출처·기준일·이용 조건은 `tickets/doc/RFP-17.md`에서 확인한 내용이다. 파일 데이터는 공공저작물 제2유형(출처표시, 상업적 이용금지)이다.
> 참고 자료(검색 대상 아님): 건강보험심사평가원 「기능과 역할」 2021~2026년판은 DUR 용어와 점검 절차를 설명하는 근거로 쓰며, 쪽을 밝혀 인용만 한다. 이용 조건을 확인하지 못해 저장소에는 올리지 않는다.

## 6. 기능 요구사항
> **FR** = Functional Requirement, 즉 기능 요구사항. 시스템이 "무엇을 하는가"를 정하며, 표의 한 행이 FR 하나다. ID는 `FR-nn`으로 쓴다.

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-01 | Router: 질문에서 약품명·연령·질환 등 엔티티 추출 후 도구 분기 | 필수 |
| FR-02 | 공공 API Tool: e약은요·DUR(식약처 OpenAPI) 조회, 조회 시각 기록 | 필수 |
| FR-03 | 문서 RAG: 표를 마크다운으로 보존해 파싱, 메타데이터(문서종류·연도·부처·고시번호·기준일) 필터 검색 | 필수 |
| FR-04 | Citation: 모든 답변에 출처·조회 시각(또는 자료 기준일)·조항 표기 | 필수 |
| FR-05 | Validator: 답변이 원본 API·문서와 일치하는지 점검 후 출력 | 필수 |
| FR-06 | Guardrail: 진단·처방 금지 문구, 응급 키워드 → 119 안내, 범위 외 거절 | 필수 |
| FR-07 | 오탈자 보정: 약품명 오입력 시 정규화 후 재검색 | 권장 |
| FR-08 | 근거 없음 처리: 검색 결과가 없으면 지어내지 않고 모른다고 응답 | 필수 |

## 7. 비기능 요구사항
> **NFR** = Non-Functional Requirement, 즉 비기능 요구사항. 기능 자체가 아니라 "얼마나 잘, 어떤 조건으로 하는가"를 정하며, `FR-nn` 같은 번호는 붙이지 않는다.

- **신뢰성**: 근거 없는 사실 문장 출력 금지
- **재현성**: 같은 평가 세트로 개선 전후를 반복 측정 가능
- **보안**: API 키는 환경변수 관리, 저장소에 커밋 금지
- **고지**: 화면·응답에 "공공데이터 기반 정보 제공이며 진단·처방이 아님"을 표시하고, 사용한 자료의 출처와 기준일을 함께 표시한다. 한국의약품안전관리원 파일 데이터는 공공저작물 제2유형(출처표시, 상업적 이용금지)이므로 출처를 밝히고 상업적으로 이용하지 않는다.

## 8. 시스템 구조
```
사용자 질문 → Agent Router ─┬→ 공공 API Tool ──┐
                            ├→ Vector DB 검색 ──┼→ 답변 생성 + 출처 → Validator → 근거 답변
                            └→ 안내 전환 (응급·범위 외·근거 없음)
```
| 역할 | 후보 (1주차 확정) |
|---|---|
| 오케스트레이션 | LangGraph |
| LLM | [선택 예정] |
| 백엔드 | FastAPI |
| Vector DB | Chroma / Qdrant / pgvector |
| PDF 파싱 | pdfplumber, LlamaParse |
| 평가 | Ragas |

> DUR 금기 판정 경로(API 조회 / 파일 적재 / 혼합)와 그 안에서 RAG가 맡는 역할은 `tickets/doc/RFP-17.md`에서 결정한다.

## 9. 평가 기준
| 항목 | 측정 | 목표 | 결과 |
|---|---|---|---|
| 검색 정확도 | Context Precision·Recall (Ragas) | 기준선 대비 개선 | 측정 전 |
| 답변 충실도 | Faithfulness (Ragas) | 기준선 대비 개선 | 측정 전 |
| 오탈자 견고성 | 오탈자 질문 세트 | 정상 대비 하락 최소화 | 측정 전 |
| 안전 응답률 | 범위 외·오정보 질문 세트 | 기준선 대비 개선 | 측정 전 |
| 금기 판정 정답률 | 정상 세트 중 병용·임부 금기 질문 (금기등급 M 성분 포함) | 기준선 대비 개선 | 측정 전 |

- 평가 세트: 정상 / 오탈자 / 범위 외 / 오정보, 세트별 [__]문항 (1주차 확정)
- 금기 판정은 성분 단위 규칙 조회라 검색 지표(Context Precision·Recall)로 측정되지 않아 별도 지표를 둔다.
- 참고: 원스글로벌 Dr.DI 성능검증 기사(약업신문, 2026-07-15)의 평가 항목 구성. 수치는 비교하지 않음

| 텍스트 레이어가 없는 이미지 PDF (심평원 「기능과 역할」 2022년판에서 확인) | OCR(macOS Vision 등)로 필요한 쪽만 읽고, 불가능하면 범위에서 제외 |
| 고시 PDF의 표가 쪽마다 다르게 추출됨 (별표 2에서 확인) | 파서 시험 전에는 구조화된 파일·API를 우선하고, PDF 표는 시험을 통과한 뒤 사용 |
| 파일 데이터와 고시는 갱신되지 않는 스냅샷 (기준일 2026-07-21) | 답변에 기준일 표시, API로 교차 점검, 기준일 이후 변경을 추정하지 않음 |
| 금기등급 M은 고시에 없고 심평원 문서에만 정의됨 (처방·조제 사유 코드 M과 다른 것) | 심평원 설명("상병에 따른 1등급 또는 2등급")을 인용하고 등급은 상세정보 원문으로 전달 (RFP-17의 "M 처리 규칙") |
| 일정 지연 | FR-07 등 권장 항목부터 축소 |
