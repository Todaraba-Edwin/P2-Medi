## 1. 이슈
RFP 1~4장의 정의·목표·범위(포함/제외)를 저장소용 PRD 한 문서로 정리해, 이후 티켓과 README의 기준으로 쓴다. 특히 제외 범위(진단, 처방, 복용량 결정, 진료·처방 이력 등 의료기록 처리(사용자가 동의해 입력한 프로필의 저장은 확장 범위로 포함), 대규모 전수 수집)를 명확히 한다. RFP 1장에 대상 사용자(일반인, 비의료인), 사용 장면, 목적이 명시되었으므로 PRD에 옮긴다. 2026-10-31 RFP 변경으로 프로젝트 성격(취업 포트폴리오, 목표는 Agent-RAG를 활용한 AX 경험), 확장 사용자(의료인·약사, 전문가 전용 기능 없음), 수요 근거(Dr.DI는 수요 확인 사례일 뿐 복제·수치 비교 대상이 아님), 핵심/확장 범위 구분도 PRD에 옮긴다.

## 2. 완료 조건
- [ ] PRD 문서가 저장소에 있고 목표 5개(RFP 3장), 대상 사용자(일반인)와 사용 장면, 포함/제외 표, 데이터 소스 11행(정형 5·사용자 입력 1·비정형 5, RFP 5장), 평가 기준 5항목이 담겨 있다.
- [ ] PRD 문서 제목 바로 아래에 부제목 `**PRD (Product Requirements Document): 제품 요구사항 문서**`가 있다(`CLAUDE.md` 2장 문서 부제목 규칙).
- [ ] (PRD-06-01) PRD 문서 제목에 서비스 표시 이름 Can I Biyak(한글 삐약, 코드명 MediAgent)이 쓰여 있다.
- [ ] 문서 내 모든 요구사항이 FR/NFR ID로 추적된다.
- [ ] PRD 첫머리에 프로젝트 성격(취업 포트폴리오, 목표 = Agent-RAG 활용 AX 경험: Router·도구 선택·근거 고정·Validator·평가 수치)이 적혀 있다.
- [ ] 주 사용자(일반인)와 확장 사용자(의료인·약사, 전문가 전용 기능 없음), 사용 장면(임산부·영유아·아동이 있는 집)이 적혀 있다.
- [ ] 수요 근거 절에 Dr.DI 등을 "수요 확인 사례"로만 쓰고 복제·성능 수치 비교를 하지 않는다고 적혀 있다.
- [ ] 범위 표가 핵심(병용·연령·임부 금기, 필수)과 확장(성분 중복, DUR 효능군 중복·용량·투여기간 주의, 수유부·노인 주의는 모두 권장이며 수유부·노인 주의는 파일 데이터 확보 완료, RFP 4장)으로 나뉘고, 미달 시 확장부터 축소하며 Agent-RAG 핵심(Router·도구 선택·근거 고정·Validator·평가 수치)은 축소하지 않는다는 규칙이 있다. 응급 처리(FR-06)는 필수라 축소 대상이 아니라고 적혀 있다.
- [ ] 확장 범위에 온보딩·소셜 로그인(FR-09, 권장)이 있고 4장의 축소 순서(Apple·Naver → Kakao·Google → 프로필 저장 → FR-07 오탈자 보정 → 열린 질문 retrieval(AG-15) → 수유부·노인 주의 → 중복·용량)와 "게스트로 핵심 기능 사용 가능"이 적혀 있다.
- [ ] 온보딩 프로필 항목(연령대, 임신 여부, 복용 중인 약, 알레르기 선택)이 확정되어 있다(가정이었던 목록을 이 티켓에서 확정).
- [ ] 본인 외 가족 구성원(아내·아이) 프로필이 필요한지 결정되어 있고 이유가 적혀 있다.

## 5. 메모
- 가정: 프로필 항목(연령대, 임신 여부, 복용 중인 약, 알레르기 선택)은 이 티켓에서 확정한다. RFP 1장·6장은 "연령대, 임신 여부, 복용 중인 약 등 선택 입력"까지만 적고 알레르기는 적지 않았다.
- 가정: 본인 외 가족 구성원(아내·아이) 프로필 필요 여부는 RFP에 없다. 사용 장면이 임산부·영유아·아동이 있는 집이라 필요할 수 있으나, 개인정보 저장 범위가 커지므로 이 티켓에서 결정한다.
- 수치 확인(2026-10-31, RFP 직접 대조): 목표 5개(3장), 데이터 표 11행(5장), 평가 지표 5항목(9장), 리스크 18건(12장). 같은 날 RFP 개정 전 값은 데이터 7행, 리스크 17건이었다. 5장 표를 다시 세어 정형 5행(e약은요, DUR API, KIDS 병용·임부, KIDS 연령·용량·수유부, 심평원 품목리스트), 사용자 입력 1행, 비정형 5행(e약은요 문장, 허가정보 후보, 응급 자료, DUR 가이드, 고시 PDF)이다. 5.1절 (1)의 대상 파일 표는 별도 표이므로 이 행 수에 넣지 않았다.
- 2026-11-02 수치 갱신(RFP-24): RFP 12장에 "외부 LLM 전송"과 "프롬프트 인젝션" 행이 더해져 리스크가 22건이 되었다(12장 표 직접 세기). 이 티켓의 리스크 건수 표기는 22건 기준이다.
- 2026-11-02 수치 갱신: RFP 12장에 "에이전트 경로 비결정성·step 오류 누적" 행이 더해져 리스크가 20건이 되었다(12장 표 직접 세기). 이 티켓의 리스크 건수 표기는 20건 기준이다.
