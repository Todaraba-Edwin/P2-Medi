## 1. 이슈
사용자 지시(2026-11-09, 그대로):
> "모달의 < 와 닫기를 위해서 별도의 header를 구분하지 말고, 본문의 좌상단, 우상단에 대치되는 구성으로 별도의 티켓과 pane에서 진행"

화면 [ISSUE-006.png](../issues/ISSUE-006.png)에서 직접 확인한 사실:

- 비로그인 상태에서 "프로필 저장"을 누르면 뜨는 **로그인 모달**이다. 뒤 화면은 금기 발견 결과(병용금기 카드, "삐! 병용금" 배지 일부)이고 어둡게 덮였다.
- 모달 맨 위에 **흰 header 띠**가 모달 전체 폭으로 있고 거기에 `<`(왼쪽)와 `닫기`(오른쪽, 갈색 글자)만 있다. 띠 아래에 **가로 구분선**이 있다. 띠는 버튼 두 개 말고 아무것도 담지 않아 세로 공간만 차지하고, 본문과 분리돼 보인다.
- 본문은 2열이다. 왼쪽(크림색 배경): 질문형 병아리 마스코트(약을 들고 물음표), 로고 "Can I PPiyak"(글자 포함), 제목 "프로필을 저장하려면 로그인하세요", 설명 "나이·임신 여부·먹는 약을 저장해 두면 … 로그인하지 않아도 모든 질문은 할 수 있어요.", 빨간 밑줄 링크 "응급이면 로그인 없이 바로 119". 오른쪽(흰 배경): "이메일로 로그인", 이메일·비밀번호 입력, `로그인`(노란 버튼), `이메일로 가입하기`, `로그인 없이 계속하기`(갈색 글자 링크), "프로토타입이라 실제로 가입되지 않아요."
- **정정(사용자 지시 2026-11-09)**: 이 로그인 첫 화면의 `<`는 돌아갈 이전 단계가 없어 **결함**이다. 닫기만으로 충분한 화면에 `<`가 있을 이유가 없고, 프로필 생성의 첫 단계는 더 그렇다. 규칙은 `<`는 이전 단계가 있을 때만 존재하며 닫기만 필요한 화면에서는 그리지 않는다(§5).
- 같은 모달의 좁은 폭 화면 [ISSUE-004.png](../issues/ISSUE-004.png)(근거 상세 패널이 열린 상태)에서는 2열이 그대로 유지돼 오른쪽 폼이 잘리고("이메일로 로 / 그인", `이메일로 가입히`) **가로 스크롤바**가 생겼다. 이 티켓의 직접 지시는 아니지만 1열 전환 규칙(§4.3)의 근거로 적는다.

관련 문서에서 확인한 사실:

- **모달이라는 말이 요구 문서에 없다.** `P2-doc/PJ2-PRD.md`에서 "모달"은 0건이다. 로그인은 15.3절 S10 1단계의 화면 이름 "로그인·가입"(`P2-doc/PJ2-PRD.md:373`)이고, 15.4절 화면 상태 표에는 "프로필(확장) | 로그인·동의·프로필·대상 선택 | 상시 고지 | 마스코트 사용 가능 | … | 폼이 한 열"(`P2-doc/PJ2-PRD.md:418`) 한 줄뿐이다. 모달로 띄울지, 닫기·뒤로가 무엇인지는 정해진 것이 없다.
- `tickets/frontend/FE-04.md`(확장·권장): 첫 화면(게스트 시작 / 로그인), 온보딩 폼과 동의 체크, 이메일 로그인·프로필 화면·대상 선택, 프로필 조회·수정·삭제가 하위 작업이다(`tickets/frontend/FE-04.md:36-41`). "게스트로 시작"이 항상 먼저 보이고 게스트는 아무것도 저장하지 않는다(`FE-04.md:27-30`). 뒤로·닫기·모달은 언급이 없다.
- `tickets/doc/PRD-07.md`(유저플로우): S10은 게스트와 구분, 본인 + 가족 1명, 대상 선택, 이메일 로그인·서버 저장·수정·삭제(`tickets/doc/PRD-07.md:67`). 동의를 받는 곳은 프로필 저장 하나뿐이다(`PRD-07.md:103`). 화면 사이 이동(뒤로)은 정의하지 않는다.
- **119 규칙**: 응급 질문은 항상 로그인 없이 가능하다(`P2-doc/PJ2-PRD.md:372`, 78줄). 모달의 "응급이면 로그인 없이 바로 119" 링크는 이 규칙을 화면에 둔 것이다. 프로필 상태의 고정 문구 칸은 "상시 고지"이고 119 최상단 표시는 응급 상태(`PJ2-PRD.md:412`)의 규칙이다.
- **마스코트 규칙(PRD-06) 대조**: 마스코트는 보조 자리에만 쓰고 응급·금기 결과·"금기 목록에 없음"·고정 문구 영역에는 쓰지 않는다(`tickets/doc/PRD-06.md:108-117`, `P2-doc/PJ2-PRD.md:59`). 15.4절 프로필(확장) 상태는 마스코트 "사용 가능"(`PJ2-PRD.md:418`)이고, 그림은 PRD-06이 권한 "약을 들고 고개를 갸웃하는 질문형"(`PRD-06.md:119`)과 같다. 글자가 든 로고는 "로그인·소개 같은 정적 브랜딩 자리"에 쓸 수 있다(`tickets/frontend/FE-06.md:65`). → **이 모달의 마스코트 위치는 규칙과 충돌하지 않는다.** 확인 필요 두 가지는 §11 메모에 적었다(119 링크와 같은 열, 금기 결과 위에 겹쳐 뜸).

## 4. 배치 규칙
규칙(PRD-13-01 A, 사용자 지시):
1. 모달에 **별도 header 영역(전체 폭 띠)과 그 아래 구분선을 두지 않는다.** 본문 배경(2열이면 왼쪽 크림·오른쪽 흰색)이 모달 맨 위 모서리까지 이어진다.
2. `<`는 **본문의 좌상단 모서리**, `닫기`는 **본문의 우상단 모서리**에 둔다. 2열이면 `<`는 **왼쪽 열의 좌상단**, `닫기`는 **오른쪽 열의 우상단**이다. 1열이면 본문 좌상단·우상단 그대로다.
3. 두 버튼은 **같은 높이**(모달 위 가장자리에서 같은 상단 여백, 같은 세로 중심선)로 서로 마주 본다(대치). 한쪽이 숨어도(PRD-13-02) 다른 쪽의 위치는 바뀌지 않는다.
4. **구현 방식(사용자 추가 지시 2026-11-09, PRD-13-02·03 공통)**: 코너 버튼은 별도 header 행이 아니라 **모달 컨테이너 기준 `position: absolute`**로 둔다(`닫기` = 우상단, `<` = 좌상단, 둘 다 본문 레이아웃 흐름 밖). 본문 위 여백은 버튼 터치 영역(44px) 때문에 `padding-top`으로만 확보하고 header 높이를 따로 차지하지 않는다. 본문 첫 요소와의 간격은 §4.4로 지킨다. 색·hex·글꼴·정확한 px 간격은 디자인 세션 몫이다.

### 4.1 목업: 현행(header 띠)
```
┌──────────────────────────────────────────────────────────────┐
│  <                                                     닫기  │  ← header 띠(흰색, 전체 폭)
├──────────────────────────────────────────────────────────────┤  ← 구분선
│ (크림)                        │ (흰색)                       │
│        [질문 병아리]           │  이메일로 로그인              │
│        [로고 Can I PPiyak]     │  이메일 [               ]    │
│  프로필을 저장하려면 로그인하세요 │  비밀번호 [             ]    │
│  나이·임신 여부·먹는 약을 …     │  [        로그인        ]    │
│                               │  [   이메일로 가입하기    ]   │
│  응급이면 로그인 없이 바로 119  │     로그인 없이 계속하기       │
│                               │  프로토타입이라 실제로 …       │
└───────────────────────────────┴──────────────────────────────┘
```
- 버튼 두 개 때문에 띠 높이만큼 세로 공간이 늘고, 띠·구분선 때문에 본문과 분리돼 보인다(사용자 지적).

### 4.2 목업: 제안(본문 코너 대치)
```
┌───────────────────────────────┬──────────────────────────────┐
│ <  (크림)                      │ (흰색)                  닫기 │  ← 같은 높이, 띠·구분선 없음
│                               │                              │
│        [질문 병아리]           │  이메일로 로그인              │
│        [로고 Can I PPiyak]     │  이메일 [               ]    │
│  프로필을 저장하려면 로그인하세요 │  비밀번호 [             ]    │
│  나이·임신 여부·먹는 약을 …     │  [        로그인        ]    │
│                               │  [   이메일로 가입하기    ]   │
│  응급이면 로그인 없이 바로 119  │     로그인 없이 계속하기       │
│                               │  프로토타입이라 실제로 …       │
└───────────────────────────────┴──────────────────────────────┘
```
- `<`는 왼쪽 열 배경 위, `닫기`는 오른쪽 열 배경 위에 있다. 오른쪽 열 제목("이메일로 로그인")이 왼쪽 정렬이면 `닫기`와 같은 줄에 와도 가로로 겹치지 않는다(§4.4 ②). 마스코트는 가운데 정렬이라 `<`와 가로로 떨어진다.
- PRD-13-02 A면 로그인 첫 화면에서는 `<`가 숨고 `닫기`만 보인다(§5). 이때도 `닫기` 위치는 같다.

### 4.3 목업: 1열(모바일 360px)
```
┌────────────────────────────────┐
│ <                         닫기 │  ← 본문 좌상단·우상단, 같은 높이
│                                │
│         [질문 병아리]           │  ← 가운데 정렬, 폭 ≤ 224px(§4.4 ③)
│     프로필을 저장하려면           │
│        로그인하세요             │
│   나이·임신 여부·먹는 약을 …     │
│   응급이면 로그인 없이 바로 119   │
│  ────────────────────────────  │  ← 열 경계(배경색 전환, 선 아님)
│  이메일로 로그인                 │
│  이메일 [                    ]  │
│  비밀번호 [                  ]  │
│  [          로그인          ]   │
│  [     이메일로 가입하기      ]  │
│      로그인 없이 계속하기         │
└────────────────────────────────┘
```
- 2열 → 1열 전환: **모달 내용 폭이 2열 최소 폭보다 좁으면 1열**로 쌓는다(가로 스크롤 금지, NFR-07·FE-04). ISSUE-004처럼 폭이 좁은데 2열을 유지해 폼이 잘리는 일이 없어야 한다. 기준 값(예: 모달 내용 폭 720px)은 가정이고 디자인 세션·FE-04에서 정한다.
- 1열에서 위쪽 블록(왼쪽 열 내용)과 아래 블록(폼)의 순서는 현행 2열의 읽기 순서(왼쪽 → 오른쪽)를 따른다. 폼을 먼저 둘지는 이 티켓 범위 밖이다(FE-04).

### 4.4 겹침 방지와 터치 영역
① **터치 영역**: `<`·`닫기` 각각 최소 **44×44px**(WCAG 2.5.5 권고 크기, Apple HIG 44pt). 글자 `닫기`가 44px보다 좁아도 누르는 영역은 44×44px 이상이다.
② **상단 여백 규칙**: 본문 첫 요소(제목·마스코트·폼 제목)는 버튼 터치 영역과 **가로·세로 어느 쪽으로든 겹치지 않는다.** 둘 중 하나를 만족한다. (가) 첫 요소의 위쪽 끝이 버튼 터치 영역 아래쪽 끝보다 아래(세로 분리), 또는 (나) 같은 줄이면 첫 요소의 좌우 안쪽 여백이 버튼 터치 영역 폭(44px) + 간격(8px 가정) 이상(가로 분리). 띠를 다시 만드는 것이 아니므로 배경·구분선은 두지 않는다.
③ **1열 마스코트 폭**: 360px에서 좌우 여백 16px(가정)이면 가운데 정렬 마스코트가 코너 버튼과 가로로 겹치지 않는 최대 폭은 360 − 2×(16 + 44 + 8) = **224px**이다(같은 줄에 올 때). 세로로 분리하면(②가) 이 제한은 없다.
④ **119 링크·고정 문구와 겹침 없음**: 코너 버튼은 "응급이면 로그인 없이 바로 119" 링크와 상시 고지 문구를 가리지 않는다(스크롤 중 포함, §4.7).

### 4.5 키보드·포커스
- **Esc = 닫기**(`닫기`와 같은 동작). 단계 흐름에서도 Esc는 뒤로가 아니라 닫기다.
- **모달이 열릴 때 포커스**: 모달 제목("프로필을 저장하려면 로그인하세요", 프로그램으로 포커스 가능)에 둔다. 스크린리더가 제목을 먼저 읽고, 바로 입력창에 들어가 키보드가 올라오는(모바일) 일을 피한다. 대안은 첫 입력창(이메일)이며 디자인 세션·FE-04에서 고를 수 있다(가정).
- **탭 순서(제안)**: `닫기` → `<`(보일 때) → 왼쪽 본문 링크(119) → 폼(이메일 → 비밀번호 → 로그인 → 이메일로 가입하기 → 로그인 없이 계속하기). 닫기를 맨 앞에 두는 이유는 원하지 않은 모달에서 한 번에 빠져나오게 하기 위해서다. 화면 순서(왼쪽 `<` → 오른쪽 `닫기`)와 탭 순서가 다르므로 FE-04 구현에서 WCAG 2.4.3(포커스 순서) 점검을 한다(확인 필요, §11).
- **포커스 가둠**: 모달이 열린 동안 Tab은 모달 안에서만 돈다. 닫히면 모달을 연 버튼("프로필 저장")으로 포커스가 돌아간다.

### 4.6 접근성·라벨
- 스크린리더 라벨: `<`는 **`뒤로`**, `닫기`는 **`닫기`**(글자 그대로). 모달은 대화상자 역할과 제목 연결(개념: `role="dialog"`, `aria-modal`, 제목 id 참조)을 갖는다.
- `<` 기호만 있는 버튼은 보이는 글자가 없으므로 접근 가능한 이름 `뒤로`가 반드시 있다.
- `닫기` 표시(PRD-13-04): ★A **글자 `닫기` 유지**. 일반인(고령자 포함)이 기호 X보다 글자를 바로 이해하고, 보이는 글자와 접근 가능한 이름이 같아 음성 제어("닫기 누르기")에도 맞는다. B(X 아이콘 + 보조 라벨)는 근거 상세 패널(X)과 모양이 같아지는 장점이 있다.

### 4.7 스크롤할 때 코너 버튼
- 모달 높이가 화면보다 길면(1열 모바일) 본문이 모달 안에서 스크롤된다.
- 제안: **코너 버튼은 모달 상자에 고정**(스크롤해도 제자리)한다. 구현은 `position: absolute` 코너 + 본문만 모달 컨테이너 안에서 스크롤하도록 분리하거나 sticky 대안이며 FE-04에서 고른다(사용자 지시 2026-11-09). 본문과 함께 올라가 사라지면 긴 폼 아래에서 닫을 방법이 Esc뿐이라 터치 사용자가 갇힌다.
- 고정하면 본문 글자가 버튼 밑으로 지나간다. 버튼 터치 영역에 **불투명 배경**(작은 원·알약 모양, 색은 디자인 세션)을 두어 글자와 겹쳐 읽기 어렵지 않게 한다. 전체 폭 띠로 되돌아가지 않는다(PRD-13-01).
- 대안(본문과 함께 스크롤)은 1열 모달 높이가 화면 안에 들어오면 차이가 없다. 결정 번호는 만들지 않고 FE-04 구현에서 위 제안을 기본으로 한다(가정).

## 5. `<`의 뜻
**사실 확인 결과: 정의 없음.**
- `P2-doc/PJ2-PRD.md` 15.3절 S10(`P2-doc/PJ2-PRD.md:369-377`)은 0 게스트 → 1 로그인·가입 → 2 동의 → 3 프로필 입력 → 4 대상 선택 → 5 수정·삭제의 단계만 있고 화면 사이 뒤로 가기·닫기를 정의하지 않는다. 15.4절(`PJ2-PRD.md:418`)도 상태 한 줄뿐이다.
- `tickets/frontend/FE-04.md` §2·§3(`FE-04.md:25-41`)에 뒤로·닫기·모달 언급이 없다. `tickets/doc/PRD-07.md`에도 없다.
- 따라서 ISSUE-006 로그인 첫 화면의 `<`는 **돌아갈 이전 단계가 없고 존재 자체가 부적절하다**(사용자 지시 2026-11-09로 정정; 이전 서술 "사실상 닫기와 같은 동작"을 바꿈). 프로토타입에서 `<`가 무엇을 하는지는 문서로 확인할 수 없다(코드 미확인). 프로필 생성의 첫 단계도 같다.

**단계가 있는 흐름에서만 의미가 있다.** S10 안에서 `<`가 뜻을 갖는 곳:

| 화면(S10 단계) | 이전 단계 | `<`의 동작(제안) |
|---|---|---|
| 로그인(1, 첫 화면) | 없음 | 그리지 않음(렌더 안 함, PRD-13-02 A) |
| 이메일로 가입(1, 로그인에서 들어감) | 로그인 | 로그인 화면으로 |
| 저장 동의(2) | 로그인·가입 | 로그인 화면으로(로그인 상태는 유지, 가정) |
| 프로필 입력(3) | 동의 | 동의 화면으로(입력값은 화면 메모리에 유지, 가정) |
| 프로필 수정·삭제(5, 로그인 뒤 직접 진입) | 없음 | 숨김 |

결정 PRD-13-02: ★A **`<`는 돌아갈 이전 단계가 있을 때만 존재한다. 닫기만으로 충분한 화면(로그인·가입 첫 화면, 프로필 생성 첫 단계)에는 그리지 않는다(숨김이 아니라 렌더하지 않음). 단계에서는 이전 단계로.** 이유: 같은 동작을 하는 버튼 둘(`<`·`닫기`)은 일반인에게 "무엇이 다른가"를 묻게 하고, 숨기면 구현도 단순하다(단계 번호 > 1일 때만 렌더). B(항상 표시, 첫 화면은 닫기와 같음)는 모달마다 모양이 같아 일관성이 있지만 중복 버튼이 남는다.

## 7. 화면 시험
FE-04(적용 범위에 들면 FE-05)에서 mock으로 그려 확인한다.
① 모달에 버튼만 담는 header 요소(전체 폭 띠)와 그 아래 구분선이 DOM에 없다. ② `<`(있을 때)와 `닫기`가 모달 컨테이너 기준 `position: absolute` 코너(좌상단·우상단)에 있고 위 가장자리에서의 거리가 같다(같은 높이). `<`는 단계 2 이상에서만 DOM에 존재하고 첫 화면에서는 DOM에 없다. ③ 두 버튼의 터치 영역이 각각 44×44px 이상이다. ④ Esc로 모달이 닫히고, 닫히면 "프로필 저장" 버튼으로 포커스가 돌아온다. ⑤ 모달이 열릴 때 포커스 위치와 탭 순서가 §4.5와 같고 Tab이 모달 밖으로 나가지 않는다. ⑥ 스크린리더가 `<`를 "뒤로", `닫기`를 "닫기"로 읽는다. ⑦ 360px에서 1열로 쌓이고 가로 스크롤이 없으며(ISSUE-004 재현 0건), 코너 버튼이 제목·마스코트와 겹치지 않는다(§4.4 ②③). ⑧ 코너 버튼이 마스코트·"응급이면 로그인 없이 바로 119" 링크·상시 고지를 가리지 않는다(스크롤 중 포함). ⑨ 로그인 첫 화면에서 `<` 표시 여부가 PRD-13-02 답과 같고, 가입·동의 단계에서 `<`가 이전 단계로 간다. ⑩ ISSUE-006과 같은 상태(금기 결과 위에서 "프로필 저장")를 다시 그려 전후 화면을 비교한다.
