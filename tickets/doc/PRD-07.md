## 1. 이슈
2026-11-03 사용자 요청: RFP가 충분하므로 PRD 작성으로 넘어가 **유저플로우를 심층적으로** 다룬다. PRD-01은 범위·성공 기준·요구사항 ID를 맡고, 이 티켓은 같은 PRD 문서(`P2-doc/PJ2-PRD.md`)에 **시나리오별 유저플로우, 화면별 상태, 요구사항 추적**을 이어 쓴다. RFP 8.1절(8단계, 예외 경로 7개)과 RFP-21 §4~§5(페르소나 3명의 실제 통과 기록)가 출발점이고, 이 티켓에서 "사용자가 화면에서 무엇을 보고 무엇을 누르는지"까지 내려간다.

PRD 문서 제목에는 서비스 표시 이름 **Can I Biyak**(코드명 MediAgent)과 부제목 `**PRD (Product Requirements Document): 제품 요구사항 문서**`가 들어간다(PRD-06, `CLAUDE.md` 2장).

## 2. 완료 조건
- [x] 시나리오 목록(§4.1)별로 **유저플로우**가 단계 표(사용자 행동 · 시스템 · 화면 · 예외)로 PRD 문서에 있다. 페르소나 P1·P2·P3의 질문이 실제로 통과하는 흐름을 하나씩 포함한다(RFP-21 §4).
- [x] **화면별 상태 표**(§4.2)가 있다: 시작, 질문 입력, 로딩, 되묻기 카드, 결과(요약 먼저·근거 상세 펼침), 금기 발견, 금기 목록에 없음, 근거 없음, 범위 외 거절, 응급(119 최상단), 오류(API 실패). 상태마다 보이는 것, 고정 문구·119·마스코트·"삐!" 사용 여부(PRD-06-02·03), 휴대폰 폭(360px)에서의 배치가 적혀 있다.
- [x] 모든 FR·NFR이 **어느 단계·화면에서 충족되는지** 추적표(요구사항 ID ↔ 시나리오 ↔ 화면 ↔ 구현 티켓)가 있다. 추적되지 않는 요구사항과 요구사항에 없는 화면 동작이 없다.

- [x] 흐름에서 **측정 전 가정**(응답 시간, 데모 가능 기간, 코퍼스 범위, 고시 표 포함 여부)이 "측정 전"으로 표시되고 결과를 기다리는 담당 티켓이 적혀 있다(RFP-15는 종결되어 시험이 BE 티켓으로 이관됨, 15.7절).
