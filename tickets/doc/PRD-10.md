## 1. 이슈
사용자 지적(2026-11-09, 화면 [ISSUE-002.png](../issues/ISSUE-002.png), 질문 "엄마가 이지렉트정을 드시는데 콜드-에스 같이 드려도 돼요?", 병용금기 결과). 화면에서 확인한 사실은 다음과 같다.

- 근거 상세 소제목은 "판정 · DUR 병용금기", "사유 원문", **"자료 날짜 · 둘 다 보여 드려요"**, "허가 라벨", "출처"다. 앞의 것들은 짧은 명사형인데 "자료 날짜"만 설명 문구가 붙어 길다.
- 결과 카드(중앙)에도 같은 내용이 한 번 더 나온다: "자료 날짜가 달라 둘 다 보여 드려요 · 파일 고시일 2025-07-14 · DUR 성분 API 고시일 2017-11-06"(중복).
- "허가 라벨" 본문은 "이지렉트정은 전문의약품이라 쉬운 설명이 없어요(허가사항 원문). 콜드-에스 상호작용 문장: [허가정보 원문 인용]"이다. 용어가 **허가 라벨 / 허가사항 / 허가정보** 셋으로 섞이고, `[허가정보 원문 인용]`은 대괄호 자리표시처럼 보여 규칙이 없다(원문이 채워지지 않은 것으로 보이나 코드 출처는 미확인, §11). 출처 줄에는 "식약처 의약품 허가정보"가 따로 있다. 사용자는 이 정보가 무엇인지 모른다.
- "자료 날짜"와 "출처"는 같은 정보다(사용자 지시 2, 2026-11-09).

사용자 지시(2026-11-09):
1. "'자료 날짜'만 보여지고, 설명은 필요 없지 않을까? 해당 내용에 대한 티켓을 신설하고, 근거 상세의 소제목은 현재처럼 글자를 제한하자."
2. "이지렉트정은 전문의약품이라 쉬운 설명이 없어요(허가사항 원문). … 규칙이 정해지지 않은 형태야. 여기서 허가정보란 어떤 정보인지 사용자 편의성을 근거로 문구 수(정)" — 문장이 끊겨 "문구 수정"으로 해석했다(§11).
3. **추가 지시: "자료 날짜와 출처는 같은 정보 같아. 하나로 축약하되, 형태는 하단의 출처처럼"** — 1번의 "자료 날짜만 남기고 설명 삭제"보다 우선한다. "자료 날짜" 구역을 없애고 "출처" 한 구역으로 합친다(§5, PRD-10-02 완료).

사실 근거(직접 확인 2026-11-09):
- 허가정보는 식약처 「의약품 제품 허가정보」 OpenAPI(`DrugPrdtPrmsnInfoService08`)의 제품 허가 내용(효능·효과, 용법·용량, 사용상 주의사항)이다. 문서에서는 이를 "허가사항 본문(허가정보 API 상세 XML)"이라 부른다(`P2-doc/PJ2-PRD.md:188`).
- 전문의약품은 e약은요(쉬운 설명)에 없다(`P2-doc/PJ2-PRD.md:181` "전문의약품 없음"). 전문의약품 라벨의 1순위 출처는 허가 상세 본문이다(`tickets/doc/RFP-21.md:283`, `:287`).
- 현재 문구 "쉬운 설명 없음(허가사항 원문)"은 PRD-08-05 A(2026-11-06)로 정했고(`tickets/doc/PRD-08.md:61`, `:150`), `EASY_TEXT_MISSING` 꼬리표의 코드 문구로 적혀 있다(`P2-doc/PJ2-Agent-Harness.md:208`, `:251`). 화면 시나리오는 `P2-doc/PJ2-PRD.md:378`.
- 용법용량 원문 인용은 근거 상세에만 허용하고 바로 아래 고정 문구를 붙인다(RFP-21-03 B, `tickets/doc/RFP-21.md:311`, `tickets/agent/AG-06.md:58`).
- "허가 라벨"은 H17 문구에도 있다("제품 연령 문장·허가 라벨·제형", `tickets/doc/RFP-29.md:137`, `P2-doc/PJ2-Agent-Harness.md:207`, `P2-doc/PJ2-PRD.md:156`, `:402`). 같은 개념에 "허가 라벨 / 허가사항 / 허가정보 / 라벨"이 문서에도 섞여 있다.

## 4. 소제목 규칙

### 4.1 현재 소제목 길이
ISSUE-002 화면의 근거 상세 소제목을 공백·가운뎃점 포함 글자 수로 센 표다(직접 셈).

| 소제목 | 글자 수 | 형태 | 이 티켓 처리 |
|---|---|---|---|
| 판정 · DUR 병용금기 | 13 | 짧은 명사형 | 유지(종류별로 "판정 · 임부금기" 9자 등, PRD-09 §7.2와 같음) |
| 사유 원문 | 5 | 짧은 명사형 | 유지 |
| 자료 날짜 · 둘 다 보여 드려요 | 18 | 설명 문구가 붙음 | **구역 삭제**, 출처로 합침(§5) |
| 허가 라벨 | 5 | 짧은 명사형이나 용어 혼재 | 용어 결정 후 변경(PRD-10-01 A면 "허가사항" 4자) |
| 출처 | 2 | 짧은 명사형 | 유지, 날짜까지 담는 구역이 됨 |
| (패널 제목) 근거 상세 | 5 | 짧은 명사형 | 유지 |

- "임부금기 N등급이란?" 같은 **접힘 컨트롤 라벨**(PRD-09 §7.2)은 소제목이 아니라 펼침 버튼이라 이 규칙의 대상이 아니다. 길이는 11~12자(`임부금기 2등급이란?` 11자)다.

### 4.2 길이 제한 제안
- 제안: 근거 상세 소제목은 **공백 포함 13자 이내의 짧은 명사형**이다(결정 PRD-10-03 A). 13은 지금 짧은 소제목 중 최장인 "판정 · DUR 병용금기"를 그대로 허용하는 값이다. 더 엄격한 10자안은 "판정 · DUR 병용금기"(13자)에서 "DUR"을 빼야 하는 대신 "판정 · 병용금기"(10자)가 되어 데이터 출처 구분이 줄어든다(비교 후보).
- 설명·조건·예외는 소제목에 쓰지 않고 본문 줄로 둔다. 소제목에 "·" 뒤 설명을 이어 붙이지 않는다(판정 소제목의 `종류` 표시만 예외).
- 코드 상수의 소제목 길이를 확인하는 화면 시험을 둔다(§7 ①).

## 5. 출처 구역(자료 날짜 합침)
사용자 지시(2026-11-09): 자료 날짜와 출처는 같은 정보라 하나로 합치고 형태는 하단의 출처처럼 문장형 한 덩어리로 둔다. **결정 PRD-10-02는 이 지시로 A(합침, 완료)다.**

### 5.1 근거 상세
- "자료 날짜" 구역과 표 형태의 두 행 박스를 쓰지 않는다. "출처" 한 구역만 둔다.
- 파일과 API의 날짜가 다를 때 두 날짜는 출처 줄 안에 `출처명(고시일 …)`으로 넣는다. 한쪽을 확정하지 않는다. 설명 문장("둘 다 보여 드려요")은 쓰지 않는다.
- 날짜가 같으면 기준일 하나만 쓴다.

문구 후보(확정 아님, ISSUE-002 값 기준):

```
출처
식약처 DUR 성분정보(고시일 2017-11-06) · 한국의약품안전관리원 병용금기 파일(고시일 2025-07-14, 기준일 2026-07-21) · 식약처 의약품 허가정보
```

- 가정: "고시일"은 그 항목의 고시일자이고 "기준일"은 파일 전체의 최신 고시일(2026-07-21, `CLAUDE.md` 4장)이다. 한 줄 안에 두 뜻이 섞이면 읽기 어려우므로 날짜가 다를 때만 항목별 고시일을 쓰고, 같을 때는 기준일 하나만 쓴다(§11).

### 5.2 결과 카드
- 현재 결과 카드의 "자료 날짜가 달라 둘 다 보여 드려요 · 파일 고시일 … · DUR 성분 API 고시일 …" 줄은 근거 상세와 같은 정보의 중복이다.
- 제안: **결과 카드에서는 이 줄을 삭제**하고 날짜는 근거 상세의 출처 줄에서만 보인다. 결과 카드에는 "근거 상세 열기 · 성분코드·출처" 링크가 이미 있다. 대안(출처 줄만 짧게 복제)은 중복이 남아 권장하지 않는다. FE-01에서 확정하고 이 절을 갱신한다.

### 5.3 PRD-09 G8과의 관계
- PRD-09 G8(파일과 API의 **등급**이 다르면 출처를 붙여 둘 다 보인다)은 출처를 붙여 병기한다는 같은 원칙이다. 이 티켓은 **고시일** 병기를 출처 줄로 합쳤고, G8의 등급 병기("파일: 임부금기 2등급 · 성분 API: 임부금기 1등급")는 판정 카드 안에 그대로 둔다. 충돌하지 않는다. 다만 PRD-09 §7.2의 "파일·성분 API 일치" 한 줄과 이 절의 출처 줄이 겹치지 않는지는 FE-02 구현 때 한 번 확인한다.

## 6. 허가사항 문구 규칙

### 6.1 용어 통일
- 같은 개념을 가리키는 말이 **허가 라벨 / 허가사항 / 허가정보**로 섞여 있다. 제안(결정 PRD-10-01 A): **화면 용어는 "허가사항"** 으로 통일하고, 소제목도 "허가사항"이다. 출처 줄의 "식약처 의약품 허가정보"는 **API 이름이라 그대로** 둔다.
- 이유(사용자 편의성): 효능·용법·주의가 적힌 허가 문서라는 뜻이 "허가사항 원문"이라는 말에서 더 쉽게 읽히고, "라벨"은 상표·딱지로 읽혀 일반인이 낯설다.
- 코드·내부 문서의 "라벨(L3)" 같은 용어는 이 티켓 범위 밖이다. 화면·`finalize` 문구 상수·PRD의 화면 문구에만 적용한다.

### 6.2 허가사항이 무엇인지 한 줄 설명
- 사용자가 허가사항이 무엇인지 모른다는 지적이 있었다. 제안: 근거 상세 "허가사항" 구역의 **첫 항목에만** 한 줄을 둔다(구역마다 반복하지 않는다). 후보: "허가사항: 식약처가 의약품을 허가할 때 정한 효능·효과, 용법·용량, 사용상 주의사항이에요."
- 위치는 소제목 바로 아래 고정 한 줄이다(접힘 블록은 쓰지 않는다. 짧아 접을 필요가 없고 처음 보는 사용자가 놓치지 않게 한다). 코드 상수로 넣고 LLM이 쓰지 않는다.

### 6.3 전문의약품 안내 문구
- 전문의약품은 e약은요가 없으므로 허가사항 원문을 보여 준다. 현재 "이지렉트정은 전문의약품이라 쉬운 설명이 없어요(허가사항 원문)"는 괄호 표기가 규칙 없이 붙어 있다.
- 제안(결정 PRD-10-04 A): 약마다 앞에 한 줄 "{약 이름}은 전문의약품이라 쉬운 설명(e약은요)이 없어서 허가사항 원문을 그대로 보여 드려요". 이 문구는 PRD-08-05 A의 의도(근거를 숨기지 않고 허가 원문을 인용)를 바꾸지 않고 **표기 형식만** 바꾼다. `EASY_TEXT_MISSING` 꼬리표와 코드 문구(`P2-doc/PJ2-Agent-Harness.md:208`)는 이 결정 뒤 같이 고친다.
- 문구 예시는 후보이며 확정하지 않는다.

### 6.4 원문 인용 형식
- 대괄호 자리표시(`[허가정보 원문 인용]` 같은 형태)는 쓰지 않는다. 코드가 원문을 가져오지 못하면 그 줄을 만들지 않고 "원문을 가져오지 못했어요"를 쓴다.
- 제안 형식(후보): `{약 이름} 허가사항 원문({항목}): "원문 문장"`. 예: `타이레놀콜드-에스정 허가사항 원문(상호작용): "…MAO 억제제(항파킨슨제 등)와 함께 복용하지 마십시오…"`.
  - **약 이름**을 앞에 붙여 어느 약의 문장인지 밝힌다(ISSUE-002는 "콜드-에스 상호작용 문장"이 어느 약의 어느 항목인지 불분명했다).
  - **인용부호**(큰따옴표)로 원문임을 표시한다. 원문 일부는 `…`로 줄임을 밝힌다.
  - 항목명(상호작용·사용법·임부 등)은 괄호에 한 번만 쓴다.
- 용법용량 원문 인용 바로 아래 고정 문구는 RFP-21-03 그대로다(`허가사항 원문 인용이며 복용 지시가 아닙니다. 복용량은 약사·의사에게 확인하세요`). 이 문구가 이미 "허가사항 원문"이라는 용어를 쓰고 있어 PRD-10-01 A와 일치한다.

## 7. 화면 시험
① 근거 상세 소제목이 모두 결정된 글자 수 이내이고 "·" 뒤 설명 문장이 없다(PRD-10-03). ② 화면에 "자료 날짜" 구역과 "둘 다 보여 드려요" 문구가 없다. ③ 파일과 API 날짜가 다르면 출처 줄 안에 `출처명(고시일 …)`으로 두 날짜가 모두 보이고, 같으면 기준일 하나만 보인다(PRD-10-02). ④ 결과 카드에 자료 날짜 줄이 없다(§5.2 확정 후). ⑤ 화면 어디에도 "허가 라벨"·"허가정보 원문 인용" 같은 옛 용어가 없다(PRD-10-01 A 기준, 출처 줄의 API 이름 "허가정보"는 예외). ⑥ 대괄호 자리표시(`[...]`로 값이 비어 보이는 형태)가 화면에 없다. ⑦ 전문의약품(e약은요 없음)에 안내 한 줄과 원문 인용(약 이름·인용부호)이 나온다(PRD-10-04). ⑧ 허가사항 설명 한 줄이 구역마다 반복되지 않고 첫 항목에만 한 번 나온다. ⑨ 용법용량 원문 인용 바로 아래 고정 문구가 있다(RFP-21-03). ⑩ ISSUE-002와 같은 질문을 mock으로 다시 그려 전후 화면을 비교한다.
