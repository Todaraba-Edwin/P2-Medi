## 이슈
RFP 12장 리스크 18건의 대응이 실제 반영됐는지 확인한다. 2026-10-31 RFP 변경으로 확장(온보딩·로그인) 관련 4건(10~13번)이 더해져 13건에서 17건이 되었고, 같은 날 Retrieval 설계 범위 초과 행(17번)이 더해져 18건이 되었다. 12장 표의 행(헤더 제외)을 직접 세어 확인한 값이다.
1. API 키 발급·호출 제한 → 1주차 첫날 발급, 응답 캐싱 (BE-01, BE-02, BE-03)
2. HWP·복잡한 표 파싱 실패 → PDF 우선, 실패 문서 제외 (BE-04)
3. e약은요 상호작용은 문장형 → 병용금기 판정은 DUR 기준 (AG-05, AG-02, BE-03)
4. DUR 금기 데이터를 확보하지 못함 → OpenAPI·파일 데이터·고시 PDF 세 경로로 확보하고 기준일 표시 (RFP-17, BE-09)
5. 텍스트 레이어가 없는 이미지 PDF → OCR로 필요한 쪽만 읽고 불가능하면 범위에서 제외 (BE-04)
6. 고시 PDF의 표가 쪽마다 다르게 추출됨 → 파서 시험 전에는 구조화된 파일·API 우선 (BE-04, RFP-15, BE-09)
7. 파일 데이터와 고시는 갱신되지 않는 스냅샷 → 답변에 기준일 표시, API로 교차 점검, 기준일 이후 변경을 추정하지 않음 (AG-02, AG-06, FE-02)
8. 금기등급 M은 고시에 없고 심평원 문서에만 정의됨 → 심평원 설명 인용, 등급은 상세정보 원문 (RFP-17, AG-07, BE-09)
9. 범위 확대(중복·용량·수유부·온보딩·소셜 로그인)로 일정 초과 → 핵심(병용·연령·임부 금기)을 먼저 끝내고 4장 순서대로 확장 항목부터 축소, Agent-RAG 핵심 요소(Router·도구 선택·근거 고정·Validator·평가 수치)는 축소 금지, 응급(FR-06)은 필수라 축소 대상이 아님 (PRD-01, AG-05, AG-07)
10. 서비스 기능(로그인·프로필)이 Agent-RAG보다 커짐 → 확장은 SCH-02 필수 티켓이 끝난 뒤에만 시작, 게스트 사용으로 핵심 시연은 항상 가능 (BE-11, FE-04, RFP-20)
11. 건강 관련 프로필 저장의 개인정보 부담 → 최소 항목·동의·수정·삭제, 질문 내용 비저장, 게스트는 저장 없음 (RFP-12, BE-11, AG-05)
12. 소셜 로그인 4종 연동 부담 → Google·Kakao 먼저, Apple·Naver는 확인 후 포함 여부 결정 (BE-11)
13. Supabase 무료 플랜 한계(DB 500MB, 비활동 1주 일시정지) → RFP-15에서 적재 크기 확인, 시연 전에 프로젝트를 깨워 둠, 대안은 로컬 Chroma (RFP-15, BE-09, BE-11)
14. "금기 없음"을 안전 허락으로 오해 → 결과 없음일 때 붙는 고정 문구를 코드로 강제하고 평가 세트에 이 경우를 넣음 (AG-08, AG-04, AG-12)
15. 응급 대응 문구·연락처에 공식 근거가 없음 → RFP-19 확인 전에는 119와 약국·약사 안내 외의 응급 지침을 쓰지 않음 (RFP-19, AG-08)
16. 전문가가 DUR 시스템의 대체로 오인 → 고지에 대체 불가를 명시하고 전문가 전용 기능을 두지 않음 (AG-08, FE-02)
17. Retrieval 설계(근거 계층 6개, 저장소 3개, 하이브리드 검색)가 1주차 범위를 초과 → 설계 문서 11장의 순서를 따르고 용어집(L4)·논문 정리(L5)·약사법 조문은 맨 마지막으로 미룸, 사전(A)과 사유·고시 청크(L2·L1)를 먼저 끝냄 (BE-10, BE-05, BE-12, AG-15)
18. 일정 지연 → 4장의 축소 순서(로그인 → 프로필 저장 → FR-07 → AG-15 → 수유부·노인 주의 → 중복·용량)를 따름 (RFP-08, RFP-20)

가정: 담당 티켓은 각 대응의 내용에서 읽어 붙인 것이며, RFP 12장에 담당 티켓이 적혀 있는지는 확인하지 않았다.

## 완료 조건
- [ ] 위 18건 각각의 대응이 해당 티켓에 반영되어 있음을 확인하고 `메모`에 기록했다.
- [ ] 17번 대응(설계 문서 11장 순서)이 BE-05(사유·고시 청크 먼저, L4·L5·약사법은 이 티켓에 없음)와 BE-10(사전)에 반영되어 있고, L4·L5·약사법 조문 후순위가 어느 티켓에도 필수로 걸려 있지 않다.
- [ ] 파싱 실패로 제외한 문서가 있다면 목록과 사유가 BE-04 메모에 있다.
- [ ] 9번의 보호 대상(Router·도구 선택·근거 고정·Validator·평가 수치)이 PRD-01, AG-05, AG-06, AG-07, AG-11 메모에 같은 표현으로 적혀 있다.
- [ ] 10~13번 대응(확장은 필수 뒤에만, 게스트 사용, 개인정보 최소 저장, 제공자 단계 도입, Supabase 한도 확인)이 BE-11·FE-04·RFP-15에 반영되어 있다.
