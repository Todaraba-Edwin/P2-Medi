## 1. 이슈
RFP 6장 FR-01: "Router(입력 정리): 질문에서 약품명·연령·임신 여부·질환 등 엔티티를 추출하고 모호 여부와 질문 유형을 판정해 상태에 기록한다. 경로(도구)는 Router가 정하지 않고 에이전트(ReAct)가 고른다(RFP-25-02). 연령·임신 여부는 대화 중 입력하거나 사용자가 동의해 저장한 프로필(FR-09)에서 가져온다. 질문·대화 내용은 저장하지 않는다". 구현 티켓(AG-05)이 이 요구를 충족했는지 추적한다.

## 2. FR-01 조건별 대조

### 2.1 대조 방법과 범위
- 기준일은 2026-11-19이고 대상은 develop 브랜치의 코드다. 이 절은 코드와 시험 파일을 **읽기만** 해서 쓴 것이며 pytest는 이 작업에서 돌리지 않았다. 아래 "시험"은 시험이 존재한다는 뜻이고 통과 결과는 [AG-05](../agent/AG-05.md)의 기록을 따른다.
- FR = Functional Requirement(기능 요구사항). FR-01 문장은 `P2-doc/PJ2-RFP.md` 6장 표에 있다. 이 문장을 쉼표 단위 조건 6개로 나눠 대조했다.
- 근거 표기는 `파일:줄`이며 코드가 바뀌면 줄이 밀린다. 근거 줄은 2026-11-19 develop 기준이다.
- 이 절은 상태·체크박스·결정 표를 바꾸지 않는다. 체크 제안은 §2.5에 적는다.

### 2.3 RFP 8장 구조도와 분기 비교
구조도(`PJ2-RFP.md` 8장 코드 블록, `:344-348`)와 그래프 코드를 분기별로 비교했다. 그래프는 `backend/app/agent/graph/build.py:35-41`, 간선 함수는 `backend/app/agent/graph/nodes.py:303-321`이다.

| 구조도 분기 | 코드 | 일치 |
|---|---|---|
| Router → 공공 API Tool / 금기 조회 Tool / Vector DB 검색 | 간선에 이 3분기가 없다. `router` 다음은 `model`뿐이고 도구 선택은 `model ⇄ tools`가 한다(`build.py:37-39`) | 일치. 구조도 아래 주석(`PJ2-RFP.md:350`)이 "코드가 나누는 경로가 아니라 에이전트가 고르는 도구 호출의 기본 경로"라고 이미 밝혔다 |
| 안내 전환(범위 외) | `guardrail_in`에서 거절이고 응급이 아니면 `finalize`로 직행(`nodes.py:303-304`) | 일치 |
| 안내 전환(근거 없음) | 구조도의 한 분기가 아니라 `router` 라벨(`근거 없음`)과 도구 결과 상태 `NO_EVIDENCE`로 나뉜다(`router.py:905-917`) | 부분 일치: 구조도는 한 갈래로, 코드는 두 곳에서 처리 |
| (구조도에 없음) 되묻기 | `after_router`가 모호하면 `finalize`로 보낸다(`nodes.py:307-308`) | 구조도 밖. 8.1절 예외 경로 표(`PJ2-RFP.md:430`)에는 있다 |
| 응급: 119 고정, 위 경로는 막지 않고 병행 | 응급은 `proceed_tools`가 항상 참이고(`guardrail.py:219`), 응급만 있으면 `router`로 간다(`nodes.py:304`). 119는 `finalize`가 맨 위에 둔다(`finalize.py:653-654`) | 일치 |
| 응급 감지는 Router가 아니라 Guardrail | `router.py`에 응급 키워드 목록이 없다. `emergency`는 읽기만 하고 그대로 통과(`router.py:196-197`) | 일치 / `test_ag05_router.py:300`·`:322` |

- 8.2절 사다리와의 관계: Router는 L0 입력 정리 단계이고 기준선 도구 선택은 L1 ReAct(`PJ2-RFP.md` 8.2절 RFP-25 결정 인용문)다. 코드도 이 구분을 지킨다.
- 구조도 보완 제안(가정): 구조도에는 "되묻기"가 없다. 8.1절 예외 경로와 맞추려면 `안내 전환` 갈래 옆에 "되묻기(모호)" 한 줄을 더하는 편이 정확하다. RFP 본문 수정은 이 티켓 범위 밖이라 확인 필요로 둔다.

### 2.4 게스트 비저장 점검
FR-01은 "질문·대화 내용은 저장하지 않는다"를 요구한다. 게스트 요청에서 질문·연령·임신 여부가 디스크·DB·로그로 가는 경로가 있는지 코드와 시험 존재를 확인했다.

| 점검 대상 | 근거 | 시험 |
|---|---|---|
| Router: 질문·연령·임신 여부는 상태에만 존재 | `router.py:13`, `:132-141`(`ProfileState` 설명) | `test_ag05_router.py:314`(`test_pure_no_side_effects`, 실행 뒤 작업 폴더가 비어 있음) |
| 요청 본문: 서버는 대화 상태를 저장·로그하지 않음 | `backend/app/api/request.py:3`, `:60` / `backend/app/api/chat.py:11`, `:79` / `backend/app/api/runner.py:8` | `backend/tests/test_be06_route.py:63`, `test_be06_chat_stream.py:212`·`:317` |
| 그래프 상태의 질문 원문은 로그에 넣지 않음 | `backend/app/agent/graph/state.py:6` | 위 시험과 같음 |
| 서비스 로그는 내용 없는 집계만 | `backend/app/logging/spans.py:6` | `backend/tests/test_be15_logging.py:76`·`:95`·`:173-180`, `test_be06_l4_metrics.py:83` |
| 서비스 경로는 `data/mock/`을 읽거나 쓰지 않고 원장·캐시도 만들지 않음 | 시험 이름이 근거(코드 줄은 이 작업에서 읽지 않음) | `backend/tests/test_be06_service_split.py:190` |
| 오류 로그에 질문 원문 없음 | `backend/app/api/stream.py:155` | `test_be15_logging.py:173-180` |

- **결과**: 게스트 경로의 질문·연령·임신 여부는 코드상 어디에도 저장되지 않으며, 이를 확인하는 시험이 존재한다. 이 작업에서 시험을 실행하지는 않았다.
- **예외(주의)**: dev·eval 로그 모드는 `input_text`를 남길 수 있다(`test_be15_logging.py:126-131`). 서비스 모드가 아니라 개발·평가용이며 합성 평가 질문에만 켠다(`PJ2-RFP.md` 8.2절 "질문 대화는 저장하지 않으므로 trace는 합성 평가 질문에만 켠다"). 서비스 모드로 같은 입력이 새지 않는다는 시험은 위 표의 시험들이다.
- **프로필 사용 시(확장)**: 현재 `backend/app/api/me.py`는 계정 확인(`GET /me`)만 있고 프로필 저장 코드는 찾지 못했다(`me.py`를 `profile`·`프로필`·`저장`으로 검색해 일치는 문서 경로가 적힌 주석 1건(`me.py:7`)뿐, 가정: BE-11 S2 대기). 따라서 "프로필 저장 범위가 동의 항목뿐" 조건은 지금 점검할 대상이 없다. 4번째 완료 조건은 BE-11 S2 구현 뒤에 확인한다.

### 2.5 미충족과 남은 일
| 항목 | 상태 | 이유·다음 |
|---|---|---|
| 질환 엔티티 추출 | 미충족 | 규칙 Router에 질환 추출이 없다. 분류기(`router_classify`)가 AG-13 후보라 그래프 연결·끝까지 비교 뒤에 판단([AG-05 §3](../agent/AG-05.md#3-하위-작업) AG-05-14 A) |

- 체크 제안(보고에만, 이 티켓 체크박스는 바꾸지 않음): 완료 조건 2번(도구 선택과 응급 병행)은 §2.3으로 확인됐다고 볼 수 있다. 1번은 질환 미충족이라 AG-05가 done이 되기 전에는 체크하지 않는다. 3번은 §2.4 표로 코드·시험 존재를 확인했으나 통합 시험이 없어 사용자가 갈음할지 정한다.
