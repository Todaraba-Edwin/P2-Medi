## 이슈
PJ2-W1 구현을 시작하기 전에 e약은요·DUR 품목정보·DUR 성분정보를 실제로 호출해, 이 프로젝트를 실제 공공 API로 진행할 수 있는지 확인한다. 결과는 RFP 5.2절에 기록하고 서비스별 응답은 `P2-doc/PJ2-API-응답확인.md`에 둔다. 근거는 RFP 10장 사전 행("공공 API 3종 실측 확인(RFP-21)")이다. 2026-11-01 사용자 요청: API 테스트 상황을 Pre-Week에서 확인하고 RFP-번호 문서로 PJ2-RFP.md에 기록한다.

### 관련 코드·자료
용어: **프로브**는 공공 API를 실제로 불러 응답을 점검하는 용도의 작은 코드를 부르는 말이다. **목(mock) 픽스처**는 실제 응답을 파일로 저장해 둔 것으로, API를 다시 부르지 않고 테스트 입력으로 쓴다.

| 파일 | 무엇인가 | 언제 쓰나 |
|---|---|---|
| [manifest.json](../../tests/fixtures/api/manifest.json) | 저장해 둔 실제 응답 9건의 목록. 사례 이름, 어느 API를 어떤 조건으로 불렀는지, 무엇을 보여 주는지, 파일 위치 | 어떤 사례가 있는지 찾을 때 |
| [field_survey.json](../../tests/fixtures/api/field_survey.json) | 오퍼레이션 17개의 필드 조사표: 필드 이름, 타입, 값이 채워진 비율, 예시 | 어떤 필드가 있고 비는 필드가 무엇인지 볼 때 |
| [capture_fixtures.py](../../scripts/api_probe/capture_fixtures.py) | 실제 API를 불러 위 응답 9건과 필드 조사표를 다시 저장하는 프로그램. 저장 뒤 키가 파일에 섞였는지도 검사 | 픽스처를 새로 만들거나 갱신할 때 |
| [probe.py](../../scripts/api_probe/probe.py) | 세 API를 실제로 호출해 응답을 요약하는 점검 도구(프로브). 인증키는 `.env`에서만 읽고 출력하지 않는다 | 응답 확인, 키·주소 문제 진단 |
| [app.py](../../scripts/api_probe/app.py) | 점검 도구를 웹 주소로 쓰게 한 FastAPI 앱. `/battery`(전체 점검 21회), `/probe/...`(한 건 호출), `/mock/...`(저장된 응답 반환) | API 한도를 쓰지 않고 개발·테스트할 때(`/mock`) |
| [.env.example](../../.env.example) | 필요한 환경변수 이름 6개만 적은 견본. 값은 없다 | 새 환경에서 `.env`를 만들 때 |

> `data/api_samples/`(원본 응답 저장 폴더)는 git에 올리지 않아 링크가 없다.

- 이 티켓에서 확인한 항목은 BE-01·BE-02·BE-03의 일부 체크박스에 "(Pre-Week RFP-21에서 확인)"으로 연결했다. 그 티켓들의 나머지 W1 구현 조건은 미완이다.
- 가정: 우선순위는 `필수`(사용자 지시). `rfp` 항목은 사용자 지시대로 `5.2`, `10장`으로 적었다.
- 2026-11-01 연결 문서: 응답 값·엔티티 `P2-doc/PJ2-API-엔티티.md`, 목 픽스처 `tests/fixtures/api/`(9건), 서비스별 요약 `P2-doc/PJ2-API-응답확인.md`, RFP 기록 `P2-doc/PJ2-RFP.md` 5.2절. 사용자 결정 2건(허가정보 API 활용신청 시점, 파일↔API 성분 연결 규칙)의 근거 실측: 영문 성분명 정규화 일치 임부 64%·병용 36%, 품목 `EDI_CODE` 표본 8개 중 4개, 허가정보 API는 현재 키로 403(키 미등록). 정정: 앞서 "문자열 null"로 적은 것은 착오이고 실제는 JSON null이다.
