## 이슈
현재 `P2-doc/PJ2-RFP.md`에 초안이 있다. 다만 LLM 선택(`[선택 예정]`)과 평가 세트 세트별 문항 수(`[__]`)가 비어 있다. 이 두 항목은 RFP-15(1주차 결정사항 확정)에서 확정하므로, 이 티켓에서는 초안의 나머지 내용을 사용자가 확인·확정하고 두 빈칸은 RFP-15로 넘긴다.

## FR이란
FR은 Functional Requirement, 즉 **기능 요구사항**이다. [`P2-doc/PJ2-RFP.md`](../../P2-doc/PJ2-RFP.md) 6장 표의 **한 행이 FR 하나**이고, 시스템이 "할 수 있어야 하는 한 가지 기능"을 뜻한다.

표는 세 칸으로 읽는다.

| 칸 | 읽는 법 |
|---|---|
| ID | 요구사항 번호(`FR-01`~`FR-08`). 티켓과 대화에서 이 번호로 해당 기능을 가리킨다 |
| 요구사항 | `이름: 설명` 형태. 콜론 앞이 기능 이름, 뒤가 해야 할 일이다 |
| 우선순위 | `필수`는 반드시 구현한다. `권장`은 일정이 부족하면 줄일 수 있다(RFP 12장 위험 표에서 일정 지연 시 FR-07 등 권장 항목부터 축소한다고 적혀 있다) |

7장 비기능 요구사항(NFR = Non-Functional Requirement)은 성격이 다르다. FR이 "무엇을 하는가"라면 NFR은 "얼마나 잘, 어떤 조건으로 하는가"이다. 7장은 신뢰성, 재현성, 보안, 고지 네 가지이며 `FR-nn` 번호가 없다.

## 번호 혼동 방지
`FR-nn`과 `RFP-nn`은 서로 다른 번호다.

| 번호 | 정체 | 위치 |
|---|---|---|
| `FR-nn` | RFP 6장의 요구사항 번호 | `P2-doc/PJ2-RFP.md` |
| `RFP-nn` | FR 등을 추적하는 티켓 번호 | `tickets/doc/` |

현재는 **FR-nn = RFP-(nn+1)** 이다. 이 문서의 번호 변경 메모(메모 섹션)에 따라 RFP-01이 "RFP 문서 작성" 티켓이 되면서 한 칸씩 밀렸다.

| FR | 추적 티켓 | FR | 추적 티켓 |
|---|---|---|---|
| FR-01 | [RFP-02](RFP-02.md) | FR-05 | [RFP-06](RFP-06.md) |
| FR-02 | [RFP-03](RFP-03.md) | FR-06 | [RFP-07](RFP-07.md) |

## FR-01부터 FR-08까지 의미
각 항목의 입력→출력 예시는 RFP에 없는 내용이라 모두 `가정:`이다. 구현 티켓은 각 티켓 frontmatter의 `rfp` 항목에 해당 FR이 있는 것을 찾았다.

### FR-01 Router
- **한 줄 정의**: 질문에서 약품명·연령·질환 같은 엔티티(핵심 정보)를 뽑고, 알맞은 도구로 보낸다.
- **쉬운 설명**: 질문마다 필요한 조회처가 다르다. 약품 정보는 공공 API, 제도·검진 안내는 문서 검색이 맞다. 길잡이 역할을 하는 Router가 없으면 엉뚱한 곳을 찾게 된다.
- **예시 (가정:)**: "65세인데 와파린이랑 아스피린 같이 먹어도 돼?" → 약품명 2개, 연령 65세를 추출하고 DUR 조회 도구로 분기.
- **우선순위**: 필수
- **RFP 근거**: 6장 FR-01, 8장 시스템 구조(Agent Router)
- **연결된 티켓**: 추적 [RFP-02](RFP-02.md) / 구현 [AG-05](../agent/AG-05.md), [BE-06](../backend/BE-06.md)

### FR-02 공공 API Tool
- **한 줄 정의**: e약은요·DUR 공공 API를 조회하고, 조회한 시각을 기록한다.
- **쉬운 설명**: 약품 사실은 LLM의 기억이 아니라 공공 API에서 가져온다. 조회 시각을 남겨야 나중에 "언제 기준 정보인지" 밝힐 수 있다.
- **예시 (가정:)**: 약품명 "타이레놀" → e약은요 조회 → 효능·주의사항 원문과 조회 시각 2026-10-30 14:00.
- **우선순위**: 필수
- **RFP 근거**: 6장 FR-02
- **연결된 티켓**: 추적 [RFP-03](RFP-03.md) / 구현 [AG-02](../agent/AG-02.md), [BE-02](../backend/BE-02.md), [BE-03](../backend/BE-03.md)

### FR-03 문서 RAG
- **한 줄 정의**: 문서의 표를 마크다운으로 살려 파싱하고, 문서종류·연도·부처 메타데이터로 걸러서 검색한다.
- **쉬운 설명**: RAG(Retrieval-Augmented Generation)는 문서를 검색해 그 내용으로 답하는 방식이다. 검진·보건사업 기준은 표로 된 경우가 많아, 표가 깨지면 답도 틀린다. 연도·부처로 걸러야 옛 기준이 섞이지 않는다.
- **예시 (가정:)**: "올해 국가건강검진 대상 연령은?" → 문서종류=검진 안내, 연도=올해로 필터 → 해당 표 조각 반환.
- **우선순위**: 필수
- **RFP 근거**: 6장 FR-03
- **연결된 티켓**: 추적 [RFP-04](RFP-04.md) / 구현 [AG-03](../agent/AG-03.md), [BE-04](../backend/BE-04.md), [BE-05](../backend/BE-05.md)

### FR-04 Citation
- **한 줄 정의**: 모든 답변에 출처·조회 시각·조항을 표기한다.
- **쉬운 설명**: 답변의 사실마다 "어디서 나왔는지"를 붙인다. 사용자가 직접 확인할 수 있고, 근거 고정(grounding, 답변의 사실을 조회한 근거에만 묶어 두는 것)의 한 축이다. [`claude-prompt/03_legal_and_medical.md`](../../claude-prompt/03_legal_and_medical.md)에서는 숫자마다 출처 라벨을 정확히 전달하는 규칙에 대응한다고 설명한다.
- **예시 (가정:)**: 답변 끝에 "출처: e약은요 · 조회 2026-10-30 14:00" 또는 "출처: 건강검진 시행 안내 제3조"를 붙임.
- **우선순위**: 필수
- **RFP 근거**: 6장 FR-04
- **연결된 티켓**: 추적 [RFP-05](RFP-05.md) / 구현 [AG-06](../agent/AG-06.md), [BE-06](../backend/BE-06.md), [FE-02](../frontend/FE-02.md)

### FR-05 Validator
- **한 줄 정의**: 답변이 원본 API·문서와 일치하는지 점검한 뒤에 출력한다.
- **쉬운 설명**: LLM이 문장을 만들면서 숫자나 내용을 바꿀 수 있다. 출력 직전에 답변과 원본을 다시 비교해 어긋나면 내보내지 않는다. 위 문서에서는 공식 사본과 대조하는 단계에 대응한다고 설명한다.
- **예시 (가정:)**: 초안 "하루 4회"인데 원본에는 "하루 3회" → 불일치로 판정, 수정하거나 출력 보류.
- **우선순위**: 필수
- **RFP 근거**: 6장 FR-05, 8장 시스템 구조(Validator)
- **연결된 티켓**: 추적 [RFP-06](RFP-06.md) / 구현 [AG-07](../agent/AG-07.md)

### FR-06 Guardrail
- **한 줄 정의**: 진단·처방 금지 문구를 넣고, 응급 키워드는 119 안내로 돌리며, 범위 밖 질문은 거절한다.
- **쉬운 설명**: 이 서비스는 정보 제공이지 의료 판단이 아니다. 위험한 질문에서 억지로 답하지 않고 안전한 안내로 바꾼다.
- **예시 (가정:)**: "가슴이 너무 아파요, 숨이 안 쉬어져요" → 약품 조회 없이 "119에 연락하세요" 안내.
- **우선순위**: 필수
- **RFP 근거**: 6장 FR-06, 7장 고지
- **연결된 티켓**: 추적 [RFP-07](RFP-07.md) / 구현 [AG-08](../agent/AG-08.md)

### FR-07 오탈자 보정
- **한 줄 정의**: 약품명을 잘못 입력하면 정규화(올바른 이름으로 바로잡기)한 뒤 다시 검색한다.
- **쉬운 설명**: 약 이름은 길고 비슷해서 오타가 잦다. 보정하지 않으면 "없음"으로 처리되어 사용자가 불편하다. 유일한 `권장` 항목이라 일정이 밀리면 가장 먼저 줄인다.
- **예시 (가정:)**: "타이레놀" 대신 "타이레놀ㄹ" 또는 "타일레놀" 입력 → "타이레놀"로 보정해 재검색.
- **우선순위**: 권장
- **RFP 근거**: 6장 FR-07, 12장 위험 표(일정 지연 시 축소)
- **연결된 티켓**: 추적 [RFP-08](RFP-08.md) / 구현 [AG-10](../agent/AG-10.md), [BE-07](../backend/BE-07.md)

### FR-08 근거 없음 처리
- **한 줄 정의**: 검색 결과가 없으면 지어내지 않고 모른다고 응답한다.
- **쉬운 설명**: 근거가 없을 때 LLM이 그럴듯하게 채우는 것이 가장 위험하다. 근거가 없으면 답을 만들지 않고 멈춘다. 위 문서에서는 라벨을 못 찾으면 기억으로 숫자를 말하지 않는 규칙에 대응한다. FR-04·FR-05와 함께 근거 고정을 이루며, 흐름은 근거 조회 → 없으면 멈춤(FR-08) → 출처 표기(FR-04) → 일치 점검(FR-05) 순서다.
- **예시 (가정:)**: 데이터에 없는 약품을 검색했는데 결과 0건 → "조회된 정보가 없어 답변드릴 수 없습니다."
- **우선순위**: 필수
- **RFP 근거**: 6장 FR-08, 7장 신뢰성
- **연결된 티켓**: 추적 [RFP-09](RFP-09.md) / 구현 [AG-09](../agent/AG-09.md)

## DUR 데이터 확보 점검
DUR = Drug Utilization Review, 의약품 처방·조제 점검이다. 병용금기 등 금기 규정 데이터를 실제로 얻을 수 있는지 점검한다. 아래에서 확인된 것과 확인하지 못한 것을 구분해 적는다.

### 문제
사용자 관찰(2026-10-30): 이 프로젝트의 핵심은 약과 약, 약과 사용자 조건(연령·임부 등) 사이의 금기 규정이다. 그런데 DUR을 API로 제공받을 수 있는지 불분명해 보인다. 금기 데이터를 확보하지 못하면 병용금기 등 핵심 기능을 진행할 수 없다.

### 확인해야 할 것
- DUR을 병원(요양기관) 단위에서만 쓸 수 있는지, 개인 단위에서도 쓸 수 있는지.
- 관련 자료가 PDF로 있으면 가져와 문서 RAG 경로(FR-03)로 쓸 수 있는지. RFP 5장에도 "DUR 가이드" PDF가 비정형 소스로 적혀 있다.

### 조사 결과 2026-10-30 웹 확인
**확인된 것**
- (a) 공공데이터포털에 식품의약품안전처 제공 DUR API가 두 개 있다.
  - [의약품안전사용서비스(DUR)품목정보](https://www.data.go.kr/data/15059486/openapi.do): 오퍼레이션 9개. 병용금기, 노인주의, DUR품목정보 조회, 특정연령대금기, 용량주의, 투여기간주의, 효능군중복, 서방정분할주의, 임부금기.
  - [의약품안전사용서비스(DUR) 성분정보](https://www.data.go.kr/data/15056780/openapi.do): 오퍼레이션 7개. 병용금기, 특정연령대금기, 임부금기, 용량주의, 투여기간주의, 노인주의, 효능군중복.
  - 둘 다 JSON+XML을 지원하고, 수정일은 2025-09-16이다.
- (b) 이 둘이 RFP가 말한 병용·연령·임부 금기를 조회할 수 있는 형태다.

**RFP와 다른 점**: RFP 5장은 "DUR"의 출처를 "심평원"으로 적었지만, 포털에서 확인한 DUR API의 제공기관은 식약처다. 출처 표기를 바꿀지는 사용자가 판단한다. 지금은 RFP를 고치지 않는다.

**확인하지 못한 것**
- (c) 포털 페이지에서 활용신청 승인 방식과 일일 트래픽 제한이 "없음"으로 읽혔지만, 항목이 없다는 뜻인지 제한이 없다는 뜻인지 구분하지 못했다. 활용신청과 키 발급이 실제로 되는지는 확인하지 않았다.
- (d) 심평원 DUR은 요양기관이 처방·조제 때 쓰는 실시간 점검 시스템으로 알려져 있고, 검색 결과에는 전송에 요양기관 인증서가 필요하다는 내용이 있었다. 기관 단위로 보이지만 개인이 쓸 수 있는지는 확인하지 못했다. 검색 요약이라 심평원 공식 자료로 직접 확인해야 한다.
- (e) 응답 형식과 필드는 설명서나 실제 응답으로 확인하지 않았다.

### 경로 비교
| 경로 | 내용 | 단위 | 현재 판단 |
|---|---|---|---|
| A 식약처 DUR OpenAPI(포털) | 병용·연령·임부 등 금기 조회 | 규칙 조회(개인 의료기록 불필요) | 가장 유력. 활용신청과 응답 확인 필요 |
| B 심평원 DUR 시스템 | 처방·조제 실시간 점검 | 요양기관 단위로 보임 | 개인 이용 가능 여부 미확인. 이 프로젝트에는 맞지 않을 가능성 |
| C PDF 자료 | DUR 가이드 등 문서 | 문서 RAG(FR-03) | A가 막힐 때의 대안이며 자료 수집 필요 |

### 진행 조건과 다음 확인
- 금기 데이터(경로 A 또는 C)를 확보하지 못하면 병용금기 기능은 진행할 수 없다. 이는 [BE-03](../backend/BE-03.md), [AG-02](../agent/AG-02.md), [RFP-03](RFP-03.md)에 영향을 준다.
- 다음 확인
  1. 포털에서 활용신청이 되는지.
  2. 응답 샘플로 필드를 확인.
  3. 사용자가 DUR 설명서를 첨부.
  4. 심평원 쪽 개인 이용 가능 여부를 공식 자료로 확인.
  5. 경로 A가 막히면 경로 C의 PDF 확보.
- 확인 시점과 담당은 사용자가 정한다.

## 메모
- 작업 기간: 2026-10-30(금) ~ 2026-11-01(일), 사용자 지정.
- 사용자가 확인하기 전에는 `done`으로 바꾸지 않는다.
- 가정: 우선순위는 `필수`로 둔다(RFP에 이 작업의 우선순위 표기가 없다).

- 번호 변경: 2026-10-30 사용자 요청으로 기존 RFP-16이 RFP-01이 되었고, 기존 RFP-01~15는 RFP-02~16으로 한 칸씩 밀렸다. 이에 따라 "RFP-01~08 = FR-01~08" 번호 일치는 더 이상 성립하지 않는다(FR-nn = RFP-(nn+1)).

- 후속 계획: DUR 설명서는 사용자가 첨부할 예정이다(2026-10-30 사용자 결정). 받으면 documents-writer로 `P2-doc/`에 정리하고, 그때 첨부 문서의 관련 티켓에 BE-03을 연결하며 DUR 환경변수 이름도 함께 적는다. 다만 DUR 데이터를 확보할 수 있는지는 위 "DUR 데이터 확보 점검" 섹션을 먼저 해소해야 한다.
