## 1. 이슈
2026-11-03 사용자 제안: 서비스 이름을 **Can I Biyak**으로 하고, **병아리가 약을 먹는 이미지**를 구상한다. 병용금기처럼 "이 약을 먹어도 되는지" 확인하는 서비스 성격을 이름과 이미지로 드러내려는 것이다. `Biyak`은 한글 **삐약**(병아리 소리)의 영어 음역이다(사용자 확인). 같은 날 사용자가 "**삐!!**"(경고음) = **금지의 의미**도 함께 담을 수 있다고 덧붙였다. 지금 이름 MediAgent는 프로젝트 코드명으로 쓰였고, PRD·README·발표 자료·화면에서 사용자에게 보일 이름이 필요하다. 이 티켓은 이름과 마스코트의 방향을 정하고, 이름을 쓸 범위와 확인할 것을 기록한다.

## 4. 이름 검토: Can I Biyak (PRD-06-01)
> 이름 판단은 취향이 크게 들어가므로 결정은 사용자가 한다. 아래는 서비스 목적(오남용 방지, 일반인 대상, 근거 기반)에 비추어 본 장점·우려다.

### 4.1 제안 내용
| 항목 | 내용 |
|---|---|
| 표시 이름 | **Can I Biyak** (한글 병기 후보: 삐약) |
| 말장난 | ① `Biyak` = 한글 **삐약**(병아리 소리)의 영어 음역이고 안에 "약"(medicine)이 있다. "Can I (take) 약?" = "이 약 먹어도 되나요?" ② **삐!!** = 경고음(방송에서 금지·가림 표시로 쓰는 소리). 병용금기를 찾으면 "삐!"로 알려 주는 **금지의 의미**를 함께 담는다 |
| 이미지 | 병아리가 약을 먹는 장면 |
| 서비스 연결 | 병용·연령·임부 금기 확인 = "먹어도 되는지" 묻는 질문에 근거와 함께 답한다 |

### 4.2 장점
- 사용자가 실제로 하는 질문("먹어도 돼요?")이 이름에 들어 있어 무엇을 하는 서비스인지 바로 떠오른다.
- 병아리는 친근하고 어린이·초보를 연상시켜 비의료인인 일반인 대상 서비스와 어울린다. 어려운 의약 정보를 쉬운 말로 요약한다는 방침(요약 먼저, 근거 상세는 펼침)과 톤이 맞는다.
- 짧고 기억에 남으며 포트폴리오·발표에서 스토리를 만들기 쉽다.

### 4.3 우려
| 우려 | 설명 | 완화 |
|---|---|---|
| **가벼워 보일 수 있음** | 임산부·영유아·고령자의 약 복용, 응급 상황을 다루는 서비스인데 귀여운 이름과 이미지가 신뢰감을 낮출 수 있다 | 이름과 마스코트는 첫 화면·보조 자리에 쓰고, 응급·금기 결과 화면은 차분하게 둔다(PRD-06-02) |
| **"병아리가 약을 먹는다" = 복용 권유로 오해** | 이 서비스는 복용 여부·용량을 정해 주지 않는다. 병아리가 약을 먹는 이미지가 "먹어도 된다"는 신호로 읽힐 수 있다 | 금기 발견·근거 없음·응급 화면에는 쓰지 않고, 이미지는 약을 먹는 장면보다 "약을 들고 고개를 갸웃하는" 모양처럼 질문형으로 구상한다(§5.3) |
| **영문 표기 `Biyak`을 "비약"으로 읽을 수 있음** | 의도는 "삐약"의 음역이다(사용자 확인). 다만 영문만 보면 "비약"(논리의 비약 등)으로 읽는 사람도 있고, 국어 로마자 표기법상 "삐약"은 `ppiyak`이다 | 화면·문서에 한글 "삐약"을 병기하고 병아리 이미지와 함께 보이게 해 읽는 법을 알려 준다 |
| **이름이 의학 서비스로 보이지 않음** | 검색·소개 글에서 "의약품 금기 확인"이 이름만으로는 드러나지 않는다 | 부제목으로 설명을 붙인다(예: "먹어도 되는지 근거로 확인하는 병용금기 도우미", 문구는 별도) |

### 4.4 확인하지 못한 것
- **상표·도메인·앱 이름 중복**: 이 대화에서 검색하지 못했다. 사용자가 확인해야 한다(상표는 특허정보검색서비스 키프리스 등, 도메인, 앱 스토어, 검색). 취업 포트폴리오라 상업 상표 출원이 목표는 아니지만, 이미 같은 이름의 서비스가 있으면 혼동된다.
- 이름에 대한 사용자(일반인) 반응은 확인하지 않았다.

### 4.5 이름 적용 범위
이름을 정하면 **표시 이름**과 **코드명**을 나눠서 쓰는 안을 제안한다. 문서·저장소 전체를 바꾸면 파일 경로, 한 줄 정의 동기화 검사(`scripts/check_schedule.py`), 환경변수 이름 등에 영향이 크기 때문이다.

| 대상 | 쓰는 이름 | 이유 |
|---|---|---|
| 화면, README 첫머리, PRD 제목·부제목, 발표 자료, 데모 | **Can I Biyak** | 사용자·심사자에게 보이는 이름 |
| 저장소 이름(P2-Medi), 코드 패키지, 티켓 번호, 환경변수 | 기존 유지(**MediAgent**·P2-Medi) | 이미 문서·검사·링크가 이 이름에 묶여 있고 바꿀 이득이 작다 |
| `PJ2-RFP.md` 제목 | `PJ2-RFP · Can I Biyak (코드명 MediAgent)` 처럼 병기 | 요구서의 연속성 유지 |
| 산출물 발표 자료 파일명(RFP 11장 `MediAgent 포트폴리오 발표.pdf`) | 이름 결정 후 `Can I Biyak 포트폴리오 발표.pdf`로 바꿀지 결정 | RFP 11장 표기가 달라짐 |

## 5. 마스코트 이미지 방향 (PRD-06-02)


### 5.1 구상
병아리가 약을 먹는 이미지(사용자 구상). 서비스 질문("이 약을 먹어도 되는지")을 시각화한다.

### 5.2 오해 위험
- 이미지가 **복용을 권유하거나 안전하다는 신호**로 읽히면 이 서비스의 핵심 원칙(안전하다고 말하지 않음, 복용 여부를 정하지 않음, 고정 문구는 코드로 강제)과 충돌한다.
- 금기가 발견된 화면이나 응급(119) 안내 화면에서 귀여운 이미지가 나오면 위험 신호를 약하게 보이게 할 수 있다.
- 이 원칙은 문구뿐 아니라 이미지에도 적용한다. 이미지는 고정 문구를 대신하지 못하고, 고정 문구는 코드로 붙는다.

### 5.3 사용 범위 제안
| 화면·상태 | 마스코트 | 이유 |
|---|---|---|
| 시작 화면, 질문 입력 안내, 로딩, 빈 상태, 오류 | 사용 | 위험 정보와 무관한 보조 자리 |
| 되묻기 카드(모호한 약 이름) | 작은 크기로 사용 가능 | 정보를 묻는 화면이라 위험 신호와 충돌하지 않음 |
| 금기 발견·주의 결과 | 사용하지 않음 | 위험 정보를 가볍게 보이게 할 수 있음 |
| "금기 목록에 없음"·근거 없음 | 사용하지 않음 | 안전하다는 신호로 읽히지 않게 함 |
| 응급(119 안내) | 사용하지 않음 | 119 안내가 맨 위에 눈에 띄어야 함 |
| 고정 문구·면책 영역 | 사용하지 않음 | 법적 고지의 무게를 유지 |

이미지 자체는 병아리가 **약을 먹는 장면보다 약을 들고 고개를 갸웃하는 모양**(질문형)을 권한다. 약을 입에 넣는 장면은 복용을 권유하는 인상을 줄 수 있다.

### 5.4 "삐!"(경고음·금지) 표현 (PRD-06-03)
"삐!"는 병아리 소리 "삐약"과 이어지면서 **금지·경고를 알리는 소리**로도 읽힌다. 병용·연령·임부 금기가 발견된 결과에 이 표현을 쓰면, 귀여운 마스코트를 쓰지 않는 금기 화면(§5.3)에서도 브랜드를 유지하면서 위험 신호를 분명히 보이게 할 수 있다.

| 사용 | 내용 | 주의 |
|---|---|---|
| 금기 발견 결과의 **경고 표지** | "삐!" 글자·아이콘을 눈에 띄는 경고색으로 표시하고 그 옆에 금기 내용·등급·근거를 쓴다 | 귀엽게 꾸미지 않는다. 표지가 문구를 대신하지 못하고, 고정 문구와 근거 상세는 그대로 코드가 붙인다 |
| **소리** | **쓰지 않는다**(사용자 결정 2026-11-03) | "삐"는 소리가 아니라 **한글 글자의 의미 전달**로만 쓴다. 병원·밤·응급 환경과 청각 접근성 문제도 피한다 |
| **"금기 목록에 없음"** | "삐!"를 쓰지 않는다 | 경고가 없다는 것이 안전하다는 뜻이 아니므로 안전 신호도 경고 신호도 아닌 중립 표시로 둔다 |
| **응급(119)** | "삐!"를 쓰지 않는다 | 119 안내가 맨 위에서 가장 눈에 띄어야 한다 |
| 마스코트와의 관계 | 분리한다. 금기 화면에서는 마스코트 대신 "삐!" 표지만 쓴다 | 병아리가 경고를 내는 모양은 위험을 가볍게 보이게 할 수 있다 |

방송의 "삐" 처리(가림)와 혼동될 수 있어 "금지·경고"의 뜻이 설명 없이 전달되는지는 사용자 반응을 확인하지 못했다(미확인).

### 5.5 제작 방법과 라이선스
미정이다. 후보: 직접 그림, 생성형 AI 이미지 도구, 무료 라이선스 일러스트. 생성형 AI 이미지는 도구별 이용 약관과 상업·포트폴리오 이용 조건을 확인해야 한다(이 티켓에서는 확인하지 않았다). 이미지 제작은 Agent-RAG 핵심이 아니므로 시간을 쓰지 않는 방법(단순한 모양, 1~2컷)을 권한다.
