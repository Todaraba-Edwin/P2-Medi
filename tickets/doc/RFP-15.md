## 이슈
RFP는 "후보 (1주차 확정)"로 LLM `[선택 예정]`, Vector DB(Chroma/Qdrant/pgvector, Supabase 무료 플랜의 pgvector 포함), PDF 파싱(pdfplumber/LlamaParse)을 남겨 두었고, 평가 세트 세트별 `[__]`문항도 1주차 확정이다. 8장은 DB·인증으로 Supabase 무료 플랜 검토를 적어 두었다(Postgres·Auth·pgvector, DB 500MB, 월간 활성 사용자 5만 명, 비활동 1주 뒤 일시정지). 금기 데이터(BE-09)를 어디에 적재할지도 이 결정에 달려 있다. 이 결정을 한 곳에 기록한다. 이 티켓은 BE-04·BE-09·BE-11의 선행이다.

## 완료 조건
- [ ] LLM, Vector DB, PDF 파서 선택과 이유 한 줄씩이 `메모`에 기록되어 있다.
- [ ] 평가 세트 4종(정상/오탈자/범위 외/오정보)의 세트별 문항 수가 정해져 있다.
- [ ] 결정 내용이 PRD-01 또는 README에 반영되어 있다.
- [ ] (a) 표 파서 시험 결과가 기록되어 있다(RFP-17 결정 12). 고시 별표 2의 46~50쪽에서, 합격 기준은 행 수가 211과 같고 무작위 20행이 원문과 일치하는 것이다. 통과한 파서가 BE-04의 파서가 된다. 통과하지 못하면 PDF 표는 쓰지 않고 구조화된 파일·API를 우선한다고 적는다.
- [ ] (b) DB·벡터 저장소: **Supabase 무료 플랜(Postgres + pgvector)으로 결정됨(RFP-15-03, 2026-11-02, 배포 요건)**. 남은 기록은 다음이다. 금기 데이터(BE-09)의 적재소, Vector DB(BE-05)의 위치, 적재 크기가 Supabase 무료 한도(DB 500MB)에 들어가는지 확인한 값, 비활동 1주 일시정지 대응(시연 전에 깨워 둠), 확장 BE-11(Auth)을 Supabase로 할지 여부.

- [ ] (d) 배포 환경이 기록되어 있다. 프론트(Vercel), 백엔드(AWS 무료 인스턴스 1대), DB·벡터(Supabase) 구성과 프론트 프레임워크, AWS 무료 제공의 범위·기간, 서비스 간 HTTPS·CORS·환경변수(비밀키) 관리 방식이 적혀 있다. 배포는 3주차 후반의 최소 구성으로 하며 BE-13이 맡는다.
- [ ] (c) 근거 코퍼스(BE-05, ③)와 제품·성분 사전(BE-10, ②)의 색인 방식과 임베딩 모델이 결정·기록되어 있다. 색인은 BM25(문자 n-gram)와 임베딩을 함께 쓰는 하이브리드가 RFP 5.1절 (3)의 전제이며, 임베딩 모델은 한국어 약 이름·성분명 질의를 시험해 정한다.

## 메모
- 가정: 오케스트레이션 LangGraph 1.x(노드 안 부품으로 LangChain 패키지, 구성은 RFP-22-03), 백엔드 FastAPI, 평가 Ragas는 RFP에 단일 후보로 적혀 있어 확정으로 본다.
- 2026-11-02 사용자 방향: LLM은 **OpenAI 계열**(`gpt-6-luna`, 임베딩 `text-embedding-3-small` 후보)로 진행하고, 평가용 LLM judge는 추후 **Claude Sonnet 계열**로 한다. 이 티켓에서 남은 확인: `gpt-6-luna`의 구조화 출력·병렬 도구 호출·context·호출 한도, 임베딩 모델 확정, Ragas judge를 Claude로 바꾸는 방법과 Anthropic 키 변수 이름(사용자가 알려 주면 `.env.example`에 이름만 추가), 질문 텍스트를 외부 LLM API로 보내는 것이 NFR(질문 비저장)과 어떻게 맞는지.
- 가정: Supabase 무료 플랜을 택해도 BE-11(로그인)은 확장이라 SCH-02 필수 뒤에만 한다. 적재소 결정과 Auth 사용 여부는 분리해서 기록한다.
- 2026-10-31 추가 확인: 프론트 프레임워크(FE-01 메모의 예: Streamlit) 선택이 이 티켓의 결정 목록에 없다. FE-04의 로그인 화면 난이도가 여기에 달려 있어 함께 정한다. 또한 핵심 경로의 저장소는 Supabase 일시정지·한도와 무관하게 동작해야 한다(RFP 8장).
- 2026-11-01 API 확인 결과(`P2-doc/PJ2-API-응답확인.md`): e약은요에 전문의약품이 없음이 확인되어 의약품 제품 허가정보 API 활용신청 시점(설계 결정 4)을 다시 정해야 한다. 성분코드 체계가 둘(API `D######`, KIDS 9자리)이라 사전·판정 테이블 설계에 영향이 있다. `.env`의 DUR 성분정보 키는 403이라 사용자가 확인 중이다.
- 2026-11-01 해결: `.env`의 DUR 성분정보 키가 교체되어 정상이다. 남은 것은 허가정보 API 활용신청 시점과 성분코드 체계 대응이다.
- 2026-11-01 결정: 허가정보 API 활용신청은 보류(RFP-21 결정 1). 라벨 본문은 품목정보 `NB_DOC_ID`의 원문 PDF로 확보하고, 품목↔성분은 API 안에서 M-코드(`MAIN_INGR` ↔ `ORI_INGR`)로 이을 수 있다. 결정 ②(파일↔API 성분 연결)는 남아 있다.
- 2026-11-01 후속: 허가정보 API 승인(RFP-21 결정 1). 라벨 본문은 허가 상세 XML, 품목↔성분은 주성분 상세 M-코드로 얻는다. 허가사항 용법용량 표의 인용 여부(RFP-21 결정 3)가 새로 생겼다.
- 2026-11-02 사용자 결정(RFP-15-03): 배포가 필요하고 일반 RDB도 쓰므로 DB와 Vector DB 모두 Supabase 무료 플랜(Postgres + pgvector)으로 간다. 이전 가정("핵심 경로는 로컬 저장소를 기본", Supabase는 확장만)은 이 결정으로 대체된다. 새 리스크: 일시정지되면 핵심 기능도 멈추므로 적재 크기 확인과 시연 전 깨우기가 필수다. BE-05·BE-09는 Supabase를 적재소로 쓴다. Auth(BE-11)는 여전히 확장이다.
- 2026-11-02 사용자 방향(RFP-15-06): 프론트는 Vercel, 백엔드는 AWS의 무료 인스턴스 1대에 배포하는 안을 고려 중이다. 따라서 FE-01 메모의 프레임워크 예(Streamlit)는 재검토 대상이다. 미확인: AWS 무료 제공의 범위·기간, Vercel 무료 플랜 한도, Vercel(프론트) → AWS(백엔드) → Supabase 사이의 CORS·HTTPS·지연. 이 확인은 코드를 만들지 않고 문서와 계정 화면으로 한다(Pre-Week 방침).
