## 1. 이슈
사용자 지시(2026-11-09, 그대로):
> "ISSUE-010.png에 대한 접근
> - 뿌셔캡슐 사례
> - 근거 상세에도 뿌셔캡슐에 한 내용이 있어야 할 것 같아.
> - '약 이름 사전'이라는 내부 규정이 없는데 등장한 부분, 삐약(약 이름 사전)이 존재하니?
> - 본문의 '이름 다시 입력', '약 사진 올리기' 버튼의 축소 - 크기는 '이렇게 물어보세요 · 눌러서 시나리오 확인'에 있는 버튼과 폰트 참고"

화면 [ISSUE-010.png](../issues/ISSUE-010.png)(질문 "뿌셔캡슐이랑 타이레놀정500 같이 먹어도 돼요?")에서 직접 확인한 사실:

- **본문**: `약 이름을 찾지 못해 확인하지 못했어요. 금기가 없다는 뜻이 아니에요.` 아래 "확인 결과" 카드(헤더 오른쪽 `방금 조회`)에 **뿌셔캡슐 한 항목만** 있고 점선 표지 `근거 없음`, 보조줄 `사전·e약은요·허가정보에서 찾지 못함`이 붙는다. **같은 질문의 타이레놀정500은 결과 카드에 없다**(식별됐는지 사용자가 알 수 없다). 카드 맨 아래 줄은 `근거 상세 열기 · 성분코드·출처`다. 카드 밖에 큰 버튼 둘 `이름 다시 입력`, `약 사진 올리기`가 한 줄 반씩 넓고 높게 놓였다.
- **근거 상세(오른쪽 패널)**: ① `찾아본 곳`(약 이름 사전 0건 / 식약처 e약은요 0건 / 식약처 의약품 허가정보 0건 / 다시 찾기(표기 바꿔서) 0건) ② `근거 없음의 뜻` ③ `이렇게 해 보세요` ④ `출처` 표(대그룹 `삐약` > 자료 `약 이름 사전` 조회 2026-11-09, 대그룹 `식약처` > `e약은요 쉬운 설명`·`의약품 허가정보` 조회 2026-11-09) ⑤ 고정 문구 안내. **입력한 약 이름(뿌셔캡슐)이 근거 상세 어디에도 없다.** 근거 상세 헤더 옆 `아티팩트` 칩은 디자인 도구가 붙인 표시로 보고 판단에서 뺐다(가정).
- 사용자 의문 세 가지: ① 근거 상세에 뿌셔캡슐에 대한 내용(어떤 이름을 어디서 어떻게 찾았고 결과가 무엇인지)이 있어야 한다. ② `약 이름 사전`은 문서에 정의된 용어가 아닌데 나왔고 `삐약`이 출처로 나온다. 그런 사전이 있는가. ③ 되묻기 버튼이 너무 크다.

한 줄 답(②, 근거는 §4.1): **`삐약`이라는 출처·사전은 문서에 없다.** 서비스 이름이 출처 기관 자리에 들어간 프로토타입 표기다. 다만 이름에서 성분코드를 찾는 **제품·성분 사전 자체는 있다**(BE-10, 용어 이름은 "제품·성분 사전"이고 화면용 이름이 아니다).

## 4. 사실 확인 결과
코드·문서에서 직접 찾은 것만 적는다. 이 저장소에는 프로토타입 화면 코드가 없어(`mock/`에는 `_facts.json`만 있음) 화면 문구가 어디서 만들어졌는지는 **확인하지 못했다**.

### 4.1 약 이름 사전과 삐약 출처
| # | 질문 | 확인한 사실(근거) | 판단 |
|---|---|---|---|
| 1 | `약 이름 사전`이라는 용어가 문서에 있는가 | 저장소 전체(`data/` 제외)에서 이 문자열은 **0건**이다(grep, 2026-11-09). | **정의 없음**: 프로토타입이 만든 화면 문구 |
| 2 | 사전이라는 구성요소는 있는가 | RFP 5.1절 (2) "② 제품·성분 사전"(제품명·성분명·별칭 → 성분코드), 담당 BE-10(`tickets/backend/BE-10.md:23-25`). BM25 + 임베딩 색인(`BE-10.md:35`). 재료는 병용금기 JSON의 제품 쌍(`BE-10.md:23`), e약은요 스냅샷(BE-12, `BE-10.md:36`), 허가정보 **전체** 상품명(PRD-08-07, `BE-10.md:32`)이다. 현재 사전 재료는 DUR 품목리스트 약 14,200개뿐이라는 기록이 `schedule.md`에 있다. | **있다. 단 내부 구성요소 이름은 "제품·성분 사전"** |
| 3 | 사전의 쓰임 | 미식별 입력: "사전에 없는 제품명은 빈 결과로 명시적으로 반환"(`BE-10.md:33`) → `UNIDENTIFIED`(`tickets/agent/AG-09.md:29`, `P2-doc/PJ2-Agent-Harness.md:196`). 오탈자 보정(`P2-doc/PJ2-PRD.md:343`·BE-07), 되묻기·비전 후보(BE-14) | 도구 안쪽 부품이며 사용자가 이름을 알 필요가 없다 |
| 4 | 화면 용어로 정의됐는가 | 화면 용어 규칙은 PRD-11-06(내부 용어 금지, 쉬운 말)이다(`tickets/doc/PRD-11.md:188`, `PRD-11.md:324`). 사전을 사용자에게 어떻게 부를지는 어디에도 없다. PJ2-PRD 15.3절 6b는 "사전에 없는 이름"이라고 **설계자 시점**으로 적었다(`P2-doc/PJ2-PRD.md:343`) | 사용자에게는 맞지 않는 용어(PRD-11-06 연장) |
| 5 | `삐약`이 출처 기관으로 정의됐는가 | `삐약`은 서비스 표시 이름이다(PRD-06-01, `P2-doc/PJ2-PRD.md:57`, `CLAUDE.md` 1장). 이름 적용 범위는 화면·README·PRD 제목·발표 자료이고(`CLAUDE.md` 1장, `tickets/doc/PRD-06.md` §4.5), **출처 기관으로 쓰도록 한 곳은 없다.** 출처 표의 대그룹은 **출처 기관**(식약처·한국의약품안전관리원)이다(`tickets/doc/PRD-12.md:82`). `dataset` 약칭 후보 4개에도 사전은 없다(`PRD-12.md:183`) | **정의 없음(프로토타입이 만든 표기)** |
| 6 | 사실 문장이 서비스 자체 자료에서 나오는가 | 사전은 판정 근거가 아니라 **이름 → 성분코드 찾기 도구**다. 판정·사유 원문·허가사항은 공식 자료(파일·API·고시)에서 온다(`CLAUDE.md` 1장, 하네스 H9). 사전은 공식 자료를 가공해 만든 목록이다 | 서비스가 만든 목록은 "출처"가 아니라 **재료로 쓴 공식 자료**가 출처다 |

### 4.2 다시 찾기와 찾아본 곳 구역
| # | 질문 | 확인한 사실(근거) | 판단 |
|---|---|---|---|
| 1 | `다시 찾기(표기 바꿔서)`는 설계의 무엇인가 | 오탈자 보정·정규화 재검색(FR-07, 권장; AG-10, BE-07)과, 필터·정확 일치가 0건이면 **재검색 1회 뒤 모른다고 응답**하는 규칙(FR-08, `P2-doc/PJ2-PRD.md:344`)에 해당한다. 정규화는 도구 안 사전의 일이고 Pre 훅은 인자를 고치지 않는다(`P2-doc/PJ2-Agent-Harness.md:157`) | 내부 단계(절차)다 |
| 2 | 화면에 내부 단계명이 나와도 되는가 | PRD-11-06 A: 내부 용어는 화면에 쓰지 않는다(`PRD-11.md:324`). "오탈자 보정" 자체는 사용자에게 **결과로** 보이게 한다(`"암로크정으로 보정하여 검색했습니다"`, `PJ2-PRD.md:342`) | 단계명이 아니라 **결과 문장**으로 말하는 것이 맞다 |
| 3 | `찾아본 곳` 구역이 정의됐는가 | 근거 상세 구역은 4개뿐이다: 판정 · {종류}, 사유 원문, 허가사항, 출처(`PRD-11.md:86-91`). `찾아본 곳`·`근거 없음의 뜻`·`이렇게 해 보세요`는 문서 **0건**(grep) | **정의 없음(프로토타입 추가)**. 근거 없음 결과의 구역 구성이 비어 있다 |
| 4 | `찾아본 곳`의 4행은 모두 "곳"인가 | 앞 3행은 자료다. `다시 찾기`는 자료가 아니라 **방법**이다 | 한 목록에 섞지 않는다(§5.1) |
| 5 | 결과 카드 줄 `근거 상세 열기 · 성분코드·출처`는 맞는가 | 미식별은 성분코드를 얻지 못한 상태다(`BE-10.md:33`). 코드가 없는데 `성분코드`를 연다고 적는 것은 맞지 않는다 | 미식별에서는 `근거 상세 열기 · 찾아본 곳`으로 바꾸는 안(가정, §10) |

## 5. 근거 상세 규칙
### 5.1 약 이름 단위 박스
규칙(PRD-14-01 A 완료, 사용자 지시): 질문에 나온 **약 이름마다** 근거 상세에 박스를 하나 둔다(PRD-11 §4 "소제목 + 흰 박스 + 헤더 1줄" 구조, 표지 규칙 PRD-12-03·04). 미식별 약의 박스는 입력한 이름 그대로, 찾아본 곳과 결과(건수), 못 찾은 이유, 다음 행동을 담는다. 기존 프로토타입 구역 `찾아본 곳`(약 이름 없는 목록)은 이 박스로 대체한다.

```
근거 상세
─────────────────────────────────────────────
찾아본 약 이름                                   ← 소제목(13자 이내, PRD-10-03)
┌──────────────────────────────────────────────┐
│ 뿌셔캡슐                         ┄근거 없음┄   │ ← 헤더 1줄: 입력 이름 + 점선 표지
├──────────────────────────────────────────────┤
│ 입력한 이름   뿌셔캡슐                         │
│ 찾아본 곳                                      │
│   식약처·한국의약품안전관리원 자료     0건     │ ← 기관 이름 그대로(PRD-14-02 A 수정 조건), 건수는 코드가 채움
│   e약은요 쉬운 설명                    0건     │ ← 자료 약칭(PRD-12-03과 같은 문자열)
│   의약품 허가정보                      0건     │
│ 표기를 바꿔 한 번 더 찾아봤어요 · 0건          │ ← 방법은 곳 목록 밖의 한 줄
│ 못 찾은 이유   식약처·한국의약품안전관리원     │
│               자료에서 찾지 못했어요.          │
│ 다음에 해 보세요  봉투나 상자에 적힌 제품명을  │
│               그대로 입력하거나 사진을 …       │
└──────────────────────────────────────────────┘
```
- 이 박스의 문구는 `UNIDENTIFIED` 항목에서 **코드 상수**로 나오고(H20), 건수는 도구가 센 값이다. 모델이 쓰지 않는다. `못 찾은 이유`는 `근거 없음의 뜻`("근거 없음 ≠ 금기 목록에 없음")과 합쳐도 된다(문구 후보, FE-02·AG-08에서 확정).
- **표지**: `근거 없음`(점선, PRD-09 §7 표지 계열)은 `source_kind`가 있는 근거가 아니므로 PRD-12-03의 `{종류} · {dataset}` 형식을 적용하지 않는다(해석). 약칭은 **찾아본 곳 줄**이 가진다.
- **다음 행동**: 버튼은 근거 상세에 중복해 두지 않고 문구만 둔다(버튼은 결과 카드 아래 한 곳, §5.4).
- 식별된 약의 박스는 §5.2.
- **기관 표기(PRD-14-02 사용자 수정 조건)**: `공식 약 목록` 표현은 쓰지 않는다. `찾아본 곳`·`못 찾은 이유`·근거 안내에는 자료를 낸 기관 이름을 그대로 `식약처·한국의약품안전관리원`으로 밝힌다(예: `식약처·한국의약품안전관리원 자료에서 찾지 못했어요`). 이 표기가 실제로 찾아본 자료의 기관과 맞는지는 §10 메모 "표기 vs 실제 기관"에 적었다.
- `근거 상세 열기` 줄의 `성분코드`는 미식별에 없으므로 `근거 상세 열기 · 찾아본 곳`(가정, §10).

### 5.2 식별된 약 표시
문제: 하네스는 항목마다 상태를 달지만(§4.3 4번) 한 약만 미식별일 때 식별된 약이 결과 카드·근거 상세에서 사라진다. 사용자는 타이레놀정500이 식별됐는지, 쌍 판정이 왜 안 됐는지 알 수 없다.

확정(PRD-14-04 A, 2026-11-09): 식별된 약도 **요약 한 줄**로 결과 카드에 보인다. 병용 판정은 상대 약이 미식별이라 하지 못했다는 이유 한 줄을 붙인다. 판정 단독 결과(임부·연령)는 질문에 그 정보가 있을 때만 별도 줄로 나간다(기존 규칙 그대로).

```
확인 결과                                      방금 조회
┌──────────────────────────────────────────────┐
│ 뿌셔캡슐                        ┄근거 없음┄   │
│ 공식 자료에서 같은 이름을 찾지 못함            │
├──────────────────────────────────────────────┤
│ 타이레놀정500                 ┌찾음┐            │ ← 식별 상태 글자(색만 쓰지 않음, PRD-09 G11)
│ 아세트아미노펜 · 병용 확인은 뿌셔캡슐을        │
│ 찾지 못해 하지 못했어요                        │
├──────────────────────────────────────────────┤
│ 근거 상세 열기 · 찾아본 곳·성분               │
└──────────────────────────────────────────────┘
```
- 식별된 약 줄에 **"금기 목록에 없음"을 쓰지 않는다.** 쌍 판정을 하지 못했으므로 NOT_LISTED가 아니다(H2, `Harness.md:262` (f)). 약국·약사 안내는 고정 문구 영역에 그대로 있다.
- 식별된 약의 근거 상세 박스(§5.1과 같은 틀): 제목 = 제품명, 헤더 표지 = `찾음`, 본문 = 주성분 칩(PRD-09-05)·성분코드 작은 글씨. 허가사항 구역은 기존 규칙(PRD-10)대로다.
- 순서: `FOUND`(금기 발견)가 맨 위, 그다음 식별된 약, 미식별은 그 아래가 기본이다(`finalize` 규칙 확장, 가정). 화면에서 미식별이 눈에 띄게 하는 방식은 디자인 세션 몫이다.
- 선택지: A) 식별된 약도 요약 한 줄 ★ / B) 미식별 약만(근거 상세에는 식별된 약 박스) / C) 현행. B는 카드가 단순하나 사용자 의문(타이레놀은 어떻게 됐나)이 남는다.

### 5.3 내부 용어 정리와 출처 대그룹
규칙(PRD-14-02 A 완료, 사용자 수정 조건 포함): PRD-11-06의 연장으로 **화면 문구에 내부 단계명을 쓰지 않는다.**

| 현재 화면 문구 | 문제 | 쉬운 말(확정 규칙, 문구 다듬기는 FE-02·AG-08) |
|---|---|---|
| `약 이름 사전` | 문서 정의 없음(§4.1 1번), 사용자 용어 아님 | `식약처·한국의약품안전관리원 자료`(기관 이름을 그대로 밝힘, `공식 약 목록`은 쓰지 않음, 사용자 수정 조건) |
| `다시 찾기(표기 바꿔서)` | 내부 재검색 단계명, 곳이 아니라 방법(§4.2) | `표기를 바꿔 한 번 더 찾아봤어요`(곳 목록 밖의 한 줄) |
| 결과 카드 보조줄 `사전·e약은요·허가정보에서 찾지 못함` | `사전` | `식약처·한국의약품안전관리원 자료에서 찾지 못함` |
| 출처 표 대그룹 `삐약` > `약 이름 사전` | 서비스 이름이 출처 기관 자리, 기관이 아님(§4.1 5번) | 행으로 쓰지 않음(아래) |

**출처 표 규칙(A 안)**: 대그룹은 **공식 자료 기관**(식약처·한국의약품안전관리원)만 둔다(PRD-12 §4.1). 서비스(`삐약`)와 내부 사전은 출처 행이 아니다. 서비스가 만든 목록(제품·성분 사전)은 "어떤 공식 자료로 만들었는지"를 그 자료 행으로 보인다.
- 미식별 결과의 출처 표: 찾아본 공식 자료만 행으로 둔다. 예) `식약처` > `e약은요 쉬운 설명`, `의약품 허가정보`(조회일). 사전 재료로 쓴 자료의 약칭(예: `DUR 품목정보`)은 PRD-12 약칭 후보에 없어 BE-06에서 확정한다(가정). 사전 재료의 기관이 식약처가 아닌 파일(예: 건강보험심사평가원 CSV, `CLAUDE.md` 4장)이면 그 기관 대그룹이 생긴다. 확인 필요.
- PRD-12 `publisher`·`dataset` 필드와의 관계: `publisher` = 공식 기관이라는 PRD-12 §4.1의 정의 그대로이며 `삐약`을 값으로 허용하지 않는다. 구현 검사(코드)에 `publisher`가 기관 목록(식약처·한국의약품안전관리원 …)에 있는지 확인하는 것을 둔다(제안, BE-06).
- 선택지: A) 위 규칙 ★(선택, 2026-11-09 + 사용자 수정 조건) / B) 현행 유지 / C) `약 이름 사전`을 `삐약`이 만든 목록임을 설명하는 한 줄과 함께 출처 행으로 유지.
- **출처 표 대그룹도 같은 규칙**: 대그룹은 `식약처`·`한국의약품안전관리원`(PRD-12 §4.1)만 쓰고 `삐약`·내부 사전은 쓰지 않는다. 위 표기와 실제 기관이 어긋날 수 있는 부분(건강보험심사평가원 품목리스트)은 §10 메모를 본다.
- ★A 이유(사실 확인): 사전·`삐약` 출처는 문서 정의가 0건(§4.1)이고, 출처 표는 공식 자료가 근거임을 보이는 곳이라 서비스가 만든 목록을 같은 줄에 두면 근거 계층이 흐려진다. C는 설명 한 줄이 필요해 박스가 다시 길어지고(PRD-12-04와 반대) 서비스를 출처 기관처럼 읽히게 한다.

### 5.4 되묻기 버튼 규격
규칙(PRD-14-03 A, 사용자 지시): 결과 카드 아래 `이름 다시 입력`·`약 사진 올리기`를 **시나리오 칩(`이렇게 물어보세요 · 눌러서 시나리오 확인`)과 같은 크기·폰트로 축소**한다.
- **값**: 문서에 크기·폰트 값이 없다(§4.4). "시나리오 칩과 같게"가 규칙이고 **px·글꼴·색은 프로토타입 값, 디자인 세션에서 확정**한다. 이번 작업에서 값을 만들지 않는다.
- **배치**: 결과 카드 아래 **같은 줄**에 두 버튼을 칩 간격으로 나란히 둔다(왼쪽 1차). 폭은 칩 폭이고 줄 전체를 채우지 않는다. 휴대폰 폭(360px)에서 두 버튼이 한 줄에 안 들어가면 **줄바꿈**(세로 2줄)하고 가로 스크롤은 없다(NFR-07). 버튼 높이가 칩과 같으면 터치 영역이 44px 미만일 수 있으므로 **터치 영역 44px 이상은 유지**한다(PRD-13 §4.4 ①과 같은 기준, 보이는 크기와 누르는 영역을 분리).
- **위계**: 1차 `이름 다시 입력`(텍스트 입력창으로 포커스 이동, 모호·미식별에서 입력창을 채우는 가장 단순한 길), 2차 `약 사진 올리기`(확장). 1차·2차는 같은 크기이고 색·테두리 강도로만 구분한다(디자인 세션).
- **사진 버튼 숨김**: FE-05(사진 입력)가 없거나 줄이면 `약 사진 올리기`는 그리지 않는다. 15.4절의 사진 입력 위치는 입력창 옆(`PJ2-PRD.md:419`)이라 이 버튼은 두 번째 입구이며, FE-05 완료 조건에 "미식별 결과 아래 버튼"이 들어가야 한다(§8).
- 고정 문구·119·약국·약사 안내를 밀어내지 않는다(버튼은 카드 아래 한 줄, 접히지 않는 영역 위).
- 근거 상세 박스(§5.1)에는 버튼을 두지 않는다.
