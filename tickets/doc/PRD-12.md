## 1. 이슈
사용자 지적(2026-11-09, 화면 [ISSUE-005.png](../issues/ISSUE-005.png), 오른쪽 근거 상세의 "출처" 표). 화면에서 직접 확인한 사실:

- 표 열은 `출처 | 자료 | 기준일·고시일`(PRD-11-02 A 구현)이다. 칸이 좁아 줄바꿈이 어색하다: `한국의약품안/전관리원`(출처 이름 중간에서 끊김), `DUR 성분/정보 API`, `고시일 2025-07-14 · 기준/일 2026-07-21`(날짜 문구 중간에서 끊김).
- 같은 출처 `식약처`가 1행(DUR 성분정보 API)과 3행(e약은요 API)에 **따로 반복**된다.

사용자 지시(2026-11-09, 그대로, 문장 끝이 잘려 들어옴):
> "- 기준일·고시일이 \n 되어서 가독성 향상되도록
> - 출처의 경우 출처를 대그룹으로 묶고, 자료(중그룹)이 배치되도"

해석(가정, §11): ① 기준일·고시일은 **의미 단위로 줄바꿈**해 읽기 쉽게 한다(한 날짜 = 한 줄). ② 출처를 **대그룹**으로 묶고 그 아래에 자료를 **중그룹**으로 배치한다(둘째 문장은 "배치되도록"으로 읽었다).

추가 사용자 지시(2026-11-09, 같은 화면 ISSUE-005, 그대로):
> "- '사유 원문' 공식 자료가 어디인지 누락
> - 타이레놀콜드-에스정 · 상호작용 '공식 문서에서 찾은 문장이에요', '쉬운 설명(e약은요)', '출처: 식약처 e약은요 · 조회 2026-11-09' 등의 내용이 조잡함. 컴팩트하게 정리할 것
> 위의 내용 추가 반영"

화면에서 직접 확인한 사실: ③ "사유 원문" 구역의 표지는 `공식 자료에서 직접 가져왔어요`뿐이라 **어느 공식 자료인지**(DUR 성분정보 API인지 병용금기 파일인지)가 없다. PRD-11 §7.2 표지 문구 후보에 출처 이름이 빠져 있던 것이 원인이다. ④ "타이레놀콜드-에스정 · 상호작용" 박스는 같은 출처 정보가 **세 번 반복**된다: 오른쪽 위 표지 `공식 문서에서 찾은 문장이에요`, 인용 앞 라벨 `쉬운 설명(e약은요)`, 아래 줄 `출처: 식약처 e약은요 · 조회 2026-11-09`. 맨 아래 출처 표에도 같은 내용이 있어 박스가 길고 조잡하다.

## 4. 그룹 구조

### 4.1 대그룹·중그룹·날짜 줄
| 계층 | 뜻 | 예 |
|---|---|---|
| 대그룹 | 출처 기관. 한 화면에서 **한 번만** 쓴다 | 식약처, 한국의약품안전관리원 |
| 중그룹 | 그 기관의 자료(API·파일). 기관 안에서 한 항목 = 한 자료 | DUR 성분정보 API, e약은요 API, 병용금기 파일 |
| 날짜 줄 | 자료마다 날짜 라벨+값이 한 줄씩 | `고시일 2017-11-06`, `조회 2026-11-09` |

규칙: ① 같은 기관의 자료는 **떨어져 있어도 한 대그룹**으로 모은다(ISSUE-005의 `식약처` 1행·3행 반복 해소). ② 자료 하나의 날짜는 그 자료 줄(셀) 안에 모은다. ③ PRD-11 §5.1의 "출처 1개 = 1행"은 **자료 1개 = 1행**으로 바뀌고 기관은 그 위 그룹이 된다(PRD-11-02 A 표 유지, 열 의미만 보강). ④ 파일·API 날짜가 다르면 각각 자료 행이다(PRD-09 G8, PRD-11 §5.1과 같음).

### 4.2 목업 A안: 기관별 행 병합(rowspan)
기관 칸을 세로로 합친다. 표 구조(열 3개)를 유지한다.

```
출처
┌────────────────────┬─────────────────────┬──────────────────────┐
│ 출처               │ 자료                │ 기준일·고시일         │
├────────────────────┼─────────────────────┼──────────────────────┤
│ 식약처             │ DUR 성분정보 API    │ 고시일 2017-11-06     │
│                    ├─────────────────────┼──────────────────────┤
│                    │ e약은요 API         │ 조회 2026-11-09       │
│                    ├─────────────────────┼──────────────────────┤
│                    │ 의약품 허가정보 API │ 조회 2026-11-09       │
├────────────────────┼─────────────────────┼──────────────────────┤
│ 한국의약품안전관리원 │ 병용금기 파일       │ 고시일 2025-07-14     │
│                    │                     │ 기준일 2026-07-21     │
└────────────────────┴─────────────────────┴──────────────────────┘
```
- 장점: 열 머리가 그대로라 PRD-11 표 형태를 가장 덜 바꾼다. 단점: `rowspan`은 360px 카드형 접힘에서 그룹이 풀리기 쉽고 기관 이름("한국의약품안전관리원" 10자)이 첫 열을 넓혀 날짜 칸이 좁아진다.

### 4.3 목업 B안: 기관 머리줄 + 들여쓴 자료 행
기관은 한 줄짜리 머리줄이고 자료가 그 아래 들여써서 따라온다. 열은 자료·날짜 2열이다.

```
출처
┌──────────────────────────────────────────────┐
│ 식약처                                        │  ← 대그룹 머리줄(굵게, 한 줄)
├──────────────────────────┬───────────────────┤
│   DUR 성분정보 API       │ 고시일 2017-11-06  │  ← 중그룹(들여쓰기)
│   e약은요 API            │ 조회 2026-11-09    │
│   의약품 허가정보 API    │ 조회 2026-11-09    │
├──────────────────────────┴───────────────────┤
│ 한국의약품안전관리원                           │
├──────────────────────────┬───────────────────┤
│   병용금기 파일          │ 고시일 2025-07-14  │
│                          │ 기준일 2026-07-21  │
└──────────────────────────┴───────────────────┘
```
- 장점: 기관 이름이 전체 폭을 써서 중간에서 끊기지 않고, 360px에서 "머리줄 + 자료 카드" 구조로 거의 그대로 접힌다. 단점: 표 머리(`출처`·`자료`·`기준일·고시일`) 대신 머리줄이 구분을 맡는다(접근성은 `role="rowgroup"` 같은 구조로 보완, FE-02).

### 4.4 제안과 모바일(360px)
**제안: B안(머리줄 + 들여쓴 자료 행)**. 이유 셋: ① ISSUE-005의 끊김 두 건(`한국의약품안/전관리원`, 날짜 중간)이 모두 좁은 칸 때문인데 B안은 기관 이름을 전체 폭에 두고 날짜 칸을 따로 확보한다. ② HTML은 기관별 `<section>`(또는 `rowgroup`) 안에 자료 목록이면 되어 FE-02가 단순하다(`rowspan` 계산 없음). ③ PRD-11 §5.1의 가정(360px에서 행을 카드형으로 접음)과 일치한다: 머리줄은 카드 제목, 자료 행은 카드 안 두 줄(자료 이름 / 날짜)로 접힌다.

선택(행 병합 vs 머리줄)은 **사용자에게 묻지 않고** 디자인 세션과 FE-02 구현에서 정한다(결정 번호 없음). 위 제안은 문서 쪽 기본안이다. 어느 쪽이든 §4.1 규칙, §4.5 순서, §5 날짜 규칙, §6 데이터 계약은 같다.

### 4.5 순서 규칙
1. **대그룹(기관) 순서**: 이번 답변의 **판정에 쓴 출처가 있는 기관을 앞**에 둔다(코드가 `source_kind`·판정 근거로 정함). 판정 근거가 같은 기관 사이는 PRD-11 §5.1 표의 순서(식약처 → 한국의약품안전관리원)를 기본으로 한다(가정: 구현 때 확정).
2. **같은 기관 안의 자료 순서**: 판정에 쓴 자료(DUR 성분정보 API, 병용금기 파일) → 허가사항 근거 자료(e약은요 API, 의약품 허가정보 API) 순이다.
3. 순서는 `finalize`/BE-06이 코드로 정하고 LLM이 정하지 않는다(PRD-11 §6.6 "UI 문구·구조는 코드에서만" 원칙).

## 5. 날짜 줄바꿈 규칙
1. **날짜 라벨 목록**: `고시일`·`기준일`·`조회일`(화면 문구는 "조회"로 줄여 쓸 수 있고 문구는 BE-06 상수에서 온다). 새 라벨이 필요하면 상수 목록에 먼저 추가한다.
2. **한 날짜 = 한 줄**: 한 칸에 날짜가 둘 이상이면 **줄을 나눈다**(예: `고시일 2025-07-14` ↵ `기준일 2026-07-21`). 구분점(·)으로 한 줄에 나열하지 않는다.
3. **라벨과 날짜는 한 덩어리**: `라벨 YYYY-MM-DD`는 중간에서 줄바꿈하지 않는다(개념 규칙: 비분할 공백·`white-space: nowrap` 계열. 날짜 안 하이픈에서도 끊지 않는다). 구현은 FE-02다.
4. **이름도 단어 중간에서 끊지 않는다**: 기관·자료 이름은 `word-break: keep-all` 같은 개념 규칙으로 어절·단어 중간에서 끊기지 않게 한다. 칸이 좁으면 어절 사이에서만 줄을 바꾼다(`한국의약품안전관리원`은 한 어절이라 한 줄을 차지하도록 B안 머리줄을 쓴다).
5. **파일과 API 날짜가 다르면 각각 줄**이다(PRD-09 G8과 일치). 한쪽을 "더 최신"으로 단정하지 않는다.
6. 같은 자료가 날짜를 하나만 가지면 한 줄이다(`조회 2026-11-09`). 날짜가 없는 자료는 `날짜 없음`을 코드 상수로 표시하고 칸을 비우지 않는다(가정).

## 6. 데이터 계약(BE-06)
PRD-11 §9의 BE-06 `detail`·`citations[]` 항목(출처 표 행 키)과 맞춘 제안이다. 최종 필드 이름은 BE-06 구현에서 정한다.

```json
{
  "citations": [
    {
      "publisher": "식약처",
      "dataset": "DUR 성분정보 API",
      "dates": [{ "label": "고시일", "value": "2017-11-06" }],
      "source_kind": "API_DIRECT"
    },
    {
      "publisher": "한국의약품안전관리원",
      "dataset": "병용금기 파일",
      "dates": [
        { "label": "고시일", "value": "2025-07-14" },
        { "label": "기준일", "value": "2026-07-21" }
      ],
      "source_kind": "FILE"
    }
  ]
}
```
- `publisher` = 대그룹, `dataset` = 중그룹, `dates[{label, value}]` = 날짜 줄(항목 하나가 줄 하나). 화면은 같은 `publisher`를 **그룹으로 묶어** 그리고 라벨·날짜 문자열을 만들지 않는다(라벨은 상수, 값은 코드가 채움).
- 배열 순서가 §4.5 순서다. 화면이 재정렬하지 않는다.
- `source_kind`로 근거 박스 표지와 이어진다(PRD-11-05). 같은 기관의 자료를 서버가 인접하게 두면 화면 그룹핑이 단순하다.

## 7. 표지에 출처 이름 명시
**규칙(PRD-12-03 A)**: 표지는 쉬운 말 종류 문구 뒤에 **자료 약칭**을 붙인다. 약칭은 출처 표(§4)의 **자료 열(`dataset`)과 같은 문자열**이다(표지 ↔ 출처 행 1:1, PRD-11-05). 내부 용어 금지(PRD-11-06)는 그대로다. 이 표가 PRD-11 §7.2 "쉬운 말 문구 후보" 열을 **갱신**한다(PRD-11은 reopen하지 않고 메모로 연결).

| `source_kind` | 표지 형식(후보) | 예 |
|---|---|---|
| `API_DIRECT` | `공식 자료 · {dataset}` | `공식 자료 · DUR 성분정보 API` |
| `FILE` | `공식 파일 · {dataset}` | `공식 파일 · 병용금기 파일` |
| `CORPUS_QUOTE` | `공식 문서 · {dataset}` | `공식 문서 · e약은요 쉬운 설명` |

- **자료 약칭(`dataset`) 후보**: `DUR 성분정보 API`, `병용금기 파일`, `e약은요 쉬운 설명`, `의약품 허가정보`. e약은요는 쉬운 설명 계열임이 약칭에 드러나게 한다(PRD-11 §7.1 라벨 정정은 유지: e약은요 값에 "허가사항 원문"을 붙이지 않는다). 위 §4 목업의 `e약은요 API`는 이 약칭으로 읽는다.
- **사유 원문·판정 구역도 같은 규칙**이다(박스마다 표지에 자료 이름). 예: 사유 원문 표지 `공식 파일 · 병용금기 파일`. 자료 이름이 없는 표지는 만들지 않는다(누락이면 `validator`가 막는 H29 연동).
- 약칭 문자열은 BE-06 `dataset` 한 곳에서 오고 표지·출처 표가 같은 값을 쓴다(상수 키는 AG-08).

## 8. 근거 박스 컴팩트화

### 8.1 현행의 중복
ISSUE-005의 타이레놀콜드-에스정 박스는 같은 출처 정보를 ① 표지(`공식 문서에서 찾은 문장이에요`) ② 라벨(`쉬운 설명(e약은요)`) ③ 아래 줄(`출처: 식약처 e약은요 · 조회 2026-11-09`)에 세 번 쓰고 출처 표에도 있다.

### 8.2 목업 A안: 헤더 1줄 + 본문(제안)
**규칙(PRD-12-04 A)**: 박스 안 `출처: …·조회일` 줄과 `쉬운 설명(e약은요)` 라벨을 삭제한다. 기관·조회일은 출처 표가 가진다. 문장의 성격(쉬운 설명 계열)은 표지의 자료 약칭(`e약은요 쉬운 설명`)이 말한다.

```
┌──────────────────────────────────────────────────────┐
│ 타이레놀콜드-에스정 · 상호작용  [공식 문서 · e약은요 쉬운 설명] │  ← 헤더 1줄(제목 + 표지 1개)
│ "…MAO 억제제(항파킨슨제 등)와 함께 복용하지 마십시오…"          │  ← 본문(인용 1개)
└──────────────────────────────────────────────────────┘
```
제안: **A안**. 같은 정보가 한 번만 나오고(표지 1개), 기관·조회일은 출처 표 한 곳에서 읽는다. 박스가 헤더·본문 두 덩어리로 짧아진다.

### 8.3 목업 B안: 박스 안 출처 줄 유지(짧게)
```
┌──────────────────────────────────────────────────────┐
│ 타이레놀콜드-에스정 · 상호작용                          │
│ "…MAO 억제제(항파킨슨제 등)와 함께 복용하지 마십시오…"          │
│ 출처: e약은요 쉬운 설명 · 2026-11-09                     │  ← 짧은 출처 줄(표지는 없음)
└──────────────────────────────────────────────────────┘
```
단점: 같은 출처·날짜가 출처 표에 또 있고 표지(출처 종류)가 박스에 없어 PRD-11-05(표지)와 겹친다. 채택하지 않는다.

### 8.4 박스 3단 구조 통일
모든 근거 박스는 **헤더 1줄(제목 + 표지 1개) + 본문 + (필요 시) 권고**의 3단이다. 이지렉트정 미확보 항목(구역 묶음 = 권고 1개 + 항목 목록: 항목 `이지렉트정 · 상호작용`, 본문 `MISSING_OUT_OF_SCOPE` 상수, 권고 = 약사 확인 권고 컴포넌트, FE-02-05 A)과 판정 박스(헤더 제품쌍 + 표지, 본문 성분 칩·사유)도 같다. **약사 권고 컴포넌트(PRD-11 §6.7)는 그대로**이며 접히지 않는다. 미확보 박스는 근거 값이 없어 표지가 없을 수 있다(근거를 지어내지 않음, 가정: 헤더만).

## 9. 화면 시험
① 같은 기관 이름이 표에 **한 번만** 나온다(ISSUE-005의 `식약처` 반복 0건). ② 자료가 기관 아래(또는 옆)에 묶여 보인다. ③ 한 칸에 날짜가 둘이면 줄이 나뉘고 `라벨 날짜`가 줄 중간에서 끊기지 않는다. ④ `한국의약품안전관리원`·`DUR 성분정보 API` 같은 이름이 단어 중간에서 끊기지 않는다. ⑤ 파일과 API 날짜가 다르면 각 자료 줄에 날짜가 있다. ⑥ 360px에서 머리줄(또는 병합 칸)과 자료 카드가 그룹을 유지한다. ⑦ 순서가 §4.5와 같고 판정 출처 기관이 앞에 있다. ⑧ ISSUE-005와 같은 질문을 mock으로 다시 그려 전후를 비교한다. ⑨ 박스의 출처 종류 표지 이름이 이 표의 자료와 계속 대응한다(PRD-11 §8 ⑨). ⑩ **모든 표지에 자료 이름이 있다**(사유 원문·판정 포함, PRD-12-03). ⑪ **박스 안에 출처·조회일 줄이 없고** 같은 출처 문자열이 박스 안에서 한 번만 나온다(PRD-12-04). ⑫ **표지의 자료 이름이 출처 표의 자료 열과 글자 일치**한다(PRD-12-03). ⑬ 박스가 헤더 1줄 + 본문 + (필요 시) 권고의 3단이다(§8.4).
