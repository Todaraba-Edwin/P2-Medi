## 1. 이슈
사용자 지적(2026-11-09, 화면 [ISSUE-003.png](../issues/ISSUE-003.png), 질문 "엄마가 이지렉트정을 드시는데 콜드-에스 같이 드려도 돼요?", 병용금기 결과). 화면에서 직접 확인한 사실:

- "판정 · DUR 병용금기"는 **소제목 + 흰 박스(카드)**다(제품쌍, "삐! 병용금기" 표지, 성분 칩, 작은 글씨 `성분코드·원문 염 이름 … 성분코드는 가져오지 못했어요`, `라사길린 + 덱스트로메토르판`). 기준 예시다.
- "사유 원문"(`경련, 반사항진, 이상고열, 혼수 등`)은 소제목 아래 **맨 글**이고 흰 박스가 아니다.
- "허가사항"은 연한 색 설명 박스와 제품별 흰 박스 둘이다. 이지렉트정 박스는 `이지렉트정 허가사항 원문(상호작용) · 원문을 가져오지 못했어요`, 타이레놀콜드-에스정 박스는 `허가사항 원문(상호작용): "…MAO 억제제(항파킨슨제 등)와 함께 복용하지 마십시오…"`다.
- "출처"는 **한 문단**(`식약처 DUR 성분정보(고시일 …) · 한국의약품안전관리원 병용금기 파일(고시일 …, 기준일 …) · 식약처 의약품 허가정보`)이다.

사용자 지시(2026-11-09, 그대로): "ISSUE-003.png를 보면 근거상세에 규칙이 필요해 — 소제목, 컴포넌트(흰색박스), 예시 - 판정 · DUR 병용금기 / 미반영: 사유 원문, 출처 / 출처의 경우 표 형식을 원했어, 행으로 나눠져서 / 이지렉트정 허가사항 원문(상호작용) · 원문을 가져오지 못했어요 > 원문을 가져오지 못했다는 것이 의미하는 바는? RAG의 실수를 그대로 노출해도 되는지 이슈 체크".

**사용자 방침(2026-11-09, 추가 지시, 결정됨)**:
1. 이지렉트정은 전문의약품이라 공공 API에서 설명을 가져오지 못하므로 **그 한계가 있음을 고지하기로 했다**(숨기지 않는다). 남은 질문은 고지 문구를 얼마나 구체적으로 쓸지뿐이다(PRD-11-03).
2. 타이레놀콜드-에스정 문장이 API에서 온 것인지 RAG인지 **구분해서 다루고 근거가 어디인지 함께 명시**한다(§7).
3. **RAG 결과도 근거 상세에 드러나므로** 어떻게 다룰지 이 티켓에서 정한다(§7.3).

## 4. 구역 규칙(컴포넌트)

### 4.1 구역 목록과 순서
근거 상세는 위에서 아래로 **구역 하나 = 소제목 1개 + 흰 박스 컴포넌트**다. 소제목은 짧은 명사형 13자 이내(PRD-10-03).

| 순서 | 소제목 | 박스에 담는 것 | 종류별 변형 |
|---|---|---|---|
| 1 | 판정 · {종류} | 제품쌍 또는 제품, 경고 표지, 성분 칩, 성분코드 작은 글씨 | 병용 외는 PRD-09 §7.4(임부 `판정 · 임부금기` 등) |
| 2 | 사유 원문 | 사유 문장(인용부호 없이 원문 그대로) + 출처 종류 표지(§7) | 병용·임부에만 있음. 연령 등은 PRD-09 §7.4 |
| 3 | 허가사항 | 제품별 박스 1개씩: 약 이름 + 항목 + 인용 또는 미확보 고지 | 전문의약품·e약은요 없음은 안내 한 줄(PRD-10-04) |
| 4 | 출처 | 출처 표(§5) | 모든 결과에 있음 |

### 4.2 박스 규칙
- **흰 박스에 담는 것**: 근거 값(판정·사유·인용·출처 표). 박스 하나는 한 가지 근거 단위다(제품쌍 1개, 인용 1개).
- **흰 박스에 담지 않는 것**: 고정 문구 안내(허가사항이 무엇인지 설명 한 줄(PRD-10 §6.2), 금기 없음 ≠ 안전 문구)는 **별도 색 박스**다. 흰 박스(근거)와 연한 색 박스(안내)가 섞여 읽히지 않게 한다. 고정 문구·119 영역은 PRD-09 G·PRD-06-03대로 접히지 않고 마스코트를 쓰지 않는다(충돌 없음).
- 소제목 오른쪽 또는 박스 안 작은 글씨 자리에 출처 종류 표지(§7)가 온다.
- 원문 미확보 박스 안의 **약사 확인 권고**는 흰 박스(근거)도 연한 색 안내 박스도 아닌 **별도 강조 색 안내 박스**이고 접히지 않는다(§6.7).

### 4.3 기준 예시: 판정 · DUR 병용금기
ISSUE-003의 판정 구역을 그대로 구조화한 것이다.

```
판정 · DUR 병용금기                                  ← 소제목(13자)
┌──────────────────────────────────────────────┐
│ 이지렉트정 × 타이레놀콜드-에스정   [⚠ 삐! 병용금기] │  ← 제품쌍 + 경고 표지
│ 이지렉트정           [라사길린 · 병용금기 원인]       │  ← 성분 칩 줄
│ 타이레놀콜드-에스정  [덱스트로메토르판 · 병용금기 원인] │
│                      [슈도에페드린][아세트아미노펜][클로르페니라민] │
│ 성분코드·원문 염 이름(작은 글씨): …               │
│ 라사길린 + 덱스트로메토르판                        │  ← 쌍 요약 줄
└──────────────────────────────────────────────┘
```

### 4.4 사유 원문·허가사항 예시
같은 구조(소제목 + 흰 박스 + 표지)로 바꾼 예시다. 문구는 후보이고 확정이 아니다.

```
사유 원문
┌──────────────────────────────────────────────┐
│ 경련, 반사항진, 이상고열, 혼수 등          [공식 자료] │
└──────────────────────────────────────────────┘

허가사항
 ░ 허가사항: 식약처가 의약품을 허가할 때 정한 효능·효과, 용법·용량,
 ░ 사용상 주의사항이에요.                       ← 연한 색 안내 박스(흰 박스 아님)
┌──────────────────────────────────────────────┐
│ 타이레놀콜드-에스정 · 상호작용        [쉬운 설명 자료] │
│ "…MAO 억제제(항파킨슨제 등)와 함께 복용하지 마십시오…" │
│ 출처: 식약처 e약은요 · 조회 2026-11-09               │
└──────────────────────────────────────────────┘
┌──────────────────────────────────────────────┐
│ 이지렉트정 · 상호작용                               │
│ 이지렉트정은 전문의약품이라 공공 자료로는                │  ← MISSING_OUT_OF_SCOPE(§6.6 상수)
│ 설명을 확인할 수 없어요.                          │
│ ┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓ │
│ ┃ ⚕ **복용 전에 꼭 약국·약사에게 이 두 약을 함께 먹어도    ┃ │  ← 약사 권고 박스(§6.7, 강조색, 접히지 않음)
│ ┃ 되는지 물어보세요.** 비어 있다고 괜찮다는 뜻이 아니에요. ┃ │
│ ┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛ │
└──────────────────────────────────────────────┘
```
- 이전 프로토타입의 "원문을 가져오지 못했어요"는 §6.6 매핑표에 없는 문구라 **이 예시에서 뺐다(폐기 대상)**. 미확보 박스의 문구는 항상 §6.6의 상수에서만 나온다. 허가정보 상세를 BE-12가 수집한 경우에는 이 박스 대신 `이지렉트정 허가사항 원문(상호작용): "…"` 인용 박스가 온다(PRD-10-04, 미확보 아님).

## 5. 출처 표 규칙

### 5.1 표 형식
사용자 의도는 **표(행으로 나눔)**다. 출처 1개 = 1행이다.

```
출처
┌────────────────────┬──────────────────────────┬───────────────────────┐
│ 출처               │ 자료                     │ 기준일·고시일          │
├────────────────────┼──────────────────────────┼───────────────────────┤
│ 식약처             │ DUR 성분정보 API         │ 고시일 2017-11-06      │
│ 한국의약품안전관리원 │ 병용금기 파일            │ 고시일 2025-07-14 · 기준일 2026-07-21 │
│ 식약처             │ e약은요 API              │ 조회 2026-11-09        │
│ 식약처             │ 의약품 허가정보 API      │ 조회 2026-11-09        │
└────────────────────┴──────────────────────────┴───────────────────────┘
```
- 파일과 API의 날짜가 다르면 **각각 행**이다(PRD-09 G8과 일치, 한쪽을 확정하지 않는다). 날짜가 같으면 한 칸에 기준일을 병기한다.
- 허가사항에 쓴 자료가 e약은요인지 허가정보인지 행으로 갈라 적는다(§7.1). 합쳐 부르지 않는다.
- 열 이름은 후보다: 출처 | 자료 | 기준일·고시일. 가정: 모바일 폭(360px)에서는 행을 카드형으로 접는다(FE-02에서 확인).

### 5.2 PRD-10-02와의 관계
PRD-10-02 A("자료 날짜"와 "출처를 한 구역으로 합침")는 유지한다. 그러나 **합친 형태를 문장형 한 덩어리로 구현한 것은 사용자 의도(표)와 달랐다**(해석 오류). 형태 부분은 이 티켓의 PRD-11-02가 대체한다. PRD-10은 reopen하지 않고 메모에 대체 관계를 적었다.

## 6. 원문 미확보 노출 이슈

### 6.1 "원문을 가져오지 못했어요"의 실제 출처
- 이 문구는 **PRD-10 §6.4의 제안 규칙**(`tickets/doc/PRD-10.md:136`: "코드가 원문을 가져오지 못하면 그 줄을 만들지 않고 '원문을 가져오지 못했어요'를 쓴다")과 AG-06 완료 조건(`tickets/agent/AG-06.md:37`)에서 나왔다. 저장소의 `evaluation/`·`backend/`에는 이 문자열이 **없다**(grep 확인, 2026-11-09). 화면 코드도 저장소에 없다(`frontend/` 폴더 없음).
- **정정(2026-11-09, 사용자 지적)**: 처음에 "디자인 프로토타입이 규칙을 그린 결과"로만 적은 것은 부정확했다. 실제 문제는 **하네스와 UI의 불일치(미스매칭)**다. 이 상황(전문의약품·허가사항 미확보)은 하네스가 `EASY_TEXT_MISSING`(H18)·`NO_EVIDENCE`·`API_FAIL` 상태와 코드 고정 문구로 **통제해야 하는 항목**(할루시네이션 방지)인데, 프로토타입의 박스 문구 "원문을 가져오지 못했어요"는 그 매핑에 없는 **UI가 임의로 그린 일반 실패 문구**다(PRD-10 §6.4 제안 문구가 하네스 상태 코드와 연결되지 않은 채 쓰였다). 그래서 이 문구는 폐기하고 §6.6의 상태별 상수로 바꾼다. UI 문구는 하네스 상태 코드에서만 나온다.
- **이지렉트정 허가사항이 비는 이유(mock 기준)**: `evaluation/mock_gen/facts.py:92-122`의 `label` 사전에는 202106954(콜드-에스)·202106092·202005623·202200525만 있고 **이지렉트정 항목이 없다**. `m1_chat.py:239`는 콜드-에스 상호작용만 `detail`에 넣는다. 곧 mock에서는 이지렉트정을 "가져오지 못한" 것이 아니라 **애초에 값이 없다**.
- 실제 시스템 기준: 이지렉트정은 **전문의약품**이라 e약은요에 없다(`P2-doc/PJ2-PRD.md:181`). 허가정보 API 상세는 BE-12가 **평가·페르소나 제품만** 수집·스냅샷으로 둔다(`tickets/backend/BE-12.md:36`). 이지렉트정은 S2 페르소나 제품(`m1_chat.py:222-224`)이므로 수집 대상일 가능성이 높으나 **수집 여부는 BE-12 구현 전이라 확인하지 못했다**.
- 하네스 쪽에는 이 상황의 상태·문구가 **이미 있다**: `EASY_TEXT_MISSING`("쉬운 설명 없음(허가사항 원문)", `P2-doc/PJ2-Agent-Harness.md:208`), 도구 상태 4종 `FOUND·NOT_LISTED·UNIDENTIFIED·NO_EVIDENCE`(`:196`), API 쪽 사정은 꼬리표 `API_FAIL`(`:210`). 그러나 **"원문 미확보"를 원인별로 나누는 코드는 없다**.

### 6.2 원인 구분 (a)~(d)
| 코드안 | 원인 | 성격 | 재시도 | 원문이 있나 |
|---|---|---|---|---|
| (a) `ABSENT` | 그 제품 허가사항에 그 항목(상호작용)이 원래 없음 | 데이터 사실 | 소용없음 | 없음 |
| (b) `FETCH_FAIL` | 허가정보 API 조회 실패·타임아웃 | 시스템 장애(`API_FAIL` 계열) | 가능 | 있을 수 있음 |
| (c) `SEARCH_MISS` | 허가사항 청크 검색(RAG)이 못 찾음(`NO_EVIDENCE`) | 검색 실패 | 질의 바꿔 재검색 가능 | 있을 수 있음 |
| (d) `OUT_OF_SCOPE` | 수집 범위 밖(BE-12는 평가·페르소나 제품만 수집) 또는 전문의약품이라 쉬운 설명 계열 자체가 없음 | 수집·라이선스 한계 | 소용없음(수집 전) | 있으나 우리가 안 가짐 |

전문의약품이 e약은요에 없다는 사실은 `EASY_TEXT_MISSING`(원인 (d)의 한 종류)이다. 같은 사용자 문구 "원문을 가져오지 못했어요"는 (a)~(d)를 구분하지 못한다.

### 6.3 노출 위험 네 가지
1. **오독**: "가져오지 못했어요"만으로는 (a)~(d)를 알 수 없어 사용자가 "상호작용이 없다"로 읽을 수 있다. 하네스 원칙(금기가 조회되지 않아도 안전하다고 말하지 않는다, H2)과 충돌 위험이다.
2. **내부 용어 노출**: 반대로 "검색 실패·RAG 실패"를 그대로 쓰면 일반인이 이해하지 못하고 신뢰를 잃는다. 내부 용어는 화면에 쓰지 않는 것이 맞다(결정 PRD-11-03·06).
3. **판정은 코드가 확정, 허가사항 인용은 보조 근거**: 병용금기 판정은 파일·API에서 코드가 확정했다(H9). 허가사항 문장이 비어도 판정이 바뀌지 않는다. 화면이 이 위계를 보이게 해야 허가사항 미확보가 "판정이 불확실하다"로 번지지 않는다.
4. **숨기면 "근거 있는 척"**: 미확보 행을 지우면 사용자는 허가사항을 찾아봤는지조차 모른다. 사용자 방침(2026-11-09)도 **한계 고지**다.

- 가정: 사유가 겹치면 `FETCH_FAIL` > `OUT_OF_SCOPE` > `SEARCH_MISS` > `ABSENT` 순으로 하나만 쓴다(구현 때 확정).
- **이지렉트정 사례**: 전문의약품이라 e약은요 쉬운 설명이 없다(`EASY_TEXT_MISSING`). BE-12가 허가정보 상세를 수집했으면 허가사항 원문 박스(미확보 아님), 수집하지 않았으면 `OUT_OF_SCOPE`로 `MISSING_OUT_OF_SCOPE` + 약사 확인 권고다. 수집 여부는 BE-12 완료 조건으로 이관했다(§9).
- **폐기 대상**: 프로토타입의 "원문을 가져오지 못했어요"는 이 표에 없는 문구다. (b)로 읽히면 "잠시 뒤 다시 하면 되는 일"로, (a)로 읽히면 "원래 없음"으로 오독된다. 코드·fixture·화면·mock에서 모두 없애고 위 상수로 바꾼다.

### 6.7 약사 확인 권고 컴포넌트
사용자 수정 조건(PRD-11-03, 2026-11-09): "오독을 방지하며, 약사를 찾아가도록 권고를 강하게 명시".

- **필수·코드 삽입**: 미확보 박스(§6.6)마다 `finalize`가 약사 확인 권고(`PHARMACIST_ADVICE`)를 삽입한다. LLM이 쓰지 않으므로 빠뜨릴 수 없다.
- **접히지 않고 눈에 띈다**: 미확보 박스 안에 흰 근거 박스도 연한 안내 박스(§4.2)도 아닌 **별도 강조 색 안내 박스**로 둔다. 근거 상세를 접어도 보이도록, 미확보 항목이 하나라도 있으면 접히지 않는 고정 문구 영역에도 한 줄(`PHARMACIST_ADVICE_FIXED`)을 코드가 더한다(가정: "강하게"를 이렇게 읽었다, 확인 필요). 마스코트는 쓰지 않고 "삐!" 표지는 금기 발견 전용이라 쓰지 않는다(PRD-06-02·03).
- **문구 후보**: 원인별 본문(§6.6) 뒤에 공통 권고 "**복용 전에 꼭 약국·약사에게 {약 A}와 {약 B}를 함께 먹어도 되는지 물어보세요.** 비어 있다고 괜찮다는 뜻이 아니에요." 첫 문장은 굵게 쓴다. 강도 후보(위치·굵기·약국 십자 아이콘 여부)는 디자인 세션이 정하고 hex·글꼴은 여기서 정하지 않는다.
- **오독 방지**: 어느 경우에도 "상호작용 없음·안전·괜찮다"를 암시하지 않는다. 상수의 부정형 문장("괜찮다는 뜻이 아니에요")은 안전 단정이 아니다. `validator`의 안전 단정 패턴(H2)은 LLM 출력만 검사하고 `finalize` 상수는 검사 대상에서 뺀다(오탐 방지, 구현 때 확인).

| 층 | 내용 |
|---|---|
| Guide(프롬프트) | "미확보 항목은 지어내지 말고 상태만 돌려준다. 안전하다고 말하지 말고 약국·약사 확인을 안내한다" |

## 7. 출처 종류 표지와 RAG 결과 규칙

### 7.1 콜드-에스 상호작용 문장은 API인가 RAG인가
**사실 답(맨 위)**: 이 문장은 **e약은요 API의 `intrcQesitm`(상호작용 주의) 필드 값**이다. 원본은 스냅샷 `data/mock/api_snapshots/eyak/getDrbEasyDrugList/c5bc238611c1e50e.json`(품목기준코드 202106954, e약은요 응답)이다. 그리고 mock에서는 이 문장이 **코퍼스 L3 청크 `L3:202106954:intrc`로 인용**돼 나온다(`evaluation/mock_gen/m1_chat.py:230`, `:239`). 곧 **"API에서 온 데이터가, 근거 코퍼스 L3(라벨 문장) 청크 형태로 답변에 인용된 것"**이다. RAG의 "생성"이 아니라 **코퍼스 청크의 글자 그대로 인용**이다.

| 문장 | 출처 시스템 | 도구 경로 | 필드/청크 | 근거 |
|---|---|---|---|---|
| `…MAO 억제제(항파킨슨제 등)와 함께 복용하지 마십시오…` | 식약처 e약은요 API(쉬운 설명 계열) | mock: `evidence_search` 단계의 L3 인용. 설계: `search_label`(AG-03, RAG 코퍼스 L3) 또는 `get_label_section`(AG-02, 절 본문 직접 조회) 둘 다 가능 | 필드 `intrcQesitm` / 청크 `L3:202106954:intrc` | 스냅샷 `c5bc238611c1e50e.json`, `evaluation/mock_gen/facts.py:92-100`(`_seg(…intrcQesitm…)`), `m1_chat.py:59-61`(`source="식약처 e약은요(의약품개요정보) API"`), `:230`, `:239`, `:124-128` |

- **라벨 오류**: 코드가 인용 출처를 "식약처 e약은요 API"로 적는데(`m1_chat.py:60`) 화면은 "**허가사항 원문**"이라 부른다. e약은요는 허가사항을 일반인용으로 풀어 쓴 **쉬운 설명**이고, 허가사항 원문은 허가정보 API(`DrugPrdtPrmsnInfoService08`)의 상세 XML(`EE/UD/NB_DOC_DATA`)이다(`tickets/backend/BE-05.md:69`). 이 화면의 문장에 "허가사항 원문"이라고 붙인 것은 **PRD-10-01·04(용어를 "허가사항"으로 통일)의 적용 결과 생긴 라벨 오류**다. 정정 규칙: **원문 자료 이름대로 쓴다**: e약은요에서 왔으면 `쉬운 설명(e약은요)`, 허가정보 상세에서 왔으면 `허가사항 원문`. 전문의약품은 e약은요가 없으니 허가사항 원문만 가능하다(`EASY_TEXT_MISSING`).
- 평가 모드·기준선에서 어느 쪽이 쓰이는지: 평가는 파일 기준·API 끔(`PJ2-RFP.md` 5.1절 (7)), `get_label_section`은 평가 모드에서 BE-12 스냅샷만 쓴다(`tickets/agent/AG-02.md:33`). 코퍼스 L3 적재는 BE-05(전문의약품은 허가 상세 우선, `:69`). **이 문장을 실제로 어느 도구가 가져오는지는 구현 전이라 확정할 수 없다**. 화면 규칙은 도구가 어느 쪽이든 `source_kind`로 표지를 붙여 구분하도록 정한다.

### 7.2 표지 종류와 문구 후보
근거 항목마다 **출처 종류 표지**를 붙인다. 위치는 박스 소제목 오른쪽 작은 글씨이고, 같은 말이 출처 표(§5)의 행과 1:1로 이어진다(박스의 표지 → 출처 표의 같은 이름 행).

| `source_kind` | 뜻 | 쉬운 말 문구 후보(PRD-11-06 A) | 출처 표 행 |
|---|---|---|---|
| `API_DIRECT` | 공공 API 직접 조회값(DUR 판정, e약은요·허가정보 항목). 코드가 확정 | 공식 자료에서 직접 가져왔어요 | 해당 API 행 |
| `FILE` | 한국의약품안전관리원 CSV/JSON 판정 | 공식 파일 기준이에요 | 파일 행 |
| `CORPUS_QUOTE` | 코퍼스 청크 인용(고시·사유·허가 문장 등, **RAG 검색으로 찾음**). 원문 인용 | 공식 문서에서 찾은 문장이에요 | 문서명·판·쪽·조항 또는 항목명·조회 시각을 같이 적은 행 |
| `LLM_SUMMARY` | LLM이 쉬운 말로 푼 문장(요약 영역, 근거 아님) | 쉬운 말로 풀어 쓴 설명이에요 | 없음(요약에만 쓰고 근거 상세에는 쓰지 않음) |

- `LLM_SUMMARY`는 근거 상세 박스에 들어가지 않는다. 근거 상세는 ①~③만 담는다(근거 고정).
- 내부 용어("검색·RAG·청크")는 표지에 쓰지 않는다(PRD-11-06 A). 개발자용 병기(B)는 개발자 모드 한정 후보다.

### 7.3 RAG 결과가 근거 상세에 들어올 때
1. **인용부호 안은 코퍼스 원문 그대로**다(LLM 의역 금지). 앞뒤 생략은 `…`로만 밝힌다. 등급 정의의 G7(PRD-09)·H28 제안과 같은 원칙이다.
2. **청크 출처를 같이 명시한다**: 문서명·판·쪽·조항(고시·약사법 등) 또는 허가정보·e약은요 항목명과 조회 시각. 출처 표에 행으로 올리고 박스에는 표지만 둔다.
3. **검색이 못 찾으면** "찾지 못함"을 §6.4 고정 문구 체계로 쓴다(`SEARCH_MISS`). 지어낸 인용으로 채우지 않는다(FR-08).
4. **관련성 낮은 검색 결과를 인용으로 보이지 않는다**. AG-03의 관련성 표시(코드 검사 우선)와 AG-07의 허용 근거 계층 검사와 일치시킨다. 관련성 판정이 "낮음"이면 박스를 만들지 않는다.
5. **같은 사실이 API와 RAG 양쪽에서 오면 API 값을 우선**하고 RAG 인용은 보조로 표시한다(박스 순서와 표지로). 판정·금기 여부는 파일·API만 쓴다(AG-07 매트릭스: 금기 여부는 판정 테이블 L0만). RFP-22 §6·§7의 "파일 1차 + API 병기"와 충돌하지 않는다. 충돌 여부는 구현 때 한 번 더 확인한다(확인 필요).

### 7.4 하네스 관점
`finalize`가 도구 결과의 `source_kind`로 표지·출처 행을 **코드로 렌더**한다(H29). LLM은 표지를 쓰지 않는다. 표지가 없는 근거 항목은 `validator`가 막는다(개선). BE-06 응답 `detail` 항목에 `source_kind`, 청크 ID, 조회 시각 필드가 필요하다(§9).

## 8. 화면 시험
① 근거 상세의 모든 구역이 소제목 + 흰 박스 구조이고 소제목은 13자 이내다(PRD-11-01). ② 고정 문구 안내는 흰 박스가 아닌 별도 색이다. ③ 출처가 표(1출처=1행)이고 파일과 API 날짜가 다르면 각 행에 날짜가 있다(PRD-11-02). ④ 허가사항 박스마다 약 이름·항목·출처 표지가 있다. ⑤ 원문 미확보 박스에 원인별 고정 문구가 있고 "상호작용 없음"·"안전" 암시가 없으며 약사 확인 안내가 있다(PRD-11-03). ⑥ 화면에 "RAG·검색 실패·청크·API 오류" 같은 내부 용어가 없다(PRD-11-06). ⑦ e약은요 값에 "허가사항 원문"이라는 말이 붙지 않는다(§7.1). ⑧ 인용부호 안 문자열이 원문과 글자 일치한다(H28). ⑨ 박스의 표지 이름이 출처 표의 행과 대응한다(PRD-11-05). ⑩ ISSUE-003과 같은 질문을 mock으로 다시 그려 전후를 비교한다. ⑪ 미확보 박스마다 약사 확인 권고 박스가 항상 있고 접히지 않으며(근거 상세를 접어도 고정 문구 영역에 한 줄), 강조 색이다(§6.7). ⑫ 화면·mock의 미확보·표지 문구가 §6.6 상수와 글자 일치하고 임의 문구가 없다("원문을 가져오지 못했어요" 0건).
