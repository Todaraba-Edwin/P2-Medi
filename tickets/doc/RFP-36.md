## 1. 이슈
결정과 문구 승인이 모두 끝나 **사람의 답 없이 코드로만 진행할 수 있는** 작업(AG-08 코드 이행 + BE-06-13~17 서버 상수·스키마 칸)을 Claude Code의 `/goal` 모드로 3~4시간 자율 실행하는 1회차 계획이다. 사용자 요청(2026-11-13): "클로드의 goal 모드로 다음 번에 3~4시간 정도 작업을 요청할 계획을 세우고 티켓 생성".

- **goal 모드**: `/goal <완료 조건>`은 매 턴이 끝날 때마다 조건 충족 여부를 판정하고, 충족될 때까지 계속 진행한다(`/goal status`로 확인, `/goal clear`로 중단). 출처 https://code.claude.com/docs/en/goal.md, 2026-11-13 확인.
- **포트폴리오 관점**: Guardrail과 고정 문구를 프롬프트가 아니라 코드로 강제하는 이행(RFP-29 Guide/Sensor)이다. 판정 규칙은 바꾸지 않고 문구·라벨·스키마 칸만 코드가 소유하게 해 프런트가 응답 값만으로 글자를 그리게 한다.
- **실행 지시서**(로컬 전용): `data/mock/briefs/goal/2026-11-13-goal-ag08.md`. 절대 규칙(원격 DB·LLM·공공 API 실호출 0, git 금지, 시험셋 열람 금지, 승인 문구 표의 글자만 사용), 작업 목록 11개, 시간 배분(1~5 60분 / 6~7 60분 / 8~9 60분 / 나머지), 멈출 조건, 보고 형식, 완료 조건 4개가 들어 있다.

- **교훈 반영**: 2026-11-12 재적재 사고(작업자가 승인 전에 원격 쓰기 실행)를 막으려고 원격 쓰기 도구와 승인 flag 파일을 goal 세션 범위 밖에 둔다(지시서 §0).
- 가정: 이 티켓의 우선순위는 RFP에 없는 계획 추적 작업이라 `권장`으로 두었다.
