## 1. 이슈
사용자 지시(2026-11-09, 그대로):
> "ISSUE-011.png 사례 — [등급 불일치 시험] 임신 중인데 콜드-에스 먹어도 돼요? > 근거 상세. 임부금기 2등급(파일), 1등급(API)의 뱃지 나열로 title 영역 침범에 대한 디자인 배치 고려 이슈 티켓 신설. 별도의 pane에서 진행"

화면 [ISSUE-011.png](../issues/ISSUE-011.png)에서 직접 확인한 사실:

- 질문은 `[등급 불일치 시험] 임신 중인데 콜드-에스 먹어도 돼요?`이고 결과는 **임부금기 등급 불일치**(파일 2등급 vs 성분 API 1등급, PRD-09 G8)다. 요약은 "두 자료의 등급이 달라 출처를 붙여 모두 적었어요"다.
- **왼쪽 결과 카드(넓은 폭)**: 머리줄 `금기 확인 결과 · 임신 기준`, 오른쪽 `파일 2026-07-21 · 성분 API 방금 조회`. 제목 `타이레놀콜드-에스정` 한 줄 오른쪽에 보라 배지 `⚠ 삐! 임부금기 2등급 (파일)`·`⚠ 삐! 임부금기 1등급 (성분 API)`가 같은 줄에 들어간다. 폭이 넓어 문제없다.
- **오른쪽 근거 상세 패널(좁은 폭)**: 소제목 `판정 · 임부금기`, 소제목 오른쪽 표지 `공식 파일 · 임부금기 파일`. 흰 박스 안에서 **배지 둘이 박스 윗줄을 차지하고 제목 `타이레놀콜드-에스정`이 한 글자씩 세로로 쪼개진다**(타/이/레/놀/콜/드-/에/스/정, 9줄). 박스 높이가 그만큼 늘고, 두 번째 배지는 박스 오른쪽에서 **잘려** `1등급 (성분 A…`까지만 보인다. 배지가 제목 영역을 침범해 제목이 사실상 읽히지 않는다.
- 같은 박스 아래: 성분 칩 줄(`슈도에페드린 · 금기 원인`·덱스트로메토르판·아세트아미노펜·클로르페니라민), 성분코드·원문 염 이름 작은 글씨, 등급 비교 표(`파일 (기준일 2026-07-21) 임부금기 2등급` / `성분 API (방금 조회) 임부금기 1등급` / `판정 한쪽으로 정하지 않아요`), `▼ 임부금기 2등급이란?`(고시 원문 인용 보라 박스 + `출처: 「의약품 병용금기 성분 등의 지정에 관한 규정」 제3조 제3호 나목 · 기준일 2026-07-21`), `▼ 임부금기 1등급이란?` 블록 안에 고시 원문 대신 **`근거 문장을 찾지 못했어요`**, 그 아래 출처 줄(`출처: 「의약품 병용금기 성분 등의 지정에 관한 규정」 제3조 제…`, 화면 아래에서 잘림).

관련 문서에서 확인한 사실:

- **배지 규칙(PRD-09)**: 금기 종류마다 배지를 따로 두고 병용·임부가 둘 다 해당하면 **배지 두 개가 나란히** 나온다(G14, `tickets/doc/PRD-09.md:113`). 임부 안에서 1·2·M은 같은 색·같은 "삐!"(G5, `:104`). 파일과 API 등급이 다르면 **출처를 붙여 둘 다** 보인다(G8, `:107`, 예: "파일: 임부금기 2등급 · 성분 API: 임부금기 1등급"). 모든 배지에 종류 글자가 있다(G15, `:114`). 등급은 표지에만 한 번 쓰고 항상 "임부금기 N등급"으로 쓴다(G1·G2, `:100-101`). 근거 상세 지시문은 "파일·API가 다르면 G8 형식의 두 줄로 쓴다"(§7.2, `:156`)이고 §7.4는 "두 표지가 한 줄에 나란히"(`:170`)라고 적는다. **좁은 폭에서 배지가 제목 옆에 다 들어가지 않을 때의 규칙은 PRD-09에 없다.**
- **박스 구조(PRD-11)**: 근거 상세는 구역마다 소제목 1개 + 흰 박스이고 판정 박스는 "제품쌍 또는 제품, 경고 표지, 성분 칩, 성분코드 작은 글씨"를 담는다(§4.1, `tickets/doc/PRD-11.md:89`). 기준 예시는 `이지렉트정 × 타이레놀콜드-에스정   [⚠ 삐! 병용금기]`처럼 **제목과 경고 표지 1개가 한 줄**이다(§4.3, `:106`). 출처 종류 표지는 "소제목 오른쪽 또는 박스 안 작은 글씨 자리"(§4.2, `:97`; §7.2, `:266`)다.
- **박스 헤더(PRD-12)**: 모든 근거 박스는 **헤더 1줄(제목 + 표지 1개) + 본문 + (필요 시) 권고**의 3단이고 판정 박스도 "헤더 제품쌍 + 표지"로 같다(§8.4, `tickets/doc/PRD-12.md:214`). 표지는 `{종류 문구} · {자료 약칭}`(§7, `:175-181`)이고 박스 안 출처·조회일 줄은 지운다(§8.2, `:193`).
- **사실 확인 결과: PRD-12 "헤더 1줄(제목 + 표지 1개)"이 배지 둘 이상일 때 어떻게 되는지는 정의되어 있지 않다.** ① PRD-12의 "표지"는 출처 종류 표지(`source_kind`)이고, PRD-09의 "삐!" 배지는 금기 경고 표지다. PRD-12 §8.4는 판정 박스 헤더를 "제품쌍 + 표지"라고만 적어 둘 중 무엇인지, 둘 다인지 밝히지 않는다. ② 배지가 2개(G8·G14)일 때 "1줄"을 지키는지, 줄바꿈을 허용하는지 없다. ③ 화면에서는 출처 표지가 소제목 줄로 나가고(`공식 파일 · 임부금기 파일`) 박스 헤더에는 금기 배지 둘이 들어갔다. ④ 판정 박스에 파일과 API 두 자료가 함께 쓰였는데 표지는 `임부금기 파일` 하나뿐이다(표지 1개 규칙과 자료 2개의 관계도 정의 없음, §11 확인 필요).
- **코너 패턴(PRD-13)**: 모달의 `<`·`닫기`는 header 행 대신 컨테이너 기준 `position: absolute` 코너에 두고 본문 첫 요소와 겹치지 않게 여백만 둔다(§4 규칙 4, `tickets/doc/PRD-13.md:78`; §4.4 ②, `:138`). 배지를 박스 코너에 absolute로 띄우는 방식은 배지 개수가 늘면 제목과 겹치므로 이 티켓에는 쓰지 않는다(§5.6 참고 행).
- **FE-02**: 배지 완료 조건은 "병용·임부가 둘 다 해당하면 배지 2개가 나란히 보인다(순서는 이 티켓에서 정함)"(`tickets/frontend/FE-02.md:37`), 출처 표 이름은 `word-break: keep-all` 개념으로 단어 중간에서 끊지 않는다(`:48`), 360px에서 가로 스크롤이 없다(`:35`). **배지가 제목 영역을 침범하지 않는다는 조건은 없다.**

## 4. 배지가 둘 이상 생기는 경우

### 4.1 경우 목록
글자 수는 공백·기호 포함으로 직접 셌다(2026-11-09). 배지 문구는 PRD-09 §7.1·§7.4의 형식이고 출처 꼬리 `(파일)`·`(성분 API)`는 ISSUE-011 화면 문구다(PRD-09에는 G8 예시 "파일: … · 성분 API: …"만 있고 배지 문구로 정해진 것은 아니다).

| 경우 | 근거 | 같은 줄에 오는 배지 | 개수 | 글자 수 | 어디서 |
|---|---|---|---|---|---|
| ① 등급 불일치(임부 파일 2 + API 1) | G8 | `삐! 임부금기 2등급 (파일)` + `삐! 임부금기 1등급 (성분 API)` | 2 | 16 + 20 = 36 | 결과 카드, 근거 상세 판정 박스(ISSUE-011) |
| ①' 등급 불일치 + M | G6·G8 | `삐! 임부금기 M등급 (파일)` + `삐! 임부금기 1등급 (성분 API)` | 2 | 16 + 20 = 36 | 같음 |
| ② 병용 + 임부 동시 | G14 | `삐! 병용금기` + `삐! 임부금기 2등급` | 2 | 7 + 11 = 18 | 결과 카드 제품 줄. 근거 상세는 `판정 · {종류}` 구역이 나뉘어(PRD-11 §4.1) 박스마다 1개 |
| ①+② 병용 + 등급 불일치 | G8·G14 | `삐! 병용금기` + 위 ①의 2개 | 3 | 7 + 36 = 43 | 결과 카드 제품 줄(**최악**) |
| ③ 병용 쌍 여러 개 | G14 "해당 항목마다 한 개" | 쌍마다 `삐! 병용금기` | 쌍 수 | 7 × 쌍 수 | 근거 상세는 제품쌍마다 박스 1개라 박스당 1개. **결과 카드에서 한 제품이 쌍 두 개에 걸릴 때 배지를 반복할지는 정의 없음**(제안: 한 제품 줄에는 종류당 1개, 쌍 수는 보조줄) |
| ④ 임부 + 연령 동시 | G4·§7.4 | `삐! 임부금기 2등급` + `삐! 연령금기` | 2 | 11 + 7 = 18 | 결과 카드. 임부·연령 둘 다 해당하는 사용자(예: 미성년 임부)는 드물지만 프로필 조합상 가능 |
| (참고) 성분 중복 | §7.4 | `성분 중복` | 1 | 5 | `두 제품 함께` 별도 줄이라 금기 배지와 같은 줄에 오지 않음 |

비교용 제목 글자 수: `타이레놀콜드-에스정` 10, `심바로드정20밀리그람` 11, `이지렉트정 × 타이레놀콜드-에스정` 18(병용 제품쌍 제목).

### 4.2 좁은 폭 계산
- **배지 폭(ISSUE-011 화면에서 잰 값, 화면 배율을 몰라 추정)**: `삐! 임부금기 2등급 (파일)` 약 160px, `삐! 임부금기 1등급 (성분 API)` 약 180px, 둘 + 간격 약 345px. 근거 상세 흰 박스의 안쪽 폭은 약 310px였다. **배지 둘만으로 박스 안쪽 폭을 넘어** 제목에 남는 폭이 0에 가까워졌고, 제목이 줄어들 수 있는 요소(flex 기본 `shrink`)라 한 글자 폭까지 줄었다고 본다(화면 코드는 저장소에 없어 확인 못 함).
- **근거 상세 패널 약 320~380px**: 박스 안쪽 폭 ≈ 패널 폭 − 패널 좌우 여백 − 박스 좌우 여백 ≈ 260~330px(여백 각 16·14px 가정).
- **모바일 360px**: 박스 안쪽 폭 ≈ 360 − 2×16 − 2×14 = 300px(가정). 320px이면 260px.
- **최악**: ①+②(배지 3개, 43자) ≈ 90 + 345 ≈ 440px. 300px 폭에서는 배지만으로 두 줄이 필요하다. 제목(10자, 굵게 약 140px)을 같은 줄에 둘 수 있는 경우는 ②·④(배지 2개 약 230px)조차 300px 폭에서 140 + 230 > 300이라 **안 된다.** 곧 좁은 폭에서는 배지가 하나만 있어도(`삐! 임부금기 2등급` 약 120px) 제목 18자(병용 제품쌍) 옆에는 들어가지 않는다.
- 결론: 좁은 폭에서 "제목 + 배지 한 줄"은 배지 1개·짧은 제목일 때만 성립한다. **배지를 제목 옆에 두는 배치는 배지 개수와 제목 길이에 따라 깨지므로 규칙이 필요하다.**

## 5. 배치 규칙
제안(PRD-15-01 ★A): **제목이 먼저 자리를 갖고, 배지는 남는 폭에 다 들어갈 때만 제목 옆에, 아니면 배지 묶음 전체가 제목 아래 줄로 내려가 줄바꿈한다.** 근거 상세 패널(좁은 폭)에서는 사실상 항상 아래 줄이다. 일반 규칙: **배지 개수가 늘어도 제목은 침범받지 않는다.**

### 5.7 제목 최소 폭과 넘침 규칙
1. **제목은 침범받지 않는다.** 헤더에서 제목이 먼저 폭을 갖는다. 제목의 최소 폭은 `min(제목 전체 폭, 박스 안쪽 폭)`이다(개념: 제목 `flex-shrink: 0`, `max-width: 100%`). 배지가 남는 폭에 다 들어가지 않으면 배지 묶음 전체가 다음 줄로 내려간다(개념: 헤더 `flex-wrap: wrap`, 배지 묶음은 별도 flex 컨테이너).
2. **제목은 세로로 쪼개지지 않는다.** 제목 줄바꿈은 단어 단위만 허용한다(개념: `word-break: keep-all`, `overflow-wrap: anywhere` 금지). 띄어쓰기가 없는 긴 제품명(예: `심바로드정20밀리그람`)이 박스보다 넓을 때만 예외로 글자 사이 줄바꿈을 허용하되 한 줄 최소 4글자 이상이 되게 한다(가정, FE-02에서 확인).
3. **배지는 잘리지 않는다.** `overflow: hidden`·말줄임(`…`)·가로 스크롤을 배지와 헤더에 쓰지 않는다. 배지 단위로 다음 줄로 넘기고, 배지 하나가 박스 안쪽 폭보다 넓을 때만 배지 안에서 단어 단위로 줄바꿈한다(§5.5 320px).
4. **박스는 넘치지 않는다.** 헤더의 어떤 요소도 박스 테두리 밖으로 나가지 않는다(ISSUE-011 둘째 배지 잘림 0건).
5. 출처 종류 표지(`공식 파일 · …`)는 현행처럼 소제목 줄에 두고 금기 배지 줄에 섞지 않는다(PRD-11 §4.2 "소제목 오른쪽"). 금기 배지(경고)와 출처 표지(자료 이름)의 성격이 다르기 때문이다.
6. 화면 읽기: 배지 묶음은 목록으로 읽히게 한다(개념: "금기 표지 2개" 라벨). 색·hex·글꼴·간격 px는 디자인 세션 몫이다.

### 5.8 결과 카드와 근거 상세
- **같은 규칙 하나를 쓴다**(구분 불필요, 제안). §5.7 규칙 1은 폭에 따라 결과가 저절로 달라진다: 결과 카드(넓은 폭)에서는 제목 옆에 배지가 다 들어가 현행 ISSUE-011 왼쪽 모습 그대로이고, 근거 상세 패널·모바일(좁은 폭)에서는 배지 묶음이 아래 줄로 내려간다. 폭별로 다른 규칙을 두면 FE-01·FE-02 두 컴포넌트에 분기가 생기고 시험이 늘어난다.
- 근거 상세 패널 폭 약 320~380px에서는 §4.2 계산상 배지 1개 + 10자 제목도 빠듯해 사실상 항상 아래 줄이다. "근거 상세는 항상 아래 줄"로 고정할지는 결정 번호 없이 디자인 세션·FE-02에서 고른다(폭이 고정 패널이라 결과가 같을 가능성이 높다).

## 6. 등급 정의 블록 미확보 표시
사용자 지시 밖의 관찰이다(지시서 관찰 항목). 결정 PRD-15-03으로 묻는다.

### 6.1 화면과 문서 사실
- 화면: `▼ 임부금기 1등급이란?` 블록에 고시 원문 대신 **`근거 문장을 찾지 못했어요`** 한 줄이 있고, 그 아래에 **출처 줄은 그대로 있다**(`출처: 「의약품 병용금기 성분 등의 지정에 관한 규정」 제3조 제…`). 원인 구분, 약사 확인 권고가 없다. 같은 화면의 2등급 블록은 고시 원문 인용이 있다.
- **G7·PRD-09-04**: 등급의 뜻은 근거 상세에 고시 원문 그대로(1·2) 코드가 넣고 LLM이 의역하지 않는다(`tickets/doc/PRD-09.md:106`). 접힘 블록은 **L1 청크 ID로 코퍼스 원문을 읽어** 렌더한다(§7.2, `:155`).
- **문구 출처**: `근거 문장을 찾지 못했어요`는 하네스 `NO_EVIDENCE` 문구 "근거 문장을 찾지 못함"(`P2-doc/PJ2-Agent-Harness.md:206`, AG-08 `tickets/agent/AG-08.md:38`)과 같은 말이다. `NO_EVIDENCE`는 **답변 근거 전체·검색 도구 항목**의 상태이고(PRD-11 §6.6 표 `NO_EVIDENCE`(답변 근거 전체) 행, `tickets/doc/PRD-11.md:231`), 등급 정의 블록 하나의 미확보를 뜻하는 상태가 아니다.
- **PRD-11 미확보 체계**: 원인 (a)`ABSENT`·(b)`FETCH_FAIL`·(c)`SEARCH_MISS`·(d)`OUT_OF_SCOPE`별 고정 문구 + 약사 확인 권고(접히지 않음, 코드 삽입)다(§6.2·§6.6·§6.7, `PRD-11.md:176-245`). 매핑표는 **허가사항 미확보만** 다루고 등급 정의 블록 행은 없다. 규칙 ③ "표에 없는 상황이 생기면 박스를 먼저 그리지 않고 하네스 상태·상수를 먼저 추가한다"(`:222`)에 해당한다.
- **mock**: 등급 정의는 등급 → 청크 ID가 **정해진 대응**이다(`evaluation/mock_gen/m1_chat.py:64-68` `c_grade_def`: 1 → `L1:notice-art3-item3-ga`(가목), 2 → `L1:notice-art3-item3-na`(나목), 고시 마크다운에서 원문을 읽음). 1등급 정의를 쓰는 mock 사례도 있다(`m1_chat.py:191`, `:199`). 그러나 **등급 불일치 사례 fixture는 mock 생성기에 없다**(`evaluation/mock_gen/`에서 "불일치" grep, m1_chat 0건). PRD-09 §7.5는 "파일≠API 등급" fixture를 두라고 했고(`PRD-09.md:179`) 그 일은 FE-02로 이관돼 아직 열려 있다(`tickets/frontend/FE-02.md:42`). ISSUE-011 화면의 프로토타입 코드는 저장소에 없다(`frontend/` 없음).
- **실제 시스템**: L1(고시) 청크는 BE-04(핵심 PDF 파싱, SCH-02, `todo`) 뒤에 BE-05에 추가한다(`tickets/backend/BE-05.md:70`, `tickets/backend/BE-04.md:48`). 1주차 기준선에는 L1이 적재되지 않는다.

### 6.2 원인 판단
- **`SEARCH_MISS`가 아니다.** 등급 정의는 검색(RAG)으로 찾는 것이 아니라 등급 값으로 청크 ID를 정해 읽는 **조회**다(PRD-09 §7.2, mock `c_grade_def`). 관련 문장을 "찾지 못할" 수 없다.
- **`FETCH_FAIL`은 가능하다.** 청크 저장소(Supabase pgvector) 읽기 실패·타임아웃이면 (b)다.
- **기준선(BE-04 전)에서는 비는 것이 설계상 예상된다.** L1이 아직 적재되지 않았으면 1·2등급 정의 블록이 모두 빈다. 원인은 "수집 전"이라 (d)`OUT_OF_SCOPE`(수집·적재 한계)에 가깝다.
- **ISSUE-011 화면의 원인(추정)**: 2등급 블록은 채워지고 1등급만 비었다. 같은 L1 출처에서 한쪽만 빈 것이므로 적재 문제가 아니라 **프로토타입 fixture에 1등급 정의 청크가 빠진 것**으로 보인다(등급 불일치 fixture가 mock 생성기에 없어 화면 쪽에서 만든 것으로 추정, 코드 미확인). 곧 화면 문구는 하네스 상태에서 나온 것이 아니라 UI가 임의로 그린 일반 실패 문구이고, PRD-11 §6.1이 폐기한 "원문을 가져오지 못했어요"와 같은 종류의 미스매칭이다.
- **출처 줄이 남은 것**: 원문이 없는데 조항 출처가 붙어 있어 "출처에는 있는데 문장이 없다"로 읽힌다. 미확보면 출처 줄을 그리지 않는 편이 맞다(근거를 지어내지 않음). 또 PRD-12-04(박스 안 출처 줄 삭제)가 이 접힘 블록에도 적용되는지는 정의되어 있지 않다(PRD-09 §7.2 지시문에는 정의 블록 안 출처 줄이 있음, §11 확인 필요).

### 6.3 제안
PRD-15-03 ★A: **PRD-11 미확보 체계와 같은 모양**으로 맞춘다.
1. 하네스 상태를 먼저 둔다(PRD-11 §6.6 규칙 ③): 등급 정의 블록용 사유 코드 `GRADE_DEF_MISSING`(후보) + `missing_reason`(`FETCH_FAIL` 또는 `OUT_OF_SCOPE`(L1 적재 전)). `SEARCH_MISS`는 쓰지 않는다(§6.2).
2. `finalize`가 상수 문구를 렌더한다(LLM이 쓰지 않음). 문구 후보: `FETCH_FAIL` → "지금은 임부금기 {N}등급의 뜻(고시 원문)을 불러오지 못했어요. 잠시 뒤 다시 시도해 보세요." / `OUT_OF_SCOPE` → "임부금기 {N}등급의 뜻(고시 원문)을 아직 준비하지 못했어요." 둘 다 **"등급이 낮다·괜찮다"를 암시하지 않는다.**
3. 약사 확인 권고(PRD-11 §6.7 컴포넌트)를 붙인다. 문구 후보: "**등급의 뜻이 궁금하면 약국·약사에게 물어보세요.**" PRD-11 §6.7 공통 권고("{약 A}와 {약 B}를 함께 먹어도 되는지")는 병용 문맥이라 그대로 쓰지 않고 임부 문맥 변형을 AG-08 상수로 둔다(후보).
4. 미확보 블록에는 조항 출처 줄을 그리지 않는다. 고시 이름·조항은 출처 표(PRD-12 §4)에 남는다.
5. 데이터 쪽 예방: 등급 정의는 1·2 두 문장(M은 심평원 설명 1건)뿐이라 BE-04/BE-05에서 L1 청크 `notice-art3-item3-ga`·`-na`가 적재됐는지 **적재 검사**로 막고, FE-02 이관 항목의 "파일≠API 등급" fixture에 1·2등급 정의 청크를 모두 넣는다.

B(정의 블록 숨김)는 "찾아봤는지조차 모름"(PRD-11 §6.3 위험 4, 근거 있는 척)이 생긴다. C(현행)는 하네스 상태와 미스매칭이고 `NO_EVIDENCE`와 혼동된다.

★A 이유: ① 사용자 이해 — 원인을 쉬운 말로 알리고 "등급 뜻을 모름"이 "덜 위험함"으로 번지지 않는다. ② 접근성 — 약사 권고가 접히지 않는 같은 컴포넌트라 어디서나 같은 모양이다. ③ G7 — 고시 원문이 없을 때 지어내지 않고 코드 상수로만 말한다. ④ 구현 단순함 — 새 상태 1개와 상수 2~3개를 PRD-11 §6.6 표에 한 행 더하면 된다.
