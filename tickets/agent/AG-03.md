## 이슈
Vector DB를 검색하는 노드를 만든다. 문서종류·연도·부처 메타데이터 필터를 받고, 결과에 출처(문서명·쪽/조항)를 함께 반환한다.

답이 여러 청크에 나뉘는 질문(멀티홉)도 이 노드가 다룬다(설계 문서 6장 (1), RFP 5.1절 (3)). LLM이 스스로 연쇄 검색하게 두지 않고, 주장 유형별로 나눠 허용 계층 필터로 따로 검색한 뒤 코드가 `parent_id`·`refs`·`pair_id`·`ingr_codes`로 연결 청크를 붙여 증거 묶음으로 돌려준다. 분해 검색을 만들기 전에, 단일 top-K가 실제로 근거를 얼마나 빠뜨리는지 먼저 잰다.

## 완료 조건
- [ ] 질문과 필터 조건으로 상위 k개 청크가 반환된다.
- [ ] 필터를 걸었을 때 조건에 맞지 않는 문서가 결과에 없다.
- [ ] 결과 0건 시 빈 결과를 명시적으로 반환한다(AG-09의 입력).
- [ ] (코드) `layer`·`ingr_codes`·`notice_no`·`base_date` 메타데이터 필터가 동작한다(RFP 5.1절 (3) 역할 B·C). 역할 C(근거 설명)는 판정된 성분코드(`ingr_codes`)로 먼저 거른 뒤 검색한다.
- [ ] 성분명·조항 번호는 BM25, 설명형 질의는 임베딩을 함께 쓰는 하이브리드 검색이 동작하고, 한쪽만 쓸 때보다 정답 청크가 상위에 드는 사례를 1건 이상 기록했다(RFP 5.1절 (3)).
- [ ] (측정, 분해 검색 구현 전) 샘플 질의 20개로 단일 top-K 검색만 썼을 때의 근거 누락률을 먼저 쟀다. 질의마다 정답에 필요한 청크 목록을 두고, 필요한 청크가 하나라도 top-K에 없으면 누락으로 센다. 질의 수·K 값·누락 질의 수·누락률(%)·누락 사례 2건 이상을 `메모`에 기록했고, 이 기록이 분해 검색을 구현하기 전에 남았다.
- [ ] (코드) 주장 유형 목록(설계 문서 4장 유형)을 입력으로 받아, 유형마다 허용 계층 필터(예: 금기 사유는 L2 우선·L3 보조, 등급 정의는 L1만)로 따로 검색한다. 다른 유형의 계층 청크가 해당 유형 결과에 섞이지 않음을 테스트로 확인했다.
- [ ] (코드) 검색으로 찾은 청크에 대해 `parent_id`, `refs`, 같은 `pair_id`, 같은 `ingr_codes`의 청크를 코드가 가져와 붙이고, 주장 유형별 결과를 하나의 증거 묶음으로 반환한다. 임베딩 유사도로 연결 청크를 추측하지 않는다. 조→호→목 부모, 별표 참조("별표 1에 따른"), 같은 성분쌍 사유 청크가 각각 묶음에 붙는 테스트가 통과한다.
- [ ] (코드) 홉은 2회까지다. 3회째 검색 요청은 실행되지 않고, 한도에 걸렸다는 표시가 증거 묶음에 남는 테스트가 통과한다. 그래프 RAG와 다단계 에이전트 루프는 만들지 않는다.
- [ ] 멀티홉 샘플(가설 문서 TC-15, 21, 22)에서 분해 검색의 증거 묶음이 단일 top-K보다 정답 청크를 더 많이 포함한다는 비교를 1회 기록했다(H17 선행 확인). 정식 비교는 AG-12에서 한다.

## 하위 작업
- [ ] 검색 함수·필터
- [ ] 출처 객체 생성
- [ ] 샘플 질의 20개와 질의별 정답 청크 목록 작성
- [ ] 단일 top-K 근거 누락률 측정과 기록(분해 검색 구현 전)
- [ ] 주장 유형별 분해 검색(허용 계층 필터)
- [ ] 연결 청크 결합과 증거 묶음 반환(`parent_id`·`refs`·`pair_id`·`ingr_codes`)
- [ ] 홉 2회 한도 처리
- [ ] 테스트

## 메모
- RFP-17 결정(2026-10-30): 고시 전문의 조문·정의·비고를 검색 대상으로 하고, 메타데이터에 고시번호(연도 4자리 + 번호 4자리)와 기준일을 둔다.
- 2026-11-01 멀티홉 대응: 설계 문서 6장 (1)과 RFP 5.1절 (3)을 반영했다. 신규 티켓은 만들지 않았다. 누락률 기록 칸(구현 전 측정 결과):
  - 질의 수 / K / 누락 질의 수 / 누락률: (측정 전)
- 가정: 주장 유형 목록은 Router(AG-05, SCH-02)가 만들지만, AG-03은 SCH-01이라 AG-05를 선행으로 걸 수 없다. 그래서 AG-03은 주장 유형 목록을 **입력 인자**로 받게 만들고, SCH-01의 테스트에서는 손으로 채운 목록을 쓴다. AG-05가 이 인자를 채워 넘긴다.
- 가정: 샘플 질의 20개의 출처는 RFP에 없다. 가설 문서 TC-15, 21, 22, 23과 정상 세트 문항을 변형해 만든다고 가정했다. 정답 청크 목록은 AG-04의 형식과 같게 쓴다.
- 가정: 단일 top-K의 누락률이 낮게 나오면 분해 검색 범위를 줄일지는 사용자와 정한다. 이 기준값은 RFP에 없다.
- 2026-11-02 전체 점검(RFP-22 논의 2): 벡터 검색은 항상 k개 청크를 돌려주므로 "0건" 기준은 필터·정확 일치 경로에만 해당한다. 의미 검색의 "근거 없음" 판정 방식(코드 ID 일치 우선, 애매하면 LLM grade)은 RFP-22에서 정한 뒤 이 티켓에 반영한다.
