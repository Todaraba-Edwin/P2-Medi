## 1. 이슈
RFP FR-06: 진단·처방 금지 문구, 응급 키워드가 있으면 119 안내를 맨 위에 고정하되 금기 조회는 막지 않음, 범위 외 거절. 조회 결과에 금기가 없어도 안전하다고 말하지 않는 고정 문구와 "근처 약국·약사에게 확인" 안내를 모든 답변에 코드로 붙인다(프롬프트가 아니라 코드). 7장 고지 문구도 모든 응답에 붙인다. 범위 제외 항목은 진단, 처방, 복용량 결정, 개인 의료기록 처리다(4장).

8장 구조도의 "응급 키워드: Guardrail이 119 안내를 답변 맨 위에 고정하고, 위 경로는 막지 않고 병행 실행한다"를 구현한다. **응급 키워드 감지는 이 티켓의 코드 규칙 한 곳에서만 한다.** 감지 결과는 상태의 `emergency`에 기록하고 Router(AG-05)는 이 신호를 읽기만 한다. 음성 인식 글자(FR-11)도 사용자가 전송하면 같은 텍스트 입력이라 이 한 곳(`guardrail_in`)에서 같은 감지를 받는다. 프론트는 키워드 목록을 갖지 않고 전송 전 119 표시를 하지 않는다(RFP-35-03, 2026-11-07).

규칙 구현 방식은 항목마다 (코드) / (프롬프트)로 표기한다. 고정 문구는 프롬프트가 아니라 코드가 맡는다.

## 2. 완료 조건
- [ ] (코드) 응급 키워드 질문의 응답은 119 안내가 맨 위에 고정되고, 병용·연령·임부 금기 조회와 답변 생성은 막지 않고 함께 수행된다.
- [ ] (코드) 응급 키워드 감지가 이 티켓의 한 함수에만 있고, Router 등 다른 노드와 프론트 코드에 키워드 목록이 없음을 코드 검색(`grep`)으로 확인했다(RFP-35-03). 이름·위치(제안, 구현 때 확정): 키워드 상수 `EMERGENCY_KEYWORDS`와 감지 함수 `detect_emergency()`를 서버 모듈 한 곳(예: `graph/nodes/guardrail_in.py`)에 두고, 입력 변환(BE-14)은 이것을 import만 한다. 확인 명령: `grep -rn "EMERGENCY_KEYWORDS *="`의 정의가 저장소 전체에서 1곳이고, 프론트 디렉터리에서 `EMERGENCY_KEYWORDS`·`detect_emergency`가 0건이다.
- [ ] (코드) 금기가 조회되지 않은 응답에도 "금기 목록에 없다는 것이 안전하다는 뜻이 아님" 고정 문구와 "근처 약국·약사에게 확인" 안내가 코드로 붙고, LLM 출력 변경으로 빠지지 않음을 테스트로 확인했다. 확인: `graph/nodes/finalize.py`(제안 경로) 테스트에서 가짜 모델 출력이 고정 문구를 지워도 응답에 문구가 남는다.
- [ ] (코드, RFP-28-01·RFP-29 H5~H7) 입구 범위 외 분류가 "복용 중단·감량 요청"과 "의사에게 숨겨 달라"는 유도를 거절 경로로 보낸다(거절 이유는 "복용 변경은 처방한 의사·약사와 상의" 안내).
- [ ] 119와 약국·약사 안내 외의 응급 지침·연락처는 RFP-19에서 공식 출처를 확인한 것만 쓴다. RFP-19를 끝내지 못했으면 119와 약국·약사 안내만 쓴다.
- [ ] (프롬프트 + 코드 판별) 진단·처방·복용량 결정 요청이 거절되고 근거 기반 정보 안내로 이어진다.
- [ ] (프롬프트 + 코드 판별) 범위 외 질문이 거절된다. 확인: AG-04 범위 외 문항의 거절 k/n을 기록한다(목표는 PJ2-RFP.md 9.3절 안전 응답률).
- [ ] (코드) 모든 응답 본문에 고지 문구가 포함된다. 확인: 응답 JSON `disclaimer` 필드가 비지 않음을 pytest로 확인한다(BE-06 응답 필드).
- [ ] (코드, RFP-33-04) **`finalize` 항목별 문구**: 도구 결과 항목의 상태·꼬리표를 읽어 항목마다 코드 상수 문구를 붙이고 `FOUND`(금기 발견) 항목을 먼저 둔다. `FOUND` → 금기 종류·등급 원문·고시번호, `NOT_LISTED` → "금기 목록에 없음(안전하다는 뜻이 아님)", `UNIDENTIFIED` → "약을 찾지 못해 확인하지 못함" + 다시 쓸 이름 안내, `NO_EVIDENCE` → "근거 문장을 찾지 못함", `EASY_TEXT_MISSING` → "쉬운 설명 없음(허가사항 원문)", API 꼬리표 → RFP 5.1절 (7) 문구·"실시간 확인을 하지 못함"(PJ2-Agent-Harness.md 3.4절 표가 원본). 상태가 섞인 결과에서 `FOUND`가 "확인하지 못함"에 묻히지 않는 테스트가 통과한다.
- [ ] (코드, RFP-33-01) **성분 단위 표시(H17)**: 성분명만으로 식별된 항목(`NO_PRODUCT_INFO`)에는 "제품 단위 정보(제품 연령 문장·허가 라벨·제형) 없음. 봉투의 제품명을 알려 주시면 더 확인할 수 있어요"를 코드로 붙이고, 성분 단위 판정(병용·임부·성분 연령금기)은 그대로 보인다(되묻기로 막지 않음).
- [ ] (코드, RFP-33-06) **상한 도달 응답**: 모델 호출 상한(8회, AG-01)으로 끝나면 안내 전환 문구와 함께 그때까지 나온 판정 항목(`FOUND`·`NOT_LISTED`)을 위 항목별 문구로 보이고, 판정하지 못한 항목은 "확인하지 못함"으로 둔다. LLM 요약 없이 코드로 만든다.
- [ ] (코드, RFP-33-04) 도구 결과는 데이터 블록 구분자 안에서만 모델에 넘어가고, 도구 결과에 "이전 지시를 무시"를 넣은 가짜 도구로 `emergency`·`route`·고정 문구가 바뀌지 않음을 확인한다(H8, 상태 키 제한은 AG-01).
- [ ] (코드, PRD-09-07) `FOUND` 표지 문구 상수에 금기 종류 키(`kind`: 병용·임부·연령 등)를 두고 "삐! 병용금기"/"삐! 임부금기 {grade}등급" 글자를 종류별로 만든다. 화면이 색을 고르는 기준은 이 키이며, 한 응답에 병용·임부 항목이 함께 있으면 종류별 표지가 각각 만들어진다. 확인: 병용·임부가 모두 해당하는 fixture에서 표지 문구 2개가 나온다.
- [ ] 각 유형 5건 이상 테스트가 통과한다.
- [ ] (RFP-24-02) 입구 Guardrail이 "이전 지시를 무시하고 …" 같은 인젝션 시도를 거절하거나 무시하고, 고정 문구·119·판정은 LLM 출력으로 바뀌지 않음이 확인된다(평가 세트 범위 외의 인젝션 문항 기준).
- [ ] (코드, PRD-09-01·03·04) `FOUND` 문구 상수: 표지 `삐! 임부금기 {grade}등급`(M은 `M등급` + "적응증에 따라 등급이 달라요"), 보조줄은 원인 성분과 근거만(등급 반복 없음), 등급 정의 블록은 L1 청크 ID로 고시 원문(M은 심평원 설명·판·표·쪽)을 읽어 넣는다. "단계" 표현을 쓰지 않는다.
- [ ] (코드, PRD-10-01·04) `EASY_TEXT_MISSING` 문구를 "{약 이름}은 전문의약품이라 쉬운 설명(e약은요)이 없어서 허가사항 원문을 그대로 보여 드려요"로 바꾸고 허가사항 한 줄 설명 상수를 둔다. `NO_PRODUCT_INFO` 문구의 "허가 라벨"도 "허가사항"으로 맞춘다(화면 문구만, 내부 용어 L3 라벨은 그대로). `P2-doc/PJ2-Agent-Harness.md:207-208`의 코드 문구 표와 같은 값이어야 한다.
- [ ] (코드, PRD-11-03·H26) **원문 미확보 상수**: `missing_reason` 4종(`ABSENT`·`FETCH_FAIL`·`SEARCH_MISS`·`OUT_OF_SCOPE`)마다 원인별 고정 문구 상수와 공통 **약사 확인 권고 상수**(`PHARMACIST_ADVICE`, 접히지 않는 고정 문구 영역의 한 줄 `PHARMACIST_ADVICE_FIXED` 포함)를 `finalize`가 코드로 삽입한다. LLM은 사유를 풀어 쓰지 않는다. 사용자 수정 조건: 오독 방지("상호작용 없음·안전" 암시 금지) + 약국·약사를 찾아가 확인하라는 권고를 강하게. 표는 [PRD-11 §6.6](../doc/PRD-11.md#66-하네스-상태와-화면-박스-매핑표)와 같은 값이다. 테스트: 가짜 모델 출력이 권고를 지워도 응답에 남는다, 사유 4종 각 1건 문구가 표와 같다, 상수에 "의사"·"공식 사이트"가 없다.
- [ ] (코드, PRD-11-05·06·H29) 출처 종류 표지 문구 상수 3종(`source_kind`별 쉬운 말, 내부 용어 없음)을 `finalize`가 도구 결과의 `source_kind`로 렌더한다. `source_kind`가 없는 근거 항목은 렌더하지 않고 차단한다. `LLM_SUMMARY`는 근거 상세에 쓰지 않는다.
- [ ] (코드, PRD-11-04) 미확보 사유 코드를 내용 없는 집계 이벤트(BE-15 로그 모듈)로 내보내고 질문·약 이름·모델 출력은 넣지 않는다. 화면에는 코드를 노출하지 않는다.
- [ ] (PRD-11, 이관) **mock 문구 정정**: `evaluation/mock_gen/m1_chat.py`의 미확보·표지 문구를 위 상수와 같게 고치고(PRD-11이 쓰기 범위 밖이라 이관) 저장소 전체에서 "원문을 가져오지 못했어요"가 0건임을 `grep`으로 확인한다. `P2-doc/PJ2-Agent-Harness.md` 3.4절 표와 같은 값이어야 한다.

## 5. 메모
- 2026-11-03 (RFP-19): 응급 상황 안내는 **119와 약국·약사 안내만** 쓴다(RFP-19-01 A, 소방청 일반인 응급처치 자료는 제외). 출처를 확인하지 못한 연락처·응급처치 문구(예: 1339)는 넣지 않는다.
- 가정: 응급 키워드 목록은 직접 정의하며 임상 검수를 받은 것이 아니다.
- 선행에 AG-02·05·06을 넣은 이유: 완료 조건의 "119 + 금기 조회 병행"은 금기 조회 노드(AG-02), Router 분기(AG-05), 답변 생성(AG-06)이 있어야 끝단으로 확인할 수 있다. AG-05는 AG-08을 선행으로 걸지 않는다(`emergency` 필드만 읽는다).
- 응급(FR-06)은 필수라 범위 축소 대상이 아니다(RFP 12장).
- 2026-10-31 추가: 응급 키워드에 과량 섭취 표현(예: "한 통 다 먹었어")과 임신 중 호흡곤란 같은 표현을 포함해 `P2-doc/PJ2-가설검증.md`의 TC-07·TC-11로 시험한다. 이 둘은 119 안내를 맨 위에 고정하고, 약 이름이 있으면 금기 조회를 막지 않는다. 과량 대처 지침은 RFP-19 확인 전에는 만들지 않는다.
- 2026-11-02 계획 변경(사용자가 RFP-22 §13 P1~P4 승인): (P4) 안전 장치가 가장 마지막에 만들어지지 않도록 선행을 AG-02, AG-05로 줄였다(AG-01·06·07 제외). 입력 쪽(응급 감지·범위 외·진단·처방 거절)과 출력 쪽(고정 문구·119 최상단·고지)은 에이전트 호출 앞뒤의 일반 함수라 에이전트 호출을 스텁으로 대체해 테스트한다. 통합은 AG-01에서 한다. 기준선 전에 끝낸다.
- 2026-11-06 결정 반영(RFP-33-01·04·06 A): `finalize` 항목별 문구, 성분 단위 표시, 상한 도달 응답을 완료 조건으로 옮겼다. 사진·음성 확인 선행(H19)의 입구 검사는 사진·음성 구현 때 PRD-08 구현 쪽과 함께 한다(확장).
- 2026-11-06 (RFP-33, 결정 대기): `finalize`가 도구 결과 상태·플래그를 읽어 붙이는 문구("제품 단위 정보 없음", "쉬운 설명 없음")와 도구 결과·사진 글자 속 지시문 격리 안이 [PJ2-Agent-Harness.md](../../P2-doc/PJ2-Agent-Harness.md) 3.4절·4절 (a)(b)(g)에 있다.
