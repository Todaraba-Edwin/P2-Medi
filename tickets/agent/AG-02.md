## 1. 이슈
2026-11-03 정정(전수조사): 이 티켓은 **에이전트가 부르는 도구 함수**(`@tool`)를 만든다. 별도 그래프 노드가 아니라 단일 `tools` 노드(`ToolNode`)에 등록되는 도구이며(RFP-22-01 A, RFP-23-01) 도구 6개 중 **`identify_drug`·`check_contraindications`·`get_label_section` 3개**를 맡는다(나머지 검색 3개 `search_notice`·`search_reason`·`search_label`은 AG-03). BE-02(e약은요)·BE-03(DUR API)·BE-09·BE-10(적재 데이터의 성분코드 조회, 제품명→성분코드)·BE-12(허가정보 스냅샷)를 도구 함수로 감싸, 결과와 조회 시각 또는 자료 기준일이 상태의 출처 목록에 들어가게 한다. 병용·연령·임부 금기 판정은 성분코드 정확 일치로 하고, 1차 판정은 적재 파일(BE-09, 연령금기도 KIDS 연령금기 CSV)이며 DUR API(BE-03)는 병기한다(RFP 5.1절 (7), 8장, 12장, RFP-17 결정 1). 파일과 API가 어긋나는 경우는 5.1절 (7)의 4경우로 처리한다.

## 2. 완료 조건
- [ ] **`identify_drug`**(RFP-22 §6): 약 이름 입력으로 후보 최대 5개(품목기준코드·제품명·제형·연령 문장·성분 목록(성분코드, 연결 근거: M-코드/이름)·일반/전문 구분)를 돌려주고, 못 찾으면 "없음 + 다시 쓸 이름"을 돌려준다. 결과와 조회 시각이 상태의 출처 목록(`evidence`)에 기록된다.
- [ ] 약품 2개 입력으로 병용금기 결과를 기록한다. 제품명이 BE-10으로 성분코드가 된 뒤 BE-09(파일 적재)와 BE-03(DUR API) 양쪽 결과가 함께 상태에 들어간다.
- [ ] 약품과 연령(또는 임신 여부)을 입력하면 연령 금기(BE-09 파일 1차 + BE-03 API 병기) 또는 임부 금기(BE-09 파일 1차 + BE-03 API 병기) 결과를 기록한다.
- [ ] RFP 5.1절 (7)의 불일치 4경우를 각각 테스트한다. 같음: 결론을 한 번 말하고 두 출처(파일 기준일 2026-07-21, API 조회 시각)를 함께 기록. 파일에만 있음: 둘 다 기록하고 한쪽을 확정하지 않으며 "기준일 이후 해제되었을 수 있음"과 약사·의사 확인 안내를 붙임. API에만 있음: 둘 다 기록하고 한쪽을 확정하지 않으며 "기준일 이후 새로 지정되었을 수 있음"을 붙이고 안전하다고 말하지 않음. API 호출 실패: 파일 기준으로 답하고 "실시간 확인을 하지 못함" 문구를 코드로 붙임.
- [ ] 평가 실행 모드에서는 API Tool을 끄고 파일 기준으로만 동작하는 설정이 있다(RFP 5.1절 (7), BE-08과 연동).
- [ ] 집에 있는 약 여러 개(3개 이상)를 입력하면 가능한 모든 쌍 조합(예: 3개면 3쌍)을 조회해 쌍별 결과를 기록한다. 조회되지 않은 쌍은 "금기 목록에 없음"으로, 성분코드를 얻지 못한 약은 "약 미식별"로 구분해 기록한다(AG-09의 입력).
- [ ] (확장, 권장) 입력한 약 중 두 개 이상이 같은 성분코드를 가지면 "성분 중복"으로 기록한다. 제품명이 BE-10으로 성분코드가 된 뒤 코드를 비교하는 규칙이며, DUR 효능군 중복 API(BE-03 확장)와 별개다. 일정이 모자라면 확장 중 마지막 순서로 줄인다(RFP 4장 순서)(`P2-doc/PJ2-가설검증.md` TC-02, H6).
- [ ] **`get_label_section`**(RFP-22 §6): 품목기준코드와 절 이름으로 허가 상세·e약은요의 해당 절 본문(길이 제한)을 돌려준다. 평가 모드에서는 BE-12 스냅샷만 쓴다. 용법용량은 원문 그대로이며 근거 상세에만 인용된다(RFP-21-03).
- [ ] 도구 함수 단위 테스트가 통과하고, 3개 도구가 `tools` 노드에 등록되어 `model`이 호출할 수 있다(AG-01).

## 5. 메모
- 2026-11-03 전수조사(RFP-24 §11): 도구 6개 중 `identify_drug`와 `get_label_section`을 구현하는 티켓이 없었다(BE-02 메모가 "도구 설계에서 정한다"로 미뤄 둠). 이 티켓이 `identify_drug`·`check_contraindications`·`get_label_section`을, AG-03이 `search_*` 3개를 맡는 것으로 정리했다. 본문의 `api_tool`·`contra_tool` "노드" 표현은 도구 함수로 정정했다.
- RFP-17 결정(2026-10-30): 금기 판정은 성분코드 정확 일치 결과만 근거로 한다. 금기등급 M은 심평원 설명을 인용하되 1등급 또는 2등급으로 바꿔 말하지 않고(RFP-17의 M 처리 규칙), 출처가 어긋나면 한쪽을 확정하지 않고 두 근거와 기준일을 함께 보인다.
- 2026-10-31 정정: 연령 금기의 1차 소스는 BE-09(KIDS 연령금기 CSV)이고 BE-03(API)은 병기다. 이전에는 연령 금기를 BE-03만 쓰는 것으로 적었다(RFP-17 결정 10 변경, RFP 5.1절 (1)(7)).
- 2026-10-31 정정: 이전 문구 "병용금기 판정은 DUR 결과만 근거로 한다"를 "성분코드 정확 일치, 파일 적재 + API 교차"로 고쳤다. 8장에 금기 조회 Tool이 들어왔고 DUR 금기 판정은 파일 적재 데이터와 식약처 OpenAPI를 함께 쓰는 혼합 방식이기 때문이다.
- 가정: 약이 많을 때 쌍 조합 수의 상한(예: 6개 약 = 15쌍)은 호출 제한을 보고 정한다.
- 2026-11-01: 파일과 API 결과의 "같음/다름" 판정은 같은 성분코드 비교가 아니다. 두 체계가 달라 영문 성분명 정규화 또는 품목 단위 연결로 비교해야 한다(`P2-doc/PJ2-API-응답확인.md` 4장). 불일치 4경우 처리의 입력 정의를 BE-09·BE-10과 함께 정한다.
- 2026-11-02 계획 변경(사용자가 RFP-22 §13 P1~P4 승인): (P2) 선행에서 AG-01을 뺐다. 이 티켓은 그래프 노드가 아니라 에이전트가 부르는 도구 함수이며, `check_contraindications`(병용·연령·임부를 한 번에 조회)처럼 할 일 단위로 묶는다(RFP-22 §6). 이 티켓이 먼저 끝난 뒤 AG-01이 도구를 연결한다.
- 2026-11-05 (RFP-32): `mock/api_snapshots/SCENARIO_COVERAGE.md`(네트워크 없이 S1~S8 단계 39개 중 36 재현)와 `scripts/mock/replay_check.py`가 도구 테스트 입력이 된다. 병용금기 성분 조회는 양쪽 조회(BE-03 메모), 전문의약품 라벨은 허가정보 상세만 출처다. 스냅샷은 개발용이며 서비스 근거 데이터가 아니다.
