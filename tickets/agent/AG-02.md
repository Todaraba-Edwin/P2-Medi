## 이슈
BE-02(e약은요), BE-03(DUR API) 클라이언트를 api_tool 노드로, BE-09·BE-10(적재 데이터의 성분코드 조회, 제품명→성분코드)을 금기 조회 노드(contra_tool)로 감싸, 결과와 조회 시각 또는 자료 기준일이 상태의 출처 목록에 들어가게 한다. 병용·연령·임부 금기 판정은 성분코드 정확 일치로 하고, 적재 데이터(BE-09)와 DUR API(BE-03) 결과를 교차해 근거로 삼는다(RFP 8장, 12장, RFP-17 결정 1).

## 완료 조건
- [ ] 약품명 입력으로 e약은요 노드가 결과와 조회 시각을 상태에 기록한다.
- [ ] 약품 2개 입력으로 병용금기 결과를 기록한다. 제품명이 BE-10으로 성분코드가 된 뒤 BE-09(파일 적재)와 BE-03(DUR API) 양쪽 결과가 함께 상태에 들어간다.
- [ ] 약품과 연령(또는 임신 여부)을 입력하면 연령 금기(BE-03) 또는 임부 금기(BE-09 + BE-03) 결과를 기록한다.
- [ ] 파일 적재와 API 결과가 어긋나면 한쪽을 확정하지 않고 두 근거와 기준일·조회 시각을 함께 기록하는 테스트가 통과한다.
- [ ] 집에 있는 약 여러 개(3개 이상)를 입력하면 가능한 모든 쌍 조합(예: 3개면 3쌍)을 조회해 쌍별 결과를 기록한다. 조회되지 않은 쌍은 "금기 목록에 없음"으로, 성분코드를 얻지 못한 약은 "약 미식별"로 구분해 기록한다(AG-09의 입력).
- [ ] 노드 단위 테스트가 통과한다.

## 하위 작업
- [ ] api_tool 노드 정의(e약은요, DUR API)
- [ ] contra_tool 노드 정의(BE-10 → BE-09 조회, BE-03 교차)
- [ ] 쌍 조합 생성(n개 약 → n(n-1)/2쌍)
- [ ] 출처 객체 생성
- [ ] 테스트

## 메모
- RFP-17 결정(2026-10-30): 금기 판정은 성분코드 정확 일치 결과만 근거로 한다. 금기등급 M은 심평원 설명을 인용하되 1등급 또는 2등급으로 바꿔 말하지 않고(RFP-17의 M 처리 규칙), 출처가 어긋나면 한쪽을 확정하지 않고 두 근거와 기준일을 함께 보인다.
- 2026-10-31 정정: 이전 문구 "병용금기 판정은 DUR 결과만 근거로 한다"를 "성분코드 정확 일치, 파일 적재 + API 교차"로 고쳤다. 8장에 금기 조회 Tool이 들어왔고 DUR 금기 판정은 파일 적재 데이터와 식약처 OpenAPI를 함께 쓰는 혼합 방식이기 때문이다.
- 가정: 약이 많을 때 쌍 조합 수의 상한(예: 6개 약 = 15쌍)은 호출 제한을 보고 정한다.
