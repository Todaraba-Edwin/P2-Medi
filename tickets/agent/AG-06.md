## 이슈
검색·조회된 근거만 사용해 답변을 만들고, 모든 답변에 출처·조회 시각(또는 자료 기준일)·조항을 붙인다. LLM은 설명과 종합만 맡는다(RFP 1장). 주 사용자가 일반인이므로 답변은 일반인 눈높이의 쉬운 요약을 먼저 쓰고, 성분코드·등급·조항 같은 근거 상세는 요약과 분리해 따로 만든다(RFP FR-04). 두 부분은 BE-06의 `summary`, `detail` 필드에 들어간다.

규칙 구현 방식은 항목마다 (코드) / (프롬프트)로 표기한다.

## 완료 조건
- [ ] (프롬프트) 생성 프롬프트가 제공된 근거만 사용하도록 제한되어 있다.
- [ ] (코드) 모든 사실 문장에 연결된 출처 ID가 있고, 출처 ID가 없는 문장은 출력 전에 걸러진다.
- [ ] (코드) API 출처에는 조회 시각이, 파일 데이터와 문서 출처에는 자료 기준일과 문서명·조항/쪽이 포함된다.
- [ ] (프롬프트) 쉬운 요약은 일반인 눈높이의 평이한 말이며 결론(주의가 필요한 조합인지, 확인할 점)을 먼저 말한다. 복용 여부와 용량은 정해 주지 않는다.
- [ ] (코드) 근거 상세(성분코드·금기등급·고시 조항·기준일)는 요약과 분리된 별도 필드로 만들어진다. 요약에 성분코드 같은 전문 용어가 그대로 나열되지 않음을 샘플로 확인했다.
- [ ] 샘플 10건에서 출처 누락이 0건이다.
- [ ] 제품 사용 연령·상호작용 같은 라벨 문장은 요약하지 않고 인용으로만 쓰며, Validator(AG-07)가 원문과 대조한다(`P2-doc/PJ2-가설검증.md` TC-01).
