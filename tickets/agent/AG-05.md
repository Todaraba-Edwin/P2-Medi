## 이슈
RFP FR-01: 질문에서 약품명·연령·임신 여부·질환 등 엔티티를 추출하고(연령·임신 여부는 대화 중 입력하거나 사용자가 동의해 저장한 프로필에서 가져오며, 질문·대화 내용은 저장하지 않는다) 8장 구조도의 경로, 곧 공공 API Tool / 금기 조회 Tool / 문서 검색 / 안내 전환으로 분기한다. 병용·연령·임부 금기 질문은 금기 조회 경로(성분코드 정확 일치)로 보낸다(8장, 12장).

응급 키워드 감지는 Router가 하지 않는다. AG-08(Guardrail)의 코드 규칙 한 곳에서만 감지하고, Router는 상태의 `emergency` 병행 신호를 읽기만 한다. 응급 신호가 있어도 Router는 평소처럼 도구를 고른다(금기 조회를 막지 않는다).

규칙 구현 방식은 항목마다 (코드) / (프롬프트)로 표기한다.

## 완료 조건
- [ ] (프롬프트 + 스키마 검증 코드) 샘플 질문에서 약품명·연령·임신 여부·질환 엔티티가 추출됨을 테스트로 확인했다.
- [ ] (코드) 게스트로 호출했을 때 추출한 연령·임신 여부가 요청 처리 중 상태에만 있고 DB·파일·로그에 기록되지 않음을 테스트로 확인했다.
- [ ] (코드) 프로필을 사용하는 경우에도 저장되는 것은 사용자가 동의한 프로필 항목뿐이고, 질문에서 추출한 값과 대화 내용은 저장·로깅되지 않음을 테스트로 확인했다. 프로필 연동은 확장(BE-11)이 붙은 경우에만 해당한다.
- [ ] (코드 규칙 + 프롬프트 분류) 질문 유형별(약품 정보, 병용·연령·임부 금기, 금기등급·고시 등 문서 설명, 범위 외) 분기 테스트가 통과한다.
- [ ] (코드) 상태의 `emergency` 신호가 있어도 분기 결과가 바뀌지 않고 금기 조회 경로로 간다는 테스트가 통과한다. Router 코드에 응급 키워드 목록이 없다.
- [ ] 약품 정보와 규정을 함께 묻는 질문은 두 경로를 모두 호출한다.
- [ ] 집에 있는 약 여러 개를 묻는 질문에서 약품명 엔티티를 모두 추출해 금기 조회 경로로 넘긴다.
- [ ] (코드) 역할 A 확정/모호 분기: 사전(BE-10) 후보 점수가 기준 이상이고 2위와 차이가 크면 성분코드로 확정해 금기 조회로 넘기고, 아니면 후보를 보여 주고 질문 1개를 한다(RFP 5.1절 (3) 역할 A). 기준값은 AG-04 정상·오탈자 세트로 정한다. FR-07(AG-10)이 줄어도 이 분기는 필수다.
- [ ] (코드 규칙 + 프롬프트 분류) 성분이 없는 열린 질문(예: "임신 중 피해야 할 진통제")은 역할 B 경로(AG-15)로 보낸다. AG-15가 없으면 "근거 없음" 안내로 전환한다.
- [ ] (코드 규칙 + 프롬프트 분류) 질문에서 필요한 주장 유형 목록(설계 문서 4장: 금기 여부, 등급 정의, 금기 사유, 제품 주의, 용어·절차, 한계·고지, 기준일)을 상태에 기록한다. 코드 규칙으로 정할 수 있는 것(예: 금기 판정 질문이면 금기 여부와 한계·고지, 판정된 쌍이 있으면 금기 사유)은 코드로 채우고, 규칙으로 정하기 어려운 것(등급 정의·용어 설명을 묻는지 등)은 프롬프트 분류로 채운다. 질문 유형별 샘플(TC-15, 21, 22 포함)에서 기록된 목록이 기대와 일치함을 테스트로 확인했다. 이 목록이 AG-03의 분해 검색 입력과 AG-07의 누락 검사 기준이 된다.

## 하위 작업
- [ ] 엔티티 추출 프롬프트·스키마(임신 여부 포함)
- [ ] 연령·임신 여부 비저장·비로깅 처리(게스트 / 프로필 사용 구분)
- [ ] 분기 규칙(4경로)
- [ ] `emergency` 병행 신호 읽기
- [ ] 필요한 주장 유형 목록 기록(코드 규칙 + 프롬프트 분류)과 상태 필드 연결
- [ ] 테스트

## 관련
- 선행: AG-01, AG-02, AG-03, BE-10
- 관련: AG-08(응급 감지 담당), BE-10(제품명 → 성분코드), BE-11(프로필, 확장), AG-03(주장 유형 목록을 입력으로 받는 쪽), AG-07(누락 검사)
- 관련 문서: `P2-doc/PJ2-RFP.md` 6장, 8장, 12장

## 메모
- Agent-RAG 핵심 요소(Router·도구 선택·근거 고정·Validator·평가 수치)는 확장이 일정을 압박해도 줄이지 않는다(RFP 4장).
- 2026-11-01 멀티홉 대응: 필요한 주장 유형 목록을 상태에 기록하는 조건을 추가했다(설계 문서 6장 (1) "주장 유형별 분해"). 신규 티켓은 만들지 않았다. 가정: 상태 필드 이름과 주장 유형 값의 표기는 AG-01의 상태 정의와 맞춰 구현 때 정한다.
- 가정: AG-08은 AG-05의 선행으로 걸지 않는다. Router는 AG-01이 정의한 `emergency` 필드만 읽으므로, AG-05 테스트는 이 필드를 직접 채워 넣어 진행한다.
