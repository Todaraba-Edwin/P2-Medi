## 1. 이슈
`gpt-6-luna`는 Chat Completions에서 함수 도구와 추론(`reasoning_effort`)을 같이 쓸 수 없어(HTTP 400) 도구를 쓰는 노드는 `reasoning_effort='none'`으로 호출하기로 했다(2026-11-10 사용자 방향, [AG-01 §6](AG-01.md#6-결정-현황) AG-01-01 A, 확인 결과는 [BE-15 §5](../backend/BE-15.md#5-메모)). 추론을 끄면 도구 선택·인자 품질이 달라질 수 있으므로, **기준선 측정(AG-11) 전에** 이 호출 방식이 기준선에 충분한지 점검해 조건을 고정한다. 기준선은 가장 단순한 ReAct이고(RFP-22-03) 실패를 본 뒤에 개선한다(AG-13).

이 티켓은 AG-01-01 결정의 **이행 티켓**이다. 새 결정은 없고, 사용자 지시("현재 정책의 방향에서 권고를 따름")대로 현재 방향을 유지하는 설계를 따른다.

## 2. 완료 조건
- [ ] ① LangGraph·LangChain OpenAI 부품에서 `reasoning_effort="none"`과 `parallel_tool_calls`가 **실제 요청 본문에 전달되는지** 확인했다(외부 호출 최소, 요청 본문 기록 확인).
- [ ] ② 도구 3개(`identify_drug`·`check_contraindications`·`search_docs`) 스키마로 **개발용 합성 질의 약 30개**의 첫 단계 도구 선택·인자 정확도를 k/n과 Wilson 95% 구간으로 기록했다. 질의는 평가 세트·시험셋·페르소나 질문을 쓰지 않고(RFP-26-04) 기대 도구 경로는 규칙으로 확정한다. 칸당 n이 8 이하이면 유의성을 주장하지 않는다(PJ2-RFP.md 9.1절).
- [ ] ③ 병렬 호출이 필요한 질문(두 약 병용)에서 한 응답에 도구 호출이 2개 이상 나오는 비율을 기록했고, 한 노드 호출 상한 8회(RFP-22) 안에서 종료됨을 확인했다.
- [ ] ④ 구조화 출력(AG-06-02, `AnswerDraft` strict 변환)은 **도구를 쓰지 않는 최종 요약 단계**에서 같은 `reasoning_effort` 설정으로 동작한다(도구 호출과 한 호출에 섞지 않는다).
- [ ] ⑤ 대안 B(`/v1/responses`)는 이번에는 시험하지 않는다. ②의 정확도가 기준선에 부족할 때만 시험하며, 시험하지 않은 사유를 §5에 이월로 적는다.
- [ ] ⑥ 호출 수·비용을 BE-15 원장 dev 몫에 기록했고 개발 상한 $2.5 안이다(예상 비용은 점검 스크립트 `plan` 보고 뒤 확정, 측정 전). **실호출은 사용자 승인이 필요**하며 승인 요청은 AG-02(도구 3개) 완료 뒤 합성 질의 약 30개·상한을 보고하고 받는다(지금 사용자 몫이 아니라 Recap에 올리지 않음).
- [ ] ⑦ 결과와 확정한 호출 설정을 §5에 기록했고, `reasoning_effort` 값을 바꾸면 이유와 날짜를 남긴다(평가 기간 중 모델·설정 고정, CLAUDE.md 5장).

- [ ] (AG-02-01 A 이관, 2026-11-11) AG-02 도구 3개 `REGISTRY`(`backend/app/agent/tools/registry.py`)의 도구 호출 방식(`@tool` 어댑터 스키마·인자)을 ②의 합성 질의 점검의 **입력**으로 쓴다. 어댑터 등록 자체는 [AG-01 §2](AG-01.md#2-완료-조건)가 하고, 이 티켓은 그 스키마로 도구 선택·인자 정확도를 본다.
