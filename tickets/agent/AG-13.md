## 1. 이슈
RFP 10장 3주차 "측정 → 개선 → 재측정". 기준선에서 낮은 지표의 원인을 실패 사례로 분석해 개선한다(예: 청킹, 검색 k·필터, 프롬프트, Router 규칙).

## 2. 완료 조건
- [ ] 실패 사례 상위 원인과 선택한 개선 항목이 `메모`에 기록되어 있다.
- [ ] 개선 변경이 커밋으로 분리되어 있다.
- [ ] 기준선 실패 사례에 대응하는 (개선) 조건만 구현했고, 구현하지 않은 (개선) 조건은 이유(기준선에서 실패 없음)를 `메모`에 적었다.
- [ ] 평가 세트(개발셋·시험셋)의 버전은 바꾸지 않았다(재현성). 시험셋은 열람·분석하지도 않았다(RFP-26-04).
- [ ] (RFP-25-01) 자유도 확장(L2) 후보(질문·근거 분해 검색, 종료 전 자기 점검과 재검색(되돌림 최대 2회), 되묻기를 도구로, 근거 관련성 판정)는 **기준선 실패에 대응하는 것만, 한 번에 하나씩** 더하고 **개발셋**으로 측정했다(ablation). 시험셋의 C3는 개선이 끝난 뒤 AG-14에서 한 번만 잰다(PJ2-RFP.md 9.1절 8번). 호출 수·지연·정확도를 함께 기록했다.
- [ ] (RFP-25-03) Supervisor·서브에이전트(L3) 도입 조건(RFP-25 §7.2: 긴 근거 텍스트로 Faithfulness·근거 묶음 Recall 하락, 도구 증가로 필수 도구 누락·오선택, 역할별 프롬프트 충돌)이 관찰되었는지 확인했고, 관찰되지 않았으면 도입하지 않고 이유를 `메모`에 적었다.
- [ ] (RFP-25-04) 어떤 개선도 코드 고정 불변식(금기 판정, 고정 문구·119, Validator, 입구 거절, 호출 상한)을 LLM에 넘기지 않았다.
- [ ] (RFP-26-04) 실패 분석·개선·judge 튜닝은 **개발셋만** 보고 했고, **시험셋은 열람·분석하지 않았다**.
- [ ] (입구 퓨샷, 2026-11-11 사용자 "권장대로" AG-08-02 A와 함께 후보 등록) **`agent_system@v3` 후보 — 입구 오탐·미탐 개선 퓨샷**: 같은 어휘·다른 의도의 합성 예시 쌍(예: "임신한 상태에서 먹어도 되나요"는 조회, "지금 상태로 약 줄여도 되나요"는 거절)을 시스템 프롬프트 예시(위치 A)로 먼저 시험하고, 부족하면 입구 LLM 분류(위치 B, 최종 거절 문구는 코드)를 시험한다. 제약: 프롬프트에 개발셋·시험셋 문장을 넣지 않는다(L0 검사), 기준선(AG-11) 측정 뒤에 시험한다(기준선 = 범위 외 입구 거절 8/15·정상 질문 거절 0건), 병렬 호출 0/6 개선과 같은 v3에 묶는다. 결과는 k/n과 Wilson 95% 구간으로 쓰고 칸당 n≤8이면 유의성을 주장하지 않는다(PJ2-RFP.md 9.1절). 입구 정규식은 정밀도 우선(AG-08-02 A)이라 미탐 보완은 여기서 한다
- [ ] (RFP-33-02·03·04) **개선 단계 하네스 장치**(ID 존재 `known_ids`(H21), 단위 보조 차단(H17), 반복 경고(H12 보조))는 해당 실패를 기준선 trace에서 관찰한 것만 **한 번에 하나씩** C3에 더하고, 개발셋으로만 확인했다. 상태를 읽는 검사가 필요할 때만 `tools` 자리를 `harnessed_tools` 함수 노드로 바꾸고(노드 수 6개 유지), 상태 필드 `known_ids`·`input_units`·`harness_events`를 더한다(PJ2-Agent-Harness.md 3.2·3.5절). 안전·정합 규칙은 하드 차단, 반복은 경고만 기록한다(RFP-33-02). 장치마다 조건표(BE-08)에 ablation 행으로 기록했다. `allowed_next`(다음 행동 제한)는 만들지 않는다.
- [ ] (RFP-34-04) **병목 수정과 동결**: 기준선~최종 재측정 동안 평가 조건(세트 해시·judge·루브릭·C1 규칙·지표·모델 ID·호출 상한)을 바꾸지 않았다. 병목 수정은 에이전트 쪽만 하고, 수정마다 `prompt_version`·`graph_version`을 기록했으며, 캐시·병렬화·프롬프트 단축 같은 **성능 수정도 정확도를 함께 재고** 개발셋으로만 확인했다. 병목 기록 양식(PJ2-Agent-로깅-전략.md 7장 (3))에 측정 → 가설 → 한 번에 하나 → 재측정을 남겼다.
- [ ] (PRD-16-02·03) **프롬프트 변경의 채택 절차**: 프롬프트를 바꿀 때마다 L0·L1·**L2(개발 골든 약 20 스모크)**를 돌리고 검토 카드를 사용자가 승인한 뒤 채택한다. `model`·`summary` 프롬프트(`P-AG01-model`·`P-AG06-summary`) 변경은 **L3(개발셋 전체, 개발 안전 핵심 40은 3회)**도 돌리며 개발 안전 핵심 `pass^3`가 이전 채택 버전보다 내려가면 채택하지 않는다. 골든·안전 핵심은 AG-04가 표시한 **개발셋** 것만 쓰고 시험셋(L4)은 개선 중 열람하지 않는다(RFP-26-04). 한 번에 프롬프트 하나만 바꾸고 `prompt_set@vN`을 기록한다. 칸당 n 8 이하는 유의성 주장 없이 회귀 경보로만 읽는다(`P2-doc/PJ2-프롬프트-설계.md` 5장 (3)·(6)).
