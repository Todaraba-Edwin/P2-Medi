## 1. 이슈
RFP FR-08: 검색 결과가 없으면 지어내지 않고 모른다고 응답한다. "금기 목록에 없음"(조회했고 금기가 나오지 않음)과 "근거 없음"(약 미식별·데이터 없음)을 구분해 안내한다. LLM 내부 지식으로 채우지 않고, 확인 가능한 안내(근처 약국·약사)로 연결한다.

규칙 구현 방식은 항목마다 (코드) / (프롬프트)로 표기한다.

## 2. 완료 조건
- [ ] (코드) API·금기 조회·문서 검색 모두 0건인 질문에서 "확인할 수 없다"는 응답이 나오고 사실 문장이 없다.
- [ ] (코드) 약품명을 성분코드로 바꾸지 못한 경우(약 미식별)는 "근거 없음"으로 분류되고 "찾을 수 없는 약이라 확인하지 못했다"는 안내가 나온다. 이 경우 금기가 없다는 말을 하지 않는다. 확인: 사전(BE-10)에 없는 약 이름 입력으로 `identify_drug`가 `UNIDENTIFIED`를 돌려주고 해당 문구가 나오는 pytest 테스트(입력 픽스처 `backend/tests/fixtures/dict/`(제안 경로, 구현 때 확정)). 전문의약품이라 e약은요가 0건인 경우는 `UNIDENTIFIED`가 아니라 H18 `EASY_TEXT_MISSING`이며 AG-02 §2의 H18 시험(`backend/tests/fixtures/api/eyak/empty_rx_methotrexate.json`)으로 확인한다(PJ2-Agent-Harness.md 4.1절 (b)).
- [ ] (코드) 약은 식별됐고 조회도 했지만 금기가 나오지 않은 경우는 "금기 목록에 없음"으로 분류되고, "안전하다는 뜻이 아님" 고정 문구(AG-08)와 함께 나온다. 두 경우의 응답 문구가 서로 다름을 테스트로 확인했다.
- [ ] (코드, BE-10-06 A) 사전이 코드를 붙이지 못한 제품("코드 없음")은 "금기 목록에 없음"이 아니라 "금기 목록에서 확인하지 못함"으로 분류하고(AG-02의 `UNIDENTIFIED` + 새 꼬리표), "안전하다는 뜻이 아님 + 근처 약국·약사에게 확인" 문구를 붙인다. 확인: 코드 없음 제품 입력과 `NOT_LISTED` 입력의 응답 문구가 서로 다르고 "금기 없음"·"안전" 암시가 없음을 pytest로 본다.
- [ ] (프롬프트 + 코드 분류) 일부 근거만 있을 때는 있는 부분만 답하고 없는 부분은 없다고 밝힌다. 여러 약 중 일부만 식별된 경우 식별된 쌍만 답하고 나머지는 근거 없음으로 밝힌다.
- [ ] (코드) 안내 문구는 "근처 약국·약사에게 확인"으로 통일되어 있고 "의사"나 "공식 사이트" 같은 다른 안내 문구가 없다. 확인: 응답 문구 상수에 "의사"·"공식 사이트" 안내가 없음을 `grep`으로 확인한다.
- [ ] 테스트가 통과한다. (`pytest`, 테스트 이름을 메모에 기록)
- [ ] 응급 질문에 약 이름이 없으면 119 안내를 유지한 채 약 이름을 묻는다(`P2-doc/PJ2-가설검증.md` TC-11).
- [ ] (코드) 재검색 보정(RFP 5.1절 (3) 역할 D): 결과가 0개이거나 점수 미달이면 재작성한 질의(영문 성분명, 효능군 일반화)로 재검색하고, 재검색 상한(기본 1회, AG-04 세트로 조정)을 넘으면 "근거 없음"으로 분류한다.
- [ ] (코드, PRD-11-03) 허가사항 항목 미확보(`missing_reason`, 한계 고지 문구)와 근거 없음(`NO_EVIDENCE`·`UNIDENTIFIED`, "확인할 수 없음" 문구)은 문구가 서로 다르되 둘 다 "안전" 암시가 없고 "근처 약국·약사에게 확인" 안내가 붙는다. 안내 문구가 PRD-11 §6.7 권고 상수 계열과 같은 표현이고 "의사"·"공식 사이트"가 없음을 `grep`으로 확인한다.
- [ ] (코드, PRD-14-01·02) 약 미식별 문구가 입력한 약 이름을 포함하고 `약 이름 사전`·`공식 약 목록`이 없으며 "금기 없음"·"안전" 암시가 없다. 다중 약 질문에서 한 약만 미식별이면 식별된 약은 `NOT_LISTED`가 아니라 식별 상태로만 표시하고 쌍 판정은 하지 못했다고 표시한다(pytest, 입력 예 "뿌셔캡슐 + 타이레놀정500").
