## 1. 이슈
RFP FR-05: 답변이 원본 API·문서와 일치하는지 점검한 뒤 출력한다. 불일치 시 해당 문장을 제거·수정하거나 재생성하고, 해결되지 않으면 안내 전환한다. 의미 일치는 문장 단위 근거 대조(프롬프트 판정)로, 출력 쪽 위험 표현은 코드 검사로 막는다. 코드 검사는 프롬프트 지시가 어겨져도 위험한 문구가 나가지 않게 하는 마지막 장치다.

규칙 구현 방식은 항목마다 (코드) / (프롬프트)로 표기한다.

## 2. 완료 조건
- [ ] (프롬프트 판정 + 규칙) 근거에 없는 문장·수치가 포함된 답변을 일부러 만들어 넣으면 차단 또는 수정되는 테스트가 통과한다. 확인: 불일치 답변 픽스처의 차단·수정 k/n을 기록한다(목표 수치 없음, 측정 전).
- [ ] 일치하는 답변은 그대로 통과한다. 확인: 일치 답변 픽스처의 통과 k/n을 같은 테스트에서 기록한다.
- [ ] (코드, RFP-28-01·RFP-29 H6·H7) 출력에 **복용 중단·감량 지시**("끊으세요/줄이세요" 계열)와 **의료진 우회**("의사에게 알리지 마" 계열) 패턴이 있으면 차단·수정되는 테스트가 통과한다(허가사항 원문 인용 예외는 RFP-21-03).
- [ ] (코드) 검증 결과(통과/수정/실패)가 상태에 기록된다.
- [ ] (개선) (코드) 문장 종류별 허용 근거 계층을 검사한다(설계 문서 4장 허용 매트릭스). 금기 여부 문장은 판정 테이블(L0)만, 등급 정의는 고시(L1)만, 금기 사유는 사유·상세정보(L2) 우선과 제품 라벨(L3) 보조, 제품 주의는 L3, 용어·절차는 L4(판·표·쪽 명시), 한계·고지는 코드 고정 문구, 기준일은 메타데이터만 허용한다. 인용 청크의 계층이 허용 목록에 없으면 그 문장을 지우거나 "확인할 수 없음"으로 바꾸고, 문장 종류마다 허용·비허용 인용 1건씩 넣은 테스트가 통과한다.
- [ ] (코드) 안전을 단정하는 표현("먹어도 됩니다", "안전합니다", "문제없습니다" 등)과 복용 지시 표현("드세요", "복용하세요" 등)이 포함된 답변은 차단 또는 제거된다. 금칙 표현 목록을 코드 상수로 두고 표현 5종 이상으로 테스트한다.
- [ ] (코드) 금기등급 값은 1·2·M만 허용하고 그 밖의 값이 답변에 나오면 차단한다.
- [ ] (코드) 금기등급 M이 답변에 나올 때는 근거의 상세정보 원문이 비어 있지 않아야 하고, 비어 있으면 차단한다. M을 1등급 또는 2등급으로 바꿔 쓴 문장도 차단한다(RFP-17 M 처리 규칙).
- [ ] (코드) RFP 5.1절 (7)의 "파일에만 있음/API에만 있음" 문장은 판정 테이블(L0)과 API 응답(조회 시각 포함)을 둘 다 인용할 때만 허용한다. API 응답 단독으로 "금기다/아니다"를 확정하는 문장은 허용하지 않고, "기준일 이후 변경되었을 수 있다"로 쓴다.
- [ ] (개선) (코드) 누락 검사: 상태에 기록된 필요한 주장 유형 목록(AG-05)의 유형마다, 답변에 그 유형의 허용 계층 청크를 인용한 문장이 하나 이상 있는지 검사한다. 유형이 빠졌으면 해당 근거가 증거 묶음에 없었던 것인지(검색 누락) 묶음에는 있는데 답변에서 빠진 것인지 구분해 상태에 기록하고, 재생성 또는 "확인할 수 없음" 안내로 처리한다. 유형 하나를 일부러 뺀 답변(예: TC-21에서 M 설명(L4) 문장 없음)이 걸러지는 테스트가 통과한다.
- [ ] (개선, RFP-33-04) (코드) **도구 상태와 맞지 않는 문구** 검사: 항목 상태가 `UNIDENTIFIED`(약 미식별)인데 "금기 목록에 없음"이라고 쓰거나, `NOT_LISTED`를 "안전"·"해당 없음 확정"으로 바꿔 쓴 문장을 막는다(H2, PJ2-Agent-Harness.md 4.1절 (f)). 기준선(AG-11) 실패를 관찰한 뒤 AG-13에서 더한다.
- [ ] (개선, RFP-33-01·04) (코드) **제품 단정 패턴** 검사(H17): 성분 단위 항목(`NO_PRODUCT_INFO`)에 대해 답변이 특정 제품의 연령 문장·허가 라벨·제형을 단정하면 그 문장을 지우거나 "제품 단위 정보 없음"으로 바꾼다. 도구 출력 계약(AG-02)이 있는데도 제품 정보가 새는 것을 관찰했을 때만 더한다.
- [ ] (RFP-24-02) 검색 결과·API 응답에 섞인 지시 문장이 출력에 반영되어도 Validator가 안전 단정·복용 지시·등급값 오류를 차단함이 인젝션 문항(AG-04)으로 확인된다.

## 5. 메모
- 가정: 검증 방식은 문장 단위 근거 대조로 시작한다.
- 가정: 출력 쪽 코드 검사(안전 단정·복용 지시·등급값)는 AG-07 또는 AG-08 중 어느 쪽에 둘지 RFP에 정해진 바가 없어 Validator 쪽에 두었다. 구현 중 Guardrail이 더 자연스러우면 AG-08로 옮기고 두 티켓을 같이 고친다.
- 2026-10-31 추가: 허용 매트릭스 구현은 설계 문서 12장 결정 1(채택)이다. 문장 종류 분류를 코드로 할지 LLM 판정으로 할지는 정해진 바가 없다. 가정: 문장에 붙은 인용 청크의 `layer` 메타데이터(BE-05)로 검사하고, 문장 종류는 답변 생성 단계(AG-06)가 표기한 값을 쓴다.
- 2026-11-01 멀티홉 대응: 누락 검사(코드)를 추가했다(설계 문서 6장 (1) 검증, RFP 12장 멀티홉 행). 기존 허용 계층 검사는 "인용한 청크가 허용되는가"를 보고, 누락 검사는 "필요한 근거가 빠지지 않았는가"를 본다. 신규 티켓은 만들지 않았다. 가정: AG-05(같은 SCH-02)는 AG-07의 선행으로 걸지 않고, AG-07 테스트는 AG-05가 기록하는 주장 유형 목록 상태 필드를 직접 채워 진행한다(AG-05가 `emergency` 필드를 다루는 방식과 같다).
- Validator는 Agent-RAG 핵심 요소(Router·도구 선택·근거 고정·Validator·평가 수치)라 일정이 모자라도 줄이지 않는다(RFP 4장).
- 2026-11-02 계획 변경(사용자가 RFP-22 §13 P1~P4 승인): (P4·RFP-22-08) 기준선에는 안전 단정·복용 지시 표현 차단, 등급값(1·2·M) 검사, 근거 없는 문장·수치 차단, M 원문 검사, 파일/API 단독 확정 금지만 넣는다. 허용 근거 계층 검사와 주장 유형 누락 검사는 (개선)이다. **(개선) 표시**: 이 조건은 기준선 측정(AG-11) 뒤 실패를 관찰한 다음 AG-13에서 필요한 것부터 구현한다. 티켓 완료는 (개선) 표시가 없는 조건 기준이다.
- 2026-11-02 RFP-21-03(B): 용량 숫자 검사 규칙. 쉬운 요약 등 일반 문장에 용량 숫자가 나오면 차단하고, 허가사항 용법용량 절(L3)의 원문 인용 안에서만 허용한다(인용 표시와 출처가 있어야 함). 사용자 맞춤 행 선택·강조 표현도 차단한다. 근거: RFP-21 §6.3.
- 2026-11-06 결정 반영(RFP-33-01~06 모두 A): 기준선 Validator는 기존 목록(안전 단정·복용 지시·등급값 등, RFP-22-08) 그대로이고, 하네스 문서의 출구 검사 두 가지(상태 불일치 문구, 제품 단정 패턴)는 **(개선)**으로 더했다(RFP-33-04 A: 관찰하지 않은 실패용 장치는 쌓지 않음). 개선 장치는 C3에만 한 번에 하나씩 더하고 조건표에 기록한다(RFP-33-03, AG-16).
- 2026-11-05 (RFP-31): 개발·테스트용 mock이 로컬 `data/mock/`(git 제외)에 있다. `data/mock/validator_pairs/`(220쌍: 통과 59·실패 161, 해로운 문장은 고정 템플릿)로 Validator 규칙을 테스트할 수 있다. 정규식 함정(`세포`가 `세`+`포`(용량)로 오탐)에 주의.
