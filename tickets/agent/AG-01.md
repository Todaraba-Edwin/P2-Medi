## 1. 이슈
2026-11-02 사용자 방침과 결정: MediAgent는 Agent-RAG이므로 **에이전트가 중심**이고 LangGraph로 구성한다(RFP-22-03 A). 이 티켓은 기준선 **ReAct 그래프**를 만든다. 핵심 루프는 `model` 노드와 `tools` 노드(`ToolNode`)를 `tools_condition`으로 잇는 것이다(실습 1-3과 같은 부품). 다만 이것은 강의 실습(도구 2개) 수준이다. MediAgent는 도구가 6개이고 입구·출구 안전 장치가 있어 실제 노드는 두 개보다 늘어난다. **노드 구성은 RFP-23-01에서 정하며**(6노드 안: `guardrail_in`·`router`·`model`·`tools`·`validator`·`finalize`) 이 티켓은 확정된 구성을 따른다. 개선용 부품(grade, sensor, 되돌림)은 실패를 본 뒤에 더한다(RFP-22-08). 도구 함수(AG-02·AG-03), 시스템 프롬프트, 모델 호출 상한을 연결하고, 앞뒤에 Guardrail 입력·출력 코드(AG-08)와 Router(AG-05)를 붙인다. 기준선 측정(AG-11) 뒤에 실패를 보고 노드·분기를 더하는 일은 AG-13의 (개선)이다. 이전 제목은 "LangGraph 그래프 골격·상태 정의", 그다음 "기준선 에이전트 조립(create_agent …)"이었다.

## 2. 완료 조건
- [ ] LangGraph `StateGraph`로 RFP-23-01에서 확정한 노드 구성(핵심 루프 `model` ⇄ `tools`, `tools_condition` 분기 포함)이 컴파일되고, 모델 `gpt-6-luna`에 도구 함수(AG-02·AG-03)와 시스템 프롬프트를 연결한 샘플 질문 1건이 도구를 호출해 근거가 붙은 답을 낸다. 도구 호출 경로(메시지 목록)가 결과에 남는다.
- [ ] 모델 호출 횟수 상한이 8회로 설정되어 있고(RFP-22-05 A), 상한에 닿으면 "호출 상한 종료"(안내 전환, RFP-33-06, PJ2-PRD.md 15.4절 상태 이름)로 끝난다. FR-08의 "근거 없음"과는 다른 종료다. 하네스 차단 메시지를 받고 다시 부르는 호출도 8회 안에 센다. 필수 도구를 빼먹었을 때 되돌림 횟수 2회는 (개선)에서 쓴다.
- [ ] (RFP-33-06) 상한에 닿아 끝날 때 `finalize`(AG-08)가 안내 전환 문구와 함께 **이미 나온 판정 항목**(`FOUND`·`NOT_LISTED`)을 코드 문구로 보이고, 판정하지 못한 항목은 "확인하지 못함"으로 둔다. 가짜 모델이 계속 호출하는 테스트로 8회 안에 끝나고 앞서 얻은 `FOUND`가 답에 남는지 확인한다(PJ2-Agent-Harness.md 4.1절 (h)).
- [ ] 에이전트(그래프) 호출 앞에 Guardrail 입력 코드(AG-08)가, 뒤에 출력 코드(고정 문구·119 최상단)가 연결되어 있고, 응급 신호가 있어도 호출이 막히지 않고 끝까지 흐른다.
- [ ] LLM 호출이 인터페이스로 분리되어 있어 모델 이름·제공자를 설정으로 바꿀 수 있다(평가 judge는 Claude Sonnet 5.5로 별도 호출, RFP-22-07·RFP-26-01).
- [ ] 도구 호출 기록(trace)은 개발·평가 모드(합성·가상 질문만)에서만 켜지고 서비스 모드에서는 꺼진다(RFP-22-06 A, PJ2-RFP.md 7장 로깅). 서비스 모드는 내용 없는 집계 지표만 남긴다(RFP-34-01 A, 구현은 BE-06 L4). 확인: `MEDIAGENT_MODE=service`로 돈 pytest에서 `logs/`에 trace 파일이 생기지 않는다(BE-15 개발 하네스).
- [ ] (개선) 종료 직전 sensor·관련성 판정 분기 노드를 더하고 필요한 노드·엣지를 추가한다(기준선 실패가 확인된 경우만, AG-13).
- [ ] (RFP-25-01·04) 기준선은 단일 ReAct 에이전트(L1)이고, **코드로 고정하는 불변식**(금기 판정, 고정 문구·119, Validator, 입구 거절, 호출 상한)이 LLM 노드 밖에 있어 LLM 출력으로 바뀌지 않음이 테스트로 확인된다. `router` 노드는 입력 정리만 하고 경로를 정하지 않는다(RFP-25-02).
- [ ] (RFP-33-04) **기준선 하네스 장치 5개**가 정해진 코드 위치에 있고 새 노드를 더하지 않는다(노드 6개·단일 `ToolNode` 유지, RFP-23 §4.2). ① 도구 출력 계약(항목별 상태·근거 ID·성분명 일치 시 제품 필드 제외·라벨 출처·API 병기 양방향): 도구 함수 안(AG-02·AG-03), ② 인자 스키마(Pydantic): 도구 함수 안, ③ `finalize` 항목별 문구·`FOUND` 먼저: `graph/nodes/finalize.py`(제안 경로, 구현 때 확정)(AG-08), ④ 도구 결과가 쓸 수 있는 상태 키 제한(`POST_WRITABLE_KEYS`, `emergency`·`route`·`profile`·`confirmed_mentions` 제외): `graph/state.py`(제안 경로, 구현 때 확정), ⑤ 사진 확인 선행(`inputs_confirmed` 기본 거짓, 음성은 사용자가 전송한 텍스트라 텍스트 경로): `guardrail_in`(사진·음성 구현 때). ⑤는 텍스트 입력에서 동작이 바뀌지 않으므로(텍스트 경로는 `inputs_confirmed` 참) SCH-03에 구현해도 텍스트 평가 세트의 `harness@v1` 동작은 같다. 구현 커밋은 결과 파일의 `graph_version`에 기록한다(PJ2-RFP.md 9.6절 측정 기간 동결). 이 목록은 기준선 측정(AG-11) 전에 `harness@v1`로 고정하고 C1·C1+·C2에 공통으로 적용한다(RFP-33-03). 개선 단계 장치(`known_ids`·단위 보조 차단·반복 경고, `harnessed_tools` 래퍼)는 여기 넣지 않는다(AG-13). PreToolUse 위반 중 안전·정합 규칙은 하드 차단(도구 미실행 + `[HARNESS]` 메시지), 효율 규칙은 경고만 기록한다(RFP-33-02, PJ2-Agent-Harness.md 3.6절).
- [ ] (RFP-33-04) 정상 경로 회귀: RFP-21 §4.8 골든 문항(P1~P3)을 가짜 모델 스크립트로 돌려 하네스 차단·경고가 0건이고 판정에 도달한다(`tests/e2e/`(제안 경로, 구현 때 확정), LLM 호출 없음).
- [ ] (RFP-34-02) **그래프 계측(L2)**: 로컬 JSONL 로깅 모듈(BE-15 L1)과 LangGraph 콜백/스트림으로 6노드 span, 도구 6개 자식 span, 토큰·지연, 하네스 이벤트(`harness_event`, 동작 `block`·`warn`·`flag`), LLM 캐시 상태(`llm_cache.py`)를 채운다. 외부 SaaS로 보내지 않는다(PJ2-Agent-로깅-전략.md 2장·5장).
- [ ] (PRD-16-01·03) 첫 프롬프트 `backend/prompts/agent_system@v1.md`를 `P2-doc/PJ2-프롬프트-설계.md` 6장 규칙(정적 프런트매터 `id`·`version`·`ticket`·`model`·`h_rules`·`golden_ids`(개발셋 ID만)·`status`, 평가 결과는 파일 밖 카드)대로 쓰고, **프롬프트 검토 카드(같은 문서 7장 다섯 칸)를 사용자가 승인한 뒤에만** 기준선에 연결한다(승인 전에는 `status: draft`). L0(정적 검사)·L1(가짜 모델 하네스 회귀)·L2(개발 골든 스모크, 개발 골든은 AG-04)를 통과한 결과를 카드에 적는다. 로그에는 묶음 이름 `prompt_set@vN`을 남긴다(BE-15).
- [ ] (RFP-26-05) 개발·평가 모드 trace에 도구 호출 순서·입력·**돌려받은 청크 ID**·모델 호출 수·종료 사유(정상/상한/안내 전환/오류)가 기록되어 경로 평가(코드)와 인용 청크 ID 검증이 이 기록만으로 가능하다. 서비스 모드에서는 꺼져 있다(RFP-22-06).
- [ ] (AG-01-01 A, 2026-11-10) **도구를 쓰는 에이전트 노드(`model`)는 Chat Completions + `reasoning_effort="none"`으로 호출한다.** 이 설정에서 `parallel_tool_calls` 옵션이 동작함은 BE-15 확인에서 봤다([BE-15 §5](../backend/BE-15.md#5-메모)). 추론을 끄면 도구 선택 품질이 달라질 수 있어 **기준선 측정(AG-11) 전에 도구 선택 정확도를 먼저 점검**(이행은 [AG-19](AG-19.md)가 맡는다)하고(개발셋·합성 질문만, 시험셋 열람 금지 RFP-26-04) 결과는 AG-19 §5에 적고 여기에는 확정 설정만 옮긴다.

## 5. 메모
- 2026-11-03 (RFP-25-01~04 권장대로 A): 기준선은 **단일 ReAct(L1)**, `router`는 입력 정리만, Supervisor는 도입 조건(RFP-25 §7.2)이 관찰될 때만. 자유도는 사다리(L2는 AG-13)로 늘리고 **금지선(판정·고정 문구·119·Validator·입구 거절·호출 상한은 코드)**은 어떤 단계에서도 유지한다. 근거는 RFP-25 §4~§7.
- 가정: LLM은 `gpt-6-luna`로 확정됐다(RFP-15-09, 2026-11-04). 모델 교체에 대비해 LLM 호출은 인터페이스로 분리해 둔다.
- 가정: 노드 이름은 RFP-23 §4.2 표(`guardrail_in`·`router`·`model`·`tools`·`validator`·`finalize`)를 따르고 PRD-02에서 실제 코드와 대조한다. 도구 6개는 단일 `tools` 노드에 등록한다(AG-02: `identify_drug`·`check_contraindications`·`get_label_section`, AG-03: `search_*` 3개).
- 응급 키워드 감지는 AG-08(Guardrail)의 코드 규칙 한 곳에서만 한다. 이 골격에서는 `emergency` 상태 필드와 병행 엣지만 정의하고, Router(AG-05)는 이 신호를 읽기만 한다.
- 2026-11-02 전체 점검: RFP-22-03(기준선 `create_agent` → 개선 LangGraph 직접 조립)이 정해질 때까지 착수를 보류한다. AG-02·AG-03·AG-05의 선행이 이 티켓이라, RFP-22-03 결정 뒤 "그래프 노드"가 아니라 "도구 함수"로 먼저 만들 수 있는지 선행 관계를 다시 본다(RFP-22 §10 제안 P2).
- 2026-11-02 계획 변경(사용자가 RFP-22 §10 P1~P4 승인): (P2) SCH-01 → SCH-02로 옮기고 제목·완료 조건을 "기준선 에이전트 조립"으로 바꿨다. 선행은 도구 함수(AG-02·03), Router(AG-05), Guardrail(AG-08)이다. 이전 가정(노드 이름 임시, 응급 병행 엣지)은 AG-13의 LangGraph 재조립 때 다시 정한다.
- 2026-11-02: 사용자 방향이 "프로젝트는 LangGraph로 구성"이라 이 티켓의 `create_agent` 표현은 RFP-22-03 결정(A 최소 ReAct 그래프 / B `create_agent`) 전까지 임시다. A로 정해지면 제목·완료 조건을 "기준선 ReAct 그래프 조립"으로 바꾼다.
- 2026-11-02 정정(사용자 지적, RFP-23): "최소 ReAct 그래프 = `model ⇄ tools` 두 노드"는 강의 실습 수준이다. 실제 노드 수와 구성은 RFP-23-01에서 정한다. 위 2026-11-02 RFP-22-03 결정 문장의 "최소"는 "개선 부품 없이 시작"이라는 뜻이다.
- 2026-11-02 RFP-22-03 결정(A): 기준선은 처음부터 최소 ReAct 그래프로 만든다. 이 티켓의 `create_agent` 표현은 모두 대체되었다.
- 2026-11-06 (RFP-33, 결정 대기): 도구 실행 전후 검사(PreToolUse·PostToolUse)를 새 노드가 아니라 `tools` 노드 안의 래퍼로 두는 안과 상태 필드 추가안이 [PJ2-Agent-Harness.md](../../P2-doc/PJ2-Agent-Harness.md) 3절에 있다.
- 2026-11-06 결정 반영(RFP-33-01~06·RFP-34-01~05 모두 A, 사용자 "권장대로"): 구현은 새 티켓 없이 기존 티켓 완료 조건으로 나눴다. 이 티켓에는 기준선 장치 5개의 코드 위치(RFP-33-04), 상한 도달 시 판정 표시(RFP-33-06), 그래프 계측 L2(RFP-34-02)를 더했다. Pre/Post는 기준선에서 도구 함수 안에 있고, 래퍼 노드 교체는 개선 단계(AG-13)에서만 하며 그때도 노드 수는 6개다.

- 2026-11-10 (AG-01-01 A, BE-15 `gpt-6-luna` 확인): 기본(추론 켬)에서 함수 도구는 `/v1/chat/completions`에서 HTTP 400이라 도구를 쓰는 노드는 `reasoning_effort="none"`(Chat Completions)으로 진행하기로 했다. 근거와 확인 결과: [BE-15 §5](../backend/BE-15.md#5-메모). **고칠 위치(이 티켓에서는 고치지 않음)**: `tickets/doc/RFP-15.md` §8, `P2-doc/PJ2-RFP.md` 8.2절의 모델·호출 방식 문구. 영향: 추론을 끈 상태의 도구 선택 정확도는 AG-11 전에 이 티켓에서 점검한다(위 완료 조건).
