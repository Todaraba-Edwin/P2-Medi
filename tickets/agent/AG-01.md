## 이슈
2026-11-02 사용자 방침: MediAgent는 Agent-RAG이므로 **에이전트가 중심**이다. 이 티켓은 가장 단순한 기준선 에이전트를 만든다. LangChain 1.x `create_agent`에 도구 함수(AG-02·AG-03)와 시스템 프롬프트, 모델 호출 상한을 연결하고, 앞뒤에 Guardrail 입력·출력 코드(AG-08)와 Router(AG-05)를 붙인다(RFP-22 (2)·(7), RFP-22-03). 기준선 측정(AG-11) 뒤에 실패를 보고 LangGraph로 재조립하는 일은 AG-13의 (개선)이다. 이전 제목은 "LangGraph 그래프 골격·상태 정의"였다.

## 완료 조건
- [ ] `create_agent`(모델 `gpt-6-luna`)에 도구 함수(AG-02·AG-03)와 시스템 프롬프트를 연결한 에이전트가 만들어지고, 샘플 질문 1건이 도구를 호출해 근거가 붙은 답을 낸다. 도구 호출 경로(메시지 목록)가 결과에 남는다.
- [ ] 모델 호출 횟수 상한이 설정되어 있고(RFP-22-05 초안 8회), 상한에 닿으면 "근거 없음/안내 전환"으로 끝난다.
- [ ] 에이전트 호출 앞에 Guardrail 입력 코드(AG-08)가, 뒤에 출력 코드(고정 문구·119 최상단)가 연결되어 있고, 응급 신호가 있어도 에이전트 호출이 막히지 않고 끝까지 흐른다.
- [ ] LLM 호출이 인터페이스로 분리되어 있어 모델 이름·제공자를 설정으로 바꿀 수 있다(평가 judge는 Claude Sonnet 계열로 별도 호출, RFP-22-07).
- [ ] (개선) LangGraph `StateGraph`로 ReAct 루프를 직접 조립하고 종료 직전 sensor·관련성 판정 분기를 넣는다(RFP-22-03, 기준선 실패가 확인된 경우만, AG-13).

## 메모
- 가정: LLM 확정(RFP-15) 전에는 LLM 호출을 인터페이스로 분리해 둔다.
- 가정: 노드 이름(contra_tool, guardrail 등)은 이 티켓에서 정한 임시 이름이며 PRD-02에서 실제 코드와 대조한다.
- 응급 키워드 감지는 AG-08(Guardrail)의 코드 규칙 한 곳에서만 한다. 이 골격에서는 `emergency` 상태 필드와 병행 엣지만 정의하고, Router(AG-05)는 이 신호를 읽기만 한다.
- 2026-11-02 전체 점검: RFP-22-03(기준선 `create_agent` → 개선 LangGraph 직접 조립)이 정해질 때까지 착수를 보류한다. AG-02·AG-03·AG-05의 선행이 이 티켓이라, RFP-22-03 결정 뒤 "그래프 노드"가 아니라 "도구 함수"로 먼저 만들 수 있는지 선행 관계를 다시 본다(RFP-22 (10) 제안 P2).
- 2026-11-02 계획 변경(사용자가 RFP-22 (10) P1~P4 승인): (P2) SCH-01 → SCH-02로 옮기고 제목·완료 조건을 "기준선 에이전트 조립"으로 바꿨다. 선행은 도구 함수(AG-02·03), Router(AG-05), Guardrail(AG-08)이다. 이전 가정(노드 이름 임시, 응급 병행 엣지)은 AG-13의 LangGraph 재조립 때 다시 정한다.
- 2026-11-02: 사용자 방향이 "프로젝트는 LangGraph로 구성"이라 이 티켓의 `create_agent` 표현은 RFP-22-03 결정(① 최소 ReAct 그래프 / ② `create_agent`) 전까지 임시다. ①로 정해지면 제목·완료 조건을 "기준선 ReAct 그래프 조립"으로 바꾼다.
