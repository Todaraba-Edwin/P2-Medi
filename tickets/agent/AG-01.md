## 이슈
RFP 8장 구조(Router → 공공 API Tool / 금기 조회 Tool / Vector DB 검색 / 안내 전환 → 답변 생성 → Validator)와 "응급 키워드: Guardrail이 119 안내를 답변 맨 위에 고정하고, 위 경로는 막지 않고 병행 실행한다"를 담을 LangGraph 상태와 빈 노드 골격을 먼저 만든다. 2주차 노드들이 이 골격에 들어간다.

## 완료 조건
- [ ] 상태 스키마(질문, 엔티티, 성분코드, 검색 결과, 출처 목록, 답변, 경로, 응급 여부 `emergency`)가 코드로 정의되어 있다.
- [ ] 노드 자리(router, api_tool, contra_tool, doc_search, guardrail, generate, validator, fallback)가 8장 구조도대로 연결된 그래프가 컴파일되고 더미 입력이 끝까지 흐른다.
- [ ] 응급 병행 엣지가 있다. 더미 입력에 `emergency=true`를 주면 guardrail이 119 안내 자리를 상태에 채우면서도 router 이후 경로(도구 호출 → generate → validator)가 막히지 않고 끝까지 흐른다.
- [ ] guardrail의 출력 쪽 자리(고정 문구 부착)가 validator 뒤에 있어, 모든 경로(안내 전환 포함)가 이 자리를 거쳐 끝난다.

## 하위 작업
- [ ] 상태 스키마(`emergency` 포함)
- [ ] 노드·엣지 골격(금기 조회 노드, guardrail 노드, 응급 병행 엣지 포함)
- [ ] 더미 실행 테스트(일반 / 응급 병행)

## 관련
- 선행: 없음
- 후속: AG-02(금기 조회 노드 연결), AG-05, AG-08
- 관련 문서: `P2-doc/PJ2-RFP.md` 8장

## 메모
- 가정: LLM 확정(RFP-15) 전에는 LLM 호출을 인터페이스로 분리해 둔다.
- 가정: 노드 이름(contra_tool, guardrail 등)은 이 티켓에서 정한 임시 이름이며 PRD-02에서 실제 코드와 대조한다.
- 응급 키워드 감지는 AG-08(Guardrail)의 코드 규칙 한 곳에서만 한다. 이 골격에서는 `emergency` 상태 필드와 병행 엣지만 정의하고, Router(AG-05)는 이 신호를 읽기만 한다.
