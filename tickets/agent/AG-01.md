## 1. 이슈
2026-11-02 사용자 방침과 결정: MediAgent는 Agent-RAG이므로 **에이전트가 중심**이고 LangGraph로 구성한다(RFP-22-03 A). 이 티켓은 기준선 **ReAct 그래프**를 만든다. 핵심 루프는 `model` 노드와 `tools` 노드(`ToolNode`)를 `tools_condition`으로 잇는 것이다(실습 1-3과 같은 부품). 다만 이것은 강의 실습(도구 2개) 수준이다. MediAgent는 도구가 6개이고 입구·출구 안전 장치가 있어 실제 노드는 두 개보다 늘어난다. **노드 구성은 RFP-23-01에서 정하며**(6노드 안: `guardrail_in`·`router`·`model`·`tools`·`validator`·`finalize`) 이 티켓은 확정된 구성을 따른다. 개선용 부품(grade, sensor, 되돌림)은 실패를 본 뒤에 더한다(RFP-22-08). 도구 함수(AG-02·AG-03), 시스템 프롬프트, 모델 호출 상한을 연결하고, 앞뒤에 Guardrail 입력·출력 코드(AG-08)와 Router(AG-05)를 붙인다. 기준선 측정(AG-11) 뒤에 실패를 보고 노드·분기를 더하는 일은 AG-13의 (개선)이다. 이전 제목은 "LangGraph 그래프 골격·상태 정의", 그다음 "기준선 에이전트 조립(create_agent …)"이었다.

## 2. 완료 조건
- [ ] LangGraph `StateGraph`로 RFP-23-01에서 확정한 노드 구성(핵심 루프 `model` ⇄ `tools`, `tools_condition` 분기 포함)이 컴파일되고, 모델 `gpt-6-luna`에 도구 함수(AG-02·AG-03)와 시스템 프롬프트를 연결한 샘플 질문 1건이 도구를 호출해 근거가 붙은 답을 낸다. 도구 호출 경로(메시지 목록)가 결과에 남는다.
- [ ] 모델 호출 횟수 상한이 8회로 설정되어 있고(RFP-22-05 A), 상한에 닿으면 "근거 없음/안내 전환"으로 끝난다. 필수 도구를 빼먹었을 때 되돌림 횟수 2회는 (개선)에서 쓴다.
- [ ] 에이전트(그래프) 호출 앞에 Guardrail 입력 코드(AG-08)가, 뒤에 출력 코드(고정 문구·119 최상단)가 연결되어 있고, 응급 신호가 있어도 호출이 막히지 않고 끝까지 흐른다.
- [ ] LLM 호출이 인터페이스로 분리되어 있어 모델 이름·제공자를 설정으로 바꿀 수 있다(평가 judge는 Claude Sonnet 계열로 별도 호출, RFP-22-07).
- [ ] 도구 호출 기록(trace)은 평가 모드에서만 켜지고 서비스 모드에서는 꺼진다(RFP-22-06 A).
- [ ] (개선) 종료 직전 sensor·관련성 판정 분기 노드를 더하고 필요한 노드·엣지를 추가한다(기준선 실패가 확인된 경우만, AG-13).
- [ ] (RFP-25-01·04) 기준선은 단일 ReAct 에이전트(L1)이고, **코드로 고정하는 불변식**(금기 판정, 고정 문구·119, Validator, 입구 거절, 호출 상한)이 LLM 노드 밖에 있어 LLM 출력으로 바뀌지 않음이 테스트로 확인된다. `router` 노드는 입력 정리만 하고 경로를 정하지 않는다(RFP-25-02).

## 5. 메모
- 2026-11-03 (RFP-25-01~04 권장대로 A): 기준선은 **단일 ReAct(L1)**, `router`는 입력 정리만, Supervisor는 도입 조건(RFP-25 §7.2)이 관찰될 때만. 자유도는 사다리(L2는 AG-13)로 늘리고 **금지선(판정·고정 문구·119·Validator·입구 거절·호출 상한은 코드)**은 어떤 단계에서도 유지한다. 근거는 RFP-25 §4~§7.
- 가정: LLM 확정(RFP-15) 전에는 LLM 호출을 인터페이스로 분리해 둔다.
- 가정: 노드 이름(contra_tool, guardrail 등)은 이 티켓에서 정한 임시 이름이며 PRD-02에서 실제 코드와 대조한다.
- 응급 키워드 감지는 AG-08(Guardrail)의 코드 규칙 한 곳에서만 한다. 이 골격에서는 `emergency` 상태 필드와 병행 엣지만 정의하고, Router(AG-05)는 이 신호를 읽기만 한다.
- 2026-11-02 전체 점검: RFP-22-03(기준선 `create_agent` → 개선 LangGraph 직접 조립)이 정해질 때까지 착수를 보류한다. AG-02·AG-03·AG-05의 선행이 이 티켓이라, RFP-22-03 결정 뒤 "그래프 노드"가 아니라 "도구 함수"로 먼저 만들 수 있는지 선행 관계를 다시 본다(RFP-22 §10 제안 P2).
- 2026-11-02 계획 변경(사용자가 RFP-22 §10 P1~P4 승인): (P2) SCH-01 → SCH-02로 옮기고 제목·완료 조건을 "기준선 에이전트 조립"으로 바꿨다. 선행은 도구 함수(AG-02·03), Router(AG-05), Guardrail(AG-08)이다. 이전 가정(노드 이름 임시, 응급 병행 엣지)은 AG-13의 LangGraph 재조립 때 다시 정한다.
- 2026-11-02: 사용자 방향이 "프로젝트는 LangGraph로 구성"이라 이 티켓의 `create_agent` 표현은 RFP-22-03 결정(A 최소 ReAct 그래프 / B `create_agent`) 전까지 임시다. A로 정해지면 제목·완료 조건을 "기준선 ReAct 그래프 조립"으로 바꾼다.
- 2026-11-02 정정(사용자 지적, RFP-23): "최소 ReAct 그래프 = `model ⇄ tools` 두 노드"는 강의 실습 수준이다. 실제 노드 수와 구성은 RFP-23-01에서 정한다. 위 2026-11-02 RFP-22-03 결정 문장의 "최소"는 "개선 부품 없이 시작"이라는 뜻이다.
- 2026-11-02 RFP-22-03 결정(A): 기준선은 처음부터 최소 ReAct 그래프로 만든다. 이 티켓의 `create_agent` 표현은 모두 대체되었다.
