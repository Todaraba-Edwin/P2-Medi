## 1. 이슈
RFP 5.1절 (2)의 **③ 근거 코퍼스**를 만든다. 대상은 (가) BE-04가 파싱한 고시 PDF 청크(조문·정의·별표), (나) 병용금기·임부금기·연령금기 파일의 사유·상세정보 청크(고유 조합만), (다) BE-12가 수집한 e약은요 문장 청크(효능·사용법·주의·상호작용)다. 청크마다 메타데이터(`layer`·`issuer`·`doc_type`·`notice_no`·`base_date`·`locator`·`ingr_codes`·`license`)를 붙여 Vector DB와 BM25에 적재한다. FR-03 필터 검색과 FR-04 조항 표기, retrieval 역할 B·C의 기반이다.

**적재 담당 분담(RFP 5.1절 (2))**: ① 판정 테이블 = BE-09, ② 제품·성분 사전 = BE-10, ③ 근거 코퍼스 = 이 티켓(BE-05). 이 티켓은 ③만 맡는다. 병용금기 JSON·임부금기·연령금기 CSV를 **판정용으로** 적재하는 일은 BE-09가, 제품명·성분명 사전은 BE-10이 맡는다. 이 티켓은 같은 파일에서 사유·상세정보 문장만 골라 청크로 만든다.

  - **약한 필터 후필터 문제**: `layer` 같은 선택도 낮은 필터를 HNSW 벡터 검색에 걸면 후필터라 결과가 0~2건으로 줄어든다(`ef_search` 100, 10질의 중 4개, `layer='L3'`는 0건 사례). `hnsw.iterative_scan`을 켜면 채워지나 L3는 평균 1.6~2.2초(최대 10.8초), L1은 54~163ms다. **검색 설계 규칙: 성분코드·품목기준코드 같은 강한 필터로 먼저 좁히고 검색하며, `layer` 단독 필터 벡터 검색은 피한다**(AG-03·AG-09에 반영, 문서 반영은 documents-writer 후속).
  - **DB→`CorpusIndex` 로더 미작성**: AG-03 도구는 본문·메타를 로컬 `CorpusIndex`(jsonl)에서 읽는다. 서버가 청크 본문을 쓰려면 DB에서 읽어 `CorpusIndex`를 만드는 로더가 필요하다(AG-03 후속·BE-06 서버 기동 시 1회 구성, 로컬 기준 약 3.5초).
  - **512차원 축소**: 벡터·HNSW가 1/3로 줄어 약 370MB로 추정한다(**미실측**, 필요 없어진 시험이지만 기록).
  - **롤백**: 사용자 지시가 있을 때만 `load_corpus.py --dsn-env SUPABASE_DB_URL --drop --yes`(`corpus_chunks`만 삭제). 이번에는 쓰지 않았다.
  - **미확인**: 컴퓨트 사양(RAM)·Pro 비활동 일시정지 면제 여부(Recap 0-2, BE-13 시연 전 점검에 연결).
  - **체크하지 않은 완료 조건과 이유**: ① 메타데이터 조건(연결 없는 제품 비율 미측정, `license` 일부 "확인 필요"·"미확인") ② 표 조건(허가 상세 표 청크 1,576개 중 821개 짝 확인 필요, UD 표 33개(24%), 선별·UD 표 처리 수준은 Recap 17) ③ BE-05-01 ④b(별표 1·3 인식 확인 미시험). 이 셋이 남아 BE-05는 done이 아니다.
- **표 깨짐 사례**: 허가 상세 용법용량 표는 XML `<PARAGRAPH tagName="table">` CDATA 안의 HTML이고, **한 셀에 `<p>`가 쌓인 표가 UD+NB 217개**라서 태그만 벗겨 이어붙이면 열 이름과 값의 짝이 사라진다(반코트린주 `크레아티닌청소율 반코마이신용량 100 90 80 … 1545 1390 …`). 구조 파서는 열 수와 같은 `<p>` 개수의 셀을 행으로 풀어 "크레아티닌청소율=100; 반코마이신용량=1545"를 만든다. 깨진 사례: 옴니파큐300주(열 이름이 빈 4열, 셀마다 쌓인 `<p>` 개수가 달라 풀리지 않아 값 여러 개가 이어 붙고 값이 빈 열 이름에 들어감)와 비지파크주(하위 제목 행 "1. 동맥투여"가 빈 값 행이 됨). 6행 묶음마다 열 이름은 반복되지만 **헤더 행이 여러 개이거나 하위 제목 행이 있는 표는 값 짝이 틀릴 수 있어** 샘플 검수 또는 표 단위 청크 폴백이 필요하다(어디까지 할지는 열린 질문, 결정 번호 없음). `sentence` 단위는 표를 평문으로 깨뜨려 최대 59,016자 청크(19개)가 3,000자에서 임베딩 입력이 잘린다. 별표 2 행은 열 이름이 청크 안에 있고(`row_hdr`) 짝 맞춤이 깨진 행은 없었다.
- **한계**: ① 질의가 합성이고 kw 스타일이 BM25에 유리하다. 일상어 질의는 칸당 n≤8~10이라 유의성을 주장하지 않는다 ② 샘플 코퍼스(40+40 등)의 방해 청크가 실제 규모보다 훨씬 적어 실제 적재 규모에서는 적중률이 더 낮을 수 있다(추론) ③ 용량은 추정이고 pgvector 실제 크기를 재지 않았다 ④ 별표 1·3과 고시 조문(조·호·목)은 시험하지 않았다 ⑤ `parent_id` 형식은 시험용(`eyak:{seq}:{field}` 등)이라 BE-05 확정 스키마와 맞추는 일이 남는다 ⑥ `ingr_codes`는 L2에만 채웠고 e약은요·허가 상세의 사전 연결은 하지 않았다 ⑦ 하이브리드가 BM25 단독보다 나쁜 칸도 있다(eyak 절+머리말 kw 12/15 vs 14/15, 임부·연령 성분 단위 26/30 vs 30/30). 실제 에이전트 질의(AG-03)로는 재지 않았다.
