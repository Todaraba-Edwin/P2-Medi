## 1. 이슈
약봉투 사진에서 약 이름 후보를 뽑는 변환 API다(확장, 권장). PRD-08-07 A(2026-11-06)로 1단계(`gpt-6-luna` + 확대 전처리 + 확인·수정 카드 + 허가정보 사전 후보, 자동 확정 금지)까지 구현하기로 했고, 비전 모델은 `gpt-6-luna` 하나다(PRD-08-06 A). 이 API는 **에이전트 그래프 앞의 변환 함수**이며 판정·설명·요약은 하지 않는다. 사용자가 확인 카드에서 승인한 뒤에만 기존 흐름(`identify_drug`부터)으로 들어간다(H19).

시험 근거(소표본, 유의성 주장 안 함): 같은 4장·같은 검수 정답·3회에서 확대 상품명 34/51, 사전 후보(top-5) 포함 35/51, 한 번이라도 맞힌 약 12/17, 개인정보 유출 0/24. 실존하는 다른 제품명을 `high` 확신도로 내는 경우가 있어 확신도는 화면 판단에 쓰지 않는다(PRD-08 §5.1, §11).

일정이 모자라면 확장이라 **가장 먼저 줄인다**(RFP 4장, PRD-08-07 A).

## 2. 완료 조건
- [ ] (PRD-08-07) `/ingest/image`(가칭) 엔드포인트가 이미지 1장을 받아 상품명·성분명(봉투에 있으면)·용량·제형 후보 목록만 JSON으로 돌려준다. 판정·설명·요약 필드는 응답에 없다.
- [ ] 이미지는 요청 처리 중 메모리에서만 쓰고 파일·DB·로그에 저장하지 않는다는 것을 테스트로 확인했다(PRD-08-04).
- [ ] 모델은 `gpt-6-luna`(Chat Completions + 이미지 data URL + JSON 스키마 strict, `temperature` 미지정)이고, 외부 AI 제공자는 OpenAI 하나이며 새 환경변수가 늘지 않는다(PRD-08-06).
- [ ] 긴 변을 1400px로 맞추는 확대 전처리를 서버 메모리에서 하며, 파일을 만들지 않는다. 이미지 형식·크기 검사를 코드가 한다.
- [ ] 출력 필드를 코드가 스키마로 제한하고 허용 밖 값은 버린다. 환자 이름·병원·약국·연락처 필드는 스키마에 없고, 응답에 나타나면 버린다는 단위 테스트가 있다. `strength_or_form`에 알약 색·모양 같은 값이 들어오면 버린다(PRD-08 §11 값 검증 후보).
- [ ] 모델의 확신도 값은 화면 판단(자동 선택·자동 확정)에 쓰지 않는다. 응답에서 확신도로 기본 선택을 만들지 않는다.
- [ ] 추출한 이름마다 허가정보 **전체** 상품명 사전(BE-10)에서 정확 일치/유사 후보 top-5를 함께 돌려주고, 후보에는 기본 선택이 없다. 추출 원문과 후보를 병기한다.
- [ ] 이름을 하나도 못 읽거나 모델 오류·거절·형식 오류가 나면 오류 응답이 아니라 "읽지 못함" 결과로 돌려주고, 화면이 텍스트 입력으로 이어갈 수 있다(PJ2-PRD.md 15.4절 인식 실패).
- [ ] 판정 도구(`identify_drug`·`check_contraindications`)는 이 API 안에서 호출되지 않는다. 확인 전 호출 차단은 AG-01의 H19(`inputs_confirmed`)가 맡고 이 API는 그 값을 만들지 않는다.
- [ ] (RFP-34-01) 서비스 모드 로그에 이미지·추출된 약 이름·프롬프트·모델 출력이 남지 않고 집계 지표(요청 수·지연·토큰·비용·오류 유형)만 남는다.
- [ ] (RFP-34-05) 비전 호출 비용이 개발 비용 상한 원장에 기록되고, 상한을 넘으면 호출이 멈춘다.
- [ ] 단위 테스트가 통과한다. 테스트는 합성·가상 이미지 또는 모의 응답을 쓰고 개인정보가 있는 실제 사진은 저장소에 넣지 않는다.
