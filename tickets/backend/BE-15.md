## 1. 이슈
BE-01이 골격·`/health`에 개발 하네스(RFP-29-01), `gpt-6-luna` 호출 확인(RFP-15 이관), LLM 호출 캐시 연결(RFP-32), 로깅 모듈·비용 원장(RFP-34)까지 쌓여 W1 첫 티켓으로 커졌다. 사용자가 2026-11-09 "권고를 따름"(★ 분할)으로 승인해 **개발 도구·계측·비용 통제**를 이 티켓으로 나눴다. BE-01의 골격(설정 모듈·`/health`) 위에서 만든다. 이 티켓에서 `gpt-6-luna` 호출 확인으로 1회 비용을 잰 뒤 비용 원장 상한(초안 2.5 USD)을 조정한다. OpenAI 크레딧이 $8로 빠듯하므로(schedule.md Recap) 시험 호출 수를 최소로 한다.

## 2. 완료 조건
- [ ] (RFP-15-09·24-03, 이관) **`gpt-6-luna` 호출 확인 스크립트**가 있고 결과가 RFP-15 §8·PJ2-RFP.md 9.7절에 기록되어 있다: 구조화 출력·병렬 도구 호출·임베딩 지원 여부, 1회 호출의 토큰·비용·지연·한도. 문제가 있으면 LLM 선택을 다시 정한다(결정 필요).
- [ ] (RFP-29-01 A) 개발 하네스가 있다: `pytest`(판정·Validator·guardrail·finalize 단위 테스트 틀, `backend/tests/fixtures/api/` 사용), `ruff`, pre-commit(`check_schedule.py` 실행·비밀 문자열/`.env` 커밋 차단·큰 파일 차단), Claude Code 훅(`.claude/settings.json`: 메인 세션 `.env` 읽기 deny). 프롬프트·도구 설명은 `prompts/`에 두고 파일 이름에 버전(`@v1`)을 붙인다. CI(GitHub Actions)는 만들지 않는다.
- [ ] (RFP-34-02) **로깅 모듈(L1)**: 로컬 JSONL(외부 SaaS 없음)로 `MEDIAGENT_MODE`(dev/eval/service, 기본 service)·span 스키마 `@v1`·필드 화이트리스트·모드 필터·비밀 마스킹·JSONL 쓰기를 둔다(PJ2-Agent-로깅-전략.md 4장). 단위 테스트(H13): 서비스 모드 레코드에 내용 필드가 남지 않음, 비밀 값 마스킹, `eval` 모드 ↔ `MEDIAGENT_EVAL=1` 일치.
- [ ] (RFP-34-01) **서비스 모드는 질문 원문·해시·약 이름·프로필·모델 출력을 쓰기 전에 버린다**(기록 직전이 아니라 레코드를 만들 때 제외). 남는 것은 내용 없는 집계 지표뿐이며 집계는 BE-06(L4)이 한다. 테스트로 확인한다.
- [ ] (RFP-34-03) **로그 위치·보관**: 로그는 로컬 `logs/`에만 쓰고 `.gitignore`에 `logs/`를 넣으며, pre-commit이 `logs/` 아래 파일의 커밋을 막는다. 개발 trace는 14일 뒤 지우는 정리 명령이 있고, 평가 trace는 결과 파일과 함께 발표(프로젝트 종료)까지 둔다. 서비스 모드는 앱이 따로 저장하지 않는다. **실제 사용자 질문을 개발(dev) trace에 넣지 않는다**는 규칙을 개발 하네스 문서(README 또는 `tests/` 안내)에 적는다.
- [ ] (RFP-34-05) **개발 비용 상한 원장(L5)**: `evaluation/mock_gen/_common.py`와 같은 구조의 원장으로 개발·디버깅 중 OpenAI 호출 누적 비용을 기록하고 상한(초안 **2.5 USD**)을 넘으면 실호출을 막고 `replay`만 허용한다. 평가 실행 몫은 따로 센다. 상한 값은 이 티켓의 `gpt-6-luna` 호출 확인으로 1회 비용을 잰 뒤 조정하고 바꾼 값과 이유를 메모에 적는다.
