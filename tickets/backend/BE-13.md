## 1. 이슈
사용자가 "PJ2는 배포되어야 한다"고 했다(2026-11-02). 방향은 프론트 Vercel, 백엔드(FastAPI) AWS 무료 인스턴스 1대, DB·벡터 저장소 Supabase Pro 플랜이다(2026-11-02 무료 플랜 결정을 BE-05-03 D, 2026-11-11로 변경, RFP 8장, RFP-15-06 확정 후). 이 구성을 올리는 일을 맡는 티켓이 없어서 3주차 후반의 최소 구성으로 만든다. 새 기능은 만들지 않고, 이미 동작하는 기준선·개선본을 외부에서 쓸 수 있게 연결하는 일이다.

## 2. 완료 조건
- [ ] (RFP-15-06, 이관) **배포 환경이 기록되어 있다.** 프론트(Vercel)·백엔드(AWS 무료 인스턴스 1대)·DB(Supabase) 구성, AWS 개설일·플랜·무료 제공 범위·기간, 인스턴스 유형·메모리, 서비스 간 HTTPS·CORS 방식, 환경변수(비밀키) 관리 방식을 `메모`에 적었다(RFP-15 §7).
- [ ] 백엔드(FastAPI)가 AWS 인스턴스에서 실행되고 `/health`가 외부에서 응답한다.
- [ ] 프론트가 Vercel에 배포되어 백엔드 `/chat`을 HTTPS로 호출하고, 쉬운 요약·근거 상세·고정 문구·119 안내가 화면에 보인다(CORS 설정 포함).
- [ ] Supabase(Postgres + pgvector)에 적재된 데이터로 배포 환경에서 질문 → 답변이 끝까지 동작한다.
- [ ] 키·비밀은 각 플랫폼의 환경변수로만 관리하고 저장소에 없다(RFP-12 점검 기준).
- [ ] (BE-09-03 A, 2026-11-10: BE-09 첫 조건에서 이관 — 비활동 1주 일시정지 대응. 적재 스크립트 재실행 복구는 BE-09에서 확인됨) 시연 전 점검 절차(Supabase Pro 플랜 유지 확인(2026-11-12 Recap 0-2: Pro는 비활동 일시정지 면제, 사용자 확인), 인스턴스 기동 확인)가 README(PRD-04)에 적혀 있다.
- [ ] AWS 무료 제공의 범위·기간과 Vercel 무료 플랜 한도를 확인해 `메모`에 기록했다.
- [ ] (BE-15-01) OpenAI 크레딧 잔액을 확인하고 배포·시연 호출 예산을 고려해 충전 여부를 정했다(결정과 이유를 `메모`에 기록). 사용자가 2026-11-10 충전 판단을 이 배포 단계로 미뤘다.

## 5. 메모
- 2026-11-03 (RFP-15 §7): 백엔드(FastAPI+LangGraph)는 AWS EC2 1대, Supabase 연결은 **Session pooler(IPv4)**(EC2는 IPv4, direct는 IPv6 기본). 브라우저(HTTPS)→백엔드는 HTTPS가 필요하다: ① 백엔드에 도메인·인증서(CORS 필요) ② Vercel rewrite 프록시(http origin 허용·제한 시간 미확인). 이 티켓에서 시험해 정한다. AWS 신규 계정은 6개월 뒤 계정이 닫히므로(공식 문서) 시연 직전에 기동하고 데모 영상을 남긴다. 확인 남음: 인스턴스 유형·메모리(FastAPI·LangGraph·BM25), Supabase 연결 수 제한.
- 가정: AWS 무료 인스턴스의 범위·기간, Vercel 무료 한도는 확인하지 못했다. 일정이 모자라면 데모는 로컬 실행 화면으로 대체하고 이 티켓을 축소한다(RFP 11장 "영상 또는 실행 화면"). 사용자와 정한다.
- 배포 대상 프론트는 Vercel에 배포하며(유지), 2026-11-12 FE-01-01로 프레임워크가 Vite + React 정적 SPA(RFP-15-07)에서 Next.js로 대체돼 정적 SPA 전제는 더 이상 쓰지 않는다. 백엔드 HTTPS·CORS는 이 티켓에서 확인하며, **Next 서버 측 프록시(`next.config` rewrites) 사용 여부는 FE-01 새 결정(FE-01-06)에서 정한다**(rewrites 사용 시 스트리밍 지속 시간 한도도 함께 점검).
- 2026-11-04 사용자 결정: **AWS 계정은 W3 시작 때 개설**한다(신규 Free Plan의 6개월 시계를 배포 직전에 시작하려고). 개설 때 개설일·플랜·EC2 인스턴스 유형과 크레딧 소모를 확인해 완료 조건의 "AWS 무료 제공의 범위·기간" 항목에 기록한다. 인스턴스 메모리(FastAPI·LangGraph·BM25)는 W2 중에는 로컬 메모리 사용량으로 어림한다.
- 2026-11-11 (BE-05-03 D 결정 완료·**결제 확인됨 2026-11-11**, 면제 여부는 2026-11-12 사용자 확인으로 갱신, 아래 2026-11-12 항목): Supabase Pro($25/월)로 올렸으므로 시연 전 점검의 "무료 비활동 1주 일시정지 깨우기" 조건이 달라진다. (옛 문구: 면제 여부 미확인, 실측과 공식 약관으로 확인 예정)(근거: [BE-05 §5](BE-05.md#5-메모) 2026-11-11 Pro 검토).
- 2026-11-11 (시연 전 점검 연결, 결정 번호 없음): BE-05 원격 실측에서 HNSW 1차 빌드가 `maintenance_work_mem` 512MB·병렬에서 `DiskFull: could not resize shared memory segment`로 실패해 컴퓨트 메모리 사양이 작다는 신호가 나왔다(사양은 미확인). 컴퓨트 사양(RAM)은 2026-11-11 확인(Micro 1GB), 비활동 일시정지 면제는 아래 2026-11-12 항목으로 확인됐다(Recap 0-2 종결). 위 시연 전 점검 조건(일시정지 해제·인스턴스 기동 확인)과 인덱스 재생성 규칙(`maintenance_work_mem` 128MB·병렬 0)을 이에 맞춰 고친다. 근거: [BE-05 §5](BE-05.md#5-메모) 원격 적재·용량 실측.
- 2026-11-12 (Recap 0-2 해소, 사용자 `0-2 일시정지 면제 예`): **면제(사용자 확인, Pro 유지 조건)**. 사용자 전달 문구: "Pro 플랜에 속한 프로젝트는 비활동을 이유로 자동 일시 정지되지 않는다. 이 보호는 프로젝트가 실제로 유료 플랜에 속할 때 적용된다. Pro 비용은 별도로 계속 청구될 수 있다." **출처는 사용자 전달이며 대시보드 직접 확인이 아니다.** 조건은 프로젝트가 Pro를 유지하는 것(BE-05-03 D)이다. 그래서 위 "일시정지 해제" 점검 항목은 Pro 유지 시 필요 없는 것으로 보되 시연 전 점검에 **"Supabase 프로젝트가 Pro 플랜에 속해 있는지 확인"** 한 줄을 넣는다(README, PRD-04). 아래 하위 조건에도 같은 줄을 더했다.
- 2026-11-16 **배포 리허설 W2로 당김(AG-13-01 A)과 AWS 계정 개설 W2 주말로 변경(BE-13-01 A)**: 배포를 W3 마지막에 처음 하면 실패 때 복구할 시간이 없어 W2에 리허설한다. 그래서 위 2026-11-04 결정("AWS 계정은 W3 시작 때 개설")을 **W2 주말(11-21~22)로 바꾼다**(§6). 이 티켓의 SCH 소속은 SCH-03을 유지한다. 평가 규칙(시험셋 열람 금지·측정 동결)은 영향이 없다.
