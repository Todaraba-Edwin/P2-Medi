## 1. 이슈
질문을 받아 LangGraph를 실행하고 답변·출처·조회 시각·고지를 JSON으로 반환하는 FastAPI 엔드포인트가 필요하다. 프론트와 평가 스크립트가 이 응답 형식을 공유한다. RFP FR-04·FR-06에 따라 쉬운 요약과 근거 상세를 분리하고, 코드로 붙이는 고정 문구와 응급 안내를 별도 필드로 둔다.

## 2. 완료 조건
- [ ] `POST /chat`이 질문을 받아 `summary`(쉬운 요약), `detail`(근거 상세), `citations[]`(출처·조회 시각 또는 자료 기준일·조항), `fixed_notice`(코드로 붙인 고정 문구와 "근처 약국·약사에게 확인" 안내), `emergency`(응급 여부와 119 안내), `disclaimer`, `route` 필드를 반환한다. `answer`는 요약과 상세를 합친 본문으로 함께 둔다.
- [ ] `fixed_notice`는 모든 응답(거절·근거 없음 포함)에 비어 있지 않고, `emergency`는 응급 키워드가 있을 때만 119 안내를 담는다.
- [ ] 빈 질문·과도한 길이 입력에 4xx를 반환한다.
- [ ] (PRD-07-01 A) 서버는 대화 상태를 **저장·로그하지 않고** 요청에 실린 값만 쓴다. 대화 상태는 요청의 한 입력 묶음으로 받는다(추후 서버 임시 보관 등으로 확장할 수 있게 분리).
- [ ] (RFP-34-01) **서비스 집계 지표(L4)**: 서비스 모드에서는 내용 없는 집계 지표만 분 단위로 남긴다(요청 수·지연·토큰·비용·오류 유형·종료 사유·하네스 규칙별 차단 건수). 질문 원문·해시·약 이름·프로필·모델 출력은 남기지 않으며, 앱이 따로 저장하지 않고 표준 출력으로만 낸다(RFP-34-03). 집계 레코드에 내용 필드가 없음을 테스트로 확인한다(H13).
- [ ] 엔드포인트 테스트가 통과한다.
- [ ] (PRD-01-02) 응급 신호가 있으면 `/chat` 응답이 **스트리밍의 첫 이벤트로 119 안내(`emergency`)를 먼저 보낸다**(LLM 호출 전, 입구 `guardrail_in` 코드). 이후 진행 상태 이벤트(약 찾는 중·금기 확인 중·근거 찾는 중)와 최종 답이 이어진다. 응답 시간 목표 수치는 RFP-15 측정 뒤 정한다.
- [ ] (PRD-09-05) `/chat` 응답 `findings[]`에 제품별 `ingredients[]`(성분코드·표시명·`contra_kinds`·`dup`)가 들어 있고 성분명으로만 식별한 약은 그 성분 하나만 담긴다.
- [ ] (PRD-10-02·04) 응답 `detail` 항목에 약 이름·항목명(상호작용·사용법 등)과 출처별 고시일 필드가 있어 화면이 출처 줄과 허가사항 원문 인용(약 이름·인용부호)을 코드 값으로 만들 수 있다. 원문 값이 비면 그 줄을 보내지 않는다.
- [ ] (PRD-11-02·03·05) 응답 `detail` 항목에 `source_kind`(`API_DIRECT`·`FILE`·`CORPUS_QUOTE`), 청크 ID, 조회 시각, 출처 표 행 키, 미확보일 때 `missing_reason`과 코드 상수로 렌더한 문구가 들어 있고 `LLM_SUMMARY`는 없다. `citations[]`는 출처 표 행(출처·자료·기준일·고시일, 1출처 = 1행, 파일·API 날짜가 다르면 각 행)이다. 미확보가 있으면 `fixed_notice`에 약사 확인 권고 한 줄이 포함된다.
- [ ] (PRD-12-01·02) `citations[]` 항목이 `publisher`(대그룹 = 출처 기관)·`dataset`(중그룹 = 자료)·`dates[{label, value}]`(한 날짜 = 한 항목, 라벨은 고시일·기준일·조회일 상수)를 갖고, 배열 순서가 PRD-12 §4.5(판정에 쓴 출처 기관 우선, 같은 기관 안은 판정 자료 → 허가사항 근거 자료)다. 파일·API 날짜가 다르면 각각 항목이다(PRD-09 G8). 필드 이름 최종안은 구현에서 정한다. (PRD-12-03) `dataset`은 근거 박스 표지의 자료 약칭과 같은 문자열이다(`DUR 성분정보 API`·`병용금기 파일`·`e약은요 쉬운 설명`·`의약품 허가정보` 후보).
- [ ] (PRD-14-01·02·04) `findings[]` 미식별 항목에 `input_name`(입력한 약 이름 그대로)·`searched[{dataset, count}]`·`retried`(재검색 여부)가 있고, 같은 응답의 식별된 약은 `status`·`ingredients[]`(PRD-09-05)로 한 줄 표시용 값을 가진다(제안, Harness 3.4절 `UNIDENTIFIED` 필드와 같음). `citations[].publisher`가 `삐약` 같은 서비스 이름이 아닌 공식 기관(식약처·한국의약품안전관리원 등) 값인지 코드가 검사한다.
- [ ] (PRD-15-01·02, 제안) `findings[]` 항목에 **순서 있는 배지 목록** `badges[{kind, grade, source}]`(`kind` = 병용·임부·연령, `grade` = 1·2·M 또는 없음, `source` = 파일·성분 API 또는 없음)가 있고 순서가 병용 → 임부 → 연령, 등급 불일치는 파일 → 성분 API다. 화면이 배지를 조합·재정렬하지 않고 문구는 AG-08 상수에서 온다. 파일·API 등급이 같으면 `source` 없이 한 개, 다르면 둘이다. 필드 이름 최종안은 구현에서 정한다. (PRD-15-03) 등급 정의 블록 항목에 `missing_reason`(`FETCH_FAIL`·`OUT_OF_SCOPE`)과 상수로 렌더한 문구가 들어 있고, 원문이 없으면 조항 출처 줄 필드를 보내지 않는다.
- [ ] (FE-01-07 B, 2026-11-12) `/chat`이 NDJSON 또는 SSE 스트림으로 **진행 단계·최종 응답·오류** 이벤트를 보내고, 이벤트 형식(이벤트 종류·필드·종료 신호)이 문서와 스키마로 고정돼 프런트 ky `response.body` 리더와 평가 스크립트가 같은 형식을 쓴다. 응급 119 첫 이벤트(PRD-01-02)와 같은 형식 안에 둔다.
- [ ] (BE-06-01 A, 2026-11-12) 병용 같은 쌍(A × B) 판정은 `findings[]`에 **쌍 항목을 새로 둔다**(제품 항목에 짝 필드를 두지 않고, 화면이 두 제품을 조합하지 않는다). 필드 이름 최종안은 구현에서 정한다.
- [ ] (BE-06-02 A) 응급은 `end_reason`에 값을 더하지 않고 **`emergency` 필드**로만 표현한다(금기 조회와 병행하는 별개 신호).
- [ ] (BE-06-03 A) 되묻기(CLARIFY) 후보는 응답의 **`candidates[]`**로 전달한다(별도 스트림 이벤트 아님).
- [ ] (BE-06-04 B) 용법용량은 표 구조 없이 **원문 인용 텍스트만** 보낸다(RFP-21-03 "원문 그대로 인용", 요약에는 용량 숫자를 쓰지 않음).
- [ ] (BE-06-05 A) 출처 표 행(`citations[]`)에 **고시 번호·판·쪽**을 넣는다(출처 표가 기준, PRD-12 §6).
- [ ] (BE-06-06 A) 상단 배너(API 실패) 자리는 **기존 `notice`** 필드를 쓰고 새 필드를 만들지 않는다.
- [ ] (BE-06-07 B) 응답에 **조회 시각 필드를 더하지 않고 날짜만** 둔다(시·분을 요구한 문서 없음, FE-07-06 A와 맞음).
- [ ] (BE-06-08 A, 2026-11-12) 날짜 값은 `YYYY-MM-DD` 또는 `YYYY-MM`(월 단위, 발간일 2025-11, FE-07-05 B)을 허용하고 없는 날(1일)을 지어내지 않는다. 날짜 라벨 상수에 `발간일`을 더한다(AG-08 `CITATION_DATE_LABELS`). `DateLine.value` 형식 확장과 라벨 상수는 BE-06·AG-08 구현 몫이다. 확인: `YYYY-MM` 값이 스키마 검증을 통과하고 `YYYY-MM-DD`는 그대로 통과한다.
- [ ] (FE-01-11 A, 2026-11-12) 백엔드가 `/openapi.json`을 노출하고 `ChatResponse`·스트림 이벤트 스키마가 거기 들어 있어 `openapi-typescript`로 타입을 만들 수 있다. 프런트는 Next.js rewrites 프록시(FE-01-06 A)로 호출하므로 CORS 설정이 필요 없음을 확인한다.

## 5. 메모
- 가정: `answer`를 유지할지 `summary`+`detail`로 완전히 대체할지는 RFP에 없다. 일단 호환용으로 `answer`를 남긴다. 중복이면 FE-02 구현 때 제거를 결정한다.
- 질문·대화 내용은 저장하지 않고 로그에도 남기지 않는다(RFP 7장 개인정보). 요청 본문을 로깅하는 미들웨어를 두지 않는다.
- 2026-11-02 계획 변경(사용자가 RFP-22 §13 P1~P4 승인): (P3) 기준선 측정(AG-11)의 선행이 아니다. 기준선(AG-11) 뒤에 착수하고, 일정이 모자라면 FE-01·02와 함께 SCH-03 앞부분으로 넘긴다(RFP 10장: 미달 시 다음 주 범위 축소).
- 2026-11-02 RFP-22-06 결정(A): 서비스 모드(/chat)에서는 trace를 켜지 않는다. 질문·대화 내용을 기록하지 않는 원칙과 맞춘다(RFP-22-06 A).
- 2026-11-06 결정 반영(RFP-34-01·03 A): 서비스 집계 지표(L4)를 완료 조건에 더했다. 로깅 모듈과 모드 필터는 BE-15(L1)가 만든다.
- 2026-11-05 (RFP-31): 개발·테스트용 mock이 로컬 `data/mock/`(git 제외)에 있다. `data/mock/chat_responses/`: `/chat` 응답 fixture 19건과 스트림 이벤트(S1~S8). **필드 모양은 mock 작성자의 가정**(BE-06에 없는 `summary_points` 등 포함)이라 이 티켓의 응답 스키마를 확정할 때 맞춘다. 평가 측정 값으로 쓰지 않는다.
- 2026-11-11 **야간 2차 N5: 응답 스키마 골격(지시서 n-be, 보고 `backend-architect.md`(로컬), schedule-writer가 보고에서 옮김)**: 신규 `backend/app/api/schemas.py`·`backend/tests/test_be06_schema.py`(13건), 가산 수정 `backend/app/tools/provenance.py`(`CITATION_DATE_LABELS`). 모델: `DateLine`(라벨 상수 고시일·기준일·조회·날짜 없음, 한 날짜 = 한 항목)·`Citation`(기관·자료 약칭·`dates[]`·`source_kind`·`evidence_ids`, 기관에 '삐약' 거부)·`DetailItem`·`Finding`·`Badge`·`Emergency`·`SentenceRef`·`Quote`·`ChatResponse`(`schema_version` `chat_response@v0`, `extra=forbid`, `fixed_notice` 최소 1줄·`disclaimer` 비어 있으면 거부). 변환은 `finalize` 출력의 `emergency`·`entries`→`findings`·`badges`·`detail`(+ 기관·약칭·날짜 줄)·`citations`(기관·자료마다 한 행, 날짜 합집합, 판정 자료가 있는 기관 먼저)·`fixed_notice`(미확보가 있으면 약사 확인 권고가 앞)를 옮기고 `events`·`warnings`·`text`는 싣지 않는다. **PRD-12·AG-08-03 B 표현 시험**: P3 출처 표가 PRD-12 §4 목업과 같은 행·날짜·순서, 병용 07-31과 임부 07-21 기준일을 자료마다 따로, 조회 시각 KST 날짜 변환, 날짜 없는 근거는 `날짜 없음`. **미완(완료 조건 미체크)**: 엔드포인트·그래프 호출 연결·오류 처리, 완료 조건의 `findings[].ingredients[]`(PRD-09-05, `finalize.entries`에 값이 없어 골격 범위 밖), 스트리밍 첫 이벤트 119. **가정(BE-06 본 작업 때 확정 필요)**: `fixed_notice`를 문자열이 아니라 줄 목록으로 정했고, 자료 키가 없는 근거(고시 조문 청크)는 출처 문자열이 공식 기관명으로 시작할 때만 출처 표에 넣는다. 참고: `provenance.DATE_LABELS`("자료 기준일"·"조회 시각", 사용처 없음)와 PRD-12 라벨("기준일"·"조회")이 달라 응답은 새 `CITATION_DATE_LABELS`만 쓴다(옛 상수 정리는 AG-02 쪽 판단). 선행 AG-05·06·07·08·09가 아직이라 이 티켓은 착수 전 상태다.
