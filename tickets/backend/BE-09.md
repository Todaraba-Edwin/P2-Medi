## 1. 이슈
RFP 8장 구조도에 "금기 조회 Tool (적재 데이터, 성분코드 일치)" 경로가 있고, RFP 5.1절 (2)는 적재 결과를 세 저장소로 나눈다. 이 티켓은 그중 **① 판정 테이블**을 만든다. 한국의약품안전관리원(KIDS) 병용금기 JSON, 임부금기 CSV, 연령금기 CSV를 적재하고(핵심), 확장으로 용량주의 CSV, 수유부주의 CSV, 심평원 노인주의 품목리스트 2종을 같은 판정 테이블에 넣어, 성분코드 정확 일치로 조회하는 도구를 만든다. 판정은 성분코드 정확 일치이고(RFP-17 결정 1), RAG는 판정을 하지 않는다. 적재소는 RFP-15에서 정한다(Supabase Postgres가 후보).

**적재 담당 분담(RFP 5.1절 (2))**: ① 판정 테이블 = 이 티켓(BE-09), ② 제품·성분 사전 = BE-10, ③ 근거 코퍼스(고시 PDF 청크, 사유·상세정보 청크, e약은요 문장 청크) = BE-05. 이 티켓은 ①만 맡는다. 사유·상세정보 문장을 청크로 만드는 일은 BE-05가 한다.

## 2. 완료 조건
- [ ] (RFP-15-03, 이관)  [2026-11-09: 이 티켓의 완료 조건으로 진행, 새 스크립트 없음] 판정 테이블의 적재 크기가 Supabase 무료 한도(DB 500MB)에 들어가는지 실측해 `메모`에 적었다(성분 쌍 23,619쌍과 제품 쌍 512,464건 중 무엇을 적재할지 포함). 비활동 1주 일시정지 대응(시연 전 깨움)과 적재 스크립트 재실행으로 복구 가능함을 확인했다.
- [ ] 병용금기 JSON(스트리밍 처리, 약 540MB)과 임부금기 CSV(CP949)가 RFP-15에서 정한 저장소의 판정 테이블에 적재되고, 적재 스크립트를 재실행해도 중복이 생기지 않는다.
- [x] 연령금기 CSV(CP949)가 적재되고, 판정 키는 성분코드 + 특정연령·단위·처리조건이다. 연령 값을 넣으면 해당 성분의 연령 금기 여부와 상세정보 원문이 반환된다(RFP 5.1절 (1), 연령금기 1차는 파일).
- [x] (확장, 권장, 적재·조회 로직 구현, 실 DB 적재는 BE-09-02 대기) 용량주의약물 CSV(일반명코드 키), 수유부주의 CSV(주성분코드 키), 심평원 노인주의 품목리스트 2종(성분코드 키)이 판정 테이블에 적재되고, 성분코드를 넣으면 주의 여부가 반환된다. 핵심(병용·연령·임부)의 완료 조건을 채운 뒤에 하며, 일정이 모자라면 RFP 4장 순서(수유부·노인 주의 → 중복·용량)로 줄인다.
- [ ] (확장, 권장) 심평원 병용·연령·임부 금기 품목리스트 3종(교차 점검용)이 KIDS 파일과 함께 읽혀, 같은 성분코드 기준으로 다르면 한쪽을 확정하지 않고 두 결과를 기준일과 함께 보이는 점검 결과가 만들어진다(RFP-17 결정 3).
- [x] 모든 CSV는 CP949로 읽어 UTF-8로 바꿔 적재하고, 큰 파일(병용금기 JSON, 심평원 병용금기 CSV 약 255MB)은 한 번에 읽지 않고 행 단위로 처리한다.
- [x] 적재 단위(성분코드 기준 약 23,619쌍 / 성분명 기준 약 2,106쌍)를 정하고 이유를 `메모`에 기록했다. 판정은 성분코드 정확 일치로 한다(RFP-17 결정 1).
- [x] 성분코드 2개를 넣으면 병용금기 여부, 금기사유, 고시번호, 기준일(2026-07-21)이 반환된다.
- [x] 성분코드 1개를 넣으면 임부금기 여부와 금기등급(1·2·M), 상세정보 원문이 반환된다.
- [x] 금기등급 M 레코드는 등급을 M 그대로, 상세정보를 원문 그대로 반환하고 1·2로 환산하지 않음을 테스트로 확인했다(RFP-17의 M 처리 규칙).
- [x] 조회 결과에 출처(한국의약품안전관리원 또는 건강보험심사평가원)와 파일별 기준일이 포함된다(KIDS 2026-07-21, 수유부주의 2025-11-27, 심평원 품목리스트 2026.6, RFP 5.1절 (5)).
