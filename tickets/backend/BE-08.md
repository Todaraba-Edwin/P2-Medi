## 1. 이슈
RFP 7장 재현성: 같은 평가 세트로 개선 전후를 반복 측정할 수 있어야 한다. 세트를 읽어 에이전트를 실행하고 결과를 버전별로 저장하는 스크립트가 필요하다.

## 2. 완료 조건
- [ ] 명령 한 줄로 평가 세트 전체를 실행하고 결과 파일(질문·답변·검색 컨텍스트·정답)을 저장한다.
- [ ] 결과 파일명에 실행 일시와 설정 식별자가 들어간다.
- [ ] 같은 설정으로 2회 실행했을 때 입력 세트가 동일함을 확인했다.
- [ ] 평가는 파일 기준으로 실행한다. 평가 모드에서는 API Tool(DUR·e약은요 런타임 호출)을 끄고, 결과 파일의 설정 식별자에 "API 끔"이 기록된다(RFP 5.1절 (7)). 파일 기준일(2026-07-21 등)도 결과에 함께 저장한다.
- [ ] 파일 판정과 API 응답의 일치율은 평가 점수와 별도 관찰값으로 기록한다. 데모·실제 질문에서 API를 켠 소규모 실행으로 얻고, 평가 지표 계산에는 섞지 않는다.
- [ ] 설정으로 에이전트 필요성 비교 조건(C0 LLM 단독 / C1 고정 파이프라인 기본·C1+ 강화(AG-16) / C2 ReAct 에이전트 / C3 개선 후 확장 자유도(AG-13), RFP-23·RFP-25. C4 Supervisor는 조건부 확장)과 API 끔을 전환하고, 같은 질문 N회 반복 실행(`pass^3`)을 돌릴 수 있다. 기존 보조 세 조건(LLM 단독 / 규칙·조회만 / 전체)도 선택으로 전환할 수 있고, 어느 조건으로 실행했는지 설정 식별자에 기록된다. "규칙·조회만"은 근거 코퍼스 검색(역할 B·C)만 끄고 사전(역할 A)과 Validator는 켠다.
- [ ] 코드 채점 함수가 있다: 금기 판정 정답률(구조화 필드·등급값 대조), 안전 응답률의 고정 문구·119·안전 단정 검사, 경로 평가(필수·불필요 도구 호출, 호출 수). 정의는 PJ2-RFP.md 9.3·9.4절을 따르고 judge(온도 0)는 의미 판단 항목(루브릭 J1~J5: Faithfulness·Context·오정보 정정·범위 외 거절·근거 없음 응답)에만 쓴다.
- [ ] 결과 파일에 e약은요 스냅샷 수집일, 색인 버전, 임베딩 모델, LLM 온도를 함께 기록한다(재현성).
- [ ] (RFP-26) judge 실행기가 있다: `claude-sonnet-5-5`·온도 0·블라인드(조건 이름 비공개)·루브릭 J1~J5(RFP-26 §7.5) 프롬프트를 버전과 함께 읽고, 구조화 JSON을 받아 항목별 pass와 이유·근거 ID를 저장하며, 형식 오류 1회 재시도·"judge 오류" 집계·호출 수·토큰 기록을 한다. 개발셋·시험셋을 선택해 실행할 수 있고 시험셋 실행은 기록에 남는다. 사람 라벨과 judge 결과의 항목별 일치율·κ를 계산하는 보정 스크립트가 있다.
