## 1. 이슈
> **2026-11-18 밤 사용자 결정으로 바뀜(PRD-01-09, 아래 §6·§5)**: 2026-11-03의 "소셜 로그인(SNS 연동)은 이 프로젝트에서 다루지 않는다"를 **대체**한다. 소셜 로그인은 **Google·Kakao(S1)·Naver(S2, 연동 방식 확인 뒤)**이고 **Apple은 제외**한다(Apple Developer Program이 유료). 프로필은 이메일 계정과 소셜 계정 모두 Supabase Auth로 서버에 저장한다(PRD-01-05 B는 저장 방식으로 유지).

RFP FR-09(확장, 권장): 첫 시작 때 프로필(연령대, 임신 여부, 복용 중인 약 등 선택 입력)과 저장 동의를 받고, 계정(이메일·소셜)을 만들어 프로필을 저장·수정·삭제한다. 로그인 없이도 핵심 기능은 모두 쓸 수 있어야 한다. Supabase Pro 플랜(Auth)을 쓴다(BE-05-03 D).

이 티켓은 **확장(권장)** 이지만 **2026-11-18 밤 AG-10-06 A로 축소 대상에서 빠져** W2~W3(스프린트 S1~S3, RFP-30-08 A) 범위가 됐고 Agent 트랙과 병렬로 한다. 응급 상황을 위해 게스트 경로는 그대로다. 필수 임계 경로(AG-13 개선·재측정)를 늦추면 안 되므로 `backend/app/agent`는 건드리지 않는다.

## 2. 완료 조건
> **상세 재작성은 후속이다(2026-11-18 밤 늦게 설계 문서 `P2-doc/PJ2-계정-프로필-데이터.md` 966줄 도착, 7장 완료 조건 초안 있음)**: 새 결정 BE-11-06~19에 답이 오면 그 초안을 이 절에 반영해 다시 쓴다(결정에 따라 RLS 방식·구간·시험 환경이 바뀐다). 아래는 2026-11-18 밤 결정으로 바뀐 줄만 정정한 상태이며, 정정하지 않은 줄은 옛 기준(본인 + 가족 1명 등)이 남아 있을 수 있다.

- [ ] (AG-10-06 A로 바뀜) 스프린트 S1(인증, 11-19~20)에 착수했고, 핵심 필수 티켓(Router·Citation·Validator·Guardrail·근거 없음 처리·/chat·평가 스크립트·기준선 측정)의 진행을 막지 않았다. 미달 시 가장 먼저 줄이는 것은 Naver(S2)·가족 프로필이다.
- [ ] (PRD-01-09) **이메일 가입·로그인**(Supabase Auth, PRD-01-05 B)과 **소셜 로그인 Google·Kakao**(S1)가 동작한다. **Naver는 S2**(연동 방식 확인 뒤), **Apple은 제외**. 이메일 인증 메일·비밀번호 재설정의 발송 방식과 한도는 확인해 `메모`에 적는다(미확인).
- [ ] (BE-11-01 B) 프로필 테이블에 **본인 + 가족 구성원 최대 3명**(구성원마다 관계 칸)이 저장되고, 행 수준 보안(RLS)으로 **본인 계정만** 읽고 수정·삭제할 수 있음을 다른 계정으로 시험해 확인했다. (본인 포함 여부는 설계 문서에서 확정, 가정 §5)
- [ ] (BE-11-04 A) 계정 탈퇴 시 서버의 프로필·복용 약이 **즉시** 지워지고, 동의 기록만 식별자를 제거한 뒤 보관한다. 보관 기간은 헬스케어 일반 관행·법 조사 뒤 확정하며 즉시 삭제도 검토한다(§5). 프로필 삭제도 실제로 지워짐을 시험한다.
- [ ] (BE-11-02 A) 약관·동의 문구를 DB에서 관리하고 프런트는 API로 받아 표시한다. 저장 전에 동의 여부와 동의 시각이 기록된다.
- [ ] (BE-11-03 A) 건강 정보(임신 여부·복용 약 등) 저장은 **별도 선택 동의**가 있을 때만 한다. 동의하지 않아도 계정 로그인은 된다.
- [ ] (BE-11-05 A) 복용 중인 약은 사용자가 입력한 **원문**과 식별된 경우 `item_seq`를 함께 저장한다.
- [ ] 프로필 저장·조회·수정·삭제 API가 동작한다.
- [ ] 저장하는 항목이 동의한 프로필(연령대·임신 여부·복용 중인 약 등)과 로그인 최소 정보(이메일 또는 소셜 식별자)뿐임을 스키마로 확인했다.
- [ ] 질문·대화 내용이 DB에도 로그에도 남지 않음을 확인했다(`/chat` 경로 점검).
- [ ] 로그인 없이(게스트) `/chat`을 호출하면 아무것도 저장되지 않고 핵심 기능이 동작한다.
- [ ] 서비스 롤 키가 브라우저(프론트)로 노출되지 않고, 키와 URL은 환경변수 이름으로만 문서에 적혀 있다.
- [ ] 로그인한 사용자의 프로필(연령대·임신 여부)이 Router 엔티티의 입력으로 전달되는 경로가 테스트로 확인된다. (`backend/app/agent` 변경이 필요하면 Agent 트랙과 파일 소유를 나눈다)
