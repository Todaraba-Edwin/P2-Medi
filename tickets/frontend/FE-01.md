## 2. 완료 조건
- [ ] 질문 입력 → `/chat` 호출 → 답변 표시가 동작한다.
- [ ] 로딩·오류 상태가 표시된다.
- [ ] (PRD-07-01 A) 같은 대화 안의 상태(이미 말한 나이·임신 여부, 되묻기 후 재질문)는 **브라우저 메모리에만** 두고 새로고침하면 사라진다. 요청마다 필요한 값만 보내며, **저장 위치를 바꿔 끼울 수 있게 대화 상태를 하나의 입력 묶음으로 분리**한다(3주 범위의 결정, 추후 확장 고려).
- [ ] (RFP-24-04) 휴대폰 화면 폭(360px 안팎)에서 질문 입력·답변 요약·근거 상세 펼침이 가로 스크롤 없이 쓰인다.
- [ ] (PRD-06-02) 병아리 마스코트는 시작·로딩·빈 상태·오류 같은 보조 자리에만 쓰고(작은 크기의 되묻기 카드 가능), 응급(119)·금기 결과·"금기 목록에 없음"·고정 문구 영역에는 쓰지 않는다. 화면의 표시 이름은 Can I PPiyak(한글 삐약 병기)이다(PRD-06-01).
- [ ] (FE-06-01) favicon·앱 아이콘은 로고의 캡슐 말풍선 심볼(병아리 없음)이고, 시작 화면은 질문 병아리(메인 이미지) + 로고로 구성한다. Agent 도구 호출 중 진행 표시에는 돋보기 병아리를 쓰되 119 안내·금기 결과가 나오면 숨긴다. 서비스 이름은 헤더에서 텍스트로 표시한다(이미지 글자는 정적 브랜딩 자리만).
- [ ] (PRD-09-07) 결과 카드 한 줄에 병용금기와 임부금기가 모두 해당하면 종류별 배지 2개가 나란히 보인다(색·글자 규칙은 FE-02의 PRD-09-07·08 조건과 PRD-09 G14·G15).
- [ ] (PRD-01-02) 응급이면 119 안내가 답변이 오기 전에 맨 위에 먼저 보이고, 일반 질문은 진행 상태(약 찾는 중·금기 확인 중·근거 찾는 중)가 표시된다.
- [ ] (PRD-09-01·05, §7.1) 결과 카드의 표지는 `삐! 임부금기 {N}등급`(M이면 `M등급`)이고, 그 아래에 주성분 칩 줄(`금기 원인`·`중복` 글자 상태)과 `근거: 임부금기 고시`를 두며 등급은 표지에만 쓴다. 병용금기는 두 제품의 원인 성분 칩에 `병용금기 원인`을 붙이고 줄 아래에 `{성분A} + {성분B}`를 적는다. "목록에 없음" 항목은 `임부금기 목록에 없음` + "안전하다는 뜻은 아니에요"를 유지한다.
- [ ] (PRD-10 §5.2) 결과 카드에 "자료 날짜가 달라 둘 다 보여 드려요 …" 줄을 두지 않는다(날짜는 근거 상세의 출처 줄에서만 보인다. 구현하며 이 방침이 맞는지 확인하고 다르면 PRD-10 §5.2를 고친다).
- [ ] (PRD-11-05·03) 결과 카드의 근거 요약 문구가 출처 종류 표지 규칙(PRD-11 §7.2)과 모순되지 않는다(쉬운 설명을 "허가사항 원문"이라 부르지 않고, 미확보 항목을 "없음·안전"으로 읽히게 쓰지 않는다). 미확보 항목이 있는 결과 카드에도 약국·약사 확인 권고가 접히지 않는 영역에 보인다(가정: 문구·위치는 FE-02와 함께 확정).
- [ ] (PRD-14-03, §5.4) 미식별 결과 카드 아래 `이름 다시 입력`(1차)·`약 사진 올리기`(2차)가 시작 화면 시나리오 칩(`이렇게 물어보세요 · 눌러서 시나리오 확인`)과 같은 크기·폰트로 한 줄에 나란히 놓이고, 360px에서 줄바꿈되며 가로 스크롤이 없고 터치 영역은 44px 이상이다. px·글꼴·색은 디자인 세션 확정이다(문서에 값 없음). FE-05가 없으면 `약 사진 올리기`는 그리지 않는다. 화면 시험은 [PRD-14 §6](../doc/PRD-14.md#6-화면-시험) ⑤⑥.
- [ ] (PRD-15-01·02, §5.8) 결과 카드 제품 줄도 **같은 배지 규칙**을 쓴다: 제목(제품명)이 먼저 전체 폭을 갖고 단어 단위로만 줄바꿈하며, 배지는 제목 옆에 다 들어가면 같은 줄에, 아니면 제목 아래 줄에 가로로 나열하고 넘치면 배지 단위로 줄바꿈한다(폭별 분기 코드 없이 한 규칙, `flex-wrap`). 배지가 잘리거나 제목이 한 글자 폭으로 쪼개지지 않고 360px·320px에서 가로 스크롤이 없다. 등급 불일치는 파일·성분 API 배지 둘이다(FE-02와 같은 `badges[]` 값). 병용 쌍 두 개에 걸린 제품은 배지를 종류당 1개로 둔다(제안, 착수 때 확인). 화면 시험은 [PRD-15 §7](../doc/PRD-15.md#7-화면-시험) ①~⑥.
- [ ] (FE-01-05 A) `frontend/`가 Next.js App Router 구조이고 채팅은 클라이언트 컴포넌트, 정적 안내·약관만 서버 컴포넌트다. 빌드(`pnpm build`)가 통과한다.
- [ ] (FE-01-06 A) `next.config`의 rewrites로 `/api/*`가 백엔드로 프록시되고 커스텀 Route Handler가 없다. 브라우저에서 백엔드로 가는 직접 호출(CORS)이 없다.
- [ ] (FE-01-07 B) ky `response.body` 리더로 NDJSON·SSE 이벤트(진행 단계·최종 응답·오류)를 소비하며, 이벤트 소스를 한 모듈로 추상화해 fixture·MSW로도 같은 인터페이스를 쓴다. 이벤트 형식은 BE-06과 묶어 정한다.
- [ ] (FE-01-08 A) Zustand `persist` 미들웨어를 쓰지 않고, 대화·질문·응답은 `sessionStorage`·`localStorage`에 쓰지 않는다(UI 설정만 `localStorage` 허용). 코드 검색 또는 테스트로 확인한다.
- [ ] (FE-01-09 A) shadcn/ui·Radix는 Dialog·Sheet·Accordion·Tooltip에만 쓰고 결과 카드·배지는 직접 만든 컴포넌트다.
- [ ] (FE-01-10 A) 디자인 색·간격이 Tailwind v4 CSS 변수로 정의돼 있고 다크모드 스타일이 없다.
- [ ] (FE-01-11 A) 백엔드 `/openapi.json`에서 `openapi-typescript`로 만든 타입을 쓰고, 응답을 `zod`로 런타임 검증하며 어긋나면 오류 상태로 표시한다.
- [ ] (FE-01-12 A) pnpm·Node LTS·TypeScript strict·ESLint(`jsx-a11y`)·Vitest·Testing Library·Playwright 스모크·MSW가 설정돼 있고 `pnpm lint`·`pnpm test`가 통과하며 mock만으로 LLM 호출 없이 화면이 돈다.
