## 1. 이슈
약봉투 사진과 마이크로 질문을 넣는 입력 화면이다(확장, 권장). PRD-08-07 A(2026-11-06)에 따라 비전이 뽑은 제품명·성분명은 **사용자에게 확인을 요청하고 사용자가 승인한 뒤에만** 다음 단계로 간다. 음성은 브라우저 음성 인식으로 글자를 입력창에 채우고 사용자가 확인한 뒤 보낸다(PRD-08-03 A). 화면 상태와 시나리오는 `P2-doc/PJ2-PRD.md` 15.3절 S11·S12, 15.4절 화면 상태 13~19번이다.

일정이 모자라면 확장이라 **가장 먼저 줄인다**. 줄이면 화면에서 이 입력이 빠지고 텍스트 입력만 남는다(PJ2-PRD.md 15.4절).

## 2. 완료 조건
- [ ] (PRD-08-07) SCH-02 핵심(AG-11 기준선)이 끝난 뒤 착수했다. 미달 시 이 티켓은 제외한다.
- [ ] 사진 올리기 화면에 **개인정보 가림 안내**("환자 이름·병원·약국은 가려도 됩니다", 사진은 저장하지 않음)와 외부 AI 전송 고지(사진 포함, 제공자는 OpenAI 하나)가 올리기 위에 접히지 않고 보인다(PRD-08-04, PRD-07-02).
- [ ] 인식 중(진행 표시), 인식 실패("약 이름을 읽지 못했다" + 다시 찍기·텍스트 입력), 음성 듣는 중(멈춤 버튼), 음성 미지원 화면 상태가 각각 나온다.
- [ ] **확인·수정 카드**가 추출한 상품명·성분명 목록을 세로로 보여 주고, 항목별 수정·삭제와 "약 추가"가 동작한다. 추출 원문과 허가정보 사전 후보를 병기하며 **기본 선택이 없다**(PRD-08-06, PRD-08-07).
- [ ] (FE-06-01) 확인·수정 카드의 약 항목에는 캡슐 말풍선 아이콘을 쓰고, 사진 "인식 중" 진행 표시에는 돋보기 병아리를 쓸 수 있다(판정·결과 표시 전에는 사라진다).
- [ ] 사용자가 "이대로 확인"을 눌러 승인하기 전에는 `/chat` 호출이 일어나지 않는다. 승인된 목록만 다음 단계로 전달한다(H19).
- [ ] 모델 확신도를 화면에 근거로 쓰거나 자동 선택에 쓰지 않는다.
- [ ] 브라우저가 음성 인식을 지원하면 마이크 버튼이 있고, 인식된 글자가 입력창에 채워진 뒤 **자동 전송되지 않으며** 사용자가 고치고 보낸다. 미지원 브라우저에서는 마이크 버튼이 숨고 "글자로 입력해 주세요" 안내가 나온다.
- [ ] (RFP-35-03) 프론트 코드에 응급 키워드 목록이 없고 전송 전 119 표시를 하지 않는다(`grep`으로 확인: 프론트 디렉터리에서 `EMERGENCY_KEYWORDS`·`detect_emergency` 0건, 이름은 AG-08 §2의 제안). 음성 인식 글자를 전송하면 서버가 보낸 첫 이벤트 `emergency`의 119가 맨 위에 보인다(응급 문장 1건 수동 시험, PJ2-PRD.md 15.3절 S12).
- [ ] 휴대폰 폭(360px 안팎)에서 가로 스크롤 없이 사진 버튼·확인 카드·고정 문구·119 접근이 보인다.
- [ ] (음성 시험, PRD-08 §9에서 이관) 브라우저 음성 인식이 약 이름 10개를 한국어로 읽는지 k/n으로 기록했다(제품명 오인식은 결과에 적고, 소표본이라 유의성을 주장하지 않는다).

## 3. 하위 작업
- [ ] 사진 올리기·개인정보 가림 안내·전송 고지 화면
- [ ] 인식 중·인식 실패 화면
- [ ] 확인·수정 카드(목록·수정·삭제·약 추가·승인, 기본 선택 없음)
- [ ] 마이크 버튼·음성 듣는 중·음성 미지원 화면
- [ ] 음성 질문 전송 뒤 서버 `emergency` 첫 이벤트를 맨 위에 표시(프론트 키워드 목록 없음, RFP-35-03)
- [ ] 음성 시험(약 이름 10개 한국어)
- [ ] 360px 배치 점검
