## 1. 목적과 운영 방식
- 목적: W3-1(11-23) UI/UX 다듬기 지시를 **하나씩 받아 모은 뒤 한 번에 구현**한다. 사용자 지시(2026-11-23): "pane 하나 열어서 현재 UI/UX 수정을 위해서 티켓을 하나 생성하고, 다음 FE 작업을 위한 지시사항을 하나씩 전달해 줄 테니 먼저 생성부터. 개발은 해당 내용을 모아서 진행하자."
- 운영 방식:
  1. 사용자가 지시를 하나씩 전달하면 §3에 **원문 그대로** `U-nn` 번호로 쌓는다(요약은 "구현 기준 요약"으로 따로 적고 원문은 고치지 않는다).
  2. 사용자가 `모아서 진행`이라고 하면 쌓인 지시를 **한 번에** Opus 5.5 worktree로 구현한다.
  3. **그 전에는 구현에 착수하지 않는다.**

### 3.1 U-01 프로필 병아리 아바타·8색·프로필 전환
- 원문(2026-11-23):
  > 로그인됨에 > 프로필 현재 프로필로 교체
  > 병아리 이미지 + 이름
  > 가족추가에서 병아리에 배경색을 추가하여 프로필 대상의 차이를 인지할 수 있도록
  > 변경 가능한 색은 우선 8가지 정도로 제한해보자
  > 그렇게 되면 본문에서 누가 먹나요? 선택할 필요가 없도록
  > 현재 로그인됨 오른쪽에서 프로필 관리에서도 프로필(누가먹나요) 선택 가능하지만
  > 현재 로그인됨에 호버하면, 등록된 본인 + 가족으로 프로필(누가먹나요) 변경 가능하도록
  > 본문 INPUT에, (일반인|임산부)누가먹는지(이름)) 으로 화면에 표시되도록
  > (일반인|임산부)누가먹는지(이름)) -> 호버하면 역시 위로 프로필(누가먹나요) 선택 가능하도록 UI/UX 변경 진행
- 구현 기준 요약:
  - 계정 버튼 = 현재 프로필의 병아리 + 이름.
  - 8색: `yellow`·`coral`·`pink`·`purple`·`blue`·`teal`·`green`·`gray`(서버 `avatar_color`).
  - 호버·포커스·탭(터치) 모두 지원한다.
  - `선택 안 함` 항목을 유지한다.
  - 마스코트는 응급·금기 결과·고정 문구 영역에 쓰지 않는다(PRD-06-02·03).
  - 서버 `/me`에는 프로필이 없고 색은 `GET /profiles`에서 받는다.
- **구현 결과(2026-11-23, 완료)**:
  - 계정 버튼 = 현재 프로필의 병아리 + 이름(안 골랐으면 `로그인됨`, 게스트는 `계정`). 호버하면 팝오버가 열리고 맨 위에 `선택 안 함`·본인·가족 목록, 구분선 아래에 기존 계정 메뉴가 그대로 있다. 호버로 열 때는 초점을 옮기지 않아 입력 중인 글이 끊기지 않는다.
  - 입력창 첫 줄 칩 `(일반인|임산부) · 병아리 이름`을 누르면 목록이 위로 열린다(누르는 영역 44px). 본문 `TargetPicker`는 삭제했다. 게스트·프로필 없음은 예전 모양이다.
  - 가족 프로필 폼에 `프로필 색` 8칸 라디오(새 가족은 안 쓴 첫 색 제안). 임산부 토글 규칙은 그대로다.
  - 서버 `avatar_color` 계약은 `pnpm gen:api`로 정식 반영했다(DB 적용·verify ok 2026-11-23). 요청 `context`와 AG-21-03 의미는 그대로(색·이름은 요청에 싣지 않음, 시험으로 확인).
  - 마스코트는 기존 `face.png`를 재사용했고 `NoMascotZone` 규칙은 그대로다.

### 3.2 U-02 입력창 아래 고지 통합
- 원문(2026-11-23):
  > 본문에 [공공데이터 기반 정보 제공이며 진단·처방이 아님 · 금기 목록에 없다는 것이 안전하다는 뜻이 아님 · 요양기관의 DUR 점검을 대체하지 않음 / 누가 먹나요 / 선택 안 함] / [질문은 이 탭에만 있고 저장하지 않아요. 새로고침하거나 탭을 닫으면 사라져요. 답변을 만들기 위해 질문과 선택한 프로필 값은 외부 AI(OpenAI)로 전송되며, 제공자 정책에 따라 일정 기간 보관될 수 있어요.] 나눠진 부분도, INPUT 아래 한 문장으로 통합하여 UI 변경
- 추가 원문(2026-11-23, 구 U-05를 이 항목으로 합침):
  > body > `<p data-testid="legal-footer">`공공데이터 기반 정보 제공이며 진단·처방이 아님 · 금기 목록에 없다는 것이 안전하다는 뜻이 아님 · 요양기관의 DUR 점검을 대체하지 않음 & `<p data-testid="input-notice" role="note">`질문은 이 탭에만 있고 저장하지 않아요. 새로고침하거나 탭을 닫으면 사라져요. 답변을 만들기 위해 질문과 선택한 프로필 값은 외부 AI(OpenAI)로 전송되며, 제공자 정책에 따라 일정 기간 보관될 수 있어요.
  > 이를 묶어서 input 하단에 묶어서 배치 내용은 하나의 문구로 합쳐서 요약해줘
- 원문에 함께 적힌 `누가 먹나요 / 선택 안 함` 부분은 입력창 프로필 표시이므로 [3.1 U-01](#31-u-01-프로필-병아리-아바타8색프로필-전환)이 맡는다.
- 구현 기준 요약:
  - `legal-footer`와 `input-notice`를 없애고 입력창 바로 아래 한 단락으로 합친다(작은 글자, 접근성 `role="note"` 유지, 393px·1280px 모두 줄바꿈 확인).
  - 요약해도 **빠지면 안 되는 의미 5가지**: ① 공공데이터 기반 정보 제공·진단·처방 아님, ② 금기 목록에 없다는 것이 안전하다는 뜻 아님, ③ 요양기관 DUR 점검 대체 아님, ④ 질문은 저장하지 않음(탭을 닫으면 사라짐), ⑤ 질문·선택 프로필 값이 외부 AI(OpenAI)로 전송되며 제공자 정책에 따라 일정 기간 보관될 수 있음.
  - 고정 문구는 코드 상수이고 새 문장은 **사용자 승인 전에는 적용하지 않는다**(§4). 기존 상수를 바꾸는 것이 아니라 합친 상수를 더한다(상수 위치는 구현 때 확인).
- 요약 문구 초안(**승인 대기**, 원문에 없는 새 문장):
  > 공공데이터 기반 정보 제공이며 진단·처방이 아니에요. 금기 목록에 없어도 안전하다는 뜻은 아니고, 요양기관의 DUR 점검을 대체하지 않아요. 질문은 저장하지 않고 탭을 닫으면 사라지지만, 답변을 만들기 위해 질문과 선택한 프로필 값이 외부 AI(OpenAI)로 전송되며 제공자 정책에 따라 일정 기간 보관될 수 있어요.
- **구현 결과(2026-11-23, 완료)**: 위 초안을 `INPUT_COMBINED_NOTICE`로 추가하고(기존 `INPUT_NOTICE`·`DISCLAIMER` 상수 유지), 입력창 바로 아래 `<p role="note" data-testid="input-combined-notice">` 한 단락으로 그렸다. 본 화면의 `legal-footer`·`input-notice`는 없앴다(`LegalFooter`는 `/dev/preview`용으로 남김). 의미 5가지·통합 1회·예전 두 줄 0회·12px 이상·320×568 첫 화면 안을 시험으로 확인했다.
- 승인: 사용자 "U-02 문구 승인"(2026-11-23). 코드 주석에 "승인 대기"가 남아 있어 정정이 필요하다(메인 몫).

### 3.6 U-06 계정 버튼 선택 프로필 표기·누가 먹나요 배치·게스트로 이용

### 3.8 U-08 시작 화면 기본 프로필 명시·게스트로 이용 안내·기본 프로필 DB 저장
- 원문(2026-11-23, 사용자 답·지시 그대로):

- 구현 기준 요약(메인 **해석, 확인 대기**):
  1. 시작 화면(body 중앙 병아리 이미지 하단)에 **현재 기본 프로필을 명시**하고 `게스트로 이용` 선택 안내를 띄운다. 안내에서 `게스트로 이용`을 고르면 **기본 프로필이 변경**되고, 안내를 무시하고 질문하면 **선택된 프로필 기준**으로 진행한다. 마스코트는 보조 자리에만 쓰고 응급·금기 결과·고정 문구 영역에는 쓰지 않는다(PRD-06-02).
  2. **기본 프로필 설정을 DB에 저장**하고 **새 세션을 시작할 때마다 그 저장값이 기본값**이 되게 한다(로그인 사용자 한정, 비로그인은 저장 없음). 현재는 로그인 직후 본인을 자동 선택하고 저장은 없다(`stores/account.ts` `resolveTarget()`).
  3. 새 글자(시작 화면 기본 프로필 표시·`게스트로 이용` 안내 문구)가 필요하다. **문안은 구현 전 사용자 승인이 필요**하다(임의로 정하지 않고 후보를 구현 때 올린다).
  4. 확인 대기: 기본값의 의미가 "마지막으로 고른 프로필을 기본값으로 저장"(고를 때마다 저장)인지 "프로필 관리에서 명시적으로 지정한 기본 프로필"인지, `게스트로 이용`도 기본값으로 저장할 수 있는지, 안내를 무시한 경우 동작은 기존 선택 유지로 읽는다.
