## 1. 목적과 운영 방식
- 목적: W3-1(11-23) UI/UX 다듬기 지시를 **하나씩 받아 모은 뒤 한 번에 구현**한다. 사용자 지시(2026-11-23): "pane 하나 열어서 현재 UI/UX 수정을 위해서 티켓을 하나 생성하고, 다음 FE 작업을 위한 지시사항을 하나씩 전달해 줄 테니 먼저 생성부터. 개발은 해당 내용을 모아서 진행하자."
- 운영 방식:
  1. 사용자가 지시를 하나씩 전달하면 §3에 **원문 그대로** `U-nn` 번호로 쌓는다(요약은 "구현 기준 요약"으로 따로 적고 원문은 고치지 않는다).
  2. 사용자가 `모아서 진행`이라고 하면 쌓인 지시를 **한 번에** Opus 5.5 worktree로 구현한다.
  3. **그 전에는 구현에 착수하지 않는다.**

### 3.1 U-01 프로필 병아리 아바타·8색·프로필 전환
- 원문(2026-11-23):
  > 로그인됨에 > 프로필 현재 프로필로 교체
  > 병아리 이미지 + 이름
  > 가족추가에서 병아리에 배경색을 추가하여 프로필 대상의 차이를 인지할 수 있도록
  > 변경 가능한 색은 우선 8가지 정도로 제한해보자
  > 그렇게 되면 본문에서 누가 먹나요? 선택할 필요가 없도록
  > 현재 로그인됨 오른쪽에서 프로필 관리에서도 프로필(누가먹나요) 선택 가능하지만
  > 현재 로그인됨에 호버하면, 등록된 본인 + 가족으로 프로필(누가먹나요) 변경 가능하도록
  > 본문 INPUT에, (일반인|임산부)누가먹는지(이름)) 으로 화면에 표시되도록
  > (일반인|임산부)누가먹는지(이름)) -> 호버하면 역시 위로 프로필(누가먹나요) 선택 가능하도록 UI/UX 변경 진행
- 구현 기준 요약:
  - 계정 버튼 = 현재 프로필의 병아리 + 이름.
  - 8색: `yellow`·`coral`·`pink`·`purple`·`blue`·`teal`·`green`·`gray`(서버 `avatar_color`).
  - 호버·포커스·탭(터치) 모두 지원한다.
  - `선택 안 함` 항목을 유지한다.
  - 마스코트는 응급·금기 결과·고정 문구 영역에 쓰지 않는다(PRD-06-02·03).
  - 서버 `/me`에는 프로필이 없고 색은 `GET /profiles`에서 받는다.

- 이미지(로컬 전용): [이미지 1·3] [ISSUE-101-01](../issues/ISSUE-101-01.png) = 제품 고르기 카드(A/B 칩 + `바꾸기` + `어느 제품인지 고르면…` 줄 + `이 약들로 확인하기`), [이미지 2] [ISSUE-101-02](../issues/ISSUE-101-02.png) = `이 약들로 확인하기` 뒤 화면(`고른 약: …로 다시 확인` 말풍선), [이미지 4] [ISSUE-101-03](../issues/ISSUE-101-03.png) = 진행 표시(`약 찾는 중`·`금기 확인 중`·`근거 찾는 중`).
- 구현 기준 요약(원문 이미지 번호 해석은 **가정**):
  - 문제: `이 약들로 확인하기`를 누르면 직전 Agent 답변의 제품 선택 카드(`A 타이레놀 → … 바꾸기`·`B 게보린 → … 바꾸기`)가 사라진다(ISSUE-101-02는 안내 문장만 남음).
  - 바꾼다: ① 누른 뒤에도 `A 타이레놀 → 타이레놀콜드-에스정 / 바꾸기`와 `B …` 선택 카드는 Agent 답변 안에 **남긴다**. ② `어느 제품인지 고르면 금기를 확인해 드려요.` 줄(칩 묶음·`이 약들로 확인하기` 버튼 영역)은 **숨긴다**. ③ 그다음 `고른 약: …로 다시 확인` 말풍선 뒤에 이미지 4의 진행 표시(`약 찾는 중`→`금기 확인 중`→`근거 찾는 중`)가 이어지게 한다.
  - 숨기기만 하고 고정 문구(`금기 목록에 없다는 것이 안전하다는 뜻이 아니에요. 근처 약국·약사에게 확인하세요.`)는 지우지 않는다(코드 강제).
  - 새 글자는 없다. 기존 문구의 표시·숨김만 바꾼다.
- 확인 대기: ② 숨길 범위가 `어느 제품인지 고르면…` 줄 + 칩 + 버튼 전체인지, 줄 글자만인지(전체로 가정). ③ 이미 있는 진행 표시를 재사용하는지 새로 만드는지는 구현 때 코드를 확인한다.
