## 1. 이슈
사용자 요청(2026-11-18): "사용자의 확인이 필요한 내용을 체크리스트로 만들어서 신규 티켓 발행." 프런트 goal 보고(`data/mock/briefs/reports/goal-fe2.md`·`goal-fe67.md`, 로컬)에서 작업자가 눈으로 확인하지 못해 **사람이 봐야 한다고 남긴 항목**을 한 곳에 모았다. 각 항목은 볼 곳·판단 기준·답 형식을 적었다. 사용자는 답 형식대로 한 줄로 답하고, 답이 오면 에이전트가 항목을 체크하고 근거 티켓(FE-02·FE-06)에 반영한다. 작업자는 이 항목을 대신 체크하지 않는다. 화면을 직접 띄워 보려면 [§7 실행 세팅](#7-실행-세팅)을 따른다(프런트만 띄우면 되고 서버는 필요 없다).

## 2. 완료 조건
모든 항목에 답이 있고 해당 티켓(FE-02·FE-06)에 결과가 반영되어 있으면 이 티켓을 닫는다. 보류 표시(§2.3)는 닫는 조건에서 뺀다. 답 예: `2.1-1 확인함`, `2.2-5 동의`, `2.1-10 ISSUE-008은 …이 문제였음`.

### 7.6 끝내는 법
- 각 터미널에서 `Ctrl+C`를 누른다. 가짜 서버(터미널 2)와 프런트(터미널 1·3) 모두 같다.
- 브라우저에 MSW 서비스 워커가 남아 있어 나중에 가짜 서버로 붙었는데 응답이 이상하면, 개발자 도구에서 해당 주소의 서비스 워커를 등록 해제하고 새로고침한다(가정: MSW는 브라우저에 워커를 등록하는 도구이므로 일반적인 증상. 이 저장소에서 직접 겪은 사례는 확인하지 못함).
- `.env`와 비밀값은 어느 단계에서도 쓰지 않았다. 남는 파일은 없다.

### 7.7 실제 백엔드가 필요하지 않은 이유
실제 백엔드(`app.main`)는 키와 원격 DB(Supabase)·LLM(OpenAI) 호출이 붙어 비용이 든다. 이 체크리스트는 화면 모양·문구를 보는 것이라 필요 없고, 승인 없이 띄우지 않는다. 대신 위 (가)·(나) 구성으로 같은 화면을 그린다(응답 값은 합성이며 약 이름·문장은 원본과 다르다, [§2.1](#21-issue-화면-확인) 설명 참조). 실제 서버 응답과의 대조는 이 티켓 범위 밖이고 FE-01(실연결)과 [FE-02 §5](FE-02.md#5-메모)의 서버 몫이다.
