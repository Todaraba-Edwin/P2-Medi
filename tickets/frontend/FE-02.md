## 1. 이슈
RFP FR-04(출처·조회 시각(또는 자료 기준일)·조항 표기, 쉬운 요약을 먼저 보이고 근거 상세는 펼쳐 보게 함)와 7장 고지("공공데이터 기반 정보 제공이며 진단·처방이 아님", "금기 목록에 없다는 것이 안전하다는 뜻이 아님", "요양기관의 DUR 점검을 대체하지 않음")를 화면에 노출한다. 주 사용자가 일반인이므로 요약은 쉬운 말로 보이고, 의료인·약사를 위한 별도 화면은 두지 않는다.

## 2. 완료 조건
- [ ] 답변마다 출처, 조회 시각 또는 자료 기준일, 조항(해당 시)이 보인다.
- [ ] 답변은 `/chat` 응답의 `summary`(쉬운 요약)가 먼저 보이고, `detail`(근거 상세: 성분코드·등급·조항·기준일)은 펼침 컨트롤로 열어 볼 수 있다.
- [ ] 고지 문구(`disclaimer`)가 화면 상시 영역에 표시된다.
- [ ] 백엔드가 붙인 `fixed_notice`(고정 문구 "금기 없음 ≠ 안전"과 "근처 약국·약사에게 확인" 안내)가 접히지 않는 영역에 모든 답변에서 보인다. 화면에서 이 문구를 만들지 않고 응답 값을 그대로 표시한다.
- [ ] `emergency`가 있는 응답에서 119 안내가 답변 맨 위에 보이고 금기 조회 결과(요약·상세)가 그 아래에 이어진다.
- [ ] 119 안내·거절·근거 없음 응답도 같은 레이아웃에서 구분되어 보인다.
- [ ] (RFP-24-01, PRD-07-02) 화면 고지에 "질문과 입력한 프로필은 답변 생성을 위해 외부 AI 서비스로 전송되며, 제공자 정책에 따라 일정 기간 보관될 수 있습니다"가 포함되어 있다(학습 사용 여부는 단정하지 않는다. 정확한 문구는 이 티켓에서 확정).
- [ ] (PRD-08-07) 사진 입력(FE-05)을 구현하면 전송 고지에 올린 사진도 포함하고 제공자는 OpenAI 하나로 쓴다(문구는 FE-05와 함께 확정).
- [ ] (PRD-07-03) 응급 화면의 119 안내에 휴대폰 전화 걸기 링크가 있다.
- [ ] (RFP-24-04) 휴대폰 화면 폭(360px 안팎)에서 가로 스크롤 없이 119·고정 문구가 첫 화면에 보이고 글자 크기·색 대비가 읽기 쉽다.
- [ ] (PRD-06-03) 금기 발견 결과에는 "삐!" 경고 표지(글자·아이콘, 종류별 경고색은 아래 PRD-09-07·08)를 쓰고 마스코트는 쓰지 않으며 **소리는 쓰지 않는다**. "금기 목록에 없음"·근거 없음·응급(119) 화면에는 "삐!"를 쓰지 않는다. 표지가 고정 문구·근거 상세를 대신하지 않는다.
- [ ] (PRD-09-07·08) 금기 종류마다 배지를 따로 그린다. 병용금기 = 경고 빨강, 임부금기 = 보라/자주 계열이고, 병용·임부가 둘 다 해당하면 배지 2개가 나란히 보인다(순서는 이 티켓에서 정함). 모든 배지에 "삐! 병용금기"/"삐! 임부금기 N등급" 글자가 있어 색만으로 구분하지 않고(G15), 임부 1·2·M은 같은 색이다(G5). 색 값(hex)은 구현 때 글자·배경 대비비 4.5:1을 확인해 정한다. 화면 시험은 PRD-09 §7.5 ④⑦⑧⑨.
- [ ] (FE-06-01) 의약품 관련 영역(약 목록·제품 정보)에는 캡슐 말풍선 아이콘을 쓸 수 있다. 금기 결과·"금기 목록에 없음"·응급·고정 문구 영역에는 마스코트(병아리)를 쓰지 않는다(재확인).
- [ ] (PRD-01-01, FR-10) 되묻기 카드가 후보 표와 질문 1개로 표시되고 후보를 눌러 다시 질문할 수 있다. 가부는 표시하지 않는다. 마스코트는 작게만 쓸 수 있다(PRD-06-02).
- [ ] (PRD-09-01~04, G1~G9) 근거 상세 판정 카드에서 등급은 표지에만 "삐! 임부금기 N등급"(M이면 "M등급" + "적응증에 따라 등급이 달라요")으로 쓰고 보조줄에는 반복하지 않으며, "단계" 글자가 화면에 없다. 파일과 성분 API의 등급이 다르면 출처를 붙여 둘 다 보이고 같으면 "파일·성분 API 일치" 한 줄이다. "임부금기 N등급이란?" 접힘 블록(기본 접힘)에 고시 원문(M은 심평원 설명과 판·표·쪽)을 코드가 렌더하고 LLM이 의역하지 않는다. 화면 시험은 PRD-09 §7.5 ①~④.
- [ ] (PRD-09-05·06, G10~G13) 제품 줄마다 주성분 전체를 한글명 칩으로 보이고 상태를 글자로 붙인다(`금기 원인`·`중복`, 색만으로 구분하지 않음). 5개 이상이면 원인·중복 칩을 먼저 두고 나머지는 `외 N개`로 접는다. 성분코드·원문 염 이름은 칩 아래 작은 글씨이고 함량(mg)은 쓰지 않는다. 화면 시험은 PRD-09 §7.5 ⑤⑥⑦.
- [ ] (PRD-09, 이관) PRD-09 §7.5 ⑧⑨ 화면 시험과 mock fixture 문구(`evaluation/mock_gen/m1_chat.py`) 새 형식 확인, ISSUE-001 화면을 다시 찍어 비교한다. **임부 배지 보라/자주 계열의 hex는 디자인 작업 결과(사용자가 Claude 앱 디자인 세션에 PRD-09를 공유함, 2026-11-09)가 오면 이 티켓에서 정하고** 글자·배경 대비비 4.5:1을 확인한다.
- [ ] (PRD-10-03) 근거 상세 소제목은 공백 포함 13자 이내 짧은 명사형이고 설명 문장이 없다(소제목 상수를 길이로 검사하는 화면 시험).
- [ ] (PRD-10-02·01) "자료 날짜" 구역과 표 형태의 날짜 박스가 없고 "출처" 한 구역의 문장형 한 덩어리에 날짜가 들어간다. 파일·API 날짜가 다르면 `출처명(고시일 …)`으로 둘 다, 같으면 기준일 하나. (형태는 PRD-11-02 A가 아래 조건의 표로 대체한다.) 소제목 "허가정보/허가 라벨" 대신 "허가사항"을 쓴다(출처 줄의 API 이름 "식약처 의약품 허가정보"는 그대로).
- [ ] (PRD-10-04) 허가사항 구역 첫 항목에 허가사항이 무엇인지 한 줄 설명(코드 상수)이 한 번만 나오고, 원문은 `{약 이름} 허가사항 원문({항목}): "…"`로 약 이름·인용부호와 함께 보인다. 전문의약품에는 앞에 "쉬운 설명(e약은요)이 없어서 허가사항 원문을 그대로 보여 드려요" 한 줄이 있다. 대괄호 자리표시가 없다. 화면 시험은 PRD-10 §7 ①~⑩, ISSUE-002 화면을 다시 찍어 비교한다.
- [ ] (PRD-11-01) 근거 상세는 구역마다 소제목 1개 + 흰 박스(판정·사유 원문·허가사항·출처 순, 박스 하나 = 근거 하나)다. 사유 원문도 맨 글이 아니라 박스다. 고정 문구 안내(허가사항 한 줄 설명, 금기 없음 ≠ 안전)는 별도 색 박스다(PRD-11 §4).
- [ ] (PRD-11-02) 출처가 표(1출처 = 1행, 열: 출처·자료·기준일·고시일, 후보)이고 파일·API 날짜가 다르면 각 행에 날짜가 있다. 허가사항 근거가 e약은요인지 허가정보인지 행으로 가른다. 360px에서는 행을 카드형으로 접는다(가정, 구현 때 확인).
- [ ] (PRD-12-01·02) 출처 표는 **기관(대그룹) 한 번만 표시하고 그 아래에 자료(중그룹)를 묶어** 배치한다(같은 기관 반복 없음, 행 병합 또는 머리줄 중 디자인 세션에서 정함, PRD-12 §4). 날짜는 **한 날짜 = 한 줄**이고 `라벨 날짜`(고시일·기준일·조회일)는 줄 중간에서 끊기지 않으며, 기관·자료 이름은 `word-break: keep-all` 같은 개념으로 단어 중간에서 끊기지 않는다. 순서는 응답 배열 그대로(재정렬 없음). 360px에서도 그룹이 유지된다. 화면 시험은 PRD-12 §9 ①~⑬, ISSUE-005를 mock으로 다시 그려 비교한다.
- [ ] (PRD-12-03·04) 모든 근거 박스(사유 원문·판정 포함)의 표지에 자료 이름이 있고(`{종류 문구} · {dataset}`, 예: `공식 문서 · e약은요 쉬운 설명`) 그 문자열이 출처 표의 자료 열과 글자 일치한다. 박스는 헤더 1줄(제목 + 표지 1개) + 본문 + (필요 시) 약사 권고의 3단이고 박스 안 `출처: …·조회일` 줄과 `쉬운 설명(e약은요)` 라벨이 없다(기관·조회일은 출처 표). 문구는 `finalize` 상수를 그대로 쓴다(PRD-12 §7·§8).
- [ ] (PRD-11-05·06) 근거 박스마다 출처 종류 표지(쉬운 말: "공식 자료에서 직접 가져왔어요"·"공식 파일 기준이에요"·"공식 문서에서 찾은 문장이에요", 후보)가 있고 표지 이름이 출처 표의 행과 대응한다. 문구는 `finalize`가 준 상수를 그대로 표시하고 "검색·RAG·청크" 같은 내부 용어가 없다. 색만으로 구분하지 않는다. e약은요 문장에 "허가사항 원문" 라벨을 붙이지 않는다(PRD-11 §7.1).
- [ ] (PRD-11-03, H26·H27) 원문 미확보 박스의 문구는 응답의 상태·`missing_reason`에 대응하는 상수([PRD-11 §6.6](../doc/PRD-11.md#66-하네스-상태와-화면-박스-매핑표) 표)만 표시하고 화면이 문구를 만들지 않는다. 박스 안에 **약사 확인 권고 박스**([PRD-11 §6.7](../doc/PRD-11.md#67-약사-확인-권고-컴포넌트))가 항상 있고(강조 색, 첫 문장 굵게, 접히지 않음) 근거 상세를 접어도 접히지 않는 고정 문구 영역에 한 줄 권고가 보인다. 마스코트·"삐!" 표지는 쓰지 않는다.
- [ ] (PRD-11, 이관) 화면 시험 PRD-11 §8 ①~⑫와 ISSUE-003 같은 질문을 mock으로 다시 그려 전후를 비교한다. **mock 문구 정정**: `evaluation/mock_gen/m1_chat.py:60`·`:230-241`의 라벨("허가사항" → 자료 이름대로), 출처 행 분리, 이지렉트정 미확보 문구(ISSUE-007: "(서비스의 한계예요)" 삭제, "공공 자료로는 설명을 확인할 수 없어요.")·약사 권고를 위 상수와 같게 고치고 "원문을 가져오지 못했어요"를 `grep`으로 0건 확인한다(PRD-11이 쓰기 범위 밖이라 이관).
- [ ] (PRD-14-01·02·04, §5.1~5.3) 미식별 결과: 근거 상세에 **약 이름 단위 박스**(제목 = 입력한 이름 그대로, `입력한 이름`·`찾아본 곳`(건수)·`못 찾은 이유`·`다음에 해 보세요`)가 있고, `찾아본 곳`·보조줄에는 `약 이름 사전`·`공식 약 목록` 대신 기관 이름 `식약처·한국의약품안전관리원 자료`를 그대로 밝힌다(사용자 수정 조건, 기관 확인 전, [PRD-14 §10](../doc/PRD-14.md#10-메모)). 재검색은 곳 목록 밖의 한 줄(`표기를 바꿔 한 번 더 찾아봤어요`)이고 출처 표 대그룹에 `삐약`이 없다. 식별된 약(타이레놀정500)은 결과 카드와 근거 상세에 요약 한 줄(성분·식별 상태 글자, "금기 목록에 없음" 문구 없음)로 보이며, `근거 상세 열기` 줄은 미식별에서 `· 찾아본 곳`이다. 화면 시험 [PRD-14 §6](../doc/PRD-14.md#6-화면-시험) ①~⑧.
- [ ] (PRD-15-01·02, §5) **배지 줄**: 근거 상세 판정 박스 헤더는 **제목 줄 + 배지 줄**이다. 제목(제품명·제품쌍)이 먼저 전체 폭을 갖고(`min(제목 전체 폭, 박스 안쪽 폭)`, 개념: 제목 `flex-shrink: 0`·`max-width: 100%`, 헤더 `flex-wrap: wrap`), 배지는 제목 **아래 별도 줄**에 가로로 나열하며 넘치면 배지 단위로 다음 줄로 넘어간다. 폭이 넉넉하면 제목 옆에 다 들어갈 수 있으나 근거 상세 패널(약 320~380px)은 사실상 항상 아래 줄이다. 제목은 **단어 단위 줄바꿈만**(개념: `word-break: keep-all`, `overflow-wrap: anywhere` 금지)이고 한 글자 폭으로 세로로 쪼개지지 않으며, 배지는 `overflow: hidden`·말줄임·가로 스크롤 없이 잘리지 않고 박스 밖으로 나가지 않는다. 출처 종류 표지(`공식 파일 · …`)는 소제목 줄에 두고 금기 배지 줄에 섞지 않는다. 배지 묶음은 목록으로 읽히게 한다. 순서는 응답 `badges[]` 순서 그대로(재조합·재정렬 없음)이고 그 순서(병용 → 임부 → 연령, 등급 불일치는 파일 → 성분 API)는 BE-06·AG-08이 정한다. 화면 시험은 [PRD-15 §7](../doc/PRD-15.md#7-화면-시험) ①~⑩(ISSUE-011 같은 질문을 mock으로 다시 그려 비교). px·hex·글꼴은 디자인 세션 몫.
- [ ] (PRD-15-02, §4.1) **등급 불일치**(파일 2등급·성분 API 1등급, M 포함)는 배지를 **둘**로 그린다: `삐! 임부금기 2등급 (파일)`·`삐! 임부금기 1등급 (성분 API)`(합친 배지 없음, 등급 비교 표는 그대로 유지). 배지 안 글자는 가능하면 한 줄이고 배지 하나가 박스 폭보다 넓을 때만 단어 단위로 줄바꿈한다(320px에서도 잘림 0건). 병용 + 등급 불일치(배지 3개)도 같은 규칙이다. 배지 문구는 `badges[]`의 값으로만 만들고 화면이 조합하지 않는다.
- [ ] (PRD-15-03, §6) **등급 정의 블록 미확보**: `임부금기 N등급이란?` 블록의 고시 원문을 못 가져오면 응답의 상태·`missing_reason`(`FETCH_FAIL`·`OUT_OF_SCOPE`)에 대응하는 상수 문구와 약사 확인 권고 박스(PRD-11 §6.7)만 표시한다. 화면에 `근거 문장을 찾지 못했어요`가 없고(`grep` 0건), 원문이 없는 정의 블록에 조항 출처 줄을 그리지 않는다(원문이 있을 때는 조항 출처 줄 유지). 정의 블록 fixture는 1·2등급 청크를 모두 둔다(등급 불일치 fixture에서 한쪽만 빈 ISSUE-011 상태를 만들지 않음).
