## 1. 이슈
RFP FR-04(출처·조회 시각(또는 자료 기준일)·조항 표기, 쉬운 요약을 먼저 보이고 근거 상세는 펼쳐 보게 함)와 7장 고지("공공데이터 기반 정보 제공이며 진단·처방이 아님", "금기 목록에 없다는 것이 안전하다는 뜻이 아님", "요양기관의 DUR 점검을 대체하지 않음")를 화면에 노출한다. 주 사용자가 일반인이므로 요약은 쉬운 말로 보이고, 의료인·약사를 위한 별도 화면은 두지 않는다.

- [x] (FE-06-01) 의약품 관련 영역(약 목록·제품 정보)에는 캡슐 말풍선 아이콘을 쓸 수 있다. 금기 결과·"금기 목록에 없음"·응급·고정 문구 영역에는 마스코트(병아리)를 쓰지 않는다(재확인).
- [ ] (PRD-01-01, FR-10) 되묻기 카드가 후보 표와 질문 1개로 표시되고 후보를 눌러 다시 질문할 수 있다. 가부는 표시하지 않는다. 마스코트는 작게만 쓸 수 있다(PRD-06-02). (2026-11-16 체크 정정 [x]→[ ]: **후보 "표"의 사용법·DUR 수록 열이 응답에 없어 열이 없고**, 재질문은 **2단계**(후보 고르기 → "이 약으로 다시 묻기" 버튼, [FE-01-23](FE-01.md#6-결정-현황) A)라 "눌러 다시 질문" 문장과 다르다. 후보 카드·질문 1개·가부 미표시·마스코트 규칙은 충족. 응답에 열 값이 오거나 문장을 2단계에 맞게 정정한 뒤 다시 체크한다. 문장 정정은 사용자 확인 사항 없음, 가정.)
- [ ] (PRD-09-01~04, G1~G9) 근거 상세 판정 카드에서 등급은 표지에만 "삐! 임부금기 N등급"(M이면 "M등급" + "적응증에 따라 등급이 달라요")으로 쓰고 보조줄에는 반복하지 않으며, "단계" 글자가 화면에 없다. 파일과 성분 API의 등급이 다르면 출처를 붙여 둘 다 보이고 같으면 "파일·성분 API 일치" 한 줄이다. "임부금기 N등급이란?" 접힘 블록(기본 접힘)에 고시 원문(M은 심평원 설명과 판·표·쪽)을 코드가 렌더하고 LLM이 의역하지 않는다. 화면 시험은 PRD-09 §7.5 ①~④.

- [ ] (PRD-09, 이관) PRD-09 §7.5 ⑧⑨ 화면 시험과 mock fixture 문구(`evaluation/mock_gen/m1_chat.py`) 새 형식 확인, ISSUE-001 화면을 다시 찍어 비교한다. **임부 배지 보라/자주 계열의 hex는 디자인 작업 결과(사용자가 Claude 앱 디자인 세션에 PRD-09를 공유함, 2026-11-09)가 오면 이 티켓에서 정하고** 글자·배경 대비비 4.5:1을 확인한다.
- [x] (PRD-10-03) 근거 상세 소제목은 공백 포함 13자 이내 짧은 명사형이고 설명 문장이 없다(소제목 상수를 길이로 검사하는 화면 시험).
- [x] (PRD-10-02·01) "자료 날짜" 구역과 표 형태의 날짜 박스가 없고 "출처" 한 구역의 문장형 한 덩어리에 날짜가 들어간다. 파일·API 날짜가 다르면 `출처명(고시일 …)`으로 둘 다, 같으면 기준일 하나. (형태는 PRD-11-02 A가 아래 조건의 표로 대체한다.) 소제목 "허가정보/허가 라벨" 대신 "허가사항"을 쓴다(출처 줄의 API 이름 "식약처 의약품 허가정보"는 그대로).
- [ ] (PRD-10-04) 허가사항 구역 첫 항목에 허가사항이 무엇인지 한 줄 설명(코드 상수)이 한 번만 나오고, 원문은 `{약 이름} 허가사항 원문({항목}): "…"`로 약 이름·인용부호와 함께 보인다. 전문의약품에는 앞에 "쉬운 설명(e약은요)이 없어서 허가사항 원문을 그대로 보여 드려요" 한 줄이 있다. 대괄호 자리표시가 없다. 화면 시험은 PRD-10 §7 ①~⑩, ISSUE-002 화면을 다시 찍어 비교한다.
- [x] (PRD-11-01) 근거 상세는 구역마다 소제목 1개 + 흰 박스(판정·사유 원문·허가사항·출처 순, 박스 하나 = 근거 하나)다. 사유 원문도 맨 글이 아니라 박스다. 고정 문구 안내(허가사항 한 줄 설명, 금기 없음 ≠ 안전)는 별도 색 박스다(PRD-11 §4).
- [x] (PRD-11-02) 출처가 표(1출처 = 1행, 열: 출처·자료·기준일·고시일, 후보)이고 파일·API 날짜가 다르면 각 행에 날짜가 있다. 허가사항 근거가 e약은요인지 허가정보인지 행으로 가른다. 360px에서는 행을 카드형으로 접는다(가정, 구현 때 확인).
- [x] (PRD-12-01·02) 출처 표는 **기관(대그룹) 한 번만 표시하고 그 아래에 자료(중그룹)를 묶어** 배치한다(같은 기관 반복 없음, 행 병합 또는 머리줄 중 디자인 세션에서 정함, PRD-12 §4). 날짜는 **한 날짜 = 한 줄**이고 `라벨 날짜`(고시일·기준일·조회일)는 줄 중간에서 끊기지 않으며, 기관·자료 이름은 `word-break: keep-all` 같은 개념으로 단어 중간에서 끊기지 않는다. 순서는 응답 배열 그대로(재정렬 없음). 360px에서도 그룹이 유지된다. 화면 시험은 PRD-12 §9 ①~⑬, ISSUE-005를 mock으로 다시 그려 비교한다.
- [ ] (PRD-12-03·04) 모든 근거 박스(사유 원문·판정 포함)의 표지에 자료 이름이 있고(`{종류 문구} · {dataset}`, 예: `공식 문서 · e약은요 쉬운 설명`) 그 문자열이 출처 표의 자료 열과 글자 일치한다. 박스는 헤더 1줄(제목 + 표지 1개) + 본문 + (필요 시) 약사 권고의 3단이고 박스 안 `출처: …·조회일` 줄과 `쉬운 설명(e약은요)` 라벨이 없다(기관·조회일은 출처 표). 문구는 `finalize` 상수를 그대로 쓴다(PRD-12 §7·§8).
- [ ] (PRD-11-05·06) 근거 박스마다 출처 종류 표지(쉬운 말: "공식 자료에서 직접 가져왔어요"·"공식 파일 기준이에요"·"공식 문서에서 찾은 문장이에요", 후보)가 있고 표지 이름이 출처 표의 행과 대응한다. 문구는 `finalize`가 준 상수를 그대로 표시하고 "검색·RAG·청크" 같은 내부 용어가 없다. 색만으로 구분하지 않는다. e약은요 문장에 "허가사항 원문" 라벨을 붙이지 않는다(PRD-11 §7.1).
- [x] (PRD-11-03, H26·H27) 원문 미확보 박스의 문구는 응답의 상태·`missing_reason`에 대응하는 상수([PRD-11 §6.6](../doc/PRD-11.md#66-하네스-상태와-화면-박스-매핑표) 표)만 표시하고 화면이 문구를 만들지 않는다. 박스 안에 **약사 확인 권고 박스**([PRD-11 §6.7](../doc/PRD-11.md#67-약사-확인-권고-컴포넌트))가 항상 있고(강조 색, 첫 문장 굵게, 접히지 않음) 근거 상세를 접어도 접히지 않는 고정 문구 영역에 한 줄 권고가 보인다. 마스코트·"삐!" 표지는 쓰지 않는다.
