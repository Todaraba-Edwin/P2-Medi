## 1. 이슈
> **2026-11-18 밤 사용자 결정으로 바뀜(PRD-01-09)**: 2026-11-03의 "소셜 로그인은 다루지 않는다"를 **대체**한다. 로그인은 이메일(PRD-01-05 B) 외에 **소셜 Google·Kakao(S1)·Naver(S2, 연동 방식 확인 뒤)**이고 **Apple은 제외**한다(유료). 프로필은 본인 + 가족 구성원 **최대 3명**(관계 칸, BE-11-01 B)이고 질문할 때 대상을 고른다. 이 티켓은 AG-10-06 A로 축소 대상에서 빠져 S1~S3 범위다(완료 조건 상세 재작성은 설계 문서 `eve-erd` 뒤 후속).

RFP FR-09(확장, 권장): 첫 시작 때 프로필 입력과 저장 동의, 로그인 화면(이메일·소셜)을 제공한다. 응급 상황에서는 로그인·온보딩 없이 바로 질문할 수 있어야 하므로 "게스트로 시작" 경로가 항상 먼저 보인다.

이 티켓은 **확장(권장)** 이다. SCH-02의 필수 티켓이 끝난 뒤에만 착수하고, 일정이 모자라면 가장 먼저 제외한다(RFP 4장, 12장).

## 2. 완료 조건
- [ ] (AG-10-06 A로 바뀜) 스프린트 S1(11-19~20)에 착수했고 핵심 필수 티켓의 진행을 막지 않았다. 미달 시 Naver(S2)·가족 프로필부터 줄인다.
- [ ] 첫 화면에서 "게스트로 시작"을 누르면 로그인·온보딩 없이 채팅 화면으로 가고, 이 경우 프로필이 저장되지 않는다.
- [ ] 온보딩 화면에서 프로필 항목을 선택 입력하고, 저장 동의를 체크하지 않으면 저장 버튼이 동작하지 않는다.
- [ ] (PRD-01-05 B·PRD-01-09) 이메일 가입·로그인 화면과 **Google·Kakao 소셜 로그인 버튼**(S1)이 동작한다. **Naver 버튼은 S2**(연동 방식 확인 뒤), **Apple 버튼은 두지 않는다**(제외). 프로필 입력·수정·삭제 화면(본인 + 가족 구성원 최대 3명, 관계 칸, BE-11-01 B)과 질문 때 대상 선택("누가 먹나요")이 동작한다. 약관·동의 문구는 BE-11 API로 받아 표시하고(BE-11-02 A) 건강 정보는 별도 선택 동의다(BE-11-03 A). "게스트로 시작"이 항상 먼저 보인다.
- [ ] 로그인 후 프로필을 보고 수정·삭제할 수 있다.
- [ ] (FE-06-01) 프로필 설정의 기본 이미지에 병아리 얼굴을 쓴다(위험 정보와 무관한 자리). 본인·자녀·부모 구분 방식은 FE-06 §3.1 열린 질문 ② 답 뒤에 정한다.
- [ ] 채팅 화면(FE-01·FE-02)의 고정 문구·119 안내 배치가 로그인 여부와 관계없이 같다.
- [ ] (PRD-13-01) 로그인·가입·저장 동의·프로필 확인 모달에 버튼만 담는 header 요소·띠와 그 아래 구분선이 DOM에 없다. 코너 버튼은 별도 header 행이 아니라 모달 컨테이너 기준 `position: absolute`이고(본문 흐름 밖, 본문 위 여백은 `padding-top`으로만) `<`는 좌상단(2열이면 왼쪽 열 좌상단), `닫기`는 우상단(오른쪽 열 우상단)에 같은 높이로 마주 본다. 두 버튼의 터치 영역은 각각 44×44px 이상이고 코너 버튼은 스크롤해도 모달 상자에 고정되며(absolute + 본문만 컨테이너 안 스크롤 분리, 또는 sticky 대안은 구현에서 선택) 119 링크·고정 문구를 가리지 않는다(PRD-13 §4.4·§4.7).
- [ ] (PRD-13-02) `<`는 돌아갈 이전 단계가 있을 때만 존재한다. 로그인·가입 첫 화면, **프로필 생성 첫 단계**, 프로필 수정 직접 진입에는 `<`를 그리지 않고(숨김이 아니라 DOM에 없음) 이메일 가입·저장 동의·프로필 입력 다음 단계에서만 이전 단계로 간다. `<`가 없어도 `닫기` 위치는 그대로다(PRD-13 §5 표). ISSUE-006 첫 화면의 `<`는 결함이었다.
- [ ] (PRD-13-04) `닫기`는 글자 `닫기`이고 접근 가능한 이름도 `닫기`, `<`의 접근 가능한 이름은 `뒤로`다. Esc는 단계와 관계없이 닫기와 같다(PRD-13 §4.5·§4.6).
- [ ] (PRD-13) 모달이 열리면 포커스가 제목(또는 첫 입력창, 디자인 세션·구현에서 확정)에 가고 Tab이 모달 밖으로 나가지 않으며 닫히면 "프로필 저장" 버튼으로 돌아온다. 탭 순서(제안 `닫기` → `<`)는 화면 순서(`<` → `닫기`)와 달라 WCAG 2.4.3(포커스 순서)로 점검하고 필요하면 `<` → `닫기`로 바꾼다(PRD-13 §4.5·§11).
- [ ] (PRD-13) 360px에서 2열이 1열로 쌓이고 가로 스크롤이 없다(ISSUE-004 재현 0건). 코너 버튼이 제목·마스코트와 겹치지 않는다(전환 기준 폭은 가정, 디자인 세션·구현에서 정함, PRD-13 §4.3·§4.4).
- [ ] (PRD-13 §7) 화면 시험 ①~⑩을 mock으로 그려 확인했고 ISSUE-006과 같은 상태(금기 결과 위에서 "프로필 저장")의 전후 화면을 비교했다.
