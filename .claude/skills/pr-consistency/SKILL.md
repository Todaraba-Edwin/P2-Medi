# pr-consistency

> 출처(사용자 요청 2026-11-09): "PR 시의 규칙으로 PJ2-RFP.md, schedule.md로 시작해서 하위 전체 문서를 읽고, PR 반영으로 충돌되는 지점을 판단하고 일치성 작업을 진행한다." 등록 결정: RFP-30-03(2026-11-09, CLAUDE.md 2장 스킬 규칙).

## 기준 문서 순서
1. `P2-doc/PJ2-RFP.md`, `schedule.md`, `P2-doc/PJ2-PRD.md` (최종 기준 3종. 다른 문서가 어긋나면 다른 문서를 고치고, 3종이 낡았으면 3종을 고친다)
2. 하위: `schedule-done.md`, `schedule-changelog.md`, `tickets/**`, `P2-doc/*.md`(Harness·로깅·조사 문서), `CLAUDE.md`

## 절차
1. **변경 범위**: `git diff --name-status <base>...HEAD`와 `git diff --stat`로 변경 파일·핵심 용어·수치·결정 번호·티켓 번호를 뽑는다.
2. **기준 읽기**: 위 1번 3종을 처음부터 읽고, 하위 문서는 변경에서 뽑은 용어·번호로 `Grep`해 관련 위치를 모두 연다. 읽지 않은 문서를 "충돌 없음"으로 쓰지 않는다.
3. **충돌 판정** (각 항목에 `파일:줄` 근거):
   - 수치·정의: 평가 지표·목표·n·비용·도구/노드 수(RFP 9장 단일 원본)
   - 결정: 결정 번호·상태·`먼저 답할 결정`·Top 5 ⛔ 칸·티켓 카드 건수의 양방향 일치
   - 참조: 티켓/절 번호, Index, 링크, 선행 관계
   - 불변식: 고정 문구는 코드 강제, 금기 미조회 시 안전 단정 금지, 용량 숫자 요약 금지, 시험셋 비열람, judge 모델·루브릭 고정, 비밀 값 비기재, 표시 이름 `Can I PPiyak`
   - 스코프: 핵심 먼저, 확장 축소 순서(CLAUDE.md 1장)
4. **일치성 작업**: 충돌마다 수정 대상 파일·고칠 문구를 정한다. 분량이 크면 메인에서 직접 쓰지 말고 `schedule-writer`(일정·티켓) 또는 별도 pane 작업자에게 브리프로 맡긴다(CLAUDE.md 2장 위임 규칙). 평가 관련 변경은 RFP 9장과 AG-04·11·12·14·16, BE-08, PRD-03을 같은 작업에서 맞춘다.
5. **검증**: `python3 scripts/check_schedule.py` 실행. 결과(통과/실패/미실행)를 보고에 붙인다.
6. **보고**: 판정(충돌 N건 / 수정 N건 / 사용자 결정 필요 N건), 근거 표, 변경 파일 목록, 현재 Top 5(⛔ 포함)와 Recap, "지금 답할 번호"를 먼저 쓴다.

## 하지 않는 것
- 측정 시작 후 지표 정의·평가 세트를 조용히 바꾸지 않는다(바꾸면 이유·날짜를 9장에 남긴다).
- 사용자 결정이 필요한 충돌은 임의 확정하지 않고 결정 번호·A/B·★로 올린다.
- push·커밋은 하지 않는다(`git-actor`, 사용자 요청 시). `.env`를 열지 않는다.
- 법률 판단은 확정하지 않는다(검토 보류).
