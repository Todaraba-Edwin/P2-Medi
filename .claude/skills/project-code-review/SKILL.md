# project-code-review

> 기본 제공 `/code-review`가 있으면 **먼저 그것을 돌려 일반 결함을 잡고**, 이 스킬은 프로젝트 전용 점검만 더한다(중복 구현 금지). 등록 결정: RFP-30-03(2026-11-09, CLAUDE.md 2장). 요청 2026-11-09.

## 절차
1. `git diff <base>...HEAD`로 변경을 읽는다. 코드가 없으면(문서만) `pr-consistency`로 넘긴다.
2. 아래 프로젝트 점검을 `파일:줄` 근거로 판정한다.
   - **비밀**: 키·연결 문자열·`.env` 값이 코드·로그·테스트·문서에 없는가(변수 이름만 허용). 로그에 질문·대화 내용이 남지 않는가(RFP-34 서비스 모드는 내용 없는 집계만).
   - **고정 문구는 코드**: 119 안내, 약사 확인 안내, 금기 미조회 시 "안전하다" 단정 금지, 용량 숫자 요약 금지가 프롬프트가 아니라 코드(Validator·finalize)로 강제되는가.
   - **판정은 코드**: 금기 판정·정답 산출을 LLM에 맡기지 않았는가. 도구 결과 없이 근거 문장을 만들지 않는가.
   - **그래프 계약**: 노드·도구 이름·호출 상한(8)·되감기(2)가 RFP-23과 일치, 요청 범위 상태(대화 저장 없음).
   - **평가 고정**: judge 모델 ID·루브릭 버전, 평가 세트·지표 정의를 측정 중 바꾸지 않았는가. 개선 코드가 시험셋을 읽지 않는가.
   - **데이터**: 임부금기 CSV는 CP949, 병용금기 JSON은 스트리밍, 출처·기준일(2026-07-21) 표시, `data/`·`data/mock/`·`P2-doc/report/`·`logs/` 커밋 금지.
   - **비용**: mock 생성 20 USD 상한, 개발 비용 장부 상한을 우회하지 않는가.
   - **테스트**: 안전 핵심 경로(응급·금기 없음·오정보)에 테스트가 있는가. 실제로 실행했다면 결과를, 안 했으면 "미실행"을 적는다.
3. 보고: 심각도순 발견 목록(근거·재현 시나리오), 통과 항목, 미실행 항목. 수정은 요청받았을 때만 한다.
